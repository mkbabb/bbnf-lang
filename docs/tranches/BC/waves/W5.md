### §2.2 Endpoint reconciliation: two options + selection criteria

Mechanism: present the two candidate endpoints with selection criteria. Option A: rename `parse-that/rust/regex` to `parse-that/rust/bbnf-regex`; update parse-that workspace membership; update bbnf-lang's path patch. Option B: preserve the existing endpoint `parse-that/rust/regex`; amend BC + GESTALT references accordingly.

Selection criteria:
- **Crate-name canonicality**: the in-tree crate is named `bbnf-regex` (per `audit/MODULES-2026-05-03.md:43`); the path should match.
- **External consumer impact**: parse-that's other crates may reference `parse-that/rust/regex`; the rename touches them.
- **Future crates.io publication**: the published crate is `bbnf-regex`; the path harmony with the crate name eases publication.

Default recommendation: **Option A** (rename to `bbnf-regex`). Justification: crate-name canonicality wins; the rename is a one-time cargo-config update; future crates.io publication has clean source-of-truth.

Files: `docs/tranches/BC/audit/W5-endpoint-options.md` (create — present both options + criteria + default).

Sub-gate: the document presents both options with selection criteria; default recommendation named; user adjudication is the final closer.
