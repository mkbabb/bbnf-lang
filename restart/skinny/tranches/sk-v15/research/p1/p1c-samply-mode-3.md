## Section 1 - Method
Baseline: SK-V15 S-P0 head `279a60646` (`279a606466c60172932629dd9788cd80d6bc82b0`).
Clean source worktree: `/Users/mkbabb/Programming/bbnf-lang-skv15-profile-279a60646`; `git status --short` was empty after removing extractor pycache. The dirty main checkout was not profiled.
Build flags: `CARGO_TARGET_DIR=/tmp/skv15-p1-target RUSTFLAGS='-C target-cpu=native' cargo build --release`; `skinny/Cargo.toml` release and bench profiles carry `debug = true`.
Profile tool: `samply 0.13.1`, interactive `samply record --no-open --rate 4000 --unstable-presymbolicate`; the wrapper terminated only after samply printed the local-server marker and had written `.json.gz` plus `.json.syms.json`.
PMU source: `proc_pid_rusage(RUSAGE_INFO_V5)` via `profile_direct`; cycles and instructions are real. Branch, L1, and LLC counters are not exposed by this macOS source and are recorded absent rather than fabricated.
Command shape: `CRITERION_HOME=/tmp/skv15-p1/criterion/p1c samply record --no-open --rate 4000 --unstable-presymbolicate -o /tmp/skv15-p1/profiles-interactive/p1c/${kind}__${corpus}.json.gz <bench-binary> <filter> --sample-size 10 --warm-up-time 0.001 --measurement-time 0.05 --noplot`. Criterion rejects zero warm-up, so P1-C uses the smallest positive warm-up accepted by the harness and does not use these rows as cold PMU admission evidence.
Artifact existence is recorded in `restart/skinny/tranches/sk-v15/research/p1/evidence/artifact-manifest.tsv`.

## Section 4 - Anomalies
- `profile_direct` has no mode-III entry points; using it for P1-C would be an invented workload. The actual bench filters were used.
- Criterion refuses `--warm-up-time 0.0`; the captured profiles therefore carry a stated warm-up caveat.
- Structural scan profiles frequently show hash/checksum work as the top leaf, so S-P2 must not mistake these for parser kernel wins. These rows do not reopen REDRESS-50-55, REDRESS-60-72, REDRESS-80, REDRESS-82-84, REDRESS-88, or REDRESS-89.
