Equality is **not reached**. The divergences split into two distinct causes.

### Cause (a) — INTRINSIC: value-node vs component-token taxonomy

`track1_values=68491` counts typed-AST value **nodes**; `cssparser_values=99614`
counts component **tokens**. These taxonomies cannot be made numerically equal
without flattening the rich AST (forbidden by `preserve-rich-ast`) or adding a
token-counting projection on the typed side (defeats the typed model). The
`spans` field is similarly mutually-impossible (cssparser emits none).

### Cause (b) — BUILDER/PROJECTION BUGS (closable, not intrinsic)

Located precisely. `@media` is misclassified as an empty-name `GenericAt`
(`media 0/109` across every file; `generic` over-counts), which cascades into
declaration double-count (`decl 35852/20043`) via generic-at body descent, and
the selector slab is never populated (`sel 0` everywhere).

Root cause: `crates/core/src/runtime/css_l4/builder.rs` `push_leaf_with_str`
(lines 664-689) has match arms for `Declaration`, `Function`, `KeyframesRule`,
`KeyframeBlock`, `MediaRule`, `SelectorList`, `HexColor` — but **no arm for
`OpenFrame::GenericAtRule`**. The `GenericAtRule` frame itself IS defined
(`builder.rs:26`, opened at `:339`, closed at `:434`), but because no leaf-str
arm captures its name, the at-rule name falls through to the catch-all
`_ => self.deposit_value(CssTypedValue::Span(...))` (`builder.rs:688`), leaving
the name empty. `@media` therefore lands as an empty-name `GenericAt` instead of
a `MediaRule`. This is emitted from `xtask/runtime-projections/css_l4.toml` and
must be fixed at the projection, then regenerated — never hand-patched.

**This axis is NOT closed.**
