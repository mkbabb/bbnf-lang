## §1 Deliverable

W3 is the wave where the per-domain optimisers compose into one pipeline. The pipeline is a sequence of path-dep'd crate boundaries: CSP type inference (`crates/ir/src/passes/types/`) → e-graph saturation (`crates/ir/src/egraph/`) → recogniser miners (`crates/ir/src/passes/recognizers/`) → CSP strategy selection (`crates/ir/src/passes/csp_strategy/`) → cost-model extraction (`crates/egraph/src/extract.rs`). Each is a path-dep crate after BB.W0; output is piped to the next stage; no fused unified hypergraph per Lock 4 (`docs/HARDENING-PLAN-PROMPT.md:40`).

The auto-detection deliverables: Pratt parsing emerges from `recognizers/operator_chain.rs` mining of left-recursive operator chains in the grammar; SIMD scanner emergence from `passes/sets/structural_alphabet.rs` mining of leaf-pattern shape (charclass / keyword set / regex) feeds into the `simd-scan` kernel selector. No grammar declares `@pratt` or `@simd` per Lock 10 (`docs/HARDENING-PLAN-PROMPT.md:52`); the optimiser mines and emits accordingly. The cost model decides when SIMD overhead is worth the dispatch cost — a `simd_threshold_bytes` parameter is grammar-derived from FIRST set + structural-alphabet density, never user-declared.

Each stage's output is the next stage's input through path-dep'd crate boundaries. Per Lock 4, no fusion: e-graph operates as its own crate; CSP strategy selection consumes e-graph output via the trait surface; the cost model at `crates/egraph/src/extract.rs` is the e-graph's interface to the CSP solver, not a fused subsystem.

The Pratt detection at `recognizers/operator_chain.rs` mines left-recursive operator chains: the recogniser walks the IR and identifies rules with the shape `expr := factor (op factor)*` where `op` has a closed enumerated set. The recogniser feeds a `OperatorChainFacts { precedence, associativity, op_set }` record to the cost model. The cost model decides Pratt vs. non-Pratt emission based on the chain depth + the alt-branch cardinality.

The SIMD detection at `passes/sets/structural_alphabet.rs` mines the structural alphabet (the set of bytes the grammar dispatches on at the top level): JSON's `{`, `}`, `[`, `]`, `,`, `:` (cardinality 6); CSV's `,`, `\n` (cardinality 2); BBNF's `:`, `;`, `:=`, `|`, `(`, `)`, `[`, `]`, `{`, `}` (cardinality ~10). The cost model has a `simd_threshold_bytes` parameter computed from FIRST set + structural-alphabet density: at small alphabets (CSV cardinality 2), the SIMD cost amortises over fewer dispatch hits, so the threshold pushes scalar emit; at moderate alphabets (JSON cardinality 6), SIMD wins for inputs ≥ 1 KB; at large alphabets (CSS L4 cardinality ~25), SIMD wins for inputs ≥ 256 B.
