# AZ-IV.W2 - Path IR + Typed Path<G,T> + AscentStrategy

**Name**: W2 - Path IR + Typed Path<G,T> + AscentStrategy
**Opens after**: W1 - Grammar Generality + Test Redress
**Agents**: 5 parallel writer slots
**Hard gate**: `path!(Grammar, ...)` resolves at compile time against `StructRegistry`; invalid paths fail to compile with grammar-aware diagnostics; AscentStrategy trait is the reversal seam; wildcard returns lazy iterators; variant-selection step works on typed-enum sums
**Status**: planned

## Scope

This wave lands the typed compile-time Path IR + the `path!` proc-macro + the IR `path_check` pass + the bespoke path lexer (custom HIR exposed from `bbnf-regex`) + the hybrid sidecar `AscentStrategy`. No path *execution* yet — execution lands in W3 (lazy bail-out parse) and W5 (TS binding). This wave produces the types, the type errors, the macro, and the ascent seam.

1. Define the Path IR: `Path`, `PathSegment`, `TypedPath<G, T>`, `PathError`, `IntoPathSegment` extended with typed-enum variant selection (Q4 = (a)) and wildcard segments (Q2 = lazy-iter idiom).
2. Implement the IR `path_check` pass at `crates/ir/src/passes/path_check.rs`. Pass runs **after** `project_types` per Q1 (source rules) and traces inlined paths through an inline-trace sidecar so source rule names always resolve.
3. Land the bespoke path lexer as a custom HIR API exposed from `crates/bbnf-regex/src/path_lexer.rs` per Q-final D1 = (b). The lexer parses path-string literals (`"$.statuses[0].text"` style) and yields `proc_macro2::Span`-anchored tokens for diagnostic anchoring.
4. Land the `path!` proc-macro at `crates/bbnf-path/src/path_macro.rs`. The macro consumes the bespoke lexer's tokens, resolves each segment against the compile-time `StructRegistry` (provided by the grammar's derive input), and emits a `TypedPath<G, T>` literal. A malformed path fails the surrounding `cargo build` with a `proc_macro2::Span`-anchored diagnostic naming the offending segment, the resolved struct type, and valid alternatives at that position.
5. Define the `AscentStrategy` trait at `crates/core/src/path/ascent.rs` with the hybrid-sidecar default implementation. The trait is the **reversal seam** per BA's pre-recycle Q1 resolution: alternative impls (in-struct parent pointer, root traversal) plug in for a future tranche if benchmark evidence forces inversion.
6. Run the parent-pointer micro-bench on citm / tailwind / sheets fixtures **inside W2** (matches BA pre-recycle BA.W0 plan): three candidate strategies (in-struct pointer, root traversal, hybrid sidecar) measured against ascent-heavy paths. Default pick lands in the W2 close commit with the micro-bench artefact at `docs/tranches/AZ-IV/audit/W2-ascent-microbench.json`.
7. Variant-selection path step (Q4 = (a)). When the typed value is a sum (e.g. `CssTypedValue::Color(_) | Length(_) | Selector(_) | ...`), a name-keyed step selects the variant per the grammar's `->` annotation. `path!(CssL4, "rules", 0, "declarations", 0, "value", "color")` returns `Option<&CssColor>` from `CssTypedValue::Color(_)`. The macro reads the grammar's variant names from the `StructRegistry` populated by `project_types`.
8. Wildcard segments (Q2 hybrid). Default lane: `path!(..., "*", ...)` returns `Iter<Item = T>` lazy-flatten, zero allocation, matches sonic-rs / simdjson idioms. `.with_anchors()` adapter yields `Iter<Item = (Path<'_>, T)>` for re-anchorable usage. `.collect()` materializes when the caller wants (`Vec<T>`, no structural recursion). Wildcard depth cap with grammar-aware diagnostic on overflow.
9. Path egraph rewrites: hand-authored small ruleset for duplicate-prefix elimination, redundant downcast removal, adjacent-accessor fusion. BA recreates the discovery layer; AZ-IV ships the hand-authored seed.

## Triumvirate Dispatch

Dispatch a triumvirate if any of these occurs:

- the IR `path_check` pass needs a second IR pipeline pass (anything beyond the inline-trace sidecar) to resolve paths against post-pipeline rule names;
- macro hygiene forces a host-language-specific substitution (path-string literals containing identifier-like fragments resolving differently in different contexts);
- wildcard expansion explodes (path-resolution time grows super-linear in grammar size); the depth cap diagnostic must catch this — failure to catch is a triumvirate trigger;
- the AscentStrategy micro-bench result invalidates the hybrid-sidecar default and forces a different impl mid-wave (root-traversal default or in-struct pointer default);
- the `bbnf-regex` path-lexer API requires more than ~200 LOC or pulls in regex-syntax dependencies (per D1 commitment to bespoke lexer);
- variant-selection ambiguity (a typed-enum has two variants with the same grammar `->` annotation) cannot resolve via the StructRegistry alone;
- three diagnostic loops fail to isolate a path-resolution edge case.

Empty/no-evidence returns get one verbatim redispatch with the same worktree pointer. A second empty/no-evidence return triggers mandatory triumvirate. Three diagnostic-loop iterations without isolating root cause auto-trigger triumvirate. JSONL transcript quiet >15 minutes is an orchestrator-side auto-trigger; record the condition and dispatch time in `PROGRESS.md` alongside the wave's evidence ledger.

## Agent Units

### AZ-IV.W2.1 Path IR + Type Checker + Error

- Mechanism: define the Path IR as Rust types with no execution. `Path<'a>(&'a [PathSegment<'a>])` is the borrowed form (W1 path-alphabet stays). `TypedPath<G, T>` is the new compile-time-typed form: `G` is the grammar marker (`Json`, `CssL4`, `Sheets`, `Bbnf`); `T` is the terminal type (extracted from the grammar's StructRegistry by the macro). `PathSegment` extends with `Wildcard` and `VariantName(&'static str)` variants. `PathError` carries `{ segment_index, segment_str, struct_name, alternatives: Vec<&'static str>, reason }`.
- Files: `crates/core/src/path/ir.rs`, `crates/core/src/path/type_check.rs`, `crates/core/src/path/error.rs`, `crates/core/src/path/mod.rs`.
- Sub-gate: types compile cleanly against the workspace; no runtime resolver yet (`type_check.rs` consumes `StructRegistry` and returns `Result<TypedPath<G, T>, PathError>`); fixture tests in `crates/core/tests/path_typed_compile.rs` and `crates/core/tests/path_type_errors.rs` cover the IR surface.

### AZ-IV.W2.2 `path_check` IR Pass + Inline-Trace Sidecar

- Mechanism: add `crates/ir/src/passes/path_check.rs` to the IR pipeline. Pass runs **after** `project_types` so `StructRegistry` is populated and post-pipeline transformations are visible. The inline-trace sidecar at `crates/ir/src/passes/inline_trace.rs` records the rule-substitution map produced by `inline_acyclic` + `force_inline` + `fuse_single_use`. When a `path!` literal names a source rule the user wrote, `path_check` walks the inline trace to re-resolve the path against the post-pipeline struct that absorbed the inlined rule. Source rule names always resolve (per Q1); post-pipeline transformations stay invisible to the user.
- Files: `crates/ir/src/passes/path_check.rs`, `crates/ir/src/passes/inline_trace.rs`, `crates/ir/src/passes/mod.rs` (register pass).
- Sub-gate: a fixture grammar with a rule that gets fused by `fuse_single_use` still resolves a `path!` against the source rule name; the inline-trace sidecar produces a deterministic map (golden test); `path_check` IR-pass test surface 100 % pass.

### AZ-IV.W2.3 bbnf-regex Path Lexer (custom HIR API)

- Mechanism: expose a new path-lexer API from `crates/bbnf-regex/src/path_lexer.rs`. The lexer parses path-string literals using a hand-rolled recursive-descent over the path alphabet (`[A-Za-z_][A-Za-z0-9_]*`, `[0-9]+`, `[`, `]`, `.`, `*`, `$`). It produces a `Vec<PathToken { kind, span: proc_macro2::Span, text: &str }>`. The lexer is bespoke per D1 to keep the path-macro crate narrow (≤ 200 LOC); it does not depend on `regex-syntax`. The bbnf-regex re-export lets future tranches relocate `bbnf-regex` to a sub-crate of parse-that without breaking the macro crate's import path.
- Files: `crates/bbnf-regex/src/path_lexer.rs`, `crates/bbnf-regex/src/lib.rs` (re-export).
- Sub-gate: lexer ≤ 200 LOC; deterministic Span attribution on every token; round-trip test for adversarial path strings (whitespace, escaped quotes, Unicode identifiers); integrates with `proc_macro2` cleanly (no host-language-specific substitution).

### AZ-IV.W2.4 `path!` Proc-Macro

- Mechanism: implement the `path!` proc-macro at `crates/bbnf-path/src/path_macro.rs`. The macro consumes path-string literals + a grammar marker, dispatches through W2.3's lexer to produce tokens, walks tokens against the compile-time `StructRegistry` (provided by the grammar's derive input), and emits a `TypedPath<G, T>` literal. A malformed path produces a `proc_macro2::Span`-anchored diagnostic via `syn::Error::new` (the `proc_macro2::Span` from the lexer flows through to the diagnostic). The macro crate is `proc-macro = true` and cdylib-free (Rust-only frontend); the future TS template-literal tag (W5) is a separate cdylib that consumes the same Path IR.
- Files: `crates/bbnf-path/Cargo.toml`, `crates/bbnf-path/src/lib.rs`, `crates/bbnf-path/src/path_macro.rs`, `Cargo.toml` (workspace member).
- Sub-gate: `path!(Json, "statuses", 0, "text")` expands to a typed `TypedPath<Json, &str>` value at compile time; an invalid path (`path!(Json, "statuses", 0, "nope")`) fails compilation with a diagnostic naming `nope`, the resolved struct type for `statuses[0]`, and valid alternatives; macro test surface 100 % pass.

### AZ-IV.W2.5 AscentStrategy + Micro-Bench + Wildcard + Variant-Select

- Mechanism: define `AscentStrategy` trait at `crates/core/src/path/ascent.rs`. Three impls: `RootTraversal` (no node bloat, descent cost on every ascent), `InStructPointer` (8 B per node, O(1) ascent — node bloat even when feature unused), `HybridSidecar` (parallel `Vec<NodeId>` indexed by depth-first order, populated only when ascent is requested; default). The trait is the reversal seam: a future tranche swaps the impl by changing one type alias. Run the parent-pointer micro-bench on citm / tailwind / sheets fixtures with ascent-heavy paths. Land the default pick in the W2 close commit; commit body cites the micro-bench result.
  Wildcard implementation in `wildcard.rs`: `Wildcard` segment expands to `Iter<Item = T>` (lazy flatten, no allocation by default). `.with_anchors()` adapter wraps the iter to yield `(Path<'_>, T)`. `.collect()` is the standard collect — call-site choice. Depth cap (config: 8 by default) prevents wildcard explosion; an overflow produces a grammar-aware diagnostic.
  Variant-selection in `variant_select.rs`: when the path step is a `VariantName(name)` against a typed-enum's `StructLayout`, the resolver looks up the variant by its `->` annotation in the StructRegistry. A typed-enum with no matching variant fails compilation. Ambiguity (two variants with the same `->` annotation) is a grammar-author error and fails compilation with a fixture-named diagnostic.
- Files: `crates/core/src/path/ascent.rs`, `crates/core/src/path/wildcard.rs`, `crates/core/src/path/variant_select.rs`, `crates/core/benches/path_ascent.rs`, `docs/tranches/AZ-IV/audit/W2-ascent-microbench.json`.
- Sub-gate: AscentStrategy trait compiles with three impls; default selected via micro-bench artefact; wildcard returns `Iter<Item = T>` zero-allocation on a 100-element fixture (dhat-verified); `.with_anchors()` and `.collect()` adapters compile and pass fixture tests; variant-selection step compiles for `CssTypedValue::Color(_)` and produces `Option<&CssColor>` at call site.

## Hard Gate

1. `path!(Json, "statuses", 0, "text")` resolves at compile time to a `TypedPath<Json, &str>` with no runtime path errors.
