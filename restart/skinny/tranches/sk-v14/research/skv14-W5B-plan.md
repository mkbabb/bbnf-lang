## Decision

Do not delete provider modules or template directories under the current W5B
SPEC. W5B requires provider-free generation to exist before deletion, but HEAD
still produces runtime bytes through the old provider/template renderers inside
codegen. A deletion redress would either fail to compile or move the same
hand-written bodies under a different name. Both routes violate REDRESS-209 and
the no-workarounds discipline.

## Evidence

The provider/template roster still exists:

```sh
find skinny/crates/codegen/src -maxdepth 1 -type f -name '*_provider.rs' | sort
find skinny/crates/codegen/src -maxdepth 1 -type d -name 'css_l4_*_templates' | sort
```

The old dispatch mesh is still load-bearing:

```sh
rg -n "render_runtime_profile|RuntimeProvider|json_provider|css_l4_.*provider" \
  skinny/crates/codegen/src/lib.rs \
  skinny/crates/codegen/src/grammar_profile.rs \
  skinny/crates/codegen/src/grammar_provider.rs
```

The written SPEC grep is tool-inaccurate when run with ripgrep from repo root:

```sh
rg -nE 'match\s+\w+\s*\{[^}]*Json\s*=>|CssL4\s*=>|Bbnf\w*\s*=>|GoogleSheets\w*\s*=>' crates/
# ripgrep treats -E as encoding and errors.
```

Rewriting that command as a ripgrep pattern also scans root `crates/`, where
historical audit tag variants already exist outside W5B ownership. The intended
gate must target the skinny generic-codegen forward surface with ripgrep-correct
syntax and a production-code scope.

## Rejected Routes

- Reading committed generated runtime output as the source of generated bytes.
- Deleting provider files while preserving equivalent per-grammar templates
  under new names.
- Borrowing W6's root-runtime collapse budget to make W5B appear admitted.

2. Move provider/template deletion and post-W5 Lock 14 baseline close after
   that provider-free generator admits.
3. Repair the W5B Lock 14 grep to use ripgrep-correct syntax and the intended
