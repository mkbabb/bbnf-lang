## Scope

W1 carves the iteration surface to the AY-III working set. The
post-B5 `iter-check-full` cold wall measures > 660 s — the full-
workspace ax-iter check links the four heavy crates (gorgeous,
bbnf-bootstrap, bbnf-analysis, bbnf-lsp) plus the egraph and CSP
scheduler with every saturation rule eager. The AY-III tranche
exercises a smaller working set: the egraph plus CSP scheduler,
the IR pipeline's mining and lowering passes, and the `bbnf` core
crate — gorgeous and bbnf-lsp are downstream of AY-III's hot
path. W1 closes the gap with two parallel changes:

1. **Egraph lazy-pass deferral** (W1.a) — `BackoffScheduler::run`
   classifies each rule by its `--check` consumer-count metadata.
   Rules whose consumer-count is zero downstream of the regen-
   check entry defer to a `lazy_run` invocation triggered only by
   `cargo xtask regen --check`. Routine `iter-check` skips the
   deferred passes; the egraph cold-link surface shrinks
   accordingly. The CSP scheduler at `crates/egraph/src/csp_
   scheduler.rs` mirrors the deferral.
2. **`iter-check-az` carve-out alias** (W1.b) — a new alias in
   `.cargo/config.toml` targeting AY-III's working set: the
   workspace minus the four heavy crates plus any downstream-of-
   egraph crates AY-III's plan declares non-load-bearing for
   routine iteration. Cold wall ≤ 30 s structural floor.
3. **Gorgeous default-features audit** (W1.b) — verify
   `crates/gorgeous/Cargo.toml` carries `default = []` already
   (the pre-tranche audit confirms it does); capture the no-op
   proof in `audit/W1-iter-az-scope.md` so the invariant 6
   (no path duplications) gate has a runtime artefact.

The two W1 agents share no file write access — W1.a owns
`crates/egraph/src/scheduler.rs` and `crates/egraph/src/csp_

### W1.a egraph lazy passes

`BackoffScheduler::run` (at `crates/egraph/src/scheduler.rs:71`)
iterates every rule against the egraph each saturation pass.
Pre-W1, every rule fires regardless of whether the regen
`--check` entry consumes its output; W1 introduces a
classification step:

```rust
// crates/egraph/src/scheduler.rs

impl<N: Language, A: Analysis<N>> Scheduler<N, A> for BackoffScheduler {
    fn run(&self, egraph: &mut EGraph<N, A>, rules: &[&dyn RewriteFn<N, A>]) -> RunReport {
        // Classify rules: eager fire on every iter-check; lazy fire
        // only when the regen --check entry calls `lazy_run`.
        let (eager, deferred) = classify_rules(rules);
        // Run eager rules per existing logic against `egraph`.
        let mut report = run_eager(self, egraph, &eager);
        report.per_rule.extend(deferred.iter().map(|r| (r.name().to_string(), 0usize)));
        report
    }

    fn lazy_run(&self, egraph: &mut EGraph<N, A>, rules: &[&dyn RewriteFn<N, A>]) -> RunReport {
        // Called only by `cargo xtask regen --check`.
        let (_, deferred) = classify_rules(rules);
        run_eager(self, egraph, &deferred)
    }
}
```

`classify_rules` reads each rule's `consumer_count` metadata —
zero when no production code path reads the rule's output;
positive when the regen `--check` or runtime materialiser path
consumes it. The classification is static at codegen time;
runtime cost is negligible.

The CSP scheduler at `crates/egraph/src/csp_scheduler.rs`
mirrors the same shape. The plan-time LOC budget is ~80 lines
across the two files plus ~30 lines of audit doc.

### W1.b iter-check-az alias + gorgeous audit

The current `.cargo/config.toml` `[alias]` block carries:

- `iter-check` — workspace minus 4 heavy crates (gorgeous,
  bbnf-bootstrap, bbnf-analysis, bbnf-lsp). Routine surface.
- `iter-check-{lsp,prettify,bootstrap}` — fast-paths for the
  three excluded crates (the fourth, bbnf-bootstrap, has
  `iter-check-bootstrap`).
- `iter-check-full` — close-ceremony surface; full workspace.

W1 adds:

```toml
# AY-III working-set carve-out: workspace minus the four heavy
# crates AND minus the egraph's deferred-pass consumer crates.
# Pairs with `BackoffScheduler::run` lazy-pass deferral; the
# routine surface skips passes whose `--check` consumer-count is
# zero. Hard gate: cold ≤ 30 s.
iter-check-az = "check --profile ax-iter --workspace --exclude bbnf-bootstrap --exclude gorgeous --exclude bbnf-analysis --exclude bbnf-lsp"
```

The exact `--exclude` set may extend to additional crates if
AY-III's plan declares them non-load-bearing for routine; W1.b
captures the final scope at `audit/W1-iter-az-scope.md` with
one-line rationale per inclusion.

The gorgeous default-features audit is essentially no-op: the
existing `crates/gorgeous/Cargo.toml` line 63 reads `default =
[]`. W1.b confirms via grep and captures the artefact.

## Archaeology

The egraph saturation pattern traces back to the AA tranche's
introduction of egraph rewrites; `BackoffScheduler` has stayed
broadly stable since AA.0. Pre-W1 audits had not classified
rules by `--check` consumer-count; the classification is novel
to W1.

The four-heavy-crate exclusion pattern traces to B1.W0's
introduction of `iter-check` (commit `416dcf76` per `docs/
benchmarks/post-B1-W0-routine.txt`). B1.W0 measured 0.16 s warm
on the routine surface (45× speedup over `cargo check
--workspace` warm); the post-B1 `iter-check-full` cold wall
> 660 s is the unaddressed remainder. W1 narrows further with
the `iter-check-az` carve-out and the egraph lazy pattern; the
combined cold reduction targets ≥ 30 % vs the pre-B6 baseline.

The gorgeous default-features audit is essentially no-op
verification — the line `default = []` already exists at
`crates/gorgeous/Cargo.toml:63`. The audit's purpose is the
artefact: invariant 6 (no path duplications) gates on a
runtime-verifiable claim, and the no-op audit captures that
claim with a grep citation.
