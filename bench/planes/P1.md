# P1 — JSON check

**Unit:** sk-v27 LW2.CON-1. **Goals:** G-J1 (P1 check), G-E1 (error offsets). **Family:** F-JSON-P1.

## What an arm does

It decides whether the whole input is one JSON text under the policies below, and on rejection it reports the error offset. It builds no value. Its output-parity class is **CHK**: per input, the verdict (ACCEPT or REJECT) and, after REJECT, the error offset.

An arm that builds a value (a DOM, a tape, a typed struct) and then discards it is a P1 arm only if the row says so in its work checklist: the extra work is charged to that arm, never subtracted.

## Policies

These are the policies of `bench/contest/oracle_json.py`, the reference oracle. The JSON text is RFC 8259 §2–§7.

| Policy | P1 rule |
|---|---|
| **UTF-8 validation** | The input must be well-formed UTF-8 (RFC 8259 §8.1; Unicode 15 §3.9 D92). Every byte is checked, inside strings and outside them. A byte-order mark is rejected at offset 0 (RFC 8259 §8.1 forbids generating one; this plane does not ignore it). |
| **Escapes** | The eight two-character escapes and `\uXXXX` are accepted. A high-surrogate escape must be followed at once by a low-surrogate escape; an unpaired surrogate escape of either kind is rejected. Any other byte after `\` is rejected. A raw byte below 0x20 inside a string is rejected. |
| **Number fidelity** | The number grammar of RFC 8259 §6: no leading zero, no bare `.`, no `+` sign, no hexadecimal, no `NaN` or `Infinity`. A number whose correctly rounded binary64 value is infinite is rejected (`1e400`). P1 builds no number, but it applies this range rule, because P4 does and the two planes must reject the same inputs. |
| **Duplicate keys** | Accepted (RFC 8259 §4 permits them). P1 does not compare keys. |
| **Error offsets** | The offset is a byte offset from the start of the input. For a syntax error it is the first byte that cannot extend the input to a JSON text (the length of its longest valid prefix); for truncated input that is the input's length. For ill-formed UTF-8 it is the first byte of the maximal ill-formed subpart (Unicode §3.9 D93b). For a bad or unpaired escape it is the offset of its backslash. For a number out of range it is the offset of the number's first byte. When a syntax error comes before the first ill-formed UTF-8 byte, the syntax error's offset is reported. |
| **Nesting** | Depth is not limited by the plane. An arm with a depth limit states it in its checklist; a witness or corpus input deeper than that limit makes the pair NOT-COMPARABLE, not a rejection. |
| **Whitespace** | Only space, tab, line feed and carriage return, before and after any token. |

## Witness inputs

`bench/planes/witness/json/` (shared with P3–P6). Each file exercises one rule above; its name says which (`esc-*`, `utf8-*`, `num-*`, `dup-*`, `order-*`, `err-*`, `ws`, `nested`). Admission (`bench/contest/admit.py`) runs both arms of a cell on every witness and refuses the cell on any disagreement in the class's fields.

## Equal work

- Both arms read the whole input; neither may stop at the first structural close.
- Both arms validate UTF-8 over the whole input. An arm that validates only string contents, or skips validation of skipped values (a "skipper"), lists the missing work and is not a P1 arm until it does it.
- In-situ arms copy their buffer outside the timed region.

## Comparators

simdjson DOM parse with the tape discarded, simdjson On-Demand with a forced full traversal, simd-json and sonic-rs equivalents. A row that has no equal-work API is "no comparator" (competition C1-5). See `bench/contest/ROWS.tsv`.
