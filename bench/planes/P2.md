# P2 — CSS tokenize and parse (token and event stream)

**Unit:** sk-v27 LW2.CON-1. **Goals:** G-C1 (G-C1a against cssparser; G-C1b against lightningcss on the typed-coverage manifest only, see P7), G-G1 (CSS at P2), G-E1. **Family:** F-CSS-P2.

## What an arm does

It consumes the whole stylesheet as CSS Syntax Level 3 tokens and the rule/declaration events built from them, and walks a checksum of every token and event inside the timed region (G-C1's "full-consumption event checksum"). Its output-parity class is **TOK**: per input, the verdict and, after ACCEPT, the digest of the canonical event stream.

CSS has no fatal syntax errors: every input is ACCEPTed, and a parse error is an event in the stream (CSS Syntax 3 §2.2). REJECT is reserved for input the plane refuses before tokenizing (below).

## Policies

| Policy | P2 rule |
|---|---|
| **UTF-8 validation** | The bytes are decoded as UTF-8 with replacement (CSS Syntax 3 §3.2, "decode", which uses the WHATWG Encoding standard's UTF-8 decode: each maximal ill-formed subpart becomes U+FFFD). An arm that rejects ill-formed input instead, or reads bytes as Latin-1, is plane-inequivalent on the `utf8-*` witnesses. A leading BOM is removed by the decode. Input preprocessing then applies (§3.3): CR, FF and CR LF become LF; U+0000 becomes U+FFFD. |
| **Escapes** | Identifier, string, URL and hash token values hold their unescaped code points (§4.3.7, "consume an escaped code point"): up to six hex digits plus one optional whitespace; zero, a surrogate or a value above U+10FFFF becomes U+FFFD; an escape at EOF becomes U+FFFD. A raw-lexeme arm is refused on the `esc-*` witnesses. |
| **Number fidelity** | A number token carries its type flag (integer or number) and the binary64 value of §4.3.13 ("convert a string to a number"), correctly rounded; a percentage and a dimension carry the same, plus the unit's code points as written (case kept). The token's representation text is not part of the value. |
| **Duplicate keys** | Duplicate declarations in one block are all kept as events, in order (the cascade is not this plane's work). |
| **Error offsets** | The parse-error events carry no offset in the canonical form, because CSS Syntax 3 does not define one; G-E1's CSS rows use P7's error positions instead. A bad-string and a bad-url token are tokens, not errors. |

## Canonical form

The event stream of CSS Syntax 3 §5 "parse a stylesheet": at-rules (name, prelude tokens, block or `;`), qualified rules (prelude tokens, block), declarations (name, value tokens, `!important` flag) inside style and at-rule blocks per §5.4.4 "consume a block's contents", with nested rules kept, and a `parse-error` event wherever §5 records one. Each token is its type plus its value fields as above; whitespace tokens collapse to one `ws` token per run. The digest is SHA-256 over a length-prefixed serialization of that stream (the same scheme as P4's canonical form: `s<len>:<utf-8>` for every text field, one tag byte per token or event type). The reference oracle is owed with U5 (`bench/contest/ROWS.tsv`, row `R-CSS-P2-oracle`).

## Witness inputs

`bench/planes/witness/css/`: escapes in identifiers, strings, URLs and hashes (`esc-*`), ill-formed UTF-8 and a BOM (`utf8-*`), integer versus number and exponent forms (`num-*`), duplicate declarations (`dup-*`), bad strings and bad URLs, and recovery after an unclosed block (`err-*`).

## Equal work

- Every token is consumed and every value field produced, including unescaping, for every token the opponent produces. An arm that skips the contents of blocks it does not understand still tokenizes them.
- cssparser rows use `Parser::next_including_whitespace_and_comments` driven to the end of every nested block (the event checksum covers each token), never a skip API.
- Both arms receive the decoded, preprocessed input or both receive bytes; the row says which, and decoding is inside the timed region for both.
