# SK-V11 P2-C: Host-Arch ASM/SIMD Esoterica
Pass: S-P2 Research. Cycle: V1.
Date: 2026-05-19.
Scope: aarch64 Apple Silicon instruction inventory mapped to SK-V11 hot leaves.
Output: this file.
P1 hot-leaf antecedents: bounded_plain_string_scan; string_escape_decode; unicode_escape_hex_decode; number_digit_span; ascii_whitespace_skip; container_dispatch; simd_movemask; output_digest_hash.
Lock surface: Lock 1 + Lock 14.

## §1 — Findings (concrete; file:line on bbnf claims, citation on external claims)

1. SK-V11 implementation scope is aarch64 Apple Silicon only. The handoff binds AArch64-only SIMD/ASM as a tranche axis and requires scalar reference, differential/checkasm, same-host microbench, feature gate, and same-wave consumer for each kernel candidate (`restart/skinny/tranches/sk-v11/HANDOFF.md:67-80`). x86 is comparator context only and explicitly out of SK-V11 implementation scope (`restart/skinny/tranches/sk-v11/HANDOFF.md:105-114`, `restart/skinny/tranches/sk-v11/HANDOFF.md:123-134`). The P2-C prompt names x86 only as secondary inventory context (`restart/prompts/skinny/PASS-2-RESEARCH.md:46-53`).
2. The admitted S-P1 hot leaves for P2 research are exactly the eight header leaves: bounded plain string scan, string escape decode, Unicode escape hex decode, number digit span, ASCII whitespace skip, container dispatch, SIMD movemask, and output digest/hash (`restart/skinny/tranches/sk-v11/research/p1/hardening/HARDENING-S-P1-CONVERGED.md:41-45`). S-P1 also pre-blocks W3/substrate, sidecar/cursor, PMULL/CTZ default rewires, rejected string/materialization families, generic numeric fallback, and object/value-byte carry routes (`restart/skinny/tranches/sk-v11/research/p1/hardening/HARDENING-S-P1-CONVERGED.md:49-52`).
3. NEON TBL/TBX is the primary byte-class esoterica for SK-V11. In-tree AArch64 code already builds a low-6 64-byte table and classifies 16-byte chunks with `vqtbl4q_u8`, equality recheck, and movemask (`skinny/crates/bbnf-simd/src/aarch64/classify_tbl4.rs:7-43`, `skinny/crates/bbnf-simd/src/aarch64/classify_tbl4.rs:74-85`). `match_tiny_plain_string` carries the same shape with a scalar reference, `vqtbl4q_u8`, and low-6 collision constraints (`skinny/crates/bbnf-simd/src/aarch64/match_tiny_plain_string.rs:32-61`, `skinny/crates/bbnf-simd/src/aarch64/match_tiny_plain_string.rs:63-96`, `skinny/crates/bbnf-simd/src/aarch64/match_tiny_plain_string.rs:123-136`). Arm ACLE maps `vqtbl4q_u8` to A64 `TBL` over four 16-byte registers and `vqtbx4q_u8` to `TBX` over the same table width [ACLE-TBL], [ACLE-TBX]. P1 antecedents: bounded_plain_string_scan, ascii_whitespace_skip, container_dispatch, simd_movemask.
4. TBL also anchors the Unicode escape path. `unescape_uxxxx_scalar` is the single-quartet oracle, `unescape_uxxxx_neon` uses a `vqtbl1q_u8` low-nibble LUT plus ASCII range masks, and `unescape_uxxxx_x4_neon` decodes four packed quartets at once (`skinny/crates/bbnf-simd/src/aarch64/unescape_uxxxx.rs:33-47`, `skinny/crates/bbnf-simd/src/aarch64/unescape_uxxxx.rs:58-121`, `skinny/crates/bbnf-simd/src/aarch64/unescape_uxxxx.rs:123-166`). `parse-that-regex` already has an AArch64 batch caller for four consecutive `\uXXXX` escapes (`skinny/crates/parse-that-regex/src/lib.rs:384-458`) and consumes it from `unescape_string` (`skinny/crates/parse-that-regex/src/lib.rs:775-786`). P1 antecedents: unicode_escape_hex_decode, string_escape_decode.
5. The current string-special primitive is 16-byte NEON compare fan-out, not TBL: it returns terminator, escape, control, and non-ASCII masks against a scalar reference (`skinny/crates/bbnf-simd/src/aarch64/string_block.rs:5-27`, `skinny/crates/bbnf-simd/src/aarch64/string_block.rs:30-72`). `parse-that-regex` uses it in both raw and trusted UTF-8 plain-string scanning (`skinny/crates/parse-that-regex/src/lib.rs:462-507`, `skinny/crates/parse-that-regex/src/lib.rs:546-563`). The full string caller proof is REDRESS-rejected, so any widened special block must be treated as a new micro-proof, not as automatic production (`skinny/REDRESS.md:3150-3170`). P1 antecedents: bounded_plain_string_scan, string_escape_decode.
6. The AArch64 movemask inventory has two in-tree idioms. The shared `aarch64::movemask` uses `vshrn_n_u16`, `vsri_n_u8`, and `vzip1q_u8` before scalar packing (`skinny/crates/bbnf-simd/src/aarch64/movemask.rs:3-25`); `byte_class_from_eq_set_64` uses a pattern mask plus `vaddv_u8` across low/high halves (`skinny/crates/bbnf-simd/src/aarch64/byte_class_from_eq_set_64.rs:59-87`). Arm ACLE maps `vaddvq_u8` to A64 `ADDV`, and `vcntq_u8` to A64 `CNT` [ACLE-ADDV], [ACLE-CNT]. P1 antecedent: simd_movemask.
7. UDOT/DotProd is present as an AArch64-only digit microkernel. `parse_4_digits` gates on `target_feature = "dotprod"` and otherwise uses scalar multiply/add (`skinny/crates/bbnf-simd/src/aarch64/digit_mac.rs:4-23`); `parse_4_digits_dotprod` emits inline `udot` under `#[target_feature(enable = "dotprod")]` (`skinny/crates/bbnf-simd/src/aarch64/digit_mac.rs:25-49`). `parse-that-regex` currently scans number digits with SWAR 8/4/2-byte blocks and scalar tail accumulation (`skinny/crates/parse-that-regex/src/number/mod.rs:105-162`, `skinny/crates/parse-that-regex/src/number/mod.rs:164-223`). Arm ACLE maps `vdotq_u32` to A64 `UDOT` [ACLE-UDOT]. P1 antecedent: number_digit_span.
8. CSSC `CTZ` is inventory, not a production route. Current AArch64 `bitmap_next_set_bit_neon` delegates to the scalar oracle (`skinny/crates/bbnf-simd/src/aarch64/bitmap_next_set_bit.rs:1-4`), whose behavior is `mask >> cursor` plus `trailing_zeros` (`skinny/crates/bbnf-simd/src/scalar/bitmap_next_set_bit.rs:1-13`). The CSSC instruction counts trailing zeros under FEAT_CSSC [CSSC-CTZ], but REDRESS 89 rejects replacing the production next-bit/bulk consumer path despite green correctness and explicit `ctz` asm proof (`skinny/REDRESS.md:2542-2585`). P1 antecedents: container_dispatch, simd_movemask.
9. PMULL is also inventory, not a default hot body. Current AArch64 `bitmap_prefix_xor_64_neon` delegates to the scalar shift/XOR prefix oracle (`skinny/crates/bbnf-simd/src/aarch64/bitmap_prefix_xor_64.rs:1-4`, `skinny/crates/bbnf-simd/src/scalar/bitmap_prefix_xor_64.rs:1-14`). Arm ACLE maps `vmull_p64` to A64 `PMULL` [ACLE-PMULL]. REDRESS 88 rejects PMULL as the default hot `bitmap_prefix_xor_64` body after parse benchmark regressions, even though correctness and asm visibility were proven (`skinny/REDRESS.md:2508-2540`). P1 antecedents: string_escape_decode, simd_movemask.
10. SHA3 ternary bitwise (`EOR3`/`BCAX`) is allowed inventory but has no SK-V11 candidate yet. Lock 16 allows AArch64 SHA3 ternary bitwise (`restart/locks/LOCKS.md:94-95`), and Arm ACLE maps `veor3q_u8` to A64 `EOR3` and `vbcaxq_u8` to A64 `BCAX` [ACLE-EOR3], [ACLE-BCAX]. No requested candidate currently has a scalar-ref plus same-wave consumer whose bottleneck is a three-input boolean fold, so this stays as inventory only. P1 antecedents if later proven: simd_movemask, container_dispatch.
11. Wide shifts and cross-chunk context are already represented by `vextq_u8`: `shift_right_one` and `shift_left_one` splice adjacent 16-byte chunks (`skinny/crates/bbnf-simd/src/aarch64/byte_context.rs:1-11`). Arm ACLE maps `vextq_u8` to A64 `EXT` [ACLE-VEXT]. This is relevant only when a grammar-neutral token can span chunk boundaries without adding a second source scan. P1 antecedents: bounded_plain_string_scan, string_escape_decode, ascii_whitespace_skip.
12. Cache hints exist but are hazardous as performance candidates. `cache_hints.rs` emits `prfm pldl2strm`, `prfm pstl1strm`, and `stnp` (`skinny/crates/bbnf-simd/src/aarch64/cache_hints.rs:1-33`). Lock 16 allows AArch64 cache hints and hash primitives (`restart/locks/LOCKS.md:96-106`). A64 PRFM is a hint whose effect is implementation-defined [A64-PRFM], and STNP is a non-temporal store-pair hint [A64-STNP]. P1 antecedent: output_digest_hash.

## §2 — Candidate primitives (each: shape + scalar-ref status + arch + P1 antecedent)

1. TBL byte-set/classifier.
   Shape: grammar supplies a byte set or table; kernel scans 16-byte or 64-byte windows with `vqtbl4q_u8` low-6 table lookup, equality recheck, optional `TBX` fallback/extension for default-preserve semantics, and the existing movemask idiom. Scalar-ref status: `byte_class_from_eq_set_64_scalar` and `byte_class_from_table_64_scalar` are executable specs (`skinny/crates/bbnf-simd/src/scalar/byte_class_from_eq_set_64.rs:20-38`, `skinny/crates/bbnf-simd/src/scalar/byte_class_from_table_64.rs:1-10`); checkasm parity exists for set/table density, alignment, adversarial, and corpus cases (`skinny/crates/bbnf-simd/tests/checkasm_byte_class_from_eq_set_64.rs:1-17`, `skinny/crates/bbnf-simd/tests/checkasm_byte_class_from_eq_set_64.rs:156-180`, `skinny/crates/bbnf-simd/tests/checkasm_byte_class_from_table_64.rs:13-49`). Arch: aarch64 NEON TBL/TBX. P1 antecedents: bounded_plain_string_scan; ascii_whitespace_skip; container_dispatch; simd_movemask.
2. UDOT digit-span.
   Shape: parse digit runs in 4/8/16-byte chunks by subtracting `b'0'`, validating ASCII digit lanes, then using `UDOT`/DotProd weights for block value or digit-count facts, with scalar tail preserving JSON number syntax. Scalar-ref status: current `parse_4_digits` has scalar fallback and `parse-that-regex::number::scan_digit_run` is the parser oracle (`skinny/crates/bbnf-simd/src/aarch64/digit_mac.rs:4-23`, `skinny/crates/parse-that-regex/src/number/mod.rs:105-162`). Arch: aarch64 `dotprod`, feature-gated. P1 antecedent: number_digit_span.
3. Widened string-special block, only if micro-proof passes.
   Shape: widen the existing 16-byte `StringSpecialBlock` to a 64-byte four-lane result, preserving terminator/escape/control/non-ASCII masks and first-interesting extraction; candidate may use compare fan-out, TBL byte-class, shared movemask, and possibly `vextq_u8` for chunk-edge context. Scalar-ref status: `scan_string_special_block_scalar` and `sk_v3_intrinsic_parity_aarch64` already cover the 16-byte primitive (`skinny/crates/bbnf-simd/src/aarch64/string_block.rs:30-54`, `skinny/crates/bbnf-simd/tests/checkasm_parity.rs:617-640`); widened form needs its own scalar oracle and same-host microbench because REDRESS 106 rejected the caller-level proof. Arch: aarch64 NEON. P1 antecedents: bounded_plain_string_scan; string_escape_decode; simd_movemask.
4. x4 escape codec production.
   Shape: production route for four consecutive `\uXXXX` escapes: pack four quartets, run `unescape_uxxxx_x4_neon`, join surrogate pairs under scalar JSON policy, and emit chars without a cosmetic wrapper. Scalar-ref status: `unescape_uxxxx_scalar`, `decode_unicode_escape`, and `read_hex_unit_scalar` define the oracle (`skinny/crates/bbnf-simd/src/aarch64/unescape_uxxxx.rs:33-56`, `skinny/crates/parse-that-regex/src/lib.rs:302-344`, `skinny/crates/parse-that-regex/src/lib.rs:919-965`); checkasm covers x4 decode and AArch64 scalar parity (`skinny/crates/bbnf-simd/tests/checkasm_utf8_block.rs:58-68`, `skinny/crates/bbnf-simd/tests/checkasm_parity.rs:643-662`). Arch: aarch64 NEON TBL. P1 antecedents: unicode_escape_hex_decode; string_escape_decode.
5. Whitespace byte-set skip.
   Shape: grammar-supplied ASCII whitespace set skip using TBL or compare-fan classify over 16/64-byte windows, with first-non-whitespace extraction through movemask; JSON newline handling must remain a caller policy, not a generic primitive policy. Scalar-ref status: `skip_ascii_whitespace` and `skip_ascii_spaces` are the current parser refs (`skinny/crates/parse-that-regex/src/lib.rs:112-147`); `byte_class_from_table_64_scalar` can serve as the unit oracle for arbitrary byte-set membership (`skinny/crates/bbnf-simd/src/scalar/byte_class_from_table_64.rs:1-10`). Arch: aarch64 NEON TBL/compare + movemask; possible `ADDV` all-space test. P1 antecedent: ascii_whitespace_skip.
6. Output digest/hash scalar/cache candidate.
   Shape: no new hash algorithm. Keep the current scalar/hash semantics as oracle and research only cache placement, prefetch, or streaming store hints around output digest/hash or output-plane writeback, with a same-wave consumer proving row movement. Scalar-ref status: Lock 16 names `ahash`-shaped hashing as the admissible hash primitive, not bespoke hashing (`restart/locks/LOCKS.md:106`); `cache_hints.rs` is the only AArch64 hint surface read here (`skinny/crates/bbnf-simd/src/aarch64/cache_hints.rs:1-33`). Arch: aarch64 PRFM/STNP hints, not SIMD arithmetic. P1 antecedent: output_digest_hash.

## §3 — Grammar-neutrality (each candidate: JSON-only or CSS/Sheets/BBNF-self generalisable)

1. TBL byte-set/classifier: grammar-neutral when the byte set/table is generated from Grammar IR. JSON structural bytes, CSS delimiter/operator bytes, Sheets formula punctuation, and BBNF-self metasyntax all fit the same byte-set/classifier abstraction. Reject any hardcoded JSON structural role in `bbnf-simd`.
2. UDOT digit-span: grammar-neutral for ASCII decimal digit spans in JSON numbers, CSS numeric tokens, Sheets formula numbers, and BBNF-self numeric/count syntax. It becomes JSON-only if it bakes in JSON exponent/sign policy; those stay in the per-grammar parser.
3. Widened string-special block: generalisable if terminator, escape byte, control limit, and UTF-8 validation mode are parameters. It is JSON-only if fixed to quote/backslash/control<0x20 with JSON flags in the primitive.
4. x4 escape codec production: fixed `\uXXXX` is not fully CSS-general because CSS escapes are variable-width hex with optional trailing whitespace. It is admissible as a per-grammar escape-code-unit template for JSON-like grammars and BBNF-self only if P2-F records the CSS variant separately rather than pretending this exact primitive covers CSS L4.
5. Whitespace byte-set skip: grammar-neutral for ASCII whitespace sets emitted by each grammar. CSS full whitespace/comment policy, if broader than byte-set skip, must remain a caller/template layer and not enter the generic primitive.
6. Output digest/hash scalar/cache candidate: grammar-neutral only as an output-plane/cache-placement optimization. It must not depend on JSON object-key semantics; per-grammar hash/digest consumers decide when to call it.

## §4 — Risks (REDRESS entries any candidate must NOT re-open)

1. Do not reopen PMULL prefix-XOR as a default hot body. REDRESS 88 shows the PMULL body was correct and visible in asm but regressed hard JSON rows, including `numbers` and `unicode_escapes` (`skinny/REDRESS.md:2517-2540`).
2. Do not reopen CSSC CTZ bulk rewires. REDRESS 89 rejects the `bitmap_next_set_bit`/`bulk_emit_positions_64` production-path change despite green correctness and explicit `ctz` asm proof (`skinny/REDRESS.md:2544-2585`).
3. Do not route candidates through W3 substrate, class columns, structural vectors, streaming cursors, parser-owned sidecars, or class-lane tape changes. REDRESS 96 and 97 both failed every W3 must-improve row after green correctness checks (`skinny/REDRESS.md:2797-2848`, `skinny/REDRESS.md:2852-2905`), and REDRESS 102 firewall-closed W3 as proof-only with no behavior source or row movement (`skinny/REDRESS.md:3040-3058`).
4. Do not admit parse-only SOTA movement or parser-owned structural projection. The handoff refuses parse-only SOTA admissions, x86 implementation work, new sidecars, and JSON policy in generic crates (`restart/skinny/tranches/sk-v11/HANDOFF.md:123-142`).
5. Do not repackage the rejected full string primitive proof. REDRESS 106 says the NEON string special block was correct but caller-level aggregate speedup was only `0.774x`, with regressions on `unicode_mixed` and `unicode_basic` (`skinny/REDRESS.md:3152-3170`). A widened block needs new representative micro-proof and a narrower consumer.
6. Do not claim x4 escape production by reusing the W8 proof-only result or adding a cosmetic wrapper. REDRESS 107 admits the x4 escape micro-proof only as proof with no row movement (`skinny/REDRESS.md:3174-3196`); REDRESS 108 rejects the existing production reuse route and says future production reuse needs a new SPEC/CHALLENGE route naming a real source delta (`skinny/REDRESS.md:3200-3222`).
7. Do not convert grammar-neutral byte-set primitives into JSON-only policy. PASS-2 requires grammar-neutral expression for CSS L4, Sheets, or BBNF-self, and candidates that need JSON structural roles must be reframed as grammar-neutral primitives or host functions (`restart/prompts/skinny/PASS-2-RESEARCH.md:102-107`, `restart/prompts/skinny/PASS-2-RESEARCH.md:232-240`).
