# BB-C.W5 — layout-driven cohesive generators

## Goal

Replace grammar-special-case and handwritten template monoliths with small cohesive
generation stages driven by LoweringPlan and declarative grammar data.

## Implementation

1. Decompose generators by stable phase: model/layout, names, instruction/runtime
   selection, source emission, formatting, manifest, and test/schema emission.
   Avoid one file per tiny syntax fragment and avoid target-wide god files.
2. Move grammar variation into validated declarative data or plan values. Adding a
   synthetic grammar must not add a source `match` arm.
3. Emit Rust, TypeScript, WASM/schema, and external source-isomorphic tests from one
   semantic contract where applicable. Strip parent-module name stutter.
4. Generate headers/sidecars with all semantic/toolchain/command/output digests;
   format then hash final bytes deterministically.
5. Keep a large generated file whole when it has one regeneration and consumer
   boundary; do not create generated sand for line-count optics.

## Gates

- Every manifest grammar and a synthetic grammar regenerate twice identically from
  empty outputs.
- Generator phase graph is acyclic and every artifact has one producer/consumer.
- Removing a grammar-specific hardcoded arm is not needed to add the synthetic case.
- Generated Rust/TS compile and differential behavior matches the plan observations.

## Completion

Generation complexity follows semantic stages, not grammar count or accumulated
special cases.
