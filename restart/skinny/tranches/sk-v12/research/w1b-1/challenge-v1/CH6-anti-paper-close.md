## Verdict

ACCEPT FOR REDRESS, with mandatory fail-closed preconditions.

The W1b-1 plan has a measurable non-JSON row and, as written, avoids the known
paper-close shapes. It selects exactly `css_l4/declaration_values/direct_to_struct/main`
on the `css_l4_declaration_value_fact_stream` plane, requires generated Track 1
plus an independent Track 2/oracle, keeps W1b-1 scalar-only, and explicitly
forbids lightningcss admission language in this scaffold wave.

scaffold/equality with finite Track 1 and oracle Mbps. W1b-2 remains the first
wave allowed to consume `lightningcss_mbps + 1`.

## Blockers

- No CH6 blocker prevents redress dispatch after the SPEC owner amendments now
  present in Section 6.
- Redress is blocked until the existing companion gate is updated. The current
  schema/validator cannot consume the required W1b-1 fields and still expects
  the generic `direct_sink` output plane for `direct_to_struct`.
- Redress must reject if the CSS runtime cannot be generated and replayed from
  the CSS-owned provider/profile. A scaffold that is generated only by file path
  or directory name is a paper-close.

  lightningcss. W1b-1 is an oracle/equality scaffold only; lightningcss belongs
  to W1b-2.
- Redress must reject if artifacts are insufficient for replay: fixture bytes
  and checksum, grammar input checksums, generated LOC/module bytes, Track 1
  facts, oracle facts, benchmark artifact path, profile artifact, and gate
  report must all be present and gate-consumed.
