## Challenge Findings

### 1. Paper Close Is Blocked

The plan is CH6-acceptable because the selected production evidence is the
generated direct `parse_string_direct` caller, not a standalone helper,
micro-proof, checkasm result, PMU result, profile read, or gate/report field. The
selected helper shape may return span offsets and `needs_decode`, but that shape
does not admit anything by itself. Probe movement is only a sub-gate for running
Criterion; it cannot move `skinny/RESULTS.md`.

If implementation adds SIMD, `bbnf-simd`, `parse-that-regex` behavior, generic
codegen behavior, runtime-outside-JSON behavior, decoded scratch, retained string
tables, string facts, output hashes, retained wrappers, or REDRESS 106 replay,
this CH6 acceptance no longer applies. That deviation must return to REVISE or
reject before redress unless a new same-wave generated CSS L4 / Sheets /
BBNF-self proof has explicit authority and is gate-consumed.

### 2. Exact Row Admission

The selected admission row is exactly `random/direct_to_struct/main`. It may
admit only when generated Track 1 and independent hand Track 2 both meet or
exceed 7878 Mbps in the same native Criterion root, with same-run sonic-rs strict
direct and serde_json direct comparator rows, exact digest equality, no Track 2
coupling, direct guards, typed guards, and Unicode residual monitors recorded.

No other W5-eligible row admits under this CHALLENGE. Scout probes for
`twitter`, `github_events`, `update_center`, `distinct_values`, or `gsoc-2018`
are future-planning evidence only. `unicode_escapes`, `unicode_mixed`, and
`y_string_unicode` are not W5 guards; unless a later CHALLENGE selects one as a
floor-bearing W5 target, they remain residual rows for W6/W8 and may not be
silently admitted or demoted.

Gate/report provenance must be consumed in the same wave with
`same_wave_consumer_class=gate_json_direct_contract`, `wave_id=SK-V11-W5`,
`redress_entry=REDRESS-116` if the ledger has not advanced, digest output plane,
independent Track 2 status, and stale W2/W3/W4 provenance rejection.

### 3. Non-JSON And Close State

REDRESS 113 remains blocked. W5 may say the bounded span shape is
grammar-neutral in abstraction, but it may not claim a generated non-JSON parser
intervention, non-JSON row movement, Lock 14 close, or close-condition
satisfaction. CSS, Sheets, or BBNF grammar facts are parameter evidence only
unless a generated non-JSON Track 1, independent same-plane oracle, strict
equality, throughput baseline, and gate consumer exist under new authority.

REDRESS 114 remains a rejected W3 numeric route. REDRESS 115 remains a rejected
W4 container-tail route. W5 cannot treat either rejection as repaired by string
span evidence.

If W5 admits `random`, all other Section 0.4 direct residuals remain unclosed:
`twitter`, `canada`, `github_events`, `update_center`, `mesh`, `gsoc-2018`,
`instruments`, `numbers`, `unicode_mixed`, `unicode_escapes`,
`distinct_values`, and `y_string_unicode`. If W5 rejects, all 13 direct residual
rows remain unclosed. W0-clamped `instruments`, `numbers`, and `unicode_mixed`
remain non-admissions until a behavior or gate wave records measured provenance.

### 4. Required REDRESS On Fail

On fail, W5 must save the rejected patch at `/tmp/skv11-waveW5-rejected.patch`,
restore only the W5 touched slice, move no `RESULTS.md` row, and record a REDRESS
entry that includes:

1. Attempted intervention: scalar bounded string span in generated JSON direct
   `parse_string_direct`, selected cap 8, selected row
   `random/direct_to_struct/main`, and selected floor 7878 Mbps.
2. Exact failed predicate: probe threshold miss, Track 1 floor miss, Track 2
   floor miss, output mismatch, Track 2 coupling, guard regression, Unicode
   monitor misuse/regression, generated-output/renderer mismatch, generic
   behavior without non-JSON proof, or forbidden-route replay.
3. Measurement evidence: probe values when probe-first stops the wave; Criterion
   root and measured Track 1, Track 2/oracle, sonic-rs direct, and serde_json
   direct values when Criterion runs; run id, host, flags, sample count, and
   command set.
4. Guard and monitor status for direct guards, typed guards, and the Unicode
   residual monitors.
5. Output-plane and independence status: digest equality or mismatch, strict
   comparator status, and confirmation that Track 2 did or did not remain
   independent from generated Track 1.
6. Ledger carry-forward: REDRESS 113 remains the non-JSON block, REDRESS 114
   remains the W3 numeric rejection, REDRESS 115 remains the W4 container-tail
   rejection, and the failed W5 route is routed to W6/W8 only as measured
   evidence, not close.
