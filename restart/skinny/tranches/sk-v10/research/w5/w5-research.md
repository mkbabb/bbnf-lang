## Code Scan

The current typed DirectBuild root model is struct-only:

- `skinny/crates/codegen/src/direct_schema.rs` defines `DirectRootSchema` with
  `function_name`, `rust_type`, and `type_id`.
- `DirectSchemaSet::validate` requires every root `type_id` to exist in the
  named type table.
- `skinny/crates/codegen/src/typed_direct.rs` renders each public root by
  resolving `root.type_id` to a struct parser function.

The renderer already has the needed generic pieces below root level:

- `DirectTypeRef::Vec` renders vector helpers.
- `DirectTypeRef::MapEntriesVec` renders object-map-to-entry-vector helpers.
- `Renderer::parse_expr` can parse any `DirectTypeRef` once its helper has
  been collected.

Therefore W5 does not need JSON-specific root policy. It needs root schemas to
carry a `DirectTypeRef` instead of only a struct `type_id`, and the renderer
must collect root-level helpers before rendering public functions.

## Proof Surface

Use generated proof roots inside the existing `generated_real_typed` module,
without adding a `RESULTS.md` row:

- Array-root probe: public generated root returns
  `Vec<crate::real_typed_struct::W5ArrayEvent<'i>>`.
- Map-entry-root probe: public generated root returns
  `Vec<crate::real_typed_struct::W5MapMetricEntry<'i>>`.

Both probes can compare generated output against serde_json and sonic-rs typed
sidecars through checksums over in-test fixtures. The proof roots are synthetic
and do not dispatch `github_events` or `gsoc-2018` row movement.

## Risks

- Root-level helper collection must run before public root rendering, or a
  `Vec<T>` / `MapEntriesVec<T>` root will reference a missing helper.
- Existing struct roots must remain generated byte-for-byte aside from schema
  hash and added proof roots.
- W5 may edit generic codegen, so Section 2.1 must be answered. The intended
  proof is no JSON-specific policy in generic code plus a codegen unit test
  that asserts the generated module contains no `JsonSink` or
  `serde_json::Value`.
