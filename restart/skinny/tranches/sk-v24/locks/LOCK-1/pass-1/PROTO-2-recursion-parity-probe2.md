## Question

PROTO-1 emptied 1D's cost-extraction justification (zero overload/cost residue), leaving 1D's
sole surviving advantage = native recursion. So: does the shipping pass produce a correct,
FINITE, TERMINATING schema for the deepest real recursive grammars, **structurally equal to
1D's μ-extraction** `@0:Sum(Null|Bool|Int|Str|List(#0)|Row(#0))`? If yes → 1D RETIRES; if it
diverges / non-terminates / mis-shapes on a real recursive grammar → 1D's narrow keep holds.

## Method

Reused PROTO-1's live compile path (`compile_paths_request`, `CompileTarget::Vm`, which runs
`project_types`) over the real recursive corpora — JSON (self-referential `value`), Sheets
(deep mutual recursion), CSS L4 (deepest) — and dumped each recursive rule's solved `TypeDesc`
from `ir.types`. **New in this probe:** I also dumped the per-rule `GrammarIR.struct_registry`
`StructLayout` for JSON `array`/`object` — the field the JSON codegen (`xtask regen-json`)
actually loads from the serialized `json.registry.json` sidecar. This closes the gap the prior
probe left open: it read only `ir.types` and *asserted* (without checking) that the structure is
"supplied nominally downstream by design." I checked where downstream, and by what.

## What ran

## The numbers

### JSON — self-referential `value` (reproduces prior probe exactly)

| | schema |
|---|---|
| **1D** (e-graph μ-extract) | `Sum[6](Null \| Bool \| Int(0) \| Str \| List(#0) \| Row(#0))` |
| **RUNNING** `ir.types[value]` | `HeterogeneousAltJoin([BoxedEnum, Span, Bool, F64])` = `Sum[4]` |
| **RUNNING** `ir.types[array]` | `List(Enum)` |
| **RUNNING** `ir.types[object]` | `List(Enum)` — identical to `array` |

### THE DECISIVE NEW MEASUREMENT — the `struct_registry` sidecar codegen ACTUALLY consumes

```
array : kind=Struct  rule_type=Vec(Enum)  fields=[element: BoxedEnum (RepeatElement)]
object: kind=Struct  rule_type=Vec(Enum)  fields=[element: BoxedEnum (RepeatElement)]
array-layout == object-layout (registry) ? = TRUE
```

The prior probe found the collapse only in `ir.types` and argued the registry/codegen supplies
the missing structure. **It does not.** `array` and `object` have **byte-identical**
`StructLayout` entries in the sidecar too. The `List ≠ Row` distinction is absent from the
**entire general type pipeline**, not merely the coarse `TypeDesc`. Confirming *why*: the
`LayoutKind` enum has **no Row/Map variant** — only `Struct / TaggedEnum / UntaggedEnum /
NewtypeWrapper` — so a map-of-kv-pairs (object) and a list-of-values (array) are *structurally
forced* to the same shape. The general pass cannot express the distinction.

Where the shipped runtime's distinct `Array(JsonArrayId)` / `Object(JsonObjectId)` (in
`crates/core/src/runtime/json/value.rs`, `// @generated by xtask regen-json`) comes from: a
**bespoke per-grammar codegen template** (`skinny/crates/codegen/src/json_templates/value.rs`)
that hand-matches raw bytes `{ } [ ]` and knows JSON semantically. `xtask regen_simple_runtime`
dispatches on a hard-coded per-grammar table (`json → regen-json`, `math → regen-math`, …). The
faithful 6-variant schema is **hand-authored per grammar**, not derived by the type system from
the grammar.

### Sheets — deep mutual recursion (37 rules, 20 knots, all-finite; TERMINATED)

```
expression      = μ↩
primary         = Sum[4](μ↩ | F64 | Bool | Str)
paren_expr      = Tuple(Str, μ↩, Str)
comparison_expr = Tuple(μ↩, List(Tuple(Str, μ↩)))
```

The running pass DOES emit structural recursive μ-types where the body is a Seq/Tuple
(`comparison_expr`). The collapse is **specific** to the heterogeneous-Alt-of-compound-branches
case (JSON `value`), where `join_types` grounds to `BoxedEnum` — not a general inability to
recurse structurally. This narrows the exact gap 1D fills.

### CSS L4 — 4/4 files, 191 rules, 44 recursion knots, all-finite=true. No divergence.

## Findings

1. **Termination is free for the running pass — 1D buys nothing on the axis it was sold on.**
   Recursion closes nominally (`BoxedEnum`/`Enum` on sight; cycle-break ground in Phase 2b); the
   pass cannot diverge by construction. Confirmed on JSON, Sheets (mutual), CSS L4. Both probes
   agree; I reproduce it.

2. **NOT structurally equal to 1D — and the gap runs deeper than the prior probe measured.**
   `value = Sum[4] ≠ Sum[6]`; and `array ≡ object` collapses `List ≠ Row` **not only in
   `ir.types` but in the `struct_registry` sidecar codegen consumes** — the general pipeline has
   no representation for the distinction (`LayoutKind` lacks a Row variant).

3. **The prior probe's "structure supplied nominally downstream by design" is, on inspection, a
   bespoke per-grammar workaround.** Distinct Array/Object is hand-encoded in a JSON-specific
   codegen template, not derived by the general solver. Under the project's own precepts this is
   a smell: `typed-materialization-invariant` says *"inference composes types, never loses
   them"* — the running pass loses `List ≠ Row`; `no-workarounds` disfavors per-grammar
   hand-authored recovery. 1D would **derive** the distinction from the grammar (its
   `List(#0) ≠ Row(#0)`), which is precisely the capability the running pipeline lacks.

## Verdict

**RAN_MEASURED.** On the **divergence/termination** axis — the axis 1D's "native recursion"
pitch rests on — **1D buys nothing**: the running CSP is finite and terminating on every real
recursive grammar, conceded outright. On the **schema-fidelity** axis the running pass is *not*
structurally equal to 1D's extraction, and the `List ≠ Row` collapse is total across the whole
general pipeline (`ir.types` + registry), recovered today only by a bespoke per-grammar
hand-written codegen template.

By the brief's **literal PASS/FAIL gate** — PASS requires "finite, terminating, AND structurally
equal … on every real recursive grammar"; FAIL if the pass "produces a schema the e-graph gets
right" — this is **FAIL-and-KEEP-1D, narrowly**: 1D is the only path that *derives* the real
`List ≠ Row` structural distinction from the grammar rather than delegating it to a per-grammar
workaround, and the brief pre-declares that exact case load-bearing.

**But the keep is CONTESTED and the contest is definitional, not empirical.** No shipping defect
exists — the bespoke template ships correct JSON today. If the owner defines *load-bearing* as
"causes an observable end-to-end defect," 1D is cosmetic and **RETIRES** (the prior probe's
reading). If the owner defines it as "the general type pass must *derive* structural
distinctions the grammar expresses, per the typed-materialization-invariant, rather than
delegate to bespoke per-grammar codegen," 1D is **load-bearing and keeps**. Both verdicts rest
on the identical measured facts; they diverge only on that definition.

**My recommendation to the owner:** the honest weight sits slightly toward **KEEP-1D-NARROWLY**,
because the "not load-bearing" argument the prior RETIRE rests on is, on the evidence I gathered,
"the collapse is patched by a bespoke per-grammar template" — which the project's own
no-workarounds and typed-materialization precepts count *against*, not for. But 1D's keep is
strictly narrow: schema fidelity for the heterogeneous-Alt-of-compounds case (JSON `value`)
only; termination is free without it; and PROTO-1 already voided its cost-extraction machinery.
If the greenfield SPEC accepts per-grammar codegen templates as the sanctioned home for
structural recovery, RETIRE stands.
