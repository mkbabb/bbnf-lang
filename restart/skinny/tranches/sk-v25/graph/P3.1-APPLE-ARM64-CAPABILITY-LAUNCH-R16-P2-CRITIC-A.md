## Static root trace for the surviving `tools, build` mismatch

The report did not obtain per-field diagnostics. Therefore no critic may claim
the exact runtime differing fields as observed fact. Source nevertheless
contains a concrete non-isomorphism that is sufficient to explain precisely
the reported pair of planes.

1. The retained selection comes from the process-wide cached
   `ToolSelection::capture()` (`xtask/tests/architecture.rs` 80-84).
   `capture_from_paths(None)` chooses its invocation path through embedded paths
   or `tool_binding` (production 168-191); ordinary cargo/rustc resolution uses
   the current PATH (1461-1469, 1620-1634).
2. The live-baseline test does **not** reuse `selection.path("cargo")` or
   `selection.path("rustc")`. It replaces both with separately executed
   `rustup which` payload paths at test 1017-1039.
3. `capture_live_tool_selection` then recaptures from those replacement paths
   (production 920-943). If the retained PATH invocation was a rustup proxy,
   `effective_tool` takes the rustup branch and binds active-toolchain identity
   (1645-1681); the `rustup which` payload path takes `direct-executable`
   (1740-1742).
4. Under that demonstrable path divergence, the exact necessarily differing
   `ToolBinding` fields are `invocation_path_hash`, `proxy_hash`,
   `toolchain_selection`, and `toolchain_selection_hash` (1480-1483,
   1557-1607). `effective_path_hash`, `executable_hash`, logical argv, and
   capability can remain equal because both routes reach the same payload.
5. `validate_binding_plane_match` reports `tools` for any such row difference
   (1019-1021). The same differences flow into `build_tool_ledger_hash`
   (1052-1058, 2887), the integration-test
   `embedded_build_tool_ledger_hash` (2904-2910), and the aggregate cargo/rustc
   `toolchain_selection_hash` (2945-2950), producing `build` at 1025-1027.

This is a deterministic **design bug**: retained and live captures are not
defined from the same invocation-path map, so baseline equality depends on an
ambient PATH/rustup coincidence. It is not proved that these four fields were
the actual author's differing fields because the diagnostic never launched.
Other hypotheses remain possible but unproved: repeated Xcode resolver/selector
bytes, host facts, DYLD parsing, or an external file changed between captures.
The exact `tools, build` pair makes the cargo/rustc map divergence the strongest
source-grounded root; it must not be inflated into a retained runtime field
receipt.
