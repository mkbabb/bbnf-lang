# BA.W5 — JSON Direct-To-Struct Codegen First Cut

**Thesis** (the JSON `OpenFrame` substrate retires; direct-projection emit replaces the speculative `Vec<OpenFrame>::clone` checkpoint pattern; per-rule generated `parse_<rule>(...)` functions return typed `JsonValue<'p>` directly via byte-disjoint Alt; CSS L4, BBNF, Sheets, and the 5-grammar template cohort STAY on existing emitter path until BB). **Closer-gate** (BA-G1: `JsonParser::parse(twitter.json)` ≤ 400 µs on M1 Pro, beating sonic-rs's 436 µs by ≥ 8%; BA-G2: ≤ 2 heap allocations per parse-call; samply post-BA shows `Vec<OpenFrame>::clone` retired from JSON profile).

## §1 — Deliverable

Hereupon the JSON parse path's 86.07% inclusive pathology — the `Vec<OpenFrame>::clone` checkpoint at `crates/core/src/runtime/json/builder.rs:243` per `audit/RESTART-SKETCH-2026-05-03.md:154-220` — retires by mechanism. The mechanism is direct-projection: per-rule generated `parse_<rule>(input, &mut p, &mut arena, &mut state, &mut cursor) -> Result<JsonValue<'p>, ParseErr>` functions return typed values directly; byte-disjoint Alt emits direct `match first { b'{' => parse_object(...), b'[' => parse_array(...), b'"' => parse_string(...), b'-' | b'0'..=b'9' => parse_number(...), b't' | b'f' => parse_bool(...), b'n' => parse_null(...) }` without speculative checkpoint. `OpenFrame` deletes from the JSON path.

Per `audit/RESTART-SKETCH-2026-05-03.md:512-543` the post-restart emitter for JSON's `value` rule emits ~25 lines (versus the current `parse_object_JsonParser_object`'s 130 lines + `parse_wrap_*`'s 300 lines per `audit/RESTART-SKETCH-2026-05-03.md:592-595`). The direct-projection shape is:

```rust
fn parse_value<'p>(input: &'p [u8], p: &mut usize, ...) -> Result<JsonValue<'p>, ParseErr> {
    skip_space(input, p);
    let first = input.get(*p).ok_or(ParseErr::Eof)?;
    match first {
        b'{' => parse_object(input, p, ...),
        b'[' => parse_array(input, p, ...),
        b'"' => parse_string(input, p, ...).map(JsonValue::String),
        b'-' | b'0'..=b'9' => parse_number(input, p, ...).map(JsonValue::Number),
        b't' | b'f' => parse_bool(input, p, ...).map(JsonValue::Bool),
        b'n' => parse_null(input, p, ...).map(|_| JsonValue::Null),
        _ => Err(ParseErr::Syntax(*p)),
    }
}
```

No `OpenFrame` push, no `checkpoint`, no `Vec::clone`. The recursion stack IS the open-compound stack. Per `audit/RESTART-SKETCH-2026-05-03.md:582-590`, properties of the direct-projection emit:

- No `StructLayout` runtime literal. `String::from("object")` / `Vec::new()` for fields — gone.
- No `OpenFrame` stack. Local Rust variables hold the pair vec on the call stack; the recursion forms the stack naturally.
- No `checkpoint()` / `rollback()` on byte-disjoint Alt. The dispatcher is a `match` on first byte — no speculative entry.
- `JsonValue` is a Copy 16-byte tag-and-payload — passed by value into recursion, returned by value, stored by value.
- The arena owns interned slices.

The emitter scope is JSON only. CSS L4, BBNF, Sheets, and the 5-grammar template cohort (BNF, CSV, EBNF, CSS Pretty, Math) STAY on the existing `OpenFrame`-builder emitter path; their migration is BB.W0/W1 carry per the BA.md §Carry-tags TO BB row C1. Per the BA.md §Risks row 2 ("BA.W5 explicitly does NOT migrate non-JSON grammars; `EmitStrategy::for_grammar` retains the existing `OpenFrame` substrate for non-JSON grammars until BB.W0"), the W5 mechanism is JSON-scoped; the substrate-without-consumer concern is mitigated because BA.W5's consumer (JSON) lands in the SAME wave.

The Era V failure mode is mitigated because W5's substrate (the direct-to-struct emitter pattern) has the same-wave consumer of JSON parsing, which is benched at BA-G1 ≤ 400 µs and BA-G2 ≤ 2 heap allocations. The proof-of-mechanism IS the JSON consumer; not deferred to BB.

The performance trajectory: pre-W5 baseline (per `audit/RESTART-SKETCH-2026-05-03.md:154-220`) carries the 86.07% inclusive sample share at `Vec<OpenFrame>::clone`. W5 retires it; samply post-W5 shows the share retired. The target ≤ 400 µs (BA-G1 per `audit/SOTA-2026-05-03.md:50-58` sonic-rs benchmark_aarch64) is achievable because (per `audit/RESTART-SKETCH-2026-05-03.md:206-217`):

- Item 1 (StructLayout literal): retired by direct-projection; codegen-known type info is not re-derived at runtime.
- Item 2 (Vec deep-clone): retired; `Checkpoint` becomes O(1) tuple `(stack_depth, arena_arrays, arena_objects, root_set)` — but for byte-disjoint Alt, no checkpoint exists at all.
- Item 3 (18 attempt arms): retired; predictive byte-dispatch emits `match first { b'{' => ..., b'[' => ... }` directly.
- Item 4 (per-frame Vec::new()): retired; stack-allocated `JsonValue` returns by value; no per-frame Vec.
- Item 5 (deposit re-discrimination): retired; direct-projection emits parent-typed deposit.
- Item 6 (linear pair scan post-parse): retired at BA.W4.M2 (`Document::get<T>` reroutes through `parse_with`).
- Item 7 (Wrap frame on byte-disjoint Alt): retired; codegen elides Wrap entirely on Alt-of-Refs shapes.
- Item 8 (parse fn → __value thunk): retired; codegen inlines.
- Item 11 (persistent stack alloc): retired; recursion IS the stack.

The post-W5 emit shape for JSON's `value` rule is the canonical sonic-rs analogue. Per `audit/SOTA-2026-05-03.md:30` ("sonic-rs directly parses the JSON into a Rust struct, and there are no temporary data structures"), sonic-rs publicly cites *the absence of a tape* as the reason it beats simd-json on parse-to-struct. Per `audit/SOTA-2026-05-03.md:212` ("Direct-to-struct (no tape) | sonic-rs | One pass; minimal allocations; no skip benefit"), the architectural choice for BBNF — direct-to-struct, no tape — matches sonic-rs's discipline. The W5 emit is mechanically isomorphic to sonic-rs's parser: typed enum + recursive descent + arena-borrowed slices + zero speculative checkpoint on byte-disjoint Alt.

The CSS L4 / BBNF / Sheets / cohort grammars staying on the existing emitter path is a deliberate scope-limit. Per `audit/CENSUS-2026-05-03.md:328` ("`runtime/css_l4/builder.rs` 1014 LOC ... 14-variant OpenFrame builder ... split per variant frame modules"), the CSS L4 OpenFrame builder is 14-variant — its direct-to-struct migration is a higher-cost wave whose receiving wave is BB.W1. Per the BA.md §Risks row 1 ("BA.W2 god-module splits cascade into BA.W5 codegen breakage (renames pull through emitter)"), the W2 god-module splits land first; W5's regen comes last; xtask regen `--check` between waves verifies no cascade. The same-wave consumer (JSON) is what makes W5's substrate not Era V.

## §4 — Invariants

§I1. **Lock 1** (tape and columnar dead, direct-to-struct visible-and-internal). The JSON path's `OpenFrame` substrate retires; per `docs/HARDENING-PLAN-PROMPT.md:34`, "Direct-to-struct is *both* the visible API *and* the underlying memory layout — sonic-rs / lightning-css discipline." W5 lands the discipline for JSON; CSS L4 / BBNF / Sheets follow at BB.W1.

§I2. **Lock 3** (one parse impl). The W4-introduced `parse_with(input, &path)` is the single parse implementation; W5's direct-projection rewrites the body but preserves the unified surface.

§I3. **Lock 9** (slice-borrow primary; bumpalo + owned escape hatches). The W5 `JsonValue<'p>` is slice-borrowed by default; per `audit/SOTA-2026-05-03.md:122-123` ("`&'i str` slices over the input (lifetime `'i`), `CowArcStr<'i>` for case-folded names"), the default surface borrows. Three-surface API (parse / parse_in / parse_owned) routes to BB.W4.

§I4. **No orthogonal codepaths** (per `feedback_no_orthogonal_codepaths`). The JSON DirectToStruct strategy and the CSS L4 / BBNF / Sheets OpenFrame strategy ARE the same emitter dispatched on metadata-declared strategy — one emitter, two strategies, both consumers of the same IR. Per `feedback_no_orthogonal_codepaths`, this does NOT violate the invariant because the dispatch is at codegen time on metadata, not at runtime on a flag.

§I5. **No combinators monolithic** (per `feedback_no_combinators_monolithic`). The direct-projection emit consumes the typed IR directly; no combinator/SpanParser usage. Per the rule "ZERO combinator/SpanParser usage in monolithic arena path; extend classifier instead", W5's emit extends the alt classifier (M2) and does not introduce combinators.

§I6. **Preserve rich AST** (per `feedback_preserve_rich_ast`). The typed `JsonValue` enum preserves the rich AST shape: `Null | Bool(bool) | Number(JsonNumber) | String(&'p str) | Array(JsonArrayId) | Object(JsonObjectId)` — same shape as today's per `audit/MODULES-2026-05-03.md:942`; "Never flatten typed grammar rules for speed; rich AST parity with lightningcss is non-negotiable" applies; the JSON typed sum is preserved.

§I7. **Beat sonic-rs target** (per `feedback_beat_lightning` extended to JSON). Per BA-G1 (≤ 400 µs vs. sonic-rs's 436 µs, 8% margin), the performance target is to BEAT sonic-rs in the twitter dataset; not just approach.

§I8. **Inspect generated output** (per `feedback_inspect_generated_output`). Always inspect expanded/compiled output when working on codegen; use `cargo expand` + `cargo asm`. M1 + M2's verification requires reading the post-regen `crates/core/src/grammar/generated/json.rs` to confirm the direct-projection emit shape; the closer-gate's `rg -n 'match first {'` is the inspection step.
