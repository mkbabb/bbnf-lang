# Tranche B3 — AY-II.W0' Revert + Parser-Baseline Restoration

B3 tests the hypothesis that AY-II.W0' source landings (FusedBuilder
collapse, materializer routing, scan-policy splice, and the dependent test
+ tape refactors) are responsible for the runtime parser regression
observed at B2.W0.c. The hypothesis is plausible per the W0.c diagnostic
narrowing but unproven; B3 sequences the test as a **proof-first**
disposable-worktree dry run before any canonical history lands on master.
If the dry run restores parser baseline, the canonical revert chain lands
on master and B2 resumes; if it does not, B3 escalates per the escape
clause without polluting master with avoidable forward-revert noise.

B3 is a focused two-wave tranche. The reverted commits (whether or not
they land canonically) are preserved verbatim in B3 audit so they can
re-land as B4 under the post-B2 xtask substrate, where bisect-and-fix is
straightforward (no proc-macro re-compile cost between bisect steps).
Once B3 closes, B2 resumes from W0.c re-execution on whatever runtime
substrate B3 produced.

## Architectural thesis

The four 2026-04-25 deep audits (`docs/audit/2026-04-25-deep-audit/AUDIT-{A,B,C,D}-*.md`)
attributed the 80+ minute cold rustc-side wall to "AY-II IR-pipeline
accumulation running inside rustc's expand phase". B2's xtask transposition
(T3) was the prescribed remedy: relocate the IR pipeline out of rustc's
expand phase into a build-time `cargo xtask regen` step, then retire the
proc-macro entirely.

B2.W0.c's diagnostic probe disproves that attribution. Re-running
`cargo xtask regen --grammar bbnf` (which invokes
`bbnf::pipeline::compile_paths_request` from a release-profile xtask binary,
with no proc-macro expansion in flight) hangs > 5 min. The agent's narrowing
proves the wall lives in `BbnfBootstrap::parse` itself — the runtime parser
on `bbnf.bbnf`-shaped corpora — not in the IR pipeline. The same regression
reproduces against the smaller `json` grammar (537 bytes), which hung
> 39 s in W0.c without completing.

The actual root cause is a runtime parser regression introduced when AY-II's
W0' source landings cherry-picked onto master without a corresponding
`generated.rs` regen. The W0' commits collapsed `TapeBuilder` + `ValueBuilder`
into `FusedBuilder` (W0'.a), routed materializer lookups through raw rule
names (W0'.b), and spliced `STRUCTURAL_SCAN_POLICY` into the codegen path
(W0'.c). Each of those landings affects every compound write or scan
boundary; together they compound on `bbnf.bbnf`-shaped grammars (deep
recursion, dense alternation) into a runtime regression invisible to the
pre-W0' `compile_pipeline` bench's 911 µs `compile_bbnf` measurement.

B2 alone cannot close on this substrate. T3 relocates the wall from
rustc-expand-time to xtask-runtime, but the wall persists. Every B2 hard
gate that measures regen wall-clock observes the same regression at xtask
runtime that pre-B2 observed at rustc-expand time.

B3's response: **test the revert-as-restoration hypothesis on a disposable
worktree first, and only land canonical revert history on master once a
phase-instrumented `cargo xtask regen --grammar bbnf` confirms parser
baseline is restored**. The hypothesis is "W0' half-migration caused the
parser regression"; the disposable-worktree probe is the proof. If the
probe confirms, the canonical revert chain lands on master so B2 can
resume on a known-good runtime. If the probe disproves, B3 escalates per
the escape clause (W0' → W0-fix → W0 base scope expansion) without
polluting master with forward-revert noise.

The reverted W0' work re-lands as B4 on the post-B2 xtask substrate,
where:

1. The 80+ min cold rustc-expand wall is gone (B2 retired it).
2. Bisect cycles cost seconds rather than hours (`cargo xtask regen` runs
   the IR pipeline once per cycle; the consumer crates `include!` the
   on-disk product without re-running expansion).
3. The runtime parser regression is bisectable against the BBNF parse test
   directly, with bench evidence at every step.

This is not a workaround. The architectural posture is: **a runtime parser
regression on parity-critical types must be diagnosed against a substrate
where bisect cycles are tractable**. The pre-B2 substrate is not such a
substrate; the post-B2 substrate is. B3 re-orders the work to match.

## Operational posture

1. **B3 dispatches AFTER B2.W0.c partial-close.** Master HEAD at B3 open
   is `b8cacedd` (the B2.W0.c status-snapshot commit) plus this plan's
   `fc3b5aaf` doc commit. The xtask substrate landed at `dec67806`; the
   per-grammar boundary spec at `3c68e8c4`; the W0.c partial-close (xtask
   body + bbnf-bootstrap migration) at `21881591`. All three commits stay
   on master through B3.
2. **B3 is proof-first.** W0 splits into three phases: W0.a (disposable-
   worktree probe — apply the 14 W0' reverts as throwaway commits, build,
   run phase-instrumented xtask regen, read the parse-phase wall);
   W0.b (canonical revert chain — only IF W0.a's probe confirms thesis);
   W0.c (orchestrator cherry-pick to master with strict cherry-pick
   abort discipline, no destructive resets). The probe's verdict gates
   whether canonical history lands on master at all.
3. **The revert is `git revert`-mediated, not `git reset`.** B3 produces
   forward commits on master that undo W0' content. History stays linear;
   no force-push, no destructive operation. Cherry-pick conflicts resolve
   via `git cherry-pick --abort` + manual investigation (or sub-agent
   redispatch on a fresh worktree); `git reset --hard` is forbidden on
   master. The `git revert` form preserves the original commits in
   history so B4 can cherry-pick them onto the post-B2 substrate.
4. **Phase-instrumented xtask is a B3 amendment.** W0.a adds explicit
   per-phase wall logging to `xtask/src/regen.rs` (grammar-source read,
   `BbnfBootstrap::parse`, IR pipeline, `generate_all`,
   `prettyplease`, file write). The instrumentation lands as a SEPARATE
   commit (NOT subject to the revert chain — it's new code, not affected
   by W0'). The instrumentation persists through B3 close so B4's
   bisect-and-fix has the same diagnostic surface.
5. **Single-cargo-per-target discipline.** B3 dispatches one probe agent
   in W0.a, one canonical-revert agent in W0.b, and one verification
   agent in W1.a. W0.c is orchestrator-owned, no separate sub-agent. No
   parallel cargo invocations.
6. **No mid-tranche scope absorption.** If the W0' revert does not restore
   parser baseline at the W0.a probe, B3 expands the revert scope to
   include AY-II.W0-fix (`f8ac2cd7`, `c9142405`) and, if necessary, the
   AY-II.W0 base commits. Each expansion runs as a fresh disposable
   worktree probe; canonical history lands only after a probe confirms.
   Beyond W0 base, the revert exhausts the candidate set: if performance
   still doesn't restore, B3 closes on what landed and the residual scope
   opens B5 (B4 is reserved for W0' re-land).
6. **No new tranche-letter contention with B4.** B4 is the named successor
   for W0' re-land. It opens after B2 closes (B2 → B3 → B2 resume → B4 is
   the sequencing). B3 carries no B4 work.
7. **AY-II planning continuity.** AY-II.W0' close ceremony as authored
   under AUDIT-B no longer applies in its original form — the W0' source
   landings being reverted ARE the AY-II.W0' work. The compressed-honest
   close ceremony shifts to land as B4's close, not AY-II.W0'. AY-II.W1-W5
   sequencing remains unchanged; those waves operate on whatever substrate
   B4 produces.
