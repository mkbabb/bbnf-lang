# BB.W1 — Profile Split + Prepared-Binary Discipline

**Opens after**: W0 close
**Agents**: 2 parallel
**Hard gate**: Routine iteration, profiling preparation, and final-proof runs use distinct profiles and prepared-binary workflows with measured cost reductions.
**Status**: planned

## Scope

1. Separate routine iteration, profiling-prep, and final-proof profiles.
2. Add prepared-binary discipline for profiling runs.
3. Prove lower cost for profiling preparation and routine iteration.

| File | Access |

**Do NOT touch**: parser runtime code, replay/recovery/debug tooling,
any `.bbnf` grammar.

## Phase sub-items

### BB.W1.1 Profile split

Mechanism: define distinct routine, profiling-prep, and final-proof
profiles with intentional optimization and debuginfo tradeoffs.

Files touched: `Cargo.toml`, `.cargo/config.toml`.

Sub-gate: all three profiles compile and are selectable.

### BB.W1.2 Prepared-binary workflow

Mechanism: add a prepared-binary script or command path for profiling
so repeated Samply or perf runs stop rebuilding unnecessarily.

Files touched: `scripts/profile-prepare.sh`,
`docs/instructions/PROFILING.md`.

Sub-gate: profiling-prep can be run once and reused.

## Hard gate

1. Distinct profiles exist and are usable. Artefact:
   `docs/benchmarks/post-BB-W1-profiles.txt`.
2. Prepared-binary profiling cost improves versus baseline. Artefact:
   `docs/benchmarks/post-BB-W1-mid.json`.
3. Docs describe the prepared-binary workflow accurately. Artefact:
   `docs/benchmarks/post-BB-W1-profiles.txt`.
