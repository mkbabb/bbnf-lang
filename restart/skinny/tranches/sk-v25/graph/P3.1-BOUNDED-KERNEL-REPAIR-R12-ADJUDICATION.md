## Mandatory synthesis

### 1. Complete post-dry byte and structural work

Use these sealed exact metrics from the existing P/dry traversal:

```text
S = one structural serializer traversal's checked work (no payload scan/output)
R = total raw serialized string/byte source length
J = exact compact serialized JSON length
P = total raw length of percent-bearing dynamic strings
M = maximum dynamic string length
T = truth-row count
D = percent_decode_work_bound(P)
```

The current unoptimized post-dry path has these byte roles for an edge record:

```text
graph writer                 source + output = 2
bounded-size width scan                        1
two stable edge hash writes  2 source + 2 output = 4
no-percent scan                                1
portability DFA                                1
privacy walk width scan                        1
total                                         10
```

Blindly changing five to ten would be correct but needlessly preserves two
redundant scans. Charging seven traversal calls is also insufficient under the
source/output convention. The KISS/performance-optimal R13 repair is:

1. carry the sealed measured `J` into bounded canonical validation and compare
   it directly with the size ceiling, eliminating the second width scan;
2. make the privacy-only string walker invoke its observer without calling
   `inspect_json_string`, eliminating the second width scan while preserving
   the no-percent scan and portability DFA;
3. retain one caller-owned budget and the private scalar metadata only—no
   token, refund, replay representation, or second budget.

After those deletions a source-derived complete C bound is:

```text
graph writer:        S + R + J
two edge writers:  2S + 2R + 2J   (all edge records are disjoint graph subobjects)
privacy walk:        S + 2R + D    (no-percent scan + decoded DFA, decoded length <= R)
fixed semantics:                16T
------------------------------------------------
C = 4S + 5R + 3J + D + 16T
```

All arithmetic is checked. `D` conservatively overlaps some percent-bearing
source work; overlap is permitted, omission is not. The 16T term remains only
for fixed semantic visits; it is not used to pay byte or nested-comparison
work. This also corrects an omission not separately named by the critics:
serialized length alone did not prove coverage of arbitrarily many nested
serializer callbacks. The explicit `S` terms do.

### 2. A total generalized comparison bound

Delete `identity_comparison_text`, `common_prefix_work`, and
`canonical_comparison_depth`; their exact-subset scan adds cost while proving
the wrong property. Let `V = S + R`.

- Every truth row participates in at most two adjacent top-level `Truth`
  comparisons, so complete derived truth order is bounded by `2V`.
- Every nested attribute/condition/projection element participates in at most
  two adjacent comparisons and is a disjoint graph subobject, so all nested
  order is bounded by another `2V`.
- Every node identity participates in at most two adjacent duplicate checks,
  so that subset is bounded by another `2V`.

Thus all non-search derived/nested comparisons are bounded by `6V`, including
long common prefixes.

For endpoint searches, let `N` be node count, `E` edge count, and for `N > 0`
let `L = ilog2(next_power_of_two(N)) + 1` (otherwise zero). `L` is a safe upper
bound on comparator calls per binary search. An `Identity` has at most two
dynamic strings; therefore comparison of two identities reads at most `4M`
dynamic bytes. Thirty-two fixed actions conservatively cover the outer
discriminant, wrapper lengths, the two fields, and `PhysicalKind`. There are at
most `2E` searches. A complete checked comparison charge is therefore:

```text
comparison_work = 6(S + R) + 2E * L * (4M + 32)
```

This bound is grammar/type-shape-derived, includes every `Truth` and nested
comparison, explicitly covers long prefixes and `log N`, and uses no observed
current total. R13 must encode it as a named charge before any comparison and
prove its arithmetic independently with a long-prefix, many-edge fixture. If
implementation inspection finds an `Identity` variant with more than two
dynamic strings, the constant proof must fail closed rather than silently
retain this formula.
