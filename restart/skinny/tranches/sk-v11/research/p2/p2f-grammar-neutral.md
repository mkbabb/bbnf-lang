## §1 — Findings (concrete; file:line on bbnf claims, citation on external claims)

1. V1 final sync found P2-B, P2-C, P2-D, and P2-E present, so this file folds the available sibling candidate names into grammar-neutral families. P2-B names SIMD/process candidates such as `ESCAPE_UXXXX_X4_PRODUCTION`, `STRING_SPECIAL_BLOCK_CALLER_MICROPROOF`, `BYTE_CLASS_TBL_CLASSIFIER`, `DIGIT_SPAN_UDOT`, `WHITESPACE_BYTE_SET_SKIP`, `MOVEMASK_EXHAUSTIVE_GATE`, `CONTAINER_DISPATCH_CLASSIFIER`, and `OUTPUT_DIGEST_HASH_PROCESS` (`restart/skinny/tranches/sk-v11/research/p2/p2b-dav1d-process.md:256-264`). P2-C names the aarch64 instruction candidates as TBL byte-set/classifier, UDOT digit-span, widened string-special block, x4 escape codec, whitespace byte-set skip, and output digest/hash scalar/cache (`restart/skinny/tranches/sk-v11/research/p2/p2c-arch-esoterica.md:24-37`). P2-D names substrate/consumer candidates D1-D5 (`restart/skinny/tranches/sk-v11/research/p2/p2d-substrate-tape.md:28-34`), and P2-E names parse-that gaps plus non-candidates (`restart/skinny/tranches/sk-v11/research/p2/p2e-parse-that-gaps.md:31-111`). S-P1 hardening accepts the hot families named in the frontmatter and explicitly says JSON-only telemetry does not prove CSS L4, Sheets, or BBNF-self behavior (`restart/skinny/tranches/sk-v11/research/p1/hardening/HARDENING-S-P1-CONVERGED.md:41-55`).

2. Lock 14 is the dominant abstraction constraint. Generic crates may not carry grammar-specific match arms, modules, types, or feature flags; per-grammar runtime modules must be generated from one grammar-agnostic template that consumes grammar source plus metadata (`restart/locks/LOCKS.md:78`). Therefore every candidate below is acceptable only as a byte-set, classifier, mask, scalar decode, tape, or generated-template operation. JSON policy in `bbnf-simd`, `parse-that-regex`, `codegen`, or generic runtime code is a reject.

3. Lock 1 is the output/substrate constraint. Tape is the single retained substrate, unioned with direct-to-struct when a retained document exists; direct-only `SinkOnly` retains no queryable document; SIMD masks are transient producers, not sidecars (`restart/locks/LOCKS.md:52`). REDRESS reinforces that no precomputed structural index, event vector, whitespace bitmap, aux projection column, or parser-local second scanner is admissible (`skinny/REDRESS.md:715-740`, `skinny/REDRESS.md:742-767`, `skinny/REDRESS.md:784-813`).

4. The non-JSON grammar inventory proves the primitive surface is broader than JSON. CSS L4 declaration values include dispatch-heavy value alternatives and functions (`grammar/css/l4/values.bbnf:20-22`, `grammar/css/l4/values.bbnf:84-101`), leading-dot signed numbers and dimension units (`grammar/css/l4/value-unit.bbnf:8-16`, `grammar/css/l4/value-unit.bbnf:62-72`), dual-quoted escaped strings (`grammar/css/l4/tokens.bbnf:7-9`), and hex colors (`grammar/css/l4/color.bbnf:187-190`). Sheets formulas include leading-dot numbers, doubled-quote strings, case-insensitive booleans, error literals, cell/range spans, operators, functions, and array literals (`grammar/google-sheets/google-sheets.bbnf:6-18`, `grammar/google-sheets/google-sheets.bbnf:34-42`, `grammar/google-sheets/google-sheets.bbnf:52-63`, `grammar/google-sheets/google-sheets.bbnf:97-167`). BBNF-self includes multiple literal delimiters, regex literals, comments, rule modifiers, mapping, directives, and grammar items (`grammar/bbnf/bbnf.bbnf:9-18`, `grammar/bbnf/bbnf.bbnf:29-56`, `grammar/bbnf/bbnf.bbnf:75-85`).

5. The current local primitive code already contains both neutral kernels and JSON-overfit wrappers. Neutral examples: `scan_string_special_block_scalar(bytes, terminator, escape, control_limit)` and its aarch64 NEON body are parameterized (`skinny/crates/bbnf-simd/src/aarch64/string_block.rs:30-72`); `byte_class_from_table_64_scalar` and `byte_class_from_eq_set_64_scalar` are table/set based (`skinny/crates/bbnf-simd/src/scalar/byte_class_from_table_64.rs:1-10`, `skinny/crates/bbnf-simd/src/scalar/byte_class_from_eq_set_64.rs:20-38`). JSON-overfit examples: `match_string_at_quote_trusted_utf8` assumes double quotes, backslash escapes, and JSON control-byte policy (`skinny/crates/parse-that-regex/src/lib.rs:157-209`); `validate_string_escape` hardcodes JSON simple escapes plus `u` (`skinny/crates/parse-that-regex/src/lib.rs:283-293`); `match_number_span_from_first` is JSON-strict about leading zeros, signs, fraction, and exponent shape (`skinny/crates/parse-that-regex/src/number/mod.rs:31-103`).

6. Current skinny codegen is not yet Lock-14 clean for non-JSON generated parser waves. `emit_from_source` takes a grammar name and source generically (`skinny/crates/codegen/src/lib.rs:69-78`), but both normal and typed emission call `json_provider::ensure_runtime_profile` and emit JSON provider files (`skinny/crates/codegen/src/lib.rs:102-136`, `skinny/crates/codegen/src/lib.rs:139-167`). That is acceptable as current inventory evidence, not as an S-P3 generalization endpoint.

7. Existing old non-JSON struct-direct runtime modules are cautionary evidence, not templates for SK-V11. CSS, Sheets, and BBNF runtime modules state that their struct-direct parse paths sever the tape substrate (`crates/core/src/runtime/css_l4/mod.rs:5-10`, `crates/core/src/runtime/google_sheets/mod.rs:5-10`, `crates/core/src/runtime/bbnf/mod.rs:7-12`). Lock 1 requires any new generated direct or typed parser wave to either be `SinkOnly` with no retained document or produce typed values borrowing into the one tape substrate, not revive those severed paths.

8. SK-V11 must benchmark at least one non-JSON generated direct or typed parser intervention, preferred in order CSS L4 declaration values, Sheets, then BBNF-self (`restart/skinny/tranches/sk-v11/HANDOFF.md:74-80`). The benchmark must be a generated Track 1, an independent oracle or Track 2 on the same output plane, strict semantic equality, before/after throughput and c/B where available, primitive self-time, and explicit proof that no sidecar or JSON policy entered generic crates.

## §4 — Risks (REDRESS entries any candidate must NOT re-open)

1. Sidecars and second scanners: C1, C5, C6, C7, and C9 must not recreate aux columns, event cursors, parser-local structural cursors, or W3 union/event/class-column surfaces. REDRESS 50, 51, 53, and 102 reject these families (`skinny/REDRESS.md:715-740`, `skinny/REDRESS.md:742-767`, `skinny/REDRESS.md:784-813`, `skinny/REDRESS.md:3042-3058`).

2. JSON string materialization traps: C2, C3, and C8 must not reopen exact decoded stats, source-hook fused materializers, parser-owned decoded scratch, byte-output unescape helpers, or semantic string facts. REDRESS 54 and 67 reject representative shapes and require any future decoded-string primitive to beat the standalone materializer with scalar/checkasm parity and a same-wave generated consumer (`skinny/REDRESS.md:815-844`, `skinny/REDRESS.md:1736-1785`).

3. String cap/widening overreach: C2 may use caps only as generated per-rule cost facts. REDRESS 72 admits cap16 narrowly for generated retained OffsetTape, while REDRESS 83 rejects a JSON-specific StringBlock16 wrapper (`skinny/REDRESS.md:1996-2004`, `skinny/REDRESS.md:2320-2327`).

4. Unicode escape overfit: C3 must not promote JSON `\uXXXX` and surrogate policy as a generic primitive. REDRESS 64 rejects retained x4 Unicode-escape validation beyond the dense row, and REDRESS 82 rejects the single-quartet materializer path (`skinny/REDRESS.md:1584-1635`, `skinny/REDRESS.md:2287-2316`).

5. Numeric fallback overreach: C4 must not reopen mantissa-widen/table-only numeric work without a same-wave consumer and fresh hot leaf. REDRESS 80 routes the next numeric work to a concrete numeric-array scan/dispatch wave, not generic fallback widening (`skinny/REDRESS.md:2217-2248`).

6. Container/object JSON carry: C6 may use generated next-byte carry as a per-grammar template when measured, but may not put JSON object/array semantics in generic crates.
