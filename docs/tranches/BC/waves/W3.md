# BC.W3 — Core Crate Split

**Name**: W3 — Core Crate Split
**Opens after**: BC.W2 close (TS + WASM emitter scaffolds compile against the IR contract; trivial-grammar smoke tests pass)
**Hard gate**: `bbnf-parse`, `bbnf-codegen`, `bbnf-runtime` exist as workspace members; each compiles independently with explicit dependency arrows; `bbnf-parse` does NOT depend on `bbnf-codegen`; `cargo nextest run -p bbnf-parse -p bbnf-codegen -p bbnf-runtime` 100% pass
**Status**: superseded — split into BC.W3a (`bbnf-runtime` extraction) + BC.W3b (`bbnf-parse` extraction) + BC.W3c (`bbnf-codegen` extraction) + BC.W3d (umbrella `core` slim-down) + BC.W3e (xtask path update + migration cookbook) per surgery 8 (`audit/HARDENING-PLAN-SYNTHESIS-2026-05-03.md:60`) and `audit/W3-crate-dependency-dag.md:§6`. See `waves/W3a.md`, `waves/W3b.md`, `waves/W3c.md`, `waves/W3d.md`, `waves/W3e.md`. Per surgery 8, `bbnf-runtime` *depends on* `crates/path/`; does NOT absorb `path/`.

## §1 Deliverable

Hereupon `crates/core/` splits per `audit/MODULES-2026-05-03.md:1158-1167` into three cohesive sub-crates: `bbnf-parse` (source/parse/lower/host) + `bbnf-codegen` (codegen/) + `bbnf-runtime` (runtime/handle.rs; **depends on `crates/path/`** per surgery 8 — does NOT absorb `path/`). Each compiles independently with explicit dependency arrows; the dep graph is `bbnf-parse → bbnf-runtime`, `bbnf-codegen → bbnf-parse → bbnf-runtime`; `bbnf-parse` does NOT depend on `bbnf-codegen`. The split is the largest structural refactor of BC; gated by W0 IR contract spec landing first per `audit/MODULES-2026-05-03.md:1166-1167`.

The pre-split `crates/core/src/` layout (per BA.W0):

```
crates/core/src/
├── source/        types + directives + imports + dep-graph
├── parse/         BBNF self-host parse + CstSchema + generated/
├── lower/         BBNF AST → IR (driven by view-walk)
├── codegen/       Track 1 + Track 2 emitters (Rust + TS + WASM scaffolds post-W2)
├── runtime/       per-grammar arenas / builders / documents / views
├── path/          typed-path executor
├── pipeline/      compile orchestrator
├── host/          host-fn shims (css_types)
└── lib.rs
```

The post-split layout:

```
crates/
├── bbnf-parse/         (source/, parse/, lower/, host/, pipeline/)
├── bbnf-codegen/       (codegen/ — Rust lowerer + TS + WASM scaffolds)
├── bbnf-runtime/       (runtime/, path/, handle.rs)
└── core/               (lib.rs only — re-exports for backwards-compat surface)
```

The `bbnf-parse` sub-crate consumes `bbnf-runtime` (lower/ reads `runtime::bbnf::BbnfView`; per `audit/MODULES-2026-05-03.md:1154-1158`, the dep arrow is `bbnf-parse → bbnf-runtime`; circular dep verified absent). The `bbnf-codegen` sub-crate consumes `bbnf-parse` (codegen reads `GrammarIR` produced by `bbnf-parse`'s lowering). The `core` umbrella crate retains `lib.rs` as the public-facing re-export shell.

## §4 Invariants

§I1. **Lock 13 (no god directories at the crate level)**: the core crate splits into three cohesive sub-crates; each owns a single concern (parse / codegen / runtime); the umbrella `core` carries only re-exports. sonic-rs / lightningcss / simdjson cohesion is the standard.

§I2. **Lock 5 (IR + per-backend lower)**: post-split, `bbnf-codegen` is the home of the per-backend lowerers (Rust + TS + WASM scaffolds); `bbnf-parse` produces grammar IR + Layout; the IR contract is the boundary between the two crates.

§I3. **Lock 11 (path-deps for incubating sister crates)**: the split uses workspace path-deps (`bbnf-parse = { path = "../bbnf-parse" }`); not crates.io publication; sister-crate API freeze + publication candidates land at BC.W5.

§I4. **Lock 6 (xtask emits committed source)**: post-split, xtask regen writes to `crates/bbnf-parse/src/parse/generated/`; the regen output is committed; no proc-macro façade.

§I5. **Zero circular dependencies**: per `audit/MODULES-2026-05-03.md:1149-1156`, the dep graph is `bbnf-codegen → bbnf-parse → bbnf-runtime`; verified at W3-G3 via `cargo tree`.

§I6. **No behaviour change**: the split is structural; per-grammar parity tests against sonic-rs / lightningcss / simdjson remain green at W3 close (verified at W3-G4).

§I7. **Lock 1 (tape and columnar dead) preserved**: the post-split sub-crates do not introduce tape or columnar substrates; `bbnf-runtime` is the typed-record substrate; no `TapeRec` / `TapeCursor` / columnar SoA in any sub-crate.

§I8. **Backwards compatibility via umbrella re-exports**: the umbrella `core` crate's `lib.rs` re-exports preserve the public surface; downstream consumers (LSP, analysis, eventual crates.io publication) use `bbnf::*` paths which resolve through re-exports.

## §9 Closing posture

The core crate fractures into three cohesive sub-crates: `bbnf-parse`, `bbnf-codegen`, `bbnf-runtime`. Each owns a single concern; each compiles independently; the dep graph is acyclic per `audit/MODULES-2026-05-03.md:1149-1156`. The split is the largest structural refactor of BC; gated by W0's IR contract spec landing first per `audit/MODULES-2026-05-03.md:1166-1167`. The umbrella `core` crate retains `lib.rs` as the public-facing re-export shell. Lock 13 closes at the crate level. BC-G5 closes here; the post-split workspace is the foundation for sister-crate API freeze (W5) and BD's eventual TS/WASM activation.

## §10 Cohesion verification

Per Lane 9 (Encapsulation Audit), the split honours Lock 13's cohesive encapsulation at the crate level. The standard set by sonic-rs (`src/{parser, value, serde, util, lazyvalue, ...}`), lightning-css (`src/{rules, properties, selector, declaration, traits, ...}`), and simdjson (`{dom, ondemand, generic, ...}`) — each top-level directory names a concern, expresses it through 4–10 children at the next level, each child carries a uniform sub-API — applies. `bbnf-parse` (parse concern), `bbnf-codegen` (codegen concern), `bbnf-runtime` (runtime concern) match this discipline. The umbrella `core` crate is the re-export shell — equivalent to sonic-rs's `lib.rs` re-exporting from `parser/`, `value/`, etc. The cohesion is structural, not just nominal.

## §11 Friction-forecast for the split

Per Lane 7 (Friction-Forecast), the core crate split is a breaking change for downstream consumers. Forecast points: (1) the rename from `bbnf::backend::*` to `bbnf::codegen::*` (or `bbnf-codegen::*` if importing the sub-crate directly); (2) the introduction of `bbnf-parse`, `bbnf-codegen`, `bbnf-runtime` as new workspace members; (3) the `Cargo.toml` `[workspace.dependencies]` table grows by three entries.

Mitigation: the umbrella `core` crate's `lib.rs` re-exports preserve `bbnf::*` paths; downstream consumers may continue using the umbrella; the per-crate boundary is opt-in. The breaking change is structurally bounded; the educational artefact is `docs/tranches/BC/audit/W3-import-migration.md` (created at W3 close) naming the path remapping.
