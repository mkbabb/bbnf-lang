## T1 — one budget-aware JSON preflight and streaming primitive

`hash.rs` now contains one general Serde preflight used by graph, SCC, cycle,
and component-member hashing. It accepts a generic charge adapter backed by
the existing `ProjectionBudget`; there is no second mutable resource budget.
The preflight charges a container or scalar callback before visiting its
payload and charges `str.len()` before Serde scans string contents.

Let `n` be raw string bytes. A JSON source byte can produce at most six JSON
output bytes. Capped measurement therefore admits

```text
7n = 1n source scan + 1 * 6n output
```

and measurement-plus-streamed-hash admits

```text
14n = 2n source scans + 2 * 6n output/hash
```

before either source scan or fragment write. Every scalar/string callback
also charges 32 visit units; a declared container charges
`32 * (declared_length + 1)` with checked arithmetic. The preflight derives a
checked JSON output upper bound from the complete Serde shape, including
static names, dynamic keys, bytes, chars, maps, tuples, structs, enums,
nonfinite floats, and `collect_str`.

The admitted value is serialized once into a counting hash writer to obtain
exact compact length and digest, then serialized directly into the streamed
hash writer. No full canonical JSON buffer is built. The second pass must
match both the measured length and digest, so the same-length stateful
serializer counterexample fails closed. For long unescaped, final-byte escape,
escape-heavy, static-name, declared-length overflow, and worst-case control
inputs, one below the derived work observes zero source bytes and zero JSON
fragment writes; exact admission matches `serde_json` length and SHA-256.

## T2 — linear portable decoding and exact canonical/privacy accounting

The percent decoder preserves repeated synchronous fixpoint semantics without
an encoding-depth cap. With input length `n`, it uses a fixed linked arena of

```text
n + 2 * floor(n / 3) DecodeByte nodes
```

plus two `n`-entry `usize` worklists and three `n`-byte scratch buffers. Its
checked allocation bound is therefore

```text
(n + 2 * floor(n / 3)) * size_of::<DecodeByte>()
+ 2n * size_of::<usize>()
+ 3n bytes.
```

The live-node ancestry partitions the original input. Every lossy replacement
has a disjoint `%HH` ancestry, so replacements are at most `floor(n / 3)`,
appended arena nodes are at most twice that, and live length never exceeds
`n`. Work is bounded by `4n + 21D`, where `D` is the number of successful
decodes and `D <= floor(n / 2)`; the production admission uses the checked
integer bound `15n`. The no-percent path returns `Cow::Borrowed`.

Exhaustive inputs over `%25AFx` through length six and targeted
`%C2%25A9`, `%E2%82%AC`, `%FF`, `%25%32%35`, and mixed invalid/nested
families match the former repeated whole-round lossy semantics. Nested depths
8, 64, 512, and 4096 remain within `15n`. A global-allocator observation on a
repeated hostile Unicode/invalid/nested family stays within the independent
allocation formula above.

The portable-path predicate is now one rolling-window/state-machine pass. It
preserves the former drive, UNC, POSIX, known-root, file-URI, forbidden-byte,
and tilde-path semantics while visiting at most `n` bytes. Exhaustive inputs
through length six match the former predicate, and repeated tilde-boundary
fixtures through 32,768 bytes observe exactly `n` operations. Dynamic privacy
work is consequently `15n + n = 16n`.

For canonical validation, define:

```text
J = exact compact serialized JSON length
R = all raw serialized string bytes
D = dynamic payload string bytes
T = privacy serializer traversal callbacks
Q = truth-row count
V = exact node count
NB = total exact-node identity source bytes
M = maximum exact-node identity source bytes
E = exact edge endpoint count (two per exact edge)
EB = total endpoint identity source bytes
C = 0 when V = 0, otherwise ceil(log2(V)) + 1
K = 4R + 2NB + C * (E * M + EB)
```

`K` covers global/nested adjacent ordering, duplicate-node identity checks,
and worst-case binary-search endpoint comparisons. The whole exact
canonical/privacy work is

```text
W = 3J + 4R + 16D + T + K + 16Q.
```

Before measuring JSON, validation admits the unavoidable lower bound

```text
L = 7R + 16D + T + K + 16Q.
```

Because compact JSON length is at least its raw string payload, the remainder
is exactly `W - L = 3 * (J - R)`. Only after `L` fits may exact streaming
measurement begin; only after the remainder fits does the canonical phase
marker begin. The byte reservation is

```text
J + 2R + decoder_allocation_bound(D) + Q * size_of::<Truth>().
```

shares semantic validation with canonicalization; it no longer clones,
sorts, deduplicates, re-sizes, and compares a second full graph merely to
prove canonicality. A standard 8,000,000-work/512-MiB nested-percent graph
