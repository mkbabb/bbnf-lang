## §1 — Findings

1. CSS L4 is authoritative for SK-V12. A generated CSS L4 Track 1 row must beat `lightningcss_mbps + 1` on the same corpus, same output plane, same host, and strict equality semantics before Sheets or BBNF-self can be used as fallbacks. Sheets and BBNF-self are fallback-only after a measured CSS L4 redress attempt fails, not after preflight discomfort (`restart/skinny/tranches/sk-v12/USER-PIN-W1-CSS-L4-SOTA.md:15`, `restart/skinny/tranches/sk-v12/HANDOFF.md:54`, `restart/skinny/tranches/sk-v12/SYNTHESIS.md:42`).

2. The accepted S-P1 hot families are JSON-derived nomination evidence, not CSS proof. S-P1 converged under PIN-V6/PIN-V7 and accepted `bounded_plain_string_scan`, `container_dispatch`, `unicode_escape_hex_decode`, `number_digit_span`, `simd_movemask`, `string_escape_decode`, `output_digest_hash`, `ascii_whitespace_skip`, `typed_direct_projection`, and `serde_json_oracle_read_parse`; the same convergence states that JSON-only telemetry does not prove CSS L4, Sheets, or BBNF-self behavior (`restart/skinny/tranches/sk-v12/research/p1/hardening/HARDENING-S-P1-CONVERGED.md:47`, `:60`).

3. The current result surface contains no admitted generated CSS L4 row. `skinny/RESULTS.md` remains JSON-only with `parse_only` diagnostic rows, four direct guard rows, thirteen direct residual rows, seven typed guard rows, and overall `N-direct / NoGo`; P1-F confirms no `lightningcss` or `css_l4` row exists in the live table (`skinny/RESULTS.md:143`, `restart/skinny/tranches/sk-v12/research/p1/p1f-results-delta.md:77`).

4. Grammar neutrality is blocked at the current codegen/runtime boundary until `GrammarConfig` or an equivalent grammar-derived metadata surface lands. The value/API audit identifies five major JSON-policy leaks plus two embedded leaks: structural alphabet, value dispatch, string escape/quote policy, number policy, quoted-key/object-pair policy, `OffsetFlags` meaning, and `JsonSink` methods. CSS L4 emission is illegal until these are expressed through generated metadata/templates rather than JSON provider policy (`restart/skinny/tranches/sk-v12/research/skv12-value-api-audit.md:61`, `:71`, `:99`, `:167`, `restart/skinny/tranches/sk-v12/HANDOFF.md:120`).

5. The generic-crate Lock 14 proof is executable, not prose. Generic crates must carry zero `match grammar { Json => ... }` arms, zero grammar-named public API types, zero per-grammar feature flags, and no handwritten per-grammar runtime files outside generated modules. For SK-V12, a candidate is not grammar-neutral until the CSS L4 generated row proves no JSON-provider branch is used and the gate consumes Lock 14 status (`restart/locks/LOCKS.md:78`, `restart/skinny/tranches/sk-v12/SYNTHESIS.md:199`).

6. Lock 1 admits transient masks and same-tape operations only. A SIMD mask stream may feed a parse loop, tape builder, or direct sink, but retained structural offsets are the tape; a parser-owned structural side vector, cursor list, class lane, whitespace bitmap, or `UnionTape` is a parallel substrate. REDRESS 96/97/98 remain measured historical failures even though the user pin unblocks the category for materially different attempts (`restart/locks/LOCKS.md:52`, `skinny/REDRESS.md:2795`, `:2850`, `:2910`, `restart/skinny/tranches/sk-v12/USER-PIN-W1-CSS-L4-SOTA.md:31`).

7. Lock 16 blocks SIMD/ASM admission until scalar reference, strict checkasm/parity, corpus parity, and same-wave consumer are present. The `escape_mask_64` NEON correctness bug with falsifier seed `0xCAFEF00DBAADF00D` must be verified and resolved before any new SIMD admission. The carried orphan set is `bitmap_prefix_xor_64`, `bitmap_next_set_bit`, `bulk_emit_positions_64`, `byte_context`, and `cache_hints` (`restart/skinny/tranches/sk-v12/research/skv12-totality-fold-scout.md:72`, `restart/skinny/tranches/sk-v12/research/skv12-aarch64-simd-coverage-audit.md:36`, `restart/skinny/tranches/sk-v12/HANDOFF.md:83`).

8. The P2-B/C/D/E candidate and inventory surface collapses into four verdict classes: grammar-neutral byte-set/classifier/tape/fact-stream operations; per-grammar generated template surfaces; support-only inventory that cannot move a row without a consumer; and JSON-overfit/drop routes. Candidate admission belongs to S-P3; P2-F only names legality. Rows whose verdict starts `Inventory/drop`, `Support inventory`, `Support-only`, `Diagnostic-only`, or `Parser-candidate-ineligible` are outside the current S-P3 candidate pool unless a later folded pass adds a fresh P1 antecedent, scalar oracle, micro-proof, and same-wave consumer.

## §3 — Grammar-neutrality

CSS L4 is the first grammar-neutrality exercise. The CSS grammar already exposes the necessary surfaces: identifiers and selector identifiers with escapes, dual quoted strings, numbers/dimensions/percentages, calc/min/max/clamp functions, var/env/url functions, color/property dispatch, and declaration-value fallbacks (`grammar/css/l4/tokens.bbnf:7`, `:8`, `:9`; `grammar/css/l4/values.bbnf:29`, `:39`, `:52`, `:61`, `:84`; `grammar/css/l4/properties.bbnf:20`, `:28`, `:39`). A primitive that cannot be demonstrated against this CSS surface is not SK-V12-general, even if it still looks useful for JSON.

Sheets and BBNF-self are useful falsifiers after CSS redress, not first-line proof. Sheets exposes leading-dot/exponent numbers, doubled-quote strings, error literals, ranges, formula/operator dispatch, functions, and arrays (`grammar/google-sheets/google-sheets.bbnf:6`, `:12`, `:34`, `:63`, `:97`, `:141`, `:159`). BBNF-self exposes identifiers, three literal quote forms, regex spans, comments, directives, alternation/concatenation, closures, and value-expression numbers (`grammar/bbnf/bbnf.bbnf:9`, `:11`, `:15`, `:17`, `:41`, `:75`; `grammar/bbnf/expressions.bbnf:6`, `:7`, `:16`). They can catch JSON overfit, but they do not substitute for CSS L4 under the pin.

The neutral expression boundary is:

| Operation class | Neutral form | Per-grammar template surface | JSON-overfit/drop trigger |
|---|---|---|---|
| Byte-set/classifier | Classify bytes, pack masks, find next bit, clamp tails, or emit positions from caller-supplied sets. | Generated tables for CSS identifiers, operators, separators, strings, layout, and property/value dispatch. | Generic code embeds JSON structural bytes, JSON whitespace, or JSON node roles. |
| String/escape | Locate string-like spans, split raw/escaped segments, decode fixed hex units, and report flags. | Generated escape policy, quote forms, CSS escape width/context, Sheets doubled quote policy, BBNF literal/regex policy. | Generic code assumes JSON `"` strings, backslash-only model, JSON control rules, or JSON surrogate policy. |
| Number | Scan digit runs and optionally accumulate bounded prefixes below grammar number policy. | Generated `number_config` for CSS leading-dot/dimension/unit/percentage/calc, Sheets exponent/leading-dot, and BBNF int/float literals. | Generic code uses JSON number matcher as the only number language. |
| Dispatch | Branch through generated FIRST/follow/prefix tables and local separator probes. | CSS value/property/function dispatch tables; Sheets formula/function/operator tables; BBNF directive/rule/term tables. | Generic code dispatches on grammar names or JSON object/array/container-tail policy. |
| Tape/fact stream | Emit offsets, flags, direct sinks, output facts, and row-owned digests into the single substrate/output plane. | Generated CSS fact stream shared by Track 1, independent oracle, and lightningcss comparator; generated per-grammar view/kind/sink modules. | A retained structural sidecar, parser-owned cursor, decoded-byte cache, or digest-only proof replaces the canonical row output. |

GrammarConfig resolves the leak surface by making grammar-specific policy data, not generic-branch code: structural alphabet, dispatch tables, escape/number/layout config, flag interpretation, sink trait, NodeKind/value/view wrappers, and direct/typed output shapes are generated per grammar from one template. The Lock 14 proof for a generic crate is negative: no `JsonParser|CssL4Parser|BbnfBootstrap|GoogleSheetsParser` public API in generic crates, no `match grammar` arms selecting behavior, no grammar-named modules under generic crate source except generated output paths, and no handwritten CSS/Sheets/BBNF runtime modules.

## §4 — Risks

1. CSS L4 can be skipped accidentally by treating Sheets or BBNF-self as easier non-JSON proof. The user pin forbids this. P2-F verdicts must be benchmarked first against CSS L4/lightningcss after GrammarConfig legality lands.

2. The largest Lock 14 risk is calling JSON templates "generic" after only renaming them. Structural alphabet, `dispatch_value`, `parse_key_colon`, `match_number_span_from_first`, `skip_ascii_whitespace`, `OffsetFlags::HAS_ESC`, and `JsonSink` must be metadata/template outputs, not JSON provider leftovers.

3. The largest Lock 1 risk is importing simdjson's retained structural index as a sidecar. Transient masks and same-tape offsets are allowed; retained class lanes, structural vectors, cursor lists, whitespace bitmaps, or `UnionTape` repeat REDRESS 96/97/98 unless a new material differential is proven.

4. The largest Lock 16 risk is admitting support kernels because checkasm passes. Prefix XOR, next-bit, bulk emit, byte context, cache hints, x4 hex, UDOT digit helpers, and widened string scan all need scalar reference, strict checkasm/corpus parity, and a same-wave CSS/generated consumer before row movement.

5. REDRESS 88/89/90 and 96/97/98 are category-unblocked by the user pin, but not erased. Any PMULL/CTZ/union/ASM-gen attempt must cite the historical miss, name the material differential, and measure the CSS L4 consumer under the same gate.

6. Output digest and typed/direct projection are not parser primitive proof. They may be row-owned oracle/fact-stream surfaces, but REDRESS 118 blocks digest/host-sink as a generic route and S-P1 marks `serde_json_oracle_read_parse` as comparator context.

7. Decision-engine hardcoding can silently reintroduce overfit. The audit shows backend shape selection, recognizer nomination, regex analysis, and materialization remain hardcoded or curated. S-P3 must avoid adding new JSON-specific recognizer branches while trying to stand up CSS L4 (`restart/skinny/tranches/sk-v12/research/skv12-decision-engine-audit.md:13`, `:92`).
