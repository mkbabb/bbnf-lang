## §1 - Synthesis

The shortlist contains eight S-P2 survivor families. It does not include any S-P2 REJECT. Numeric/digit surfaces, `EOB_PAD_CLAMP`, PMULL hot-body promotion, CSSC bulk-consumer promotion, x86 routes, retained structural/cursor/class streams, schema-shaped product builders, harness hashes, and CSS broadcast evidence are excluded by the locked survivor boundary (`restart/skinny/tranches/sk-v15/research/p2/hardening/HARDENING-S-P2-V3-CONSOLIDATED.md:41`-`:45`; `restart/skinny/tranches/sk-v15/research/p2/p2f-grammar-neutral.md:104`-`:115`).

This P3-A shortlist is not a dispatch order. P3-B places W0 baseline/telemetry first, then W1 CSS admission honesty, W2 Lock 14 / Lock 16 gate restoration, W3 codegen leak abrogation, W4 Pattern H generated discipline, W5 CSS typed Value provider, W6 CSS same-workload retime, W7 Decision Engine spine, W8/W9 BackendShape lowerers, W10 FNV quarantine, and W11 close reconciliation. W1 can collapse CSS broadcast admits before typed rebuild because it removes a false admission claim; retiring `CSS_GENERATED_RS`, fact-stream-only `parse()`, or `CssFullParseSummary` is blocked until the CSS typed value/document provider lands in W5 and W6 retimes it on a same-workload comparator (`restart/skinny/tranches/sk-v15/SYNTHESIS.md:91`-`:96`). NEW-CH3-V5-01 requires a delete/rebuild dependency table for any retirement; NEW-CH5-V5-02 requires distinct measurement rows for distinct admits; NEW-CH7-V5-03 requires Lock 14/16 gates to report their own exclusion lists (`restart/skinny/tranches/sk-v15/SYNTHESIS.md:98`-`:110`).

All throughput thresholds below are pre-W0 planning floors from current `skinny/RESULTS.md` rows except the W8R CSS tuple. P3-C must rebind non-CSS floors to `SK-V15-open`; final thresholds should be `max(listed floor, SK-V15-open * stated factor)` for target rows and `max(listed maintain floor, SK-V15-open * 0.98)` for guard rows. The W8R CSS tuple is excluded from live floors and may appear only as diagnostic negative-fixture evidence.

## §3 - Falsifiability Binding

Every candidate above is conditional on W0 creating `SK-V15-open` telemetry and on W2 repairing Lock 14 / Lock 16 gate coverage. A wave closes only on measured rows, not on a source-present primitive or a passing smoke test.

| Gate class | Binding rule |
|---|---|
| JSON guard rows | All 51 JSON rows remain admitted, strict, and same-plane; any touched row is re-run against its strict comparator (`restart/skinny/tranches/sk-v15/SYNTHESIS.md:38`). |
| Target row movement | Candidate-specific target rows must meet the listed Mbps floors and the final post-W0 factor. If no target row moves, the wave rejects or demotes to scalar-only with REDRESS evidence. |
| Full-table maintain | Every non-target JSON row maintains >=98% of `SK-V15-open` Track 1 and Track 2 unless P3-C chooses a stricter row budget. |
| CSS anti-broadcast | CSS rows are either one explicit aggregate diagnostic row or independently timed typed rows; N admits require N distinct measurement rows (`restart/skinny/tranches/sk-v15/SYNTHESIS.md:39`, `:107`-`:108`). |
| Lock 14 / Lock 16 exclusion report | Any gate or checkasm admission reports scan roots and exclusions; self-exempting gates reject (`restart/skinny/tranches/sk-v15/SYNTHESIS.md:44`, `:109`-`:110`). |
| Scalar/checkasm | SIMD/ASM or mask-producing candidates require scalar reference, strict checkasm/parity, and same-wave consumer before routing to product rows (`restart/skinny/tranches/sk-v15/research/p2/p2b-dav1d-process.md:24`-`:41`). |
| Dependency table | Any wave deleting or retiring an artifact must name the retired artifact, delete/retire wave, rebuild provider wave, proof command, and evidence that the provider lands no later than the retirement wave (`restart/skinny/tranches/sk-v15/SYNTHESIS.md:102`-`:106`). |
