# B2.W0 — xtask Substrate + First Per-Grammar Emission

**Opens after**: tranche open
**Agents**: 2 parallel (W0.a, W0.b) + 1 serial closer (W0.c)
**Hard gate**: `xtask` workspace member exists; `cargo xtask regen --grammar bbnf` writes a valid `crates/core/src/grammar/generated/bbnf.rs` semantically equivalent to the pre-B2 self-host emission for the BBNF grammar; `cargo iter-check-full` cold under W0 substrate is faster than the pre-B2 80-min ceiling
**Status**: complete (W0.a `dec67806`, W0.b `3c68e8c4`, W0.c partial `21881591`, W0.c close 2026-04-25 post-B3 + post-B4.W0; iter-check-full 5.62 s warm exit 0; bbnf_parity exit 0; regen idempotent)

## Scope

W0 lands the xtask scaffold + the workspace grammar manifest + the
first per-grammar emission. The IR pipeline (`compile_paths_request`,
`generate_all`) moves into `xtask::regen` as native Rust functions,
called once at xtask invocation rather than once per consuming-crate
compile.

The W0 close gate proves the mechanism on the BBNF self-host grammar:
the post-W0 `generated/bbnf.rs` reproduces the bbnf-bootstrap surface
that the existing `crates/derive/src/lib.rs` proc-macro emits, byte-
for-byte modulo formatting and macro hygiene. W1 then mechanically
extends to every other consumer.

W0 does NOT delete `crates/derive/`; that is W2's scope. `crates/
derive/` continues to exist through W0/W1 so consumers can still build
during the cutover. W2 deletes only after W1 has proven all consumers
migrate to the `include!` pattern.

## Phase sub-items

### B2.W0.a — xtask substrate (parallel with W0.b)

**Owner**: orchestrator-dispatched sub-agent.
**Hard cap**: 60 min.

Mechanism:

1. Create `xtask/` as a workspace member:
   - `xtask/Cargo.toml` — package name `xtask`, workspace path-deps on
     `bbnf-ir = { path = "../crates/ir" }`, `bbnf = { path = "../crates/
     core" }` (lib-only path; no `bbnf_derive` since this xtask runs
     the IR pipeline directly), `parse_that = "0.4"`, `pprint = "0.3"`,
     `prettyplease = "0.2"`, `quote = "1"`, `syn = "2"`.
   - `xtask/src/main.rs` — clap-based command dispatch with `regen`,
     `regen --check`, `regen --grammar <ident>` subcommands.
   - `xtask/src/regen.rs` — the IR pipeline + emission entry point.
2. Add `xtask` to the workspace `[workspace] members = [..., "xtask"]`
   in the root `Cargo.toml`.
3. Add `[workspace.metadata.bbnf]` table enumerating each grammar:
   ```toml
   [[workspace.metadata.bbnf.grammars]]
   ident = "bbnf"
   path = "grammar/bbnf/bbnf.bbnf"
   features = []

   [[workspace.metadata.bbnf.grammars]]
   ident = "json"
   path = "grammar/json/json.bbnf"
   features = []

   # ... css_l4, google_sheets, ebnf, bnf, gorgeous-side prettify variants
   ```
   Cover every grammar that currently appears as `#[parser(path = ...)]`
   across the workspace (gorgeous's 5, bbnf-bootstrap's 1, plus any
   test-side `path` attributes). Inventory via:
   `rg -nF '#[parser(path' --type rust`.
4. `cargo iter-check-full` exits 0 with the new xtask member added
   (workspace builds clean; no behaviour change yet).

- `xtask/src/regen.rs` (new — initial scaffold; implementation lands in W0.c).
- `Cargo.toml` (workspace; add `members` entry + `[workspace.metadata.bbnf]` table).

### B2.W0.c — Implementation closer (`xtask::regen` BBNF case)

**Opens**: W0.a + W0.b sub-gates green.
**Owner**: serial closer.
**Hard cap**: 4 hours.

Mechanism:

1. Implement `xtask/src/regen.rs::regen_grammar(ident: &str)`:
   - Read the workspace `[workspace.metadata.bbnf]` table for the
     grammar's path + features.
   - Load + parse the grammar (`bbnf::pipeline::compile_paths_request`).
   - Run the 17-pass IR pipeline (`bbnf_ir::passes::*`) — same code
     `crates/derive/src/lib.rs:281-361` calls today, but invoked
     from xtask.
   - Run `generate_all` to produce a `proc_macro2::TokenStream`.
   - Format via `prettyplease::unparse(&syn::parse2(token_stream)?)`.
   - Write to `crates/core/src/grammar/generated/<ident>.rs`.
2. Implement `xtask/src/regen.rs::regen_all()`: iterate every grammar
   in the manifest; call `regen_grammar` for each.
3. Implement `xtask/src/regen.rs::regen_check()`: regen to a tempdir;
   diff against checked-in tree; exit non-zero on diff.
4. Add `crates/core/src/grammar/generated/` directory; create empty
   `mod.rs` (W1 populates the `pub mod` declarations as consumers
   migrate).
5. Run `cargo xtask regen --grammar bbnf`; output lands at
   `crates/core/src/grammar/generated/bbnf.rs`.
6. **Byte-equivalent gate**: compare the post-regen `generated/bbnf.rs`
   to the W0.b reference snapshot `docs/tranches/B2/audit/W0-bbnf-
   surface-snapshot.rs`. The two should match modulo whitespace +
   `prettyplease` formatting choices.
   - Verification: `diff <(rustfmt --emit=stdout < snapshot) <(rustfmt
     --emit=stdout < generated/bbnf.rs)` returns 0 lines OR a
     deterministic diff that audit-traces to a documented
     macro-hygiene shift (e.g., `derive`-side identifier mangling
     that the xtask-side emitter doesn't replicate; if so, the
     emitter adapts).
7. **iter-check-full sanity gate**: with `generated/bbnf.rs` in place
   AND the existing `crates/derive/` proc-macro still active for other
   consumers, `cargo iter-check-full` exits 0. The bbnf-bootstrap
   crate's own derive expansion ALSO retires at W0.c (its single
   `#[derive(Parser)]` site swaps to `include!`); other consumers
   continue to use the proc-macro until W1.

Files touched (W0.c):

## Archaeology

The pre-B2 bootstrap-bbnf.sh + crates/derive/src/lib.rs proc-macro
duo represent the "AY-era" contract where the IR pipeline lived
inside rustc's expand phase. AY-I close (2026-04-15) shipped 30 423
lines of `generated.rs`; B1 close (2026-04-24) shipped 33 293 lines.
The 80-min cold wall on `cargo check -p bbnf-bootstrap --lib`
post-B1 (vs ~10-15 min pre-AY-II per `meta-audit/04-toolchain-pain.md`)
is attributable to AY-II's IR-pipeline accumulation (project_types
totality, structural-scan emission, materializer projection emission,
egraph G1-G4 rewrites) — all now running once per consumer at expand
time. B2.W0 begins the transposition; W2 retires the legacy.

The deep audit at `docs/audit/2026-04-25-deep-audit/AUDIT-D-
architectural-transposition.md` recommended T3 (xtask + checked-in
generation) over T1 (build.rs codegen), T2 (pre-serialised IR), and
T4 (msgpack blob + thin proc-macro) on grounds of simplicity, idiomatic
fit, and elimination of the proc-macro contract entirely. W0 lands the
T3 substrate.
