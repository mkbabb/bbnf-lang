## Finding A1 — identity `M` under-reserves decoder heap

Severity: **CRITICAL — bounded byte admission is unsound**

`GraphJsonPreflight.max_dynamic_string_bytes` is populated by
`graph_identity_max_dynamic_string_bytes(graph)` in
`xtask/src/architecture/hash.rs`. That helper visits only node identities and
edge endpoints. In `admit_canonical_privacy`, the same value is passed to
`canonical_phase_peak_bytes` as `max_percent_string_bytes` whenever any
percent-bearing string exists.

The actual canonical privacy walk is broader. `fact.rs` invokes
`validate_serialized_strings_bounded`; the walker in `schema/identity.rs`
visits every dynamic serialized string and may percent-decode any of them.
Labels, resolver text, paths, and other non-identity values can therefore own
the decoder peak.

The existing allocator test does not prove the reservation. It deliberately
uses identities `"a"` and `"b"` while placing `"%41"` repeated 4,096 times in
a label. Thus production's identity metric is `M=1`, while the relevant
encoded decoder input is 12,288 bytes. The test supplies `usize::MAX` as its
byte ceiling and later checks observed allocator activity. It never asks
whether the production reservation would admit the actual peak. Its success
is compatible with the under-reservation.

Required repair:

- preserve an exact maximum percent-bearing dynamic-string width from the
  already-admitted dry preflight;
- use that metric, and only that metric, for
  `percent_decode_allocation_bound`;
- keep comparison widths in a distinct identity ledger;
- add an exact-byte-boundary test with short identities and a long percent
  label: exact reservation succeeds, one byte below fails before decoder or
  canonical allocation activity.

No alias, fallback, or dual path is justified.

## Finding A2 — the comparison-width census is uncharged work

Severity: **CRITICAL — work occurs before admission**

After the structural survey and exact dry preflight, `execute_graph_measure_with_admission`
constructs `GraphJsonPreflight` by calling
`graph_identity_max_dynamic_string_bytes(graph)`. That call is a fresh
`graph.truth.iter()` traversal. The paired dry charge covers the two serializer
traversals and a raw source-byte scan, not this graph-specific identity pass.
The comparison and canonical charges occur only later in the caller-supplied
admission closure.

The test oracle repeats this arrangement through its own fixture identity-max
walk. Repeating the same uncharged traversal independently does not admit it.
The claim that `M` was sealed by the existing preflight traversal is therefore
**DISPROVED**.

Required repair:

- charge a checked, cardinality-derived width-ledger construction envelope
  before the first identity match or length read;
- then build one fixed-size ledger in one pass, with no allocation and no
  payload-byte scan;
- expose observer events proving the charge precedes the visit;
- make the independent test ledger derive its charge without calling the
  production helper.

### Formula

For variant `v` and each of its dynamic fields `f`, let

```text
A[v,f] = maximum byte length of field f among node identities of variant v
```

For endpoint occurrence `q` of variant `v`, define

```text
W(q) = 32 + sum_f (len(q[f]) + A[v,f])
```

Then the complete endpoint-search bound is:

```text
Search = L * sum_edges (W(edge.from) + W(edge.to))
```

All additions and multiplications must be checked.

### Universal proof

1. A variant mismatch reads discriminants only; the fixed 32 units cover it.
2. Each single-field identity comparison reads at most the full endpoint field
   and the full node field. The latter is bounded by `A[v,f]`.
3. `Physical` compares repository, then possibly path, then its fixed kind.
   Summing both operands' complete repository and path widths plus 32 is safe.
4. `Virtual` compares namespace, then possibly key. The same two-field proof
   applies.
5. Long equal prefixes do not escape the bound because complete operand
   lengths, rather than observed mismatch positions, are charged.
6. A binary search performs at most `L` comparisons. Each edge performs one
   search for each of its two endpoints. The sum enumerates exactly those
   endpoint occurrences.
7. The ledger depends only on grammar-defined identity fields and current
   input cardinalities/lengths. It contains no fixture name, measured-prefix
   oracle, cap-conditioned branch, or receipt rewrite.

Therefore the formula is universal over the complete current `Identity`
grammar, not merely the measured F18 graph.
