  prototype evidence, not landed adoption.

The next honest boundary is therefore one selected Rust production vertical: a
full-consumption scalar event sink. It is preceded by one bounded falsifiable
parse-that prototype and a scalar scanner feasibility/profile row:

1. a parse-that transactional invocation kernel;
2. a grammar-derived scalar lexical-region scanner measured inside the consuming

NEON is a conditional promotion after the scalar vertical exists. There will not
be four independent full products, six co-equal sinks, a universal tape, a whole-
grammar e-graph, a full HM/effect system, or a grammar-to-ASM backend in this
tranche.

## 3. Explicit rulings

### R1 — Baseline

`af15f63e0d2d3d719938c13b906a50acbb92ea3b` is the last committed BBNF
evidence anchor, not a green product baseline. The current dirty tree is a
protected filesystem epoch. W0 must choose a clean execution base and

### R2 — Clean isolation

Parse-that main remains untouched. Future implementation begins in a separate
worktree from clean `ef10d5b78236c4a30a7bb22a6113b60bdc4bdf42`. Only
content-addressed, explicitly admitted specifications or code may enter it.

BBNF implementation likewise begins in a separate clean worktree selected by W0.
The current 204-file dirty BBNF epoch is evidence-only until every admitted byte
has an owner, digest, and disposition.

For this tranche the canonical crossing is Rust: the parse-that Rust crate emits
a typed, full-consumption grammar-module result consumed by BBNF's Rust
`SourceModule -> Program` boundary. The shipped TypeScript v1 package is a
behavioral reference and shares law vectors; it is not transposed in SK-V26.

### R3 — Consumer truth

Value 2.0.1 consumed parse-that. Value 4.0 does not. The 2026-07-17 v4 cut removed
the dependency. cand-F/cand-O prove feasibility for a bounded CSS Color consumer;
they do not establish current adoption or general parser fitness.

BBNF is the current hard parse-that Rust consumer. Its direct use of parser state,
spans, scanners, DFA internals, and generated imports makes crater/regeneration
proof part of any parse-that transposition.

### R4 — Work planes

There is no scalar phrase “faster than SOTA.” Every claim belongs to a semantic
work plane: classification, validation, token/event, lossless tape/borrowed value,
decoded DOM, selective access, direct typed decode, or transform/print.

The current BBNF JSON observation is slower than sonic-rs on four local corpora,
by about 1.35× to 2.32× in median wall time, and the two implementations do not
yet retain identical output. It is a directional observation, not a ranking.

### R5 — Representation

Tape is one sink, not the ontology of the library. The long-horizon compiler
contract must eventually admit:

- validation/check-only;
- event/token;
- unknown-structure tape/value;
- borrowed/lazy raw views;
- selective path;
- direct typed decode.

Each path pays only for the output it promises. SK-V26 implements only the scalar
full-consumption event sink. The remaining sinks are banked requirements whose
individual promotion trigger is a completed event vertical plus a named consumer
crater; they are not hidden deliverables of this tranche.

### R6 — Types and optimization

The tranche implements first-order grammar-shape inference plus the minimal
polymorphism/recursion required by the admitted grammar contract. It does not
claim “full HM” by naming HM nouns.

Direct deterministic algorithms are the baseline. E-graphs are admissible only
for bounded, action-free equality islands with proved rewrites and measured
extraction value. CSP is admissible only for a witnessed coupled decision with
hard constraints and a stable cost model. Neither may fail open.

### R7 — SIMD and ASM

Apple AArch64 is the sole native low-level target. Stable `std::arch` intrinsics
and a scalar oracle come first. Hand ASM is admitted only when:

1. a consuming profile names the hot kernel;
2. the intrinsic implementation is measurably deficient;
3. a checkasm-style differential harness is already green;
4. the ASM improves an end-to-end semantic plane, not merely a microkernel.

The selected vertical carries no x86 source, target, CI, generated output,
benchmark assumption, or explanatory allowlist. Repo-wide x86 retirement remains
an inventoried per-surface obligation; one vertical cannot authorize global
deletion.

### R8 — Review proportionality

Tri-fold review—two independent hostile views and one adjudication—belongs at:

- architecture selection;
- public API freeze;
- cutover/deletion;
- competitive performance claims;
- tranche close.

It is not an acceptance tax on every mechanical edit. Recorded platform metadata
is model provenance; an agent reciting its model name is not a technical gate.

### R9 — Frontend and design

The playground is a consumer lane, not a parser close dependency. Its eventual
design work must use the `frontend-design` skill and the requested two-design/
one-adjudication process. GOLDEN GLASS, BREATH OF LIFE, and MOVEMENT OF MOMENTUM
must first become defined visual/interaction contracts rather than slogans.

Current source/package search finds zero shadcn references. This is recorded as a
machine fact; SK-V26 will not invent a shadcn deletion campaign where none exists.
Glass adoption, Tailwind/style disposition, component pruning, colocation, and
visual proof remain owned by `LANE-CONSUMERS-AND-PLAYGROUND.md`.

2. derive a stable BBNF program and types from grammar modules;
3. generate one Rust parser without grammar/rule-name dispatch;
4. expose one full-consumption scalar event sink from the sealed plan;

   or shims.

Only then is the next single sink or backend eligible for a new bounded tranche.
