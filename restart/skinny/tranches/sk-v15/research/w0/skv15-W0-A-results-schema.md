## §2 — Recommendations (named falsifiability gates)

1. W0 should keep the visible schema-v3 header unchanged and extend only the gate-consumed manifest or an equivalent JSON payload to 42 slots: the existing 32 SK-V14 manifest fields plus the 10 exact SK-V15 fields. Alias-only mapping should be rejected unless the schema version is deliberately bumped and `gate-json` or its successor validates the mapping (`restart/skinny/tranches/sk-v15/research/p3/p3d-telemetry-schema.md:32-40`, `restart/skinny/tranches/sk-v15/research/p3/p3d-telemetry-schema.md:57-70`).

2. Gate predicate `SK-V15-open-json-51`: every JSON row listed in Finding 7 must carry explicit SK-V15 fields, `Host triple` / feature mask must remain Apple M5 Max / aarch64, and row cells must stay within the W0 baseline budget with no verdict downgrade (`restart/skinny/tranches/sk-v15/SPEC.md:256-262`).

3. Gate predicate `DEP-W1-CSS-BROADCAST`: the 24 CSS rows in Finding 8 must fail as independent admits until they either collapse to one aggregate diagnostic row or carry distinct independent typed-output measurements. The duplicate-signature key should include measurement id, origin, sample count, Track 1 Mbps, cssparser/lightningcss Mbps, run id, and profile artifact, matching P3-D's hidden one-to-N rule (`restart/skinny/tranches/sk-v15/research/p3/p3d-telemetry-schema.md:65-67`, `restart/skinny/tranches/sk-v15/SPEC.md:192-195`).

4. Gate predicate `SK-V15-no-producer-only-telemetry`: any SK-V15 field emitted by report code must be parsed and validated by the gate. The current `xtask` parser's subset behavior should not be carried forward for SK-V15 fields (`skinny/xtask/src/main.rs:526-579`, `restart/skinny/tranches/sk-v15/SPEC.md:119-122`).

## §3 — Risks (REDRESS entries to pre-block)

1. REDRESS-215 / W8R CSS full-parse evidence is a broadcast-risk route. It moved all 24 CSS rows to admitted from one W8R full-parse tuple (`skinny/REDRESS.md:5314-5342`), while SK-V15 requires no CSS broadcast admit (`restart/skinny/tranches/sk-v15/SPEC.md:54-55`).

W0 must avoid closing on alias fields such as `Sample cost`, `Run id`, `Output plane`, or `Diagnostic nonproducer` without exact gate-consumed SK-V15 names.

3. Lock 14 / Lock 16 diagnostics are not represented in the current RESULTS carrier at SK-V15 fidelity. `lock14=pass:lock14_baseline::validate` and `checkasm_or_parity=...` strings do not prove included/excluded roots, self-scan status, or strict primitive parity.
