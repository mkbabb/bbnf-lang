## Current Generated Report Flow

1. `cargo xtask gate-json` dispatches to `cargo run -p bbnf-bench --bin gate`
   unless `--with-cost-facts` is requested (`skinny/xtask/src/main.rs:241-257`).
2. The gate binary resolves `target/criterion`, sets
   `results_path = workspace_root().join("RESULTS.md")`, loads available JSON
   fixtures, creates `Report::new("Skinny JSON Bench Results")`, and iterates
   fixtures (`skinny/crates/bbnf-bench/src/bin/gate.rs:19-31`).
3. Per fixture, the binary reads Criterion slope estimates for parse, direct,
   typed, sonic/serde, and sidecar-related groups; reads metadata TOML rows;
   checks parity; classifies parse/direct/typed outcomes; pushes report rows;
   and appends notes (`skinny/crates/bbnf-bench/src/bin/gate.rs:35-193`).
4. `Report::validate_schema_v3()` currently validates only the existing report
   model. On failure the binary still writes the report and exits invalid; on
   success it writes `RESULTS.md`, prints markdown, then exits according to the
   worst verdict unless advisory mode is used
   (`skinny/crates/bbnf-bench/src/bin/gate.rs:220-242`).
5. `read_metadata_rows()` currently accepts Criterion `metadata.toml` for
   `track1_generated`, `track2_handcoded`, `sonic_rs_anchor`,
   `sonic_rs_lossy`, `simd_json_borrowed`, `simd_json_owned`, `serde_json`,
   direct rows, and real typed rows
   (`skinny/crates/bbnf-bench/src/bin/gate.rs:505-527`).
6. `Report` renders the current 26 columns from `SCHEMA_V3_HEADER`, then masking
   probes and notes. It writes `RESULTS.md` with `fs::write`, so the current
   table is generated, not manually assembled
   (`skinny/crates/bbnf-bench/src/report.rs:7-8`,
   `skinny/crates/bbnf-bench/src/report.rs:314-386`).
7. Current `RowMetadata` already carries many W0 ingredients: CPU model, arch,
   OS kernel, rustflags, target CPU, profile, input hash/bytes, commit, sample
   size, measurement time, strictness, parse/escape fields, output plane,
   feature mask, API symbol, sidecar freshness, primitive status, hot leaf,
   materialisation, parse mode, source ownership, allocator, plan variant, host
   call mode, arena counters, parity hashes, peak RSS, and cold-cache mode
   (`skinny/crates/bbnf-bench/src/metadata.rs:19-65`,
   `skinny/crates/bbnf-bench/src/metadata.rs:296-343`).

## Baseline And Delta Strategy

Preferred W0 shape:

1. Keep the current 26-column table stable. Do not add dozens of visible
   columns unless the plan chooses that over a manifest.
2. Add a generated SK-V8 telemetry manifest or JSON payload owned by
   `bbnf-bench` and consumed by `gate-json`. It can be embedded in
   `RESULTS.md` or emitted as a named gate payload, but it must be generated
   from the same `Report` data path, not hand-written.
3. On first capture, parse the current 38 rendered table rows as the
   authoritative `SK-V8-open` baseline. Store the integer Mbps values above.
4. Emit `wave_id=SK-V8-open` and `sk_v8_open_delta=baseline` for every current
   main row.
5. On confirm, recompute each row's generated Track 1 and Track 2 Mbps from the
   same Criterion estimates and compare to the captured baseline:
   `delta_pct = (current_mbps / baseline_mbps - 1.0) * 100.0`.
6. Reject W0 if any current main row is missing, any row id changes, any Track 1
   or Track 2 value moves outside +/-1.0%, any parse row is promoted beyond
   substrate-guard non-admission, or a sidecar/permissive value is used as strict
   admission.

Comparator values should be recorded as provenance, but W0's required
no-behavior-change gate should focus on the bbnf Track 1 and Track 2 cells for
the 38 current main rows. Populated sidecar comparator cells need freshness
coverage or an explicit non-strict sidecar status; missing sidecar cells should
emit `sidecar_freshness=absent:<reason>`.
