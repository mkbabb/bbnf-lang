# B3.W1 — Parity Verification + B3 Close

**Opens after**: B3.W0 close (master carries instrumentation + 14 reverts + manifest)
**Agents**: 1 agent
**Hard gate**: built-binary `bbnf_parses_its_own_grammar` runtime < 5 s wall (compile separated); `compile_pipeline::compile_bbnf` median < 50 ms; phase-instrumented `cargo xtask regen --grammar bbnf` runs with `[parse]` phase wall < 5 s + total < 5 min cold; B3 FINAL + cross-tranche doc updates committed.
**Status**: planned

## Scope

W1 verifies that B3.W0's revert + instrumentation restored the parser
baseline AND that the parse phase specifically — not just total xtask
wall — is the resolved hot path. The verification doubles as the B2-
resume handoff: the `cargo xtask regen --grammar bbnf` invocation that
hung > 5 min on `21881591` is the canonical parity probe.

The three measurements isolate distinct concerns:

1. **Built-binary parser timing** measures `BbnfBootstrap::parse`
   runtime separated from test-binary compile time. This is the
   minimum-noise parser-runtime gate.
2. **`compile_pipeline::compile_bbnf` divan bench** measures the same
   parser+IR-pipeline path the AU baseline measured (911 µs).
   Cross-history-comparable.
3. **Phase-instrumented xtask regen** measures every phase
   (read/parse/ir-pipeline/generate_all/prettyplease/write) so a
   regression in a non-parse phase doesn't masquerade as a parse-phase
   pass.

If the W0.a probe already confirmed parser baseline, W1 is verification +
documentation. If the W0.a probe DISPROVED, W1 doesn't dispatch — B3.W0's
escape clause expansion runs first.

2. **Built-binary parser timing (compile separated from runtime)**.

   Step 2a — compile the test binary once (this absorbs the heavy
   compile cost on the first run; subsequent runs of the binary are
   pure runtime):

   ```bash
   export CARGO_BUILD_JOBS=4
   find . -name .bbnf-cache -exec rm -rf {} + 2>/dev/null
   cargo test --no-run --release -p bbnf --test bbnf_parity \
     2>&1 | tee /tmp/b3-w1-build.txt
   ```

   The `--no-run` flag compiles the test binary without executing it.
   On post-B3 substrate, this should complete in single-digit minutes
   cold (the proc-macro chain is what was paying the historical 80 min
   wall).

   Step 2b — locate the test binary:

   ```bash
   TEST_BIN=$(find target/release/deps -name 'bbnf_parity-*' -type f -perm -u+x 2>/dev/null | head -1)
   echo "Test binary: $TEST_BIN"
   ls -la "$TEST_BIN"
   ```

   Step 2c — time JUST the test execution:

   ```bash
   /usr/bin/time -p "$TEST_BIN" --exact bbnf_parses_its_own_grammar \
     2>&1 | tee /tmp/b3-w1-parser.txt
   ```

   The `time -p` POSIX format outputs `real <s>`, `user <s>`, `sys <s>`
   on separate lines. `real` is the wall-clock measurement. Expected:
   `real < 5.0`.

3. **`compile_pipeline` divan bench**.

   ```bash
   find . -name .bbnf-cache -exec rm -rf {} + 2>/dev/null
   cargo bench -p bbnf --bench compile_pipeline -- compile_bbnf \
     2>&1 | tee /tmp/b3-w1-bench.txt
   ```

   Locate divan's JSON output (under `target/criterion-divan/` or per
   B1's substrate; check for the canonical path) and copy to
   `docs/benchmarks/post-B3-W1.json`.

   Verify `compile_bbnf` median < 50 ms. Pre-W0' AU baseline was
   911 µs; cold-cache + nightly drift may push the post-revert
   baseline to ~1-10 ms range; the < 50 ms ceiling is conservative.
   If median > 50 ms, this is a soft signal of incomplete revert

   same `cargo xtask regen --grammar bbnf` invocation that hung > 5 min

   walls:

   ```bash

   timeout 600 cargo run -p xtask --release -- regen --grammar bbnf \
     2>&1 | tee /tmp/b3-w1-xtask.txt || echo "EXIT: $?" | tee -a /tmp/b3-w1-xtask.txt
   ```

   Read the per-phase lines:
   - `[xtask::regen][read] <wall>` — file I/O
   - `[xtask::regen][parse] <wall>` ← KEY GATE: < 5 s
   - `[xtask::regen][ir-pipeline] <wall>` — IR pass loop
   - `[xtask::regen][generate_all] <wall>` — TokenStream emission
   - `[xtask::regen][prettyplease] <wall>` — format
   - `[xtask::regen][write] <wall>` — disk write
   - `[xtask::regen][total] <wall>` — total

   Expected: `[parse]` < 5 s; `[total]` < 5 min cold; no individual
   phase blocks > 60 s.

   Output: `crates/core/src/grammar/generated/bbnf.rs` is created or
   updated. Compare via `wc -l` against the source-of-truth

## Archaeology

The W1 verification suite is the parity probe equivalent of B2.W0.c's
"diagnostic narrowing" but executed on the post-revert substrate AND
with phase-level granularity that B2.W0.c lacked. The diagnostic
narrowing at B2.W0.c proved the wall lives in `BbnfBootstrap::parse`
itself; W1's three measurements (built-binary parser timing,
compile_pipeline bench, phase-timed xtask regen) verify the wall is
gone post-B3 AND that the resolution is in the parse phase
specifically.

The < 50 ms median ceiling on `compile_bbnf` is a 1-2 order-of-magnitude
relaxation over the AU baseline (911 µs) to allow for cold-cache and
nightly drift. A tighter ceiling would risk false-negatives under bench
variance. If the post-revert median lands closer to AU baseline (single-
digit milliseconds), B3 is over-floor; if it lands above 50 ms, B3 is
incomplete and the escape clause expansion dispatches.

The build-then-time approach to the parser test isolates compile cost
from runtime. `cargo nextest run` against the same test would conflate
the two — the test-binary compile, on the pre-B3 substrate, had hung
> 10 min in the W0.c orchestration (per the W0c status snapshot). The
isolated approach avoids the conflation: even if compile is slow, the
runtime measurement is honest.

The phase-instrumented xtask regen is the most diagnostic of the three.
A successful regen here proves both that the parser regression is gone
AND that the resolution lives in the parse phase, not somewhere else
that summed to a deceptive total. B2's W0.c re-execution becomes a
re-run with confidence, not a re-design.
