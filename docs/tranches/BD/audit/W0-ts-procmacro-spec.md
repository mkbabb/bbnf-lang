Date: 2026-05-03
Scope: Full specification of the TS proc-macro shell (`crates/path-ts/`) at BD.W0 activation. Documents the build pipeline, NAPI-RS ABI surface, isomorphism with the Rust shell (`crates/path/`), platform matrix, ABI version pinning.

The `napi-build` build-dependency invokes `napi_build::setup()` in `build.rs`; this generates the N-API symbol table at build time.

### Build commands

| Command | Purpose | Output |
|---|---|---|
| `cargo build -p path-ts --release` | Native cdylib | `target/release/libpath_ts.dylib` (or `.so` / `.dll`) |
| `napi build --release --platform` | NAPI .node binary | `path-ts.<platform>.<arch>.node` |
| `napi prepublish --skip-gh-release` | npm publish prep | per-platform sub-packages staged |
| `npm publish --access public` | npm publication | `@bbnf-lang/path-ts` + sub-packages |

### N-API ABI version

Per `docs/tranches/BD/audit/research-anchors.md:§1`, the binding uses `napi6` features (Node 14+ ABI). The N-API ABI is version-stable across Node 12-22 within the supported window; the same compiled binary runs on every Node release without recompile.

The ABI surface is documented at:
- N-API spec: https://nodejs.org/api/n-api.html
- napi-rs reference: https://napi.rs/docs/concepts

### Loading mechanism

The npm package's main `index.js`:

```javascript
// crates/path-ts/index.js (auto-generated by @napi-rs/cli)
const { existsSync, readFileSync } = require('fs')
const { join } = require('path')
const { platform, arch } = process

function loadAddon() {
  // try local development build first
  const localPath = join(__dirname, `path-ts.${platform}-${arch}.node`)
  if (existsSync(localPath)) return require(localPath)

  // fall back to platform-specific sub-package
  switch (`${platform}-${arch}`) {
    case 'darwin-arm64': return require('@bbnf-lang/path-ts-darwin-arm64')
    case 'darwin-x64':   return require('@bbnf-lang/path-ts-darwin-x64')
    case 'linux-x64':
      // Linux: detect glibc vs musl
      if (isMusl()) return require('@bbnf-lang/path-ts-linux-x64-musl')
      return require('@bbnf-lang/path-ts-linux-x64-gnu')
    case 'linux-arm64': return require('@bbnf-lang/path-ts-linux-arm64-gnu')
    case 'win32-x64':   return require('@bbnf-lang/path-ts-win32-x64-msvc')
    default:
      throw new Error(`Unsupported platform ${platform}-${arch}`)
  }
}

module.exports = loadAddon()
```

## §3 Isomorphism with Rust Shell

Per Lock 7 (`docs/HARDENING-PLAN-PROMPT.md:46`), `crates/path/` is the Rust proc-macro shell; `crates/path-ts/` is the TS proc-macro shell; `crates/path-core/` is the deduplicated path-AST + compile logic.

| Property | path (Rust shell) | path-ts (NAPI shell) |
|---|---|---|
| crate-type | `proc-macro` | `cdylib` |
| invocation | `pointer!["a", "b", 1]` macro at compile time | `compile(source)` runtime call |
| consumes | `path-core` (path AST + compile logic) | `path-core` (same) + `bbnf-codegen` (TS emit) |
| produces | TokenStream (Rust source) | String (TS source) |
| build | `cargo build -p path` | `napi build` |
| publish | `cargo publish -p path` (crates.io) | `npm publish` (`@bbnf-lang/path-ts`) |

The isomorphism: both shells consume `path-core`; both produce target-language source; both publish to their respective registries. The shells are distinct because Rust's toolchain forbids proc-macro path-dep sharing across crate types.

## §6 Compilation Flags

Release build flags at `crates/path-ts/Cargo.toml`'s `[profile.release]`:

| Flag | Value | Purpose |
|---|---|---|
| `lto` | `true` | Link-time optimisation for smaller binary |
| `codegen-units` | `1` | Maximises optimisation |
| `strip` | `"symbols"` | Removes debug symbols (smaller .node binary) |

Expected binary sizes per platform: ~2-5 MB stripped; ~15-25 MB unstripped.

## §7 Cross-Bridge Compatibility

### Bun

Bun supports N-API per `docs/tranches/BD/audit/research-anchors.md:§1`; the .node binary loads via bun's runtime without modification. Verification: `bun test crates/path-ts/__tests__/smoke.mjs` passes (analogous to `node --test`).

### Deno

Deno 2.x adds N-API compat; pre-2.x Deno cannot load napi-rs binaries. For Deno 2.x: `deno --allow-ffi crates/path-ts/__tests__/smoke.mjs` works. For pre-2.x: the `@bbnf-lang/runtime-wasm` package is the alternative (BD.W2).

### Electron

Electron 13+ supports N-API binaries; Electron's main process loads `.node` files identically to Node. Verification deferred to BD post-publication consumer testing; BD.W3 publication is the gate for general Node compat.

## §9 Closing Posture

The TS proc-macro shell at `crates/path-ts/` is the runtime activation of Lock 7's path triplet. Build pipeline isomorphic to `crates/path/` (Rust shell); ABI surface NAPI6-pinned; platform matrix Tier 1; ABI version `napi6` (Node 14+). The shell publishes to npm at BD.W3 with per-platform sub-packages resolved via `optionalDependencies`; consumers `npm install @bbnf-lang/path-ts` and the runtime auto-resolves the correct binary.
