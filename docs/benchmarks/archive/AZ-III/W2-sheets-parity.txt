Root causes (resolved)
----------------------
1. Keyword shape struct-direct emitter
   crates/core/src/backend/rust/emitter/shapes/keyword/struct_direct.rs

   Per-branch typed payload (`-> Nu8`, `-> bool`) was routed through
   `push_leaf_with_unit()` for any rule with `TypeDesc::U8`. Sheets's
   `SheetsStructBuilder::push_leaf_with_unit` panics with debug_assert
   ("Sheets grammar has no unit-typed projection"). Rules affected:
   `add_op`, `mul_op`, `compare_op`, `unary_prefix`.

   Fix: per-branch typed payload wins over rule-level `TypeDesc`.
   `IntLit` payloads route through `push_branch_tag(value)`. JSON's
   `JsonStructBuilder::push_branch_tag` is a no-op audit hook so the
   call is signature-compatible across grammars; CSS L4's keyword
   payloads benefit from the same routing (regen ripple covered in
   commit 37880832).

2. Flat shape inline Map descent
   crates/core/src/backend/rust/emitter/shapes/flat/struct_direct.rs

   Inline `Map { inner, fn_id }` positions descended into the inner
   without emitting the typed payload. Sheets's `error_literal`
   (Flat-shape, 9 branches `-> 0u8..=8u8`) and `sheet_prefix` (2
   branches) deposited empty Compound entries.

   Fix: Map descent now emits the matching `StructBuilder` payload
   push after the inner structural match. `IntLit` → `push_branch_tag`;
   `BoolLit` → `push_leaf_with_bool`; other payload shapes stay owned
   by the per-rule shape emitter.

3. Sheets runtime co-updates
   crates/core/src/runtime/google_sheets/arena.rs
   crates/core/src/runtime/google_sheets/document.rs

   Added `SheetsCompoundKind::ErrorLiteral`, `SheetPrefix`, `CompareOp`,
   `AddOp`, `MulOp`, `UnaryPrefix` so per-rule compounds preserve their
   structural-kind tag through serialization. `serialize_compact` now
   walks the new compound kinds — `ErrorLiteral` routes child `Tag(n)` /
   `Error(n)` through `error_lexeme(n)`; the operator-tag kinds route
   through `tag_lexeme(kind, n)` with their grammar-declaration-order
   discriminator alphabet. `tag_lexeme` separates Pratt-tower
   discriminants (`PRECEDENCE_ENTRIES_<rule>` order) from own-rule
   keyword discriminants.

Remaining failures (11 — pre-existing surface, not introduced by this fix)
-------------------------------------------------------------------------
Categorised root cause and named owner:

A. boolean Wrap-shape regex dispatch gap (1 test)
   - bbnf::sheets_parity::boolean_first_branch_fires_true_payload
   The Wrap-shape struct-direct emitter classifies `boolean = /TRUE/i ->
   true | /FALSE/i -> false` as Wrap-of-Refs, but its
   `emit_wrap_branch_call_struct_direct` only admits Ref branches. The
   regex-rooted Alt branches fall through to `match first { _ => {} }`
   (empty) so no payload deposits. Owner: W3c — Projection Consumption
   and Registry Authority (Wrap-shape regex-branch admission is a
   shape-classifier substrate gap, not a shape-specific projection
   in the W2 carve).

B. Sheets parser corpus pre-treatment gaps (6 tests)
   - bbnf::sheets_self_parity::corpus_simple
   - bbnf::sheets_self_parity::corpus_nested
   - bbnf::sheets_self_parity::corpus_stress
   - bbnf::sheets_self_parity::serialize_roundtrip_string_empty
   - bbnf::sheets_self_parity::serialize_roundtrip_array_literal_single_row
   - bbnf::sheets_self_parity::serialize_roundtrip_array_literal_multi_row
   Two sub-causes:
   (i) Empty quoted strings (`=""`) parse OK but serialize loses the
       quotes (`SheetsValue::String("")` round-trips to `=` then re-parse
       fails). Owner: W3c — Sheets `string` rule needs to deposit the
       full quoted span or the serializer needs to wrap the body.
   (ii) Array literal serialize emits double commas (`={1,2,3}` →
       `={1,,2,,3}`). Owner: W3c — `write_compound`'s ArrayRow /
       ArrayRows separator logic is misaligned with the parsed
       child structure.
   (iii) String corpus values (e.g. `"N/A"`, `" "`) serialize without
       their delimiting `"`s, breaking re-parse. Same root cause as
       (i).

C. Sheets parser sheet-prefix dispatch gaps (4 tests)
   - bbnf::sheets_parity::range_ref_parses_with_and_without_sheet_prefix
   - bbnf::sheets_self_parity::serialize_roundtrip_range_ref_sheet_prefixed
   - bbnf::sheets_self_parity::serialize_roundtrip_range_ref_quoted_sheet
   - bbnf::sheets_self_parity::serialize_roundtrip_range_ref_column
   Inputs `=Sheet1!A1:B2`, `='Sheet 1'!A1:B2`, `=A:A` either fail to
   parse (offset 1 / 7) or parse OK but serialize loses the prefix.
   Sheets `range_ref = sheet_prefix?, range_end, ":", range_end` parser
   dispatch on the regex-rooted `sheet_prefix` is the same Wrap-shape
   regex admission gap as (A). Owner: W3c.
