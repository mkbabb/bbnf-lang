# S-P2 V2 CH2 - Generality

Role: CH2 (Generality). Adversarial review for Lock 14 grammar neutrality, strict-vs-strict discipline, no new directive/BIR/substrate, no deferral, and no implementation-wave dispatch.

Verdict: REVISE

Score: 86/100

## Blocking Findings

1. **`StructuralAlphabet` still makes role assignment too global for grammar-generated byte sets.**

   The V1 grammar-semantic names were mostly folded: SC-6 now uses fixed roles such as `Open`, `Close`, `Separator`, `PairDelimiter`, `StringDelimiter`, `Terminator`, and `AtomBoundary` (`restart/skinny/tranches/sk-v8/research/p2-substrate-ceiling/SC-6-lock1-amendment-generalisation.md:343-360`). The remaining problem is stronger: SC-6 defines the event class as a property "per structural byte" (`SC-6-lock1-amendment-generalisation.md:343-348`) and derives it by collecting byte literals at structural positions (`SC-6-lock1-amendment-generalisation.md:363-371`). That is not general enough for grammars where the same byte is structural in multiple contexts with different parser roles. CSS `:` is shown as `PairDelimiter` for declarations (`SC-6-lock1-amendment-generalisation.md:410-415`), Sheets `:` is also `PairDelimiter` for ranges (`SC-6-lock1-amendment-generalisation.md:443-446`), and arbitrary grammars are promised the same derivation path (`SC-6-lock1-amendment-generalisation.md:469-484`). A global byte-to-role table either collapses distinct grammar contexts or forces grammar semantics into the scan table.

   This violates the CH2 standard because Lock 14 requires generic crates to avoid grammar-specific semantics, and PASS-2 requires grammar-neutral byte-set/classifier/tape expressions rather than JSON-overfit primitives (`restart/prompts/ORCHESTRATOR.md:83-85`, `restart/prompts/skinny/PASS-2-RESEARCH.md:102-107`). SC-3's safer model is byte-to-opaque ordinal data consumed by generic code, with grammar meaning interpreted by generated grammar modules (`restart/skinny/tranches/sk-v8/research/p2-substrate-ceiling/SC-3-union-substrate-design.md:286-302`). V2 must not regress from that to a scanner-owned event-role map.

2. **The `facts` column remains a grammar-policy escape hatch for EventTape recovery/layout.**

   SC-3 narrows `facts`, but still admits "EventTape-required recovery and layout facts" inside the generic tape (`restart/skinny/tranches/sk-v8/research/p2-substrate-ceiling/SC-3-union-substrate-design.md:157-165`, `SC-3-union-substrate-design.md:190-194`). Its BackendShape table repeats that EventTape populates the same column with recovery/layout facts (`SC-3-union-substrate-design.md:257-261`). SC-6's StructuralAlphabet abstraction enumerates byte set, neutral event class, escape/quote discipline, and pad/clamp policy (`SC-6-lock1-amendment-generalisation.md:337-354`), but it never defines a neutral vocabulary for recovery/layout facts.

   That gap matters for JSONL record terminators, indentation-sensitive grammars, CSS recovery, and any generated grammar whose layout is semantic. As written, "EventTape-required recovery/layout facts" can smuggle grammar-specific policy into generic tape/runtime code under a neutral name. SPEC's Lock 14 gate explicitly forbids generic code from consuming hard-coded JSON policy under neutral names and requires non-JSON proof for CSS L4, Sheets, and BBNF-self (`restart/skinny/tranches/sk-v8/SPEC.md:231-244`). V2 needs a closed neutral fact vocabulary, or opaque generated per-grammar fact ids interpreted only inside generated grammar modules.

3. **Some selection/gate language still turns JSON corpus shape into a generic fast-path criterion.**

   SC-1 says that if fusion regresses number-heavy rows, the plan can keep `OffsetTape`-via-recursive-descent for "low-quote-density rules" through `derive_backend_shape` (`restart/skinny/tranches/sk-v8/research/p2-substrate-ceiling/SC-1-offset-tape-teardown.md:362-364`). SC-4 makes the JSON string-fraction knee itself the success criterion, asking it to move from about 0.14 toward 1.0 (`restart/skinny/tranches/sk-v8/research/p2-substrate-ceiling/SC-4-string-plane-gap.md:307-310`), and then says the same primitive that closes JSON twitter closes CSS selector-heavy stylesheets and string-heavy sheets (`SC-4-string-plane-gap.md:331-342`).

   The JSON density signal is useful research, but not a grammar-neutral selector. A generic crate cannot branch on JSON corpus shape, JSON quote density, or a baked-in "string-fraction knee"; SPEC requires grammar-branch and primitive/table scans plus non-JSON proof (`restart/skinny/tranches/sk-v8/SPEC.md:231-244`). Fold this as CostFacts/RecognizerFacts data: each grammar may expose its own generated span/layout density facts and per-plane thresholds, but no generic fast path may be keyed to JSON row names, quote counts, or the JSON benchmark knee.

## Non-Blocking Notes

- Strict-vs-strict posture is now acceptable for CH2. SPEC separates same-run strict anchors from flaw probes and sidecar planning signals (`restart/skinny/tranches/sk-v8/SPEC.md:44-55`), and SC-4 marks mixed SK-V6/sidecar density rows as diagnostic rather than admission evidence (`restart/skinny/tranches/sk-v8/research/p2-substrate-ceiling/SC-4-string-plane-gap.md:178-182`).
- The old SC-6 role-name leak is materially improved. The remaining role issue is cardinality/context, not names.
- No new directive or BIR variant is proposed by the accepted core (`restart/skinny/tranches/sk-v8/research/p2-substrate-ceiling/SC-3-union-substrate-design.md:14-19`, `SC-3-union-substrate-design.md:454-458`). SC-6 also says the union is not a sixth `BackendShape` (`restart/skinny/tranches/sk-v8/research/p2-substrate-ceiling/SC-6-lock1-amendment-generalisation.md:307-312`).
- The packet mostly preserves research-only posture: SC-1 says it does not select W3 or authorize implementation (`restart/skinny/tranches/sk-v8/research/p2-substrate-ceiling/SC-1-offset-tape-teardown.md:260-266`), SC-2 keeps the fused index-tape unselected until S-P3/W3 challenge (`restart/skinny/tranches/sk-v8/research/p2-substrate-ceiling/SC-2-two-stage-sota.md:327-342`), and SPEC says the W3 nomination does not select W3 (`restart/skinny/tranches/sk-v8/SPEC.md:405-410`).
- SC-5's `tape_vs_tape` posture is grammar-neutral in principle because it compares substrate planes to substrate planes and blocks SOTA admission until same-run structural-index competitor rows exist (`restart/skinny/tranches/sk-v8/research/p2-substrate-ceiling/SC-5-k-classification-adjudication.md:178-190`).

## Required Fold Actions

1. Revise SC-6 so `StructuralAlphabet` is only a generated byte-set plus opaque structural-class ordinals in generic code. Move event-role interpretation to generated grammar modules, keyed by parser state and class/byte, so reused punctuation in BBNF, CSS, Sheets, JSONL, or arbitrary user grammars is not forced into one global role.
2. Revise SC-6-L1-R1 amendment text to state the same invariant: fixed neutral role ordinals may exist as generated parser interpretation, but the generic substrate consumes byte sets and opaque ordinals only.
3. Revise SC-3's `facts` column and EventTape row. Either enumerate a closed neutral fact vocabulary, or make recovery/layout facts opaque generated fact ids with no generic semantic branch. Add explicit JSONL record-boundary and indentation-sensitive examples to prove the layout path does not encode JSON.
4. Revise SC-1 and SC-4 fast-path/gate wording. Replace "low-quote-density" and the universal 0.14-to-1.0 knee with per-grammar CostFacts/RecognizerFacts telemetry and per-plane thresholds. JSON corpus rows may remain planning signals, not generic selector policy.
5. Update SYNTHESIS/SPEC/HANDOFF only as needed to reflect these folds: the Lock 14 gate should cover role cardinality, facts vocabulary, JSONL, indentation-sensitive grammars, and grammar-generated byte-set cases before any generic runtime/SIMD/codegen edit is accepted.
