## Rulings on critic A

### A1 — stateful preflight drift: CORRECT

Only the first call to `Serialize` computes and charges raw source bytes at
`hash.rs:666-701`. `measure` and `stream_hash` execute the second and third
serializations at `:747-785`, and only those latter two length/digest results
are compared.

The critic's arithmetic is exact. A legal serializer can emit `k` NUL bytes on
the dry preflight and the same `6k` ordinary bytes on both later calls. The
preflight upper is `6k + 2`; both later compact strings are also `6k + 2`, so
the output-upper and second/third digest checks pass. The charged string work
is `14k`, while the two real passes scan `12k` source bytes and process about
`12k` output bytes. The stale source observer at `:747-755` and `:771-779`
does not repair the budget. The existing `state-0/state-1/state-2` test at
`tests/architecture/hash.rs:65-70,190-193` exercises only second/third drift,
not stable-after-preflight drift.

This is an active T1 counterexample, not merely an API-style objection.

### A2 — legal numeric and bool map keys: CORRECT

`PreflightCompound::serialize_key` adds generic map overhead and then uses the
ordinary scalar callbacks at `hash.rs:234-247,309-358`. Those callbacks omit
the two quotes which pinned `serde_json` adds around bool and integer map keys
in `serde_json-1.0.149/src/ser.rs:834-1018`.

For `{u128::MAX: false}`, production derives 48 bytes while compact JSON is 49:
two braces, two key quotes, 39 digits, one colon, and five bytes for `false`.
Measurement therefore performs the complete legal serialization and rejects
late at `hash.rs:755-758`. Bool keys are legal for the same reason and have the
same context defect. The existing map test converts the custom values to
`serde_json::Value` first at `tests/architecture/hash.rs:159-188`, so it tests
only already-stringified keys.

### A3 — direct `collect_str` and hidden work: CORRECT, with one qualification

The asserted `collect_str` case is converted to `serde_json::Value` before the
budgeted call at `tests/architecture/hash.rs:178-188`; it never invokes the
production callback. In ordinary preflight, `fmt::Display::fmt` can traverse or
allocate arbitrary payload before its first `write_str`, while charging begins
only in `ChargingDisplay::write_str` at `hash.rs:490-516`. In the privacy
observer mode, `value.to_string()` allocates the whole result before
`self.string` at `:486-489`.

The privacy observer call happens after the canonical phase's manual
admission, so it is not literally an early privacy scan. It is nevertheless an
unreserved allocation, and the hash-side `Display` path directly violates the
claimed general preflight boundary. More fundamentally, arbitrary code run
inside a malicious `Serialize` or `Display` implementation cannot be resource
bounded by a serializer callback. A credited API must exclude such code by
type/API construction or reject the callback before invoking `Display`; it
cannot honestly claim general arbitrary-`Serialize` closure.

### A4 — scalar work: CORRECT

Every scalar gets 32 work units through `visit`, irrespective of output width
(`hash.rs:77-80,309-358`). A top-level `i128::MIN` has a 40-byte compact
representation and is formatted/hashed in two real passes, yet receives only
32 work units. A declared sequence gives container prepayment plus child
visits, still below two 40-byte passes for a sufficiently long sequence; an
unknown-length sequence gets only the initial container visit plus 32 per
child. `output_upper_bound` records scalar width but never transfers it to the
mutable work budget. The string-only `14n` assertion at
`tests/architecture/hash.rs:196-206` cannot prove scalar work.
