### B-02 — P0: normativity is inferred from byte substrings and nearby prose, discarding current normative productions

**Evidence.** `src/extract.py:180-192` labels an entire carrier `HISTORICAL` whenever
its raw body contains `b"<ins"` or `b"<del"`. This is not tag parsing. Bikeshed
references such as `<<inset-value>>` contain the byte substring `<ins` at their
second `<`. The pinned output therefore calls current carriers historical,
including:

- `css-gaps-1/Overview.bs:993` propdef and `:1003` production for
  `<<inset-value>>`;
- `css-shapes-1/Overview.bs:356` production containing `<<inset()>>`;
- additional current `inset` property/production carriers among the 16 reported
  historical records.

The exact benign mutation is:

```text
<pre class="prod"><<x>> = <<inset-value>></pre>
=> kind=prod, normativity=HISTORICAL
```

An actual `<ins>` is also not proof that the whole current carrier is historical;
in a current spec it normally contributes inserted/current text. The mutation
`<pre class="prod"><x> = a <ins>| b</ins></pre>` is classified `HISTORICAL`.
Separately, `src/extract.py:186-187` marks a carrier non-normative merely because
the previous 800 decoded characters contain “non-normative”; the mutation
`<p>This note is non-normative.</p>...<pre class=prod><x> = a</pre>` reproduces the
false classification without structural containment.

**Impact.** Current normative CSS is removed before AST construction and the matrix.
The “1,395 normative / 16 historical / 9 non-normative” disposition is not a valid
normativity measurement. Exact spans do not compensate for an incorrect semantic
selection.

**Smallest principled repair.** Parse actual tag tokens and structural normative
containers. Treat `<<...>>` as Bikeshed references before edit-tag classification.
For edit markup, preserve current `<ins>` content, exclude `<del>` content where the
pinned source convention requires it, and keep the carrier's normativity separate
from segment edit state. Remove free-window prose heuristics; use actual ancestor or
source metadata. Add raw-reference, real edit-tag, and unrelated-nearby-prose
mutations.

### B-03 — P0: the value-definition and railroad parsers accept structurally invalid ASTs as parsed

**Evidence.** `src/grammar.py:176-210` deliberately creates `empty` nodes whenever a
sequence has no item and accepts any number or order of multiplier tokens.

```text
`a |`          -> alternative(atom(a), empty)
`| a`          -> alternative(empty, atom(a))
`[]`           -> group(empty)
`a{garbage}`   -> repeat multipliers=["{garbage}"]
`a??`          -> repeat multipliers=["?", "?"]
```

`railroad_expression()` at `src/grammar.py:342-375` accepts any alphabetic operator,
does not validate legal operator vocabulary or arity, and makes every subsequent
indented node a child. `Bogus: payload\n  T: child` is returned as a
`kind=railroad` tree. The current 46 “parsed railroad trees” use at least 17 operator
spellings, but no validator defines or checks their semantics.

**Impact.** `PARSED`, `PARSED_EXPRESSION`, and `PARSED_RAILROAD` mean only “the
permissive parser returned a dictionary,” not “valid CSS Value Definition Syntax or
valid Bikeshed railroad AST.” The claimed 769/793 parse figure and the closure built
over those ASTs cannot establish grammar validity.

**Smallest principled repair.** Define the pinned CSS value-definition and railroad
operator schemas directly and validate them: nonempty combinator operands, legal
multiplier grammar and combinations, balanced/legal delimiters, railroad operator
vocabulary, payload constraints, and child arities. Keep permissive token capture as
raw evidence, but call it `UNPROVEN` until the strict AST validator passes. Add a
negative corpus including all five mutations and unknown/ill-formed railroad nodes.

**Lock / credit effect.** The grammar-AST/profile/reference gate remains RED;
