# B3.W0 — W0' Revert Probe + Canonical Chain + Master Cherry-Pick

**Opens after**: tranche open
**Agents**: 1 (W0.a probe) + 1 (W0.b canonical, only IF probe confirms) + closer (W0.c orchestrator)
**Hard gate**: W0.a probe runs to completion with phase-timed xtask output + verdict; IF CONFIRMED, W0.b lands canonical 14-revert + 1-instrumentation chain in a fresh worktree; W0.c cherry-picks the chain to master with no destructive operations; B2.W0.a/b/c partial-close commits intact.
**Status**: planned

## Scope

The AY-II.W0' source landings (commits `bd563c1d`-era through `f768f50d`)
are the candidate root cause for the runtime parser regression observed at
B2.W0.c. The hypothesis is plausible per the W0.c diagnostic narrowing but
unproven; B3.W0 sequences the test as a **proof-first disposable-worktree
probe** before any canonical history lands on master.

W0 splits into three phases:

- **W0.a (probe, sub-agent)**: instrument xtask with phase-timing logs;
  apply the 14 W0' reverts as throwaway commits on a disposable worktree;
  build; run instrumented xtask regen; read the `[parse]` phase wall;
  record verdict (CONFIRMED / DISPROVED / INDETERMINATE); tear down the
  disposable worktree regardless of verdict.
- **W0.b (canonical, sub-agent, ONLY IF W0.a verdict is CONFIRMED)**: on
  a fresh worktree, apply the instrumentation commit + the canonical 14
  forward-revert commits; record per-revert manifest; verify build + test
  green.
- **W0.c (cherry-pick, orchestrator)**: cherry-pick the 15-commit chain
  onto master; verify B2.W0.a/b/c intact; PROGRESS.md update; worktrees
  torn down. NO destructive operations on master.

## Phase sub-items

### B3.W0.a — Disposable-worktree probe

**Hard cap**: 90 min. **Worktree**: `bbnf-wt-b3-w0a-probe` (disposable;
torn down at probe close regardless of verdict).

The probe tests the W0' revert thesis WITHOUT landing canonical history
on master. If the probe DISPROVES the thesis, no master commits result;
the orchestrator escalates per the escape clause.

Mechanism:

1. **Disposable worktree setup + alias preflight**.
   ```bash
   ROOT=$(git rev-parse --show-toplevel)
   PARENT=$(dirname "$ROOT")
   git worktree add --detach "$PARENT/bbnf-wt-b3-w0a-probe" HEAD
   cd "$PARENT/bbnf-wt-b3-w0a-probe"
   "$ROOT/scripts/seed-worktree.sh" "$PARENT/bbnf-wt-b3-w0a-probe"
   rm -f target && ln -s "$ROOT/target" target

   # Preflight: cargo xtask alias must resolve before any probe step.
   cargo --list 2>&1 | grep -q '^    xtask$' || {
     echo "FATAL: cargo xtask alias not configured in .cargo/config.toml"
     echo "Expected: alias.xtask = 'run -p xtask --release --'"
     exit 1
   }
   ```

2. **Instrument regen with phase-timing logs**. Edit
   `xtask/src/regen.rs`, `crates/core/src/pipeline/compile.rs`, and
   `crates/core/src/pipeline/directives.rs`. The parse phase lives under
   `compile_paths_request -> load_merged_paths -> parse_to_pipeline_inputs`;
   xtask-only timing around `compile_paths_request` is not sufficient.
   Add lightweight, env-gated `Instant::now()` + `eprintln!` probes that
   emit only when `BBNF_REGEN_PHASE_LOG=1` is set. Phases (in order):

   | Phase | Boundary |
   |---|---|
   | `manifest` | cargo metadata + workspace grammar manifest read |
   | `load` | `compile_paths_request` grammar-file load + merge wrapper |
   | `parse` | `BbnfBootstrap::parse(source)` inside `parse_to_pipeline_inputs` — the suspected hot path |
   | `ir-pipeline` | `compile_ast_request_internal` after parsed AST/directives exist |
   | `generate_all` | TokenStream emission |
   | `prettyplease` | format pass |
   | `write` | write per-grammar source file to disk |

   Each phase logs elapsed-since-its-start, plus a final cumulative
   `[xtask::regen][total]` line. The instrumentation must be lightweight
   — `eprintln!` only, no metric crate, no JSON serialization, no
   unconditional stderr noise when `BBNF_REGEN_PHASE_LOG` is absent. It
   needs to be readable from a `cargo xtask regen 2>&1 | tee` capture.

   Commit on the disposable worktree:
   ```bash
   git add xtask/src/regen.rs crates/core/src/pipeline/compile.rs crates/core/src/pipeline/directives.rs
   git commit -m "feat(xtask): phase-timing instrumentation for parser-regression diagnostic (B3.W0.a)"
   ```

   Save the instrumentation commit's SHA — W0.b will re-apply it on
   the canonical worktree.

3. **Apply 14 W0' reverts as throwaway commits**. Reverse-chronological
   order:

   ```bash
   for sha in f768f50d 60f92743 b1bb4579 550dac11 bc8fa8b2 0993cc89 \
              30aa83aa 1bfcf359 3a7df479 91355d25 0beda457 9c9906c8 \
              4edfac88 bd563c1d; do
     git revert --no-edit "$sha" || break
   done
   ```

   On conflict: stop the loop; resolve manually preferring the pre-W0'
   shape; `git add` the resolved files; `git revert --continue`.
   Conflict resolution rationale gets noted; W0.b will reuse it.

   These are throwaway commits — they exist only on the disposable
   worktree branch and disappear at probe teardown.

4. **Build the workspace**.
   ```bash
   export CARGO_BUILD_JOBS=4
   # Preserve .bbnf-cache. B3 measures the substrate developers will use;
   # cold-cache probes are a separate explicit measurement mode.
   cargo check --workspace --profile ax-iter > /tmp/b3-w0a-check.txt 2>&1
   cargo build -p xtask --release > /tmp/b3-w0a-xtask-build.txt 2>&1
   ```

   Both must exit 0. If `cargo check` fails:
   - Read the error; if it's a missing API on the post-revert surface
     that B2.W0.c's `pub use` migration depended on (the `pub use`
     resolves through `crates/core/src/grammar/generated.rs` whose
     content was never updated post-W0'), the revert may surface a
     gen.rs / runtime mismatch. Resolution depends on whether the
     mismatch is in source types (revert resolution) or generated
     types (out-of-scope for B3.W0; halt and report).
   - If errors are localized to the reverted surfaces, fix in place
     and amend the most recent revert.
   - If the error is in a B1 or B2.W0.a/b commit's interaction with
     the reverted surface, halt and report.

5. **Run instrumented xtask regen**. The canonical probe — measure the
   parse phase directly:

   ```bash
   # zsh: preserve the left side of the timeout|tee pipeline.
   set -o pipefail
   BBNF_REGEN_PHASE_LOG=1 timeout 600 cargo xtask regen --grammar bbnf \
     2>&1 | tee /tmp/b3-w0a-probe.txt
   status=${pipestatus[1]}
   echo "EXIT: $status" | tee -a /tmp/b3-w0a-probe.txt
   test "$status" -eq 0
   ```

   The `timeout 600` (10 minutes) is the probe cap. If xtask hangs
   beyond this, the parse regression is severe enough that even a
   reverted runtime can't complete the probe — verdict DISPROVED.

6. **Verdict determination**. Read `/tmp/b3-w0a-probe.txt` for the
   `[xtask::regen][parse] <wall>` line.

   - **CONFIRMED**: `<wall>` < 5 s AND xtask completed all phases (final
     `[total]` line present, exit 0). The W0' revert restored parser
     baseline.
   - **DISPROVED**: `<wall>` >= 5 s, OR the probe hit `timeout 600`,
     OR `<wall>` is missing because the parse phase did not return.
     The W0' revert is insufficient.
   - **INDETERMINATE**: build failed (gate 4 above) OR xtask
     completed BUT a non-parse phase blocked > 60 s (suggests a
     different regression than parse-phase). Halt and report; no
     verdict.

7. **Save probe artefacts inside the disposable worktree**:
   ```bash
   mkdir -p docs/tranches/B3/audit
   cp /tmp/b3-w0a-check.txt docs/tranches/B3/audit/W0a-probe-build.txt
   cp /tmp/b3-w0a-xtask-build.txt docs/tranches/B3/audit/W0a-xtask-build.txt
   cp /tmp/b3-w0a-probe.txt docs/tranches/B3/audit/W0a-probe-output.txt
   ```

8. **Author verdict file**.
   `docs/tranches/B3/audit/W0a-probe-verdict.md` in the disposable
   worktree:
   ```markdown

   **<CONFIRMED | DISPROVED | INDETERMINATE>**

   | total | <s> |

   ## Conflict count during throwaway revert chain

   <N> conflicts; resolutions noted in audit/W0a-probe-conflicts.md
   (deliverable for W0.b reuse).

   ## Recommended next action

   - **CONFIRMED** → proceed to W0.b (canonical revert chain on a
     fresh worktree, reusing the conflict resolutions).
   - **DISPROVED** → escalate to escape-clause Escape 1 (W0' + W0-fix
   ```

9. **Commit the probe evidence in the disposable worktree**. This is a
   docs-only evidence commit. It is not canonical revert history; the
   orchestrator may cherry-pick it to master after review so a DISPROVED
   probe leaves evidence without landing source reverts.

   ```bash
   git add docs/tranches/B3/audit/W0a-probe-build.txt \
           docs/tranches/B3/audit/W0a-xtask-build.txt \
           docs/tranches/B3/audit/W0a-probe-output.txt \
           docs/tranches/B3/audit/W0a-probe-verdict.md
   git commit -m "audit(b3): W0.a disposable probe verdict"
   ```

10. **(IF conflicts encountered during step 3)** Save resolutions for
   W0.b reuse:
   ```bash

   git log --reverse --format='%H' HEAD~14..HEAD | head -14 | \

       git show "$sha" --no-color > /tmp/probe-revert-"$sha".diff
   ```

11. **Disposable worktree teardown**.
    ```bash

    git worktree remove --force "$PARENT/bbnf-wt-b3-w0a-probe"
    ```
    The throwaway branch is deleted with the worktree.

12. **Report to orchestrator**. The agent's return brief carries:
    - Verdict (CONFIRMED / DISPROVED / INDETERMINATE)
    - The `[parse]` phase wall in seconds
    - Conflict count during throwaway revert chain
    - Build/probe artefact paths + docs-only probe evidence commit SHA
    - Recommended next action

Files touched (W0.a):

### B3.W0.c — Orchestrator cherry-pick to master

**Hard cap**: 30 min. **No separate sub-agent** — orchestrator-owned.
Strict no-`git reset` discipline.

Mechanism:

1. **Audit the W0.b worktree's commits**. Read each revert commit's
   diff snapshot at `docs/tranches/B3/audit/diffs/<sha>.diff` for spot
   checks. Verify the conflict resolutions cited in
   `W0p-revert-record.md` §Conflicts. Verify the instrumentation
   commit's content matches the agreed phase-timing scaffold.

2. **Cherry-pick the 16-commit chain onto master in order**.
   ```bash
   ROOT=$(git rev-parse --show-toplevel)
   cd "$ROOT"
   WTREE_BRANCH=$(git -C "$PARENT/bbnf-wt-b3-w0b-canonical" rev-parse --abbrev-ref HEAD)
   git log --reverse --format='%H' master..$WTREE_BRANCH | \
     while read sha; do
       git cherry-pick "$sha"
       if [ $? -ne 0 ]; then
         echo "CONFLICT at $sha — aborting cherry-pick"
         git cherry-pick --abort
         exit 1
       fi
     done
   ```

3. **Conflict resolution (master cherry-pick)**:
   - `git cherry-pick --abort` reverts master to the pre-pick state
     (no destructive operation; master is exactly where it was before
     the cherry-pick attempt).
   - Inspect the conflicting hunks; either:
     - (a) Resolve manually as a fresh orchestrator-authored commit
       citing the sub-agent's worktree (and re-attempt cherry-pick
       from that point onward), OR
     - (b) Redispatch the W0.b sub-agent on a fresh worktree seeded
       at current master HEAD (the agent re-runs the canonical chain
       on the new substrate).
   - **`git reset --hard` is FORBIDDEN.** No exception.

4. **Master integrity check post-cherry-pick**:
   ```bash
   git log --oneline master | grep -E 'B2\.W0\.[abc]'
   # Expected: 21881591, 3c68e8c4, dec67806

   git log --oneline master | grep -c 'Revert.*AY-II.W0'\'
   # Expected: 14

   git log --oneline master | grep -c 'feat(xtask): phase-timing'
   # Expected: 1
   ```

5. **Master build + test verification**:

## Archaeology

The W0' work originated as part of AY-II's renumbered W0' phase
(documented at `docs/tranches/AY-II/AY-II.md` and
`docs/tranches/AY-II/audit/W0p-PAUSE-SNAPSHOT.md`). The plan-time intent
was to collapse TapeBuilder + ValueBuilder into FusedBuilder so
`Parsed::to_value()` projects from value frames without a second parse.
That intent remains valid; the revert is not architectural rejection but
sequencing correction.

The W0' commits cherry-picked from worktrees onto master before
`generated.rs` regenerated. The half-migrated state went undiagnosed
because the > 80 min cold rustc-side wall (attributed by the four 2026-04-25
deep audits to IR-pipeline-at-expand-time accumulation) masked the runtime
regression. B2.W0.c's release-profile xtask probe — running the IR
pipeline outside rustc — proved the wall actually lives in
`BbnfBootstrap::parse` itself, but at B2.W0.c's diagnostic the
attribution was at the `cargo xtask regen` granularity. B3.W0.a's phase-
timed xtask narrows the attribution further to the specific phase, with
no ambiguity left.

The disposable-worktree probe pattern (W0.a) is borrowed from B1.W0.d's
triumvirate diagnostic — the gorgeous derive-multiplication wall was
isolated by gating away from main-history work first, proving the lever
on a disposable substrate, then committing the canonical fix. B3
re-applies the pattern to a revert hypothesis.

The W0'.d4-d7 infra commits (gorgeous gating, dev-dep cleanup, build.rs
narrowing, iter-check exclude) are intentionally NOT reverted. They
landed under W0' tagging but touch independent surfaces and have no
runtime architecture impact. Their inclusion in W0' was historical
sequencing convenience, not architectural coupling.
