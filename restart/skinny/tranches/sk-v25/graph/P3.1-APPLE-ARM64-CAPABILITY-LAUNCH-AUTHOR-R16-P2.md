## Implemented source slice

`binding.rs` now has one private binding-local `AppleArmLaunchPlan` and one
constructor. The plan owns:

- logical program and complete logical argv;
- the canonical `/usr/bin/arch` launcher and its bytes;
- physical argv beginning `-arm64`, then the canonical selected program, then
  the logical arguments;
- the canonical cleared child environment and fixed locale/timezone policy;
- a role-bounded optional `DYLD_PRINT_LIBRARIES=1` addition;
- policy version, compiled macOS/aarch64 precondition, required and observed
  `arm64` premise;
- launcher path/byte identity and selected-program path/byte identity; and
- sorted execution-contract rows that digest exact OS identities without
  serializing private absolute path text.

Before accepting any plan execution, the same constructor produces an
`observed-arm-precondition` plan for `/usr/bin/uname -m`; it is physically
launched by `/usr/bin/arch -arm64`, must succeed, and must report `arm64`.
There is no direct-first execution or second plan mode.

The following receipt-producing operations use that plan:

```text
resolver                  /usr/bin/xcrun --find ar|clang|ld
selector                  /usr/bin/xcode-select -p
capability                selected ar --version, clang --version, ld -v
observed ARM premise      /usr/bin/uname -m
host/kernel premise       /usr/bin/uname -srmv
macOS premise             /usr/bin/sw_vers
runtime transcript        selected Xcode payload with bounded DYLD setting
dependency listing        /usr/bin/otool -L <selected payload>
load-command listing      /usr/bin/otool -l <selected payload>, when declared runtime paths require it
duplicate host recapture  normalized_host_facts uname/sw_vers
```

Declared Mach-O runtime dependencies are closed without a particular library
or Xcode installation path in source. The ARM-routed load-command observation
binds exact output, parses `LC_RPATH`, canonicalizes loader- and
executable-relative locations, hashes the unique payload, and fails closed on
missing, ambiguous, malformed, or non-file closure.

For bound Apple tools, existing fields now mean:

- `tool` and `argv`: logical tool and logical argv;
- `invocation_name`, `invocation_path_hash`, `proxy_hash`: `arch`, canonical
  launcher path identity, and launcher bytes;
- `effective_path_hash`, `executable_hash`: selected payload path identity and
  payload bytes;
- `capability`, `capability_hash`: exact accepted ARM-launched output;
- `execution_contract`: sorted policy, precondition, launcher, exact argv,
  selected payload, and bounded environment identities;
- `toolchain_selection_hash`: ARM-routed resolver and selector plans, exact
  outputs, developer-directory bytes, selected payload path/bytes, and policy;
  and
- `dynamic_runtime_hash`: ARM launch semantics, exact host/macOS premises, and
  the DYLD/otool observation closure.

No `ToolBinding`, `BuildReceipt`, or serialized schema field was added. The
global `canonical_child_command` was not changed. Non-Xcode Cargo, rustc,
