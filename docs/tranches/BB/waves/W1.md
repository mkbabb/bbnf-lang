# BB.W1 — First enumeration run: JSON + Sheets

**Opens after**: W0 close
**Agents**: 2 parallel
**Hard gate**: First curated rule batch lands for JSON and Sheets — at
least 5 accepted per grammar, ≥ 90% of accepts in Class 1 + 2, JSON
`generated.rs` shrinks by ≥ 10 LOC, no regression on the 17-entry
matrix.
**Status**: planned

## Scope

1. Run the W0 enumerator on JSON with narrow alphabet (literal
   fusion, repeat-unroll, Alt flattening when bounded, identity folds).
   Target N = 20 candidates after the e-graph residue split.
2. Run the same enumerator on Sheets with its analogous narrow alphabet.
   Target N = 15 candidates post-residue.
3. VM oracle validates candidates over the existing fixture corpora for
   each grammar under the budget from W0.
4. Ranker scores and tiers every validated candidate; auto-accept Class
   1, fast-track Class 2 review in batch, queue Class 3 for one-at-a-
   time deliberation.
5. Accepted rules land at `crates/ir-rewrites/src/inferred/*.ron`
   (fleet-wide) or `grammar/<name>/rewrites/*.ron` (grammar-specific),
   as the ranker determines.
6. Re-emit `generated.rs` for JSON; measure shrink.

(those are frozen at W0 close); any `crates/core/` file; CSS or BBNF
rewrites (those open in W2).

## Phase sub-items

### BB.W1.1 — JSON enumeration run

Narrow-alphabet CVC enumeration; residue split; oracle validation;
rank; tier. Emit `docs/rules/runs/W1-json.md` with the ranked
candidate list, tier assignment, cost delta, and corpus coverage.

Sub-gate: ≥ 20 validated candidates; ≥ 5 accepted; ≥ 90% in Class 1+2.

### BB.W1.2 — Sheets enumeration run

Same shape on Sheets. Emit `docs/rules/runs/W1-sheets.md`.

Sub-gate: ≥ 15 validated candidates; ≥ 5 accepted; ≥ 90% in Class 1+2.

### BB.W1.3 — Rule landing + generated.rs re-emission

Accepted rules land as RON files. Run the codegen pipeline; measure
JSON `generated.rs` line-count delta vs pre-W1.

Sub-gate: JSON shrink ≥ 10 LOC; Sheets does not regress; 17-entry
matrix does not regress; parity harnesses green.

### BB.W1.4 — Review ledger

Per-rule `docs/rules/<rule-id>.md` for every Class-2 and Class-3 rule;
Class-1 accepts get an `audit-log.ndjson` entry only. Rejected rules
get `docs/rules/rejected/<rule-id>.md` with rationale.

Sub-gate: every accepted or rejected rule has its documentation in
place.

## Hard gate

1. `cargo test --workspace --profile ax-iter` green.
2. JSON `generated.rs` line-count delta ≤ -10.
3. 17-entry AU-baseline matrix at or above AZ close on every entry.
4. lightningcss / sonic-rs / simdjson parity harnesses green.
5. Per-run markdown reports committed under `docs/rules/runs/`.
