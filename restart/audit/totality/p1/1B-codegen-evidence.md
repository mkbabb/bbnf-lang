## Executive Summary

The skinny codegen layer implements the named five-shape `BackendShape` enum, `LayoutFacts.backend_shape`, `CostFacts`, `derive_backend_shape_with_diagnostics`, and shape-dispatch modules. The current code is therefore past symbol absence. It is not yet the V1 codegen architecture claimed by `ARCHITECTURE.md`: the formal `Backend` trait is absent; `CostFacts` is a thin priority/rationale record rather than objective/Pareto evidence; most shape lowerers return marker strings rather than emitted recursive-descent/tape/event/ASM artefacts; `SinkOnly` alone walks BIR into a concrete intermediate program; runtime profile selection is hardcoded to JSON and CSS-L4 declaration values.

The spec itself contains one stale implementation-status paragraph: it says `passes::compile` still calls `shapes_for_json()` and `nominate_json`, but live `passes/src/lib.rs` now derives shape facts, recognizers, and materialization from `GrammarIr`. That improvement coexists with grammar-shaped heuristics and hardcoded codegen runtime profiles, so Lock 14 remains partially drifted at codegen emission time. V2 folds CH2 by separating explicit grammar-name leaks from grammar-shape leaks that do not name JSON, widening the generic-crate census, and treating the GrammarConfig / `RuntimeProvider` direction as row-level repair evidence rather than a complete generic-crate repair.
