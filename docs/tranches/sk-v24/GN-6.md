# GN-6 — THE SHOPWINDOW AND THE CLOSE

The terminal tranche of the greenfield novum codex. Where GN-0 through GN-5 forged the
generator, its kernels, its type plane, its value fabric, and its fleet, GN-6 mounts them in
a window the world can see and seals the campaign's evidence into a durable home. Two organs,
one tranche: **the shopwindow** — a greenfield single-page application that drives the real
wasm value surface, not a mock of it — and **the close** — the four durable documents, the
published differentiator, and the audited seal over every prompt this campaign answered.

GN-6 lands no proven patch of its own. It is the productionized presentation of the swath the
prior tranches installed: the shopwindow consumes the value lanes GN-4 exported; the documents
transcribe the certified numbers GN-1 through GN-5 measured; the close re-captures those
numbers under quiet-host certification and stamps the ledger shut. Every deliverable herein is
public-facing product, held to the productionization bar — no prototype residue, no mock
engine, no warm number wearing a certified badge.

### Refutation guards

The SPEC §0 laws that constrain this tranche. Each is a wall GN-6 must not breach:

- **No digit-scan SIMD win.** Refutation 02 (NO_GO, latency-bound CPI inversion 0.13→0.30) is
  law: its immutable content is that the canada redress attacks FLOAT CONVERSION (the eager
  `materialize_f64` / Eisel–Lemire tax, SPEC §0), NEVER the digit scan — not that a fixed loss
  magnitude is frozen. The shopwindow's number-parse demo and the PERFORMANCE-THESIS quote the
  canada `fused`/sonic figure GN-2.W5 measured — the pre-redress ~1.20× loss if that
  float-conversion redress did not land, or its post-redress value (GN-2.W5 born-RED target
  ≤1.05×, GN-2.md:455) if it did. The demo may never present a digit-scan SIMD speedup; any canada
  improvement it shows is attributed to the GN-2.W5 Eisel–Lemire conversion redress, never to a
  SIMD digit kernel.
- **No block-scheduling pursuit.** Refutation 04 (multi-block software pipelining, 1.05–1.06×
  only, the M-class core already pipelines the single-block loop) enters NEGATIVE-RESULTS as a
  closed lever. The tranche pursues no scheduling variant.
- **No shim perf claims.** Refutation 09 (portable_simd→NEON shim, 1.34–1.57× REFUTED to
  parity-or-slower) is law. The de-nightly port's value in every document is **stability**, zero
  perf claim; the shopwindow must not attribute any speedup to the shim.
- **Fold-over-cursor is dead.** The value-surface demo (2.3–4.9× behind sonic when fold) uses
  stop-early get and the offset tape — never a lazy-cursor fold.
- **Tape-navigation is not the get lane.** Refutation 06 measured tape-walk at 150–1700× the
  stop-early cost. The get demo drives stop-early get (06), not a tape traversal.
- **Warm benches are forbidden.** W4 and W5 measure cold paired PMU only. The in-browser strip
  is illustrative; a browser-wasm timing may never be quoted as a certified §0 figure.

## §4 PER-WAVE SPECIFICATION

### W1 — THE SHOPWINDOW

**Objective.** A greenfield single-page application that drives the *real* GN-4.W4 wasm value
surface — compile a grammar, feed input, and watch the four proven value lanes resolve live: the
eager offset tape, stop-early get by pointer, direct-to-struct decode, and the cross-language TS
tape view. The shopwindow's thesis is *generality made visible*: one editor, five grammars
(json/css/csv/toml/sheets), four lanes, zero name-gates. It is the largest single LOC item in
the codex and is staged into three sub-waves.

**The consumed contract (GN-4.W4 exports; W1 binds, does not author).** GN-4.W4's deliverable is
a `wasm-bindgen` `cdylib` workspace member (`crates/bbnf-wasm/`, wasm-subcrate pattern —
bindings live inside the parent workspace) producing a `wasm-pack` `pkg/`. W1 consumes exactly
this surface, which supersedes the archived hand-written binding at
`playground/src/wasm/bbnf_wasm.d.ts`:

```

#[wasm_bindgen] pub fn parse_tape(h: u32, input: &str) -> TapeHandle          // LANE 1 eager tape
#[wasm_bindgen] impl TapeHandle { pub fn decode(&self) -> JsValue }            // LANE 4 (feat 14) offset-tape → JS view
#[wasm_bindgen] pub fn get(h: u32, input: &str, pointer: &str) -> JsValue      // LANE 2 (feat 06) stop-early tape-free get
#[wasm_bindgen] pub fn parse_struct(h: u32, input: &str, schema: u32) -> JsValue // LANE 3 (feat 07) direct-to-struct sink
// LSP surface ported from playground/src/wasm/bbnf_wasm.d.ts: analyze_grammar, completions,
// document_symbols, code_actions, code_lens, find_references, compile_grammar_debug, debug_step
```

Should GN-4.W4 not have landed when W1 opens, W1 halts — a mock of this surface is a
plan-declared defect (mock-wasm ban), not a permitted bridge. The SPA imports the built `pkg/`
