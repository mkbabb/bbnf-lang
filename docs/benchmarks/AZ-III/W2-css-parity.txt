Root-cause analysis
-------------------
1. Wrap-shape Alt-of-Map(Regex) emitted an empty body. The pre-W2.2 emitter at
   `crates/core/src/backend/rust/emitter/shapes/wrap/struct_direct.rs::emit_wrap_branch_call_struct_direct`
   admitted only `IrNode::Ref` branches; the four `combinator = /\s*>\s*/ -> 1u8 |
   /\s*\+\s*/ -> 2u8 | /\s*~\s*/ -> 3u8 | /\s+/ -> 0u8` branches all returned `None`,
   so `parse_wrap_CssL4Parser_combinator` lowered to `'try_branches: loop { match
   first { _ => {} } return Err(...) }`. Every `>` / `+` / `~` combinator-led
   complex selector failed; bootstrap.css died at the first `a > code { … }` rule
   (offset 9317).

   Fix: extend the wrap struct_direct emitter to accept `Map(Regex)`, `Map(Literal)`,
   `Regex`, and `Literal` branches. Each emits an inline IIFE that performs the
   match, advances *p, and pushes the typed `-> Nu8 / -> Nu64 / -> Bool` payload
   constant-folded out of the branch's `FnDescriptor::Expr`. `branch.first_set`
   (the analysis-pass-populated `Option<CharSet128>`) drives the byte-dispatch.

2. Named-color and hex typed-payload failures (white_materialises +
   every_named_color_materialises_its_u32_payload) — root cause is in
   `crates/core/src/backend/rust/emitter/shapes/alt_dispatch/branches.rs`. That file
   is W3c carve, not W2.2. The current `emit_dispatch_arms_struct_direct` strips
   `Map(fn_id)` via `unwrap_trivia` and emits `push_leaf_with_unit() +
   push_branch_tag(idx)` for every `IrNode::Literal` branch — never the typed
   `MapExpr::IntLit(0xRRGGBBAA)` from the fn descriptor. Same defect surface as the
   wrap fix; the alt_dispatch shape needs the symmetric extension. Routed to W3c.

3. lightningcss_parity_tailwind timeout — perf regression introduced by the wrap
   fix's per-branch IIFE wrapping a `__regex_scan_<grammar>(pattern, input, *p)`
   adapter call. The combinator rule is the hottest non-leaf rule in tailwind.css
   (every adjacent compoundSelector pair attempts the four-branch combinator
   linear-try); the regex_scan adapter's pattern-string lookup is `#[cold]` and
   pays a HashMap-style match per call. Bootstrap.css (280 KB) parses in 1.4s;
   tailwind.css (3.6 MB) exceeds nextest's 90-second timeout. Pre-W2.2 the rule was
   STRUCTURALLY broken (no branches emitted); the timeout is a NEW regression
   surfaced by activating the dispatch.

   Routed to W3c: collapse the regex_scan adapter's per-pattern lookup into a
   compile-time per-shape `__regex_<grammar>_<idx>` direct call (or fold the four
   combinator branches into a single byte-class fast path; the four operators are
   `\s∪{>,+,~}` plus a run of `\s` — a single hand-written scan covers all four
   cases without four regex_scan calls). The fix sits inside the regex emit
   adapter (`generate/regex/`) or a hand-written combinator scanner for a CSS-only
   shape carve, neither of which is W2.2 file bounds.
