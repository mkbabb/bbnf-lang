# BB-B.W5 — sealed immutable analysis products

## Goal

Replace mutable heterogeneous sidecars and `FactAuthority` with total typed stage
values keyed to exact Program and TypeSolution revisions.

## Implementation

1. Define independent immutable products for nullability, FIRST/FOLLOW, width,
   recognizer eligibility, materialization/payload, semantic value shape, host
   knowledge, recovery, and any backend-neutral capability proved necessary.
2. Give each analysis an input signature containing only sealed prior stages; return
   value, revision digest, provenance, and bounded work report.
3. Prohibit analysis reads/writes on Program nodes. Encode stage order in types and
   module privacy instead of runtime `FactAuthority` assertions.
4. Canonicalize facts and diagnostics; reject missing nodes, wrong revisions,
   partial worklist exits, and incompatible TypeSolutions.
5. Wire load-bearing lowering/emission/runtime consumers to each fact family and
   add disconnect/inversion mutations proving the reads are real.
6. Compare incremental analysis to clean recomputation and declare invalidation
   causes through the W2 dependency graph.

## Gates

- No production mutable/dynamic fact map or authority facade remains in the target
  path.
- Every declared node has a fact or typed exclusion; all consumer mutations fail.
- Repeated/incremental/permuted runs are byte-identical and budget failure publishes
  no partial product.
- Stage values reject cross-revision composition at construction/deserialization.
- Graph projection is directed Program -> Graph -> TypeSolution -> AnalysisFacts.

## Completion

AnalysisFacts is the only backend-neutral semantic fact authority.
