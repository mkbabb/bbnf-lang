# AZ-IV.W5 - TS Binding + Value-API + Substrate Audit

**Name**: W5 - TS Binding + Value-API + Substrate Audit
**Opens after**: W4 - Optimization Substrate Activation
**Agents**: 5 parallel writer slots
**Hard gate**: `crates/bbnf-path-ts/` cdylib + wasm-bindgen + template-literal tag executes against representative grammars at parity with the Rust frontend; per-grammar value-enum dedup (structural skeleton) lands without disturbing the typed `*Value` enums; permanent `crates/ir/src/passes/tests/substrate_audit.rs` test enumerates every `pub` substrate at compile time and fails the build on zero-caller substrate
**Status**: complete_with_misses

## Scope

W5 lands the TS binding for the `path!` macro, finishes the per-grammar value-API consolidation (structural skeleton dedup; typed `*Value` enums survive), and lands the permanent substrate-audit test that prevents future "substrate without consumer" regressions. PROFILING.md compliance is required per the AZ-IV.md hard gates 13 + 20.

1. `crates/bbnf-path-ts/` cdylib sub-crate with wasm-bindgen (per `feedback_wasm-subcrate-pattern`). Exposes `compile_path(path_str, grammar)` and `execute_path(typed_path, document_view)` to the TS frontend. The TS template-literal tag (`` path`$.users[0].name` ``) invokes `compile_path` at load time (or build time under bundlers with constant-folding — Vite, esbuild, SWC) and produces a typed accessor closure.
2. Isomorphic error taxonomy: `PathError { segment, struct_name, alternatives, reason }` is identical across the Rust frontend (W2) and the TS frontend (W5), rendered through each host's native error surface (`syn::Error::new` in Rust; `throw new PathError(...)` in TS).
3. Node-execute proof: TS-emitted parsers (the W1 build-time work) plus the new `bbnf-path-ts` template-tag execute against a real bench fixture (twitter.json) end-to-end through Node. The integration test asserts identical leaf extraction between the Rust and TS frontends on the same fixture.
4. Per-grammar value-API dedup (structural skeleton, per Q-final B2 = (a)). Land `crates/core/src/runtime/arena_template.rs` and `crates/core/src/runtime/builder_template.rs` parameterised by `StructRegistry` + `TypeDesc`. The 9 per-grammar arena/builder pairs become per-grammar instantiations of these templates; the typed `*Value` enums (`JsonValue`, `CssTypedValue`, `SheetsValue`, etc.) survive untouched (semantic richness preserved per `feedback_preserve-rich-ast`).
5. Permanent substrate-audit test (per Q-final C1 = (b) + AUDIT-E §8 D6 split). Land `crates/ir/src/passes/tests/substrate_audit.rs` that **consumes the W4 substrate-census tool** (W4.10 lands `xtask substrate-census` machine-readable output; W5 lands the test consuming it). The test fails the build if any substrate has zero callers in production code (excluding `tests/`, `examples/`, `#[cfg(test)]` blocks). The test + CI-gating closes the substrate-with-consumer rule machine-checkably; the split (tool in W4 / test in W5) eliminates the manual-census drift pattern at the source.
5b. **AUDIT-F transposition T4**: codegen emits `pub const REGISTRY: StructRegistry` per generated grammar module. The `bbnf-path` proc-macro switches its consumption from the synthetic fixture at `crates/bbnf-path/src/registry.rs` to the production const, closing mid-tranche §R1. The macro's public surface remains stable; the swap is internal.
5c. **AUDIT-F transposition T6**: emit grammar-generated output as module-split files (`crates/core/src/grammar/generated/<grammar>/{mod,parsers,types,scanners}.rs`) rather than monolithic dumps. Aligns with `feedback_generated_size_budget`; eliminates the 17–91 KLOC per-grammar monolith pattern.
5d. **AUDIT-B routed splits**: `crates/core/src/runtime/css_l4/builder.rs` (1014 LOC) + `crates/ir/src/passes/types/mod.rs` (786 LOC) + `crates/core/src/runtime/css_l4/value.rs` (852 LOC review) split per the AUDIT-B god-module census.
6. PROFILING.md compliance. Every TS-binding bench claim cites a samply artefact under `docs/benchmarks/profiles/post-AZ-IV/W5/`. The wasm-bindgen crossing has its own profile attribution.
7. AZ-IV.md §Hard Gates 13 + 20 + 21 close here:
    - **13**: substrate-audit test CI-gated.
    - **20**: TS binding executable.
    - **21**: per-grammar value-enum dedup (skeleton).

## Triumvirate Dispatch

Dispatch a triumvirate if any of these occurs:

- the TS binding requires reimplementing the Path IR or the type-checker (i.e., violates Q4 = single-shared-IR);
- the wasm-bindgen crossing forces an FFI shape divergent from the Rust frontend's API (per `feedback_isomorphic-api`);
- per-grammar value-enum dedup requires touching the typed `*Value` enums (forbidden by Q-final B2 — typed enums survive untouched);
- the substrate-audit test reveals a substrate that cannot route to a consumer or a deletion (i.e., load-bearing-but-unconsumed substrate); this is a genuine W5 scope reveal that may require a triumvirate research lane to find the consumer or commit to deletion;
- TS Node execution test fails for a reason rooted in the W1 backend-ts build-time correctness (i.e., W1 close was incomplete);
- a profiling sub-agent reports any of the seven required artefacts missing per `PROFILING.md`, or violates the prepare-once contract.

Empty/no-evidence returns get one verbatim redispatch with the same worktree pointer. A second empty/no-evidence return triggers mandatory triumvirate. Three diagnostic-loop iterations without isolating root cause auto-trigger triumvirate. JSONL transcript quiet >15 minutes is an orchestrator-side auto-trigger.

### AZ-IV.W5.4 Permanent Substrate-Audit Test

- Mechanism: create `crates/ir/src/passes/tests/substrate_audit.rs`. The test enumerates every `pub fn`, `pub struct`, `pub enum`, `pub trait`, and `pub static` in `bbnf-ir`, `bbnf-core` (excluding `generated/`), `bbnf-egraph`, `bbnf-csp-solver`, `bbnf-simd-scan`. For each item, it walks the workspace AST (via `syn` parsing of `cargo metadata` output) and counts callers in production code (excluding `tests/`, `examples/`, `#[cfg(test)]` blocks). A substrate with zero production callers fails the test with a `panic!` naming the substrate and the file:line. The test runs as part of `cargo nextest run --workspace --cargo-profile ax-iter` and CI-gates on every PR.
- Files: `crates/ir/src/passes/tests/substrate_audit.rs`, `crates/ir/src/passes/tests/mod.rs`.
- Sub-gate: test exists, runs in < 60s, fails when fed a synthetic-fixture pub fn with no callers, passes against the AZ-IV-W5 close HEAD; CI workflow at `.github/workflows/ci.yml` runs the test.
