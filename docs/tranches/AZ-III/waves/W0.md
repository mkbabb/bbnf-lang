# AZ-III.W0 - Quarantine and Dispatch Repair

**Name**: W0 - Quarantine and Dispatch Repair
**Opens after**: AZ-II continuation handoff.
**Agents**: up to 10 parallel.
**Hard gate**: main worktree state, staged state, commit discipline, precepts alignment, and AZ-II handoff docs are reconciled before source implementation dispatch.
**Status**: planned

## Scope

1. Record current dirty/staged state and isolate unrelated work.
2. Restore a clean implementation-dispatch base or document exact blockers.
3. Apply commit discipline: concrete scopes, no subject cap, body-bearing
   large/gate-changing commits, and preserved staged work.
4. Ensure precepts submodule pointer and instruction migration are coherent.
5. Prepare W0p - Throughput Substrate, W1 - O5 Reclose, W2 - Semantic
   Parity and Bootstrap Canonicalization, W3a - Fact and Type Authority,
   W3b - CSP Strategy Globalization, and W3c - Projection Consumption
   and Registry Authority dispatch packets with sibling worktree bounds.
6. Audit recent bodyless commits and decide whether history rewrite,
   follow-up provenance commits, or archival commit notes are the chosen
   repair path.

## Triumvirate Dispatch

Any unclear state split, history-rewrite risk, precepts mismatch, or
dispatch-packet scope reveal pauses implementation and dispatches three
bounded agents: research, plan augment/synthesis, and redress/redeployment.
The orchestrator may resume implementation only after their outputs are
synthesized into this wave spec or a same-tranche replacement wave.
