# P3 — JSON tape

**Unit:** sk-v27 LW2.CON-1 (spec only). **Goal:** G-J2, stretch (Wave F, U18). **Family:** none in LW2; F-JSON-P3 is added by addendum when U18 opens.

## What an arm does

It builds a flat tape of the input (simdjson's tape: one entry per scalar and per container open and close, containers carrying the index of their matching entry, strings in a side buffer) and walks a checksum of the tape. The output-parity class is **TAPE**: the verdict and, after ACCEPT, the digest of the tape's canonical form, which is the P4 canonical form of the value the tape denotes. Two tapes with different layouts but the same value are equal: P3 compares what the tape says, never its byte layout.

## Policies

Validation, escapes and number fidelity are P4's, rule for rule: a tape that stores raw string lexemes, or numbers as unparsed text, is not a P3 arm. Duplicate keys are kept on the tape in input order; the canonical form resolves them as P4 (last wins). Error offsets are not compared on P3.

## Witness inputs

`bench/planes/witness/json/`.

## Equal work

- The tape is complete before the checksum walk starts; a lazy (On-Demand) arm is P5.
- The arm's string buffer holds unescaped bytes.
- In-situ arms copy their buffer outside the timed region.

## Comparators
