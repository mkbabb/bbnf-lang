## Root Cause — IR Loss in `lower_mapped_factor`

The post-W0.3 lowering quartet's structural detector silently drops
the `IrNode::Map { fn_id }` wrapper for every `MappedFactor` whose
value-expression compound projects to a typed leaf with no recoverable
source-text span.

Diagnostic IR dump for `x = "hello" -> 0u8`:

```
[DIAG mapped_factor] enter span="\"hello\"" num_children=2 kind=Some(MappedFactor)
[DIAG mapped_factor]   peeled span="\"hello\"" num_children=2 kind=Some(MappedFactor)
[DIAG mapped_factor]     child[0] span="\"hello\"" kind=Compound compound_kind=Some(Factor)
[DIAG mapped_factor]     child[1] span="" kind=Compound compound_kind=Some(ValueOr) num_children=1
[DIAG mapped_factor]       grandchild[1.0] span="" kind=Compound compound_kind=Some(ValueAnd)
```

The `ValueOr` compound's `byte_span()` returns `None` because the
typed-leaf projection (`int_lit -> i64`) drops the source bytes; the
wrapping `value_or` / `value_and` / `value_atom` chain has empty
`span_text()`. The mapped_factor child loop's blanket empty-span skip
then drops the value-expression child entirely, `value_expr_head`
stays `None`, and `find_unquoted(node.span_text(), "->")` fails the
typed-materialization-invariant panic guard because `node.span_text()`
is `"hello"` (no arrow) — the value_expr's bytes were never aggregated
into the parent.

Per `feedback_typed-materialization-invariant`, "every `->` in the
grammar must reach the tape emitter; inference composes types, never
loses them". The current lowering silently violates this for every
typed-Nu8 / IntLit / FloatLit / StringLit-projecting branch.

The same defect class also affects the bbnf bootstrap's int_lit
parser: `parse_hregex_BbnfBootstrap_int_lit` calls `s.parse::<i64>()`
on the raw match including the type suffix (`"0u8"`); `parse::<i64>`
fails, the `unwrap_or(0)` fallback silently emits `Int(0)` regardless
of the source text. Both `0u8` and `1u8` parse as `Int(0)`. This is a
secondary loss invariant: the codegen for `-> i64` typed regex
projections must strip the trailing type suffix before parsing.

## Applied Fixes (this worktree)

### 1. Lowering — `lower_mapped_factor` admits empty-span value-expr compound

`crates/core/src/lower/expression/wrap.rs`: extended the child-walk to
recognise compound kinds `ValueExpr | ValueClosure | ValueOr | …
ValueFnCall` as the value-expression head even when their span is
empty. Empty-span Span leaves still skip; empty-span value-expression
compounds claim `value_expr_head`.

### 2. Lowering — `lower_value_atom` handles `ValueInput` child

`crates/core/src/lower/value_expr/atom.rs`: when the atom's compound
focus has a child whose `compound_kind` is `ValueInput | ValuePath |
ValueFnCall | ValueClosure`, dispatch through `dispatch_value_expr`
on the child rather than panicking on the empty span. Mirrors the
existing typed-leaf-descend fold, extended to structural sub-grammars.

### 3. Lowering — `lower_input_chain` empty-span guard

`crates/core/src/lower/value_expr/atom.rs`: when `trimmed` lacks the
`input` keyword (typed projection consumed it), return `MapExpr::Input`
without indexing past the trim length. Prevents a `&trimmed[5..]`
out-of-bounds panic on Sheets's `string = /…/ -> input : Span`.

### 4. Codegen — `body_emits_to_builder` recognises constant-fold Map payload

`crates/core/src/backend/rust/emitter/shapes/flat/struct_direct.rs`:
when a `Map { fn_id }` wraps a constant payload (`IntLit` / `BoolLit`
/ `FloatLit` / `StringLit`), the predicate now returns `true`. This
prevents the content-only flat-shape body from synthesising a
duplicate Span leaf alongside the typed `push_branch_tag(N)` —
without this, every `error_literal -> Nu8` emission landed both a
Tag and the consumed source bytes, producing `=#NAME?#NAME?` round-trip
duplication.

### 5. Codegen — hregex i64 / u32 type-suffix stripping

`crates/core/src/backend/rust/emitter/shapes/hregex.rs`: the generated
`parse::<i64>()` / `parse::<u32>()` calls now strip the trailing
type-suffix (`u8`, `u32`, `i64`, …) before parsing. Matches the
`split_numeric_suffix` semantics already applied at the lowering
layer (`crates/core/src/lower/value_expr/literals.rs`). Without this,
every BBNF `int_lit` parsed with a suffix returned 0.

### 6. Grammar — `sheet_prefix` collapses to single-Span regex

`grammar/google-sheets/google-sheets.bbnf`: changed sheet_prefix from
two typed-Nu8 alt-of-regex branches (which lost the matched bytes
post-fix) to a single `-> input : Span` regex matching either form.
The quoted-vs-bare distinction is recoverable from the leading byte
(`'` for quoted) so the Tag was structurally redundant. This restores
round-trip parity for `=Sheet1!A1:B2` and `='Sheet 1'!A1:B2`.

## Triumvirate Routing

This halt routes to **W1.1 owner (runtime overfit)** and **W1.5 owner
(shape generality)**:

1. The lowering correction (fixes #1, #2, #3) is the canonical
   typed-materialization-invariant restoration. JSON / CSS / BBNF
   runtimes that previously exploited the buggy IR (Map drop) need
   their builder dispatch updated to handle the corrected `Map { fn_id:
   IntLit(0) }` projection. JSON `null` should still land as
   `JsonValue::Null`; CSS `combinator -> Nu8` branches should still
   land as their named arms; the runtime — not the IR — needs to
   absorb the discriminator-vs-unit distinction.

2. The hregex int-suffix-stripping (fix #5) is correct independently
   of the lowering; W1.5 owns the hregex emitter.

3. The constant-fold Map predicate (fix #4) is sheets-correct and
   stays in this worktree.

4. The sheet_prefix grammar collapse (fix #6) is sheets-internal and
   stays in this worktree.
