# BA.W3 — Beyond-Parity Scale-Out + Optional Specialization

**Opens after**: W2 close
**Agents**: 3 parallel
**Hard gate**: At least one scale-out or optional-specialization lever yields a beyond-parity win while preserving the one-substrate model and a clear activation contract.

## Scope

1. Add one or more optional specialization levers that preserve the AY
   substrate contract.
2. Add one or more scale-out levers such as document-parallel parsing
   or optional JIT/specialization where the cost model admits them.
3. Prove these levers on designated large-input benchmarks.

## File bounds

| File | Access |
|---|---|
| `crates/core/src/runtime/parse_options.rs` | modify |
| `crates/core/src/runtime/parallel.rs` | modify |
| `crates/jit/src/lib.rs` | modify |
| `crates/core/tests/parallel_parity.rs` | modify |

**Do NOT touch**: replay/recovery/debug tooling, any alternate runtime
substrate, build/profile scripts beyond activation plumbing.

## Phase sub-items

### BA.W3.1 Activation contract

Mechanism: define explicit activation surfaces for optional
specialization or scale-out so the default path stays intelligible.

Files touched: `crates/core/src/runtime/parse_options.rs`.

Sub-gate: activation semantics compile and are documented in code.

### BA.W3.2 Scale-out or specialization implementation

Mechanism: implement the chosen beyond-parity lever while preserving
the AY substrate and canonical runtime contract.

Files touched: `crates/core/src/runtime/parallel.rs`,
`crates/jit/src/lib.rs`.

Sub-gate: the chosen lever is runnable on designated large inputs.

### BA.W3.3 Correctness and benefit proof

Mechanism: prove parity and measure beyond-parity benefit on the
designated benchmark set.

Files touched: `crates/core/tests/parallel_parity.rs`.

Sub-gate: correctness tests pass and the designated benchmark set
improves.

## Hard gate

1. The chosen scale-out or specialization lever improves the designated
   benchmark set versus post-W2. Artefact:
   `docs/benchmarks/post-BA-W3-mid.json`.
2. Correctness tests continue to pass on the activated path. Artefact:
   `docs/benchmarks/post-BA-W3-tests.txt`.
3. The activation contract is explicit in code and `cargo expand` or
   rustdoc output. Artefact: `docs/benchmarks/post-BA-W3-activation.txt`.
