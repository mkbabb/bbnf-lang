## Profile-design audit

The frozen design correctly identifies `ay-final`, native ARM, separate
targets, alternating process order, 20 matched pairs, 100 Divan samples per
invocation, six BBNF rows, three Sheets parse rows, three CSS rows, and two
unavoidable Sheets format rows. An inverse patch against one exact atomic
candidate is the right comparison shape. No such candidate currently exists,
so `PROFILE-CONTROL.patch` was correctly not formed.

The design is not yet feature-complete:

   `array_row` and `array_rows` are reachable through `{ ... }`. All three

   Existing semantic tests use `={1,2,3}` and `={1,2;3,4}`, which confirms a
   small array-bearing operand already exists conceptually, but it is absent
   from every profile row. The claimed Sheets 7/7 profile closure is false.

2. **The other per-hook exposures are assumed, not counted.** Bootstrap and
   Tailwind contain 134 and 2,928 `calc`/`clamp`/`min`/`max` call spellings,

   plausible positive and negative exposures. The protocol still records no
   per-function reachability counter. The BBNF six grammar rows likewise do

3. **The timeout is post hoc, not a watchdog.** `bench_with_timeout` checks
   elapsed time only after `body` returns, and its own source states that a
   truly infinite body is not interruptible. Divan's `max_time(30s)` is not an
   external kill boundary for a hung iteration. Each harness invocation needs
   a retained external process timeout if “timeout is RED” is to be an
   enforceable gate.

4. The row-wise zero-tolerance interval rule is a legitimate conservative
   policy, but with 20 pairs it is designed to produce RED on ordinary
   uncertainty. That is a high false-RED/inconclusive cost, not evidence of a
   regression. The receipt must preserve all row classifications and must not
   reinterpret inconclusive as a semantic defect.
