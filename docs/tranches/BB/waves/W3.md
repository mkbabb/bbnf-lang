# BB.W3 — Generated-Code + Monomorphization Control

**Opens after**: W2 close
**Agents**: 3 parallel
**Hard gate**: Generated-code and monomorphization hotspots are reduced with measurable cold/warm compile-time and RSS improvements.
**Status**: planned

## Scope

1. Partition or carve generated-code hotspots that dominate compile
   cost.
2. Reduce pathological monomorphization clusters where bounded
   polymorphism is sufficient.
3. Prove compile-time and RSS improvements against baseline.

## File bounds

| File | Access |
|---|---|
| `crates/derive/src/lib.rs` | modify |
| `crates/core/src/grammar/generated.rs` | modify-carve |
| `Cargo.toml` | modify |
| `docs/instructions/PROFILING.md` | modify |

**Do NOT touch**: parser semantics, replay/recovery/debug tooling, any
`.bbnf` grammar source text.

## Phase sub-items

### BB.W3.1 Generated-code partitioning

Mechanism: partition or restructure generated output where it dominates
compile and memory cost without changing parser semantics.

Files touched: `crates/derive/src/lib.rs`,
`crates/core/src/grammar/generated.rs`.

Sub-gate: generated output compiles and its largest hot spots shrink.

### BB.W3.2 Monomorphization reduction

Mechanism: reduce pathological generic expansion where bounded
polymorphism or alternate structure suffices.

Files touched: `Cargo.toml`,
`crates/derive/src/lib.rs`.

Sub-gate: compile timings show the targeted monomorphization hot spots
reduced.

### BB.W3.3 Cost proof

Mechanism: capture cold/warm compile-time and RSS deltas after the
partitioning and reduction work.

Files touched: `docs/instructions/PROFILING.md`.

Sub-gate: the targeted cold/warm/RSS metrics improve.

## Hard gate

1. Cold and warm compile-time improve versus post-W2. Artefact:
   `docs/benchmarks/post-BB-W3-mid.json`.
2. Compile RSS improves versus post-W2. Artefact:
   `docs/benchmarks/post-BB-W3-mid.json`.
3. The largest generated or monomorphized hotspots shrink. Artefact:
   `docs/benchmarks/post-BB-W3-hotspots.txt`.
