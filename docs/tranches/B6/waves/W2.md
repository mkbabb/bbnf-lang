# B6.W2 — JSON Test Partitioning + IR Audit Feature-Gate

**Opens after**: W1 close
**Agents**: 2 parallel
**Hard gate**: warm `iter-test` ≥ 20 % faster; close ceremony exercises IR audits via `--features ir-audit`.
**Status**: closed (2026-04-27) — rationale-satisfied per SPEC §Plan-time miscalibration; see `../PROGRESS.md` §"2026-04-27 — B6.W2 dispatched + closed".

## Scope

W2 narrows the test wall to the close-ceremony scope it belongs
in. The post-B5 warm `iter-test` wall measures ~20 s — dominated
by two surfaces W2 partitions:

1. **JSON monolithic bench macro-expanded surface.** `crates/
   core/benches/json/monolithic.rs` carries five fixtures
   (`twitter`, `canada`, `citm`, `data_s`, `data_xl`) inside a
   single file via the `bench!` macro. The compile cost
   amortises across all five at routine time even when only one
   is selected. W2.a partitions into per-fixture modules; the
   compile cost localises per fixture, and the partitioned
   surface routes through a new `iter-test-json-partitioned`
   alias.
2. **IR audit tests at the routine surface.** `crates/core/
   tests/payload_layouts.rs` (314 LOC) and `crates/core/tests/
   projection_totality.rs` (417 LOC) are AY-II close-ceremony
   wire-contracts — they validate the IR pipeline's projection
   totality and payload layout activation. They sit at the
   routine surface today, but only fire at close ceremony per
   their docstrings ("This test is the wire-contract gate").
   W2.b feature-gates them behind `ir-audit`; the close
   ceremony's `make ay-bench-close WAVE=close` Makefile target
   adds `--features ir-audit`.

The two W2 agents share no file write access — W2.a owns the
JSON bench split plus the alias edit; W2.b owns the test cfg
gates plus the `crates/core/Cargo.toml` feature flag plus the
Makefile close-ceremony target. Both run in parallel.

### W2.a JSON bench partition

The current `crates/core/benches/json/monolithic.rs` (68 LOC)
carries the five fixtures inside one file:

```rust
bench!(data_s, "data.json");
bench!(twitter, "twitter.json");
bench!(citm, "citm_catalog.json");
bench!(canada, "canada.json");
bench!(data_xl, "data_xl.json");
```

Per `feedback_directory_module_structure`, W2 partitions into
a directory module:

```
crates/core/benches/json/monolithic.rs    →    mod.rs aggregator
crates/core/benches/json/monolithic/
  twitter.rs   — bench!(twitter, "twitter.json");
  canada.rs    — bench!(canada, "canada.json");
  citm.rs      — bench!(citm, "citm_catalog.json");
  data.rs      — bench!(data_s, "data.json");
  data_xl.rs   — bench!(data_xl, "data_xl.json");
```

The macro definition, the `mimalloc` global allocator, the
shared `load` function, the `timeout` and `validate` modules,
and the `divan::Divan::default()` `main` stay in the
aggregating `mod.rs`; per-fixture files carry only the
`bench!` invocation. The `[[bench]]` registration in
`crates/core/Cargo.toml` continues to point at `monolithic.rs`
as the single bench target — the partition is internal to
the file, not at the bench-surface level.

`iter-test-json-partitioned` alias addition to `.cargo/config.
toml`:

```toml
# Per-fixture JSON bench compile path. Routes the partitioned
# bench surface through nextest with substring match on
# fixture name. Used by warm iter-test; routine warm-wall
# floor ≤ 16 s.
iter-test-json-partitioned = "nextest run --cargo-profile ax-iter -p bbnf --test json"
```

The alias is read-only on the JSON bench partition; it is
purely an iteration-loop convenience for the warm-wall gate.

### W2.b IR audit feature-gate + close ceremony

`crates/core/tests/payload_layouts.rs` and `crates/core/tests/
projection_totality.rs` get a file-level cfg gate:

```rust
//! AY-II.W0'.b — projection totality wire-contract + runtime-call-count
//! evidence.

#![cfg(feature = "ir-audit")]

// ... existing test body unchanged ...
```

`crates/core/Cargo.toml` `[features]` section gains:

```toml
[features]
default = []
# IR audit tests — projection totality + payload layouts wire-
# contracts. Gated so routine iter-test does not compile the
# audits; close ceremony enables via --features ir-audit
# (Makefile ay-bench-close WAVE=close).
ir-audit = []
```

`Makefile` close-ceremony target — the existing `ay-bench-close
WAVE=close` target gains the `--features ir-audit` flag so
nextest at close ceremony compiles and runs the gated tests:

```makefile
ay-bench-close:
ifeq ($(WAVE),close)
	cargo bench --profile ay-final --features ir-audit ...
	cargo nextest run --cargo-profile ay-final --features ir-audit --workspace
else
	cargo bench --profile profiling-prep ...
endif
```

The exact Makefile shape preserves all existing logic; the W2
addition is the `--features ir-audit` flag on the close branch
only.

## Phase

Two parallel sub-phases, one per agent:

### B6.W2.a JSON bench partition

**Mechanism**: extract the five `bench!` invocations from
`monolithic.rs` into per-fixture files; preserve the macro
definition, allocator, load fn, timeout / validate imports, and
divan main inside the aggregating module; add `iter-test-json-
partitioned` alias.

**Files touched**: `crates/core/benches/json/monolithic.rs`
(modify-carve into mod.rs aggregator);
`crates/core/benches/json/monolithic/{twitter,canada,citm,data,
data_xl}.rs` (create);
`.cargo/config.toml` (add one alias line).

**Sub-gate**: `cargo bench-json` per-fixture median within 1 %
of pre-W2 (the partition is structural only); warm `iter-test`
≥ 20 % faster; nextest non-regressing.

### B6.W2.b IR audit feature-gate + close ceremony

**Mechanism**: add `ir-audit` feature flag to
`crates/core/Cargo.toml`; add file-level `#![cfg(feature =
"ir-audit")]` to the two test files; modify `Makefile`'s
`ay-bench-close` target to add `--features ir-audit` on the
`WAVE=close` branch.

**Files touched**: `crates/core/Cargo.toml`,
`crates/core/tests/payload_layouts.rs`,
`crates/core/tests/projection_totality.rs`,
`Makefile`.

**Sub-gate**: `cargo iter-test` (no `--features ir-audit`)
runs without compiling the audits; `cargo iter-test --features
ir-audit` compiles and runs the audits with exit 0; `make ay-
bench-close WAVE=close` exit 0 with the audit tests visible
in the nextest output.

## Archaeology

The JSON monolithic bench partitions trace back to AU.6.6 (the
rename of `data` to `data_s` so `--bench data` no longer matches
`data_xl` as a prefix — divan's substring filter). The structural
partition W2 lands continues that lineage: per-fixture
addressability moves from rename-time to file-time; warm compile
cost localises per fixture.

The IR audit tests trace to AY-II.W0'.b (`projection_totality.
rs`) and AR.2.1 (`payload_layouts.rs`). Both were authored as
close-ceremony wire-contracts; the routine-surface placement
was the convention at the time (`crates/core/tests/` is the
catch-all directory). The W2 feature-gate is the architectural
correction: routine iteration runs the routine tests; close
ceremony runs everything including wire-contracts. The pattern
matches `feedback_pluggable_components` — the feature flag is
the pluggable channel; close-ceremony enables, routine
disables.

The Makefile `ay-bench-close` target traces to B0.W2 (commit
`1532de45`) with the AY W5-W7 gate-command publication. The W2
addition is mechanical: `--features ir-audit` on the
`WAVE=close` branch only; routine and prep branches stay
unchanged. No other Makefile target needs modification.
