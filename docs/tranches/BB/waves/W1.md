# BB.W1 — Direct-To-Struct Generalisation

**Thesis** Hereupon BA.W5's JSON direct-to-struct demonstration generalises to the eight remaining grammars; the `OpenFrame` substrate retires across the fleet, leaving direct-projection emit as the singular substrate per Lock 1. **Closer-gate** `rg -n 'enum OpenFrame' crates/core/src/runtime/` returns zero; per-grammar LOC budget per BB-G11 met; `cargo nextest run -p bbnf` 100% pass; `tests/css_l4_parity.rs` against lightningcss canonical-form passes for every retired variant.

## §1 Deliverable

W1 extends BA.W5's emitter scaffolding (carry BA→BB.C1 per `docs/tranches/BA/BA.md:59`) to CSS L4, BBNF, and Sheets — the three remaining specialised grammars beyond JSON. The 5-grammar template cohort routes to BB.W2; here W1 confines to specialised grammars whose `OpenFrame` builders carry per-grammar payload semantics.

CSS L4 is the dominant migration: `crates/core/src/runtime/css_l4/builder.rs` at 1,014 LOC carries 14 `OpenFrame` variants (`audit/CENSUS-2026-05-03.md:464`, `audit/MODULES-2026-05-03.md:951`); each variant retires via per-variant migration so `tests/css_l4_parity.rs` against lightningcss's canonical-form emit can verify byte-equality at each step. The post-W1 file emits typed-enum + per-rule generated parse fns only; no `OpenFrame` instantiation survives. The 14-variant breakdown — declaration, color, color_function, color_mix, selector_list, hex_color, length, dimension, function, calc, at_rule, ratio, time, custom_ident — each becomes a per-rule `parse_<rule>(input, &mut p, &mut arena, &mut state, &mut cursor) -> Result<CssTypedValue<'p>, ParseErr>` function emitted by the layout-lowering pass (BA→BB.C2 carry per `docs/tranches/BA/BA.md:60`).

The bounds-recording behaviour survives the migration as a per-rule emission concern; the `OpenFrame` substrate retires. BBNF's `arena.rs` (341 LOC) and `view.rs` (280 LOC) are KEEP-AS-IS surfaces; W1 touches only the builder + the per-rule parse fn emission.

Sheets is the third migration: `crates/core/src/runtime/google_sheets/builder.rs` at 357 LOC (`audit/MODULES-2026-05-03.md:963`) carries specialised leaf-deposit logic for `cell_ref`, `identifier`, `sheet_prefix`, and `error`. The deposit logic survives; the `OpenFrame` substrate retires. Sheets's typed-value enum at `runtime/google_sheets/value.rs:189` continues to drive the typed-projection.

JSON is already migrated at BA.W5 close (carry BA→BB.C1); W1 verifies the JSON parity gate continues to pass after the workspace-wide path-dep relocation from BB.W0 (i.e., bbnf-regex relocation does not re-introduce JSON regression).

The five-grammar cohort (BNF, CSV, EBNF, CSS Pretty, Math) is OUT OF SCOPE; their migration is BB.W2's deliverable.

The OpenFrame retiral mechanism for each specialised grammar follows the same shape as BA.W5's JSON migration. Per `audit/RESTART-SKETCH-2026-05-03.md:540-595`, the post-migration emit pattern emits per-rule parse fns directly returning typed values; the speculative-branch checkpoint becomes a single `arena.checkpoint()` u32 offset rather than a `Vec<OpenFrame>::clone`. BBNF's bounds-recording extension per `audit/CENSUS-2026-05-03.md:441` deserves explicit handling. The pre-W1 BbnfStructBuilder records compound bounds (start/end byte positions for each rule's parsed range) — a feature the BBNF self-host LSP at `crates/analysis/` consumes for source-position diagnostics. The W1 migration preserves bounds-recording as a per-rule emission concern: the layout-lowering pass (BA→BB.C2 carry) emits a `record_bounds: bool` parameter on each per-rule parse fn; the BbnfStructBuilder consumer reads bounds from the parse-fn return value. The bounds-recording feature does not retire; only the OpenFrame substrate retires.

Sheets's specialised leaf-deposit logic per `audit/MODULES-2026-05-03.md:963` covers four cases — `cell_ref`, `identifier`, `sheet_prefix`, `error`. Each case carries grammar-specific normalisation logic (e.g., cell_ref normalisation collapses `A1` and `$A$1` to a canonical form). The W1 migration moves normalisation to per-leaf host fns at `crates/core/src/host/sheets.rs`; the per-rule parse fn calls the host fn directly; the SheetsStructBuilder consumer reads the normalised value from the parse-fn return.

## §10 Implementation reference

Per `audit/RESTART-SKETCH-2026-05-03.md:485-577` the post-W1 emit pattern follows the JSON direct-to-struct shape demonstrated at BA.W5. The CSS L4 declaration variant migration produces emit shape:

```rust
// post-W1: per-rule parse fn for declaration; no OpenFrame
fn parse_declaration<'i, 'p>(
    bytes: &[u8],
    p: &mut usize,
    state: &mut ScanState,
    arena: &mut CssArena<'p>,
    cursor: &mut PathCursor<'_, '_>,
) -> Result<CssTypedValue<'p>, ParseErr>
where 'i: 'p,
{
    // 1. parse property name (slice-borrow)
    let name = parse_property_name(bytes, p, state)?;
    skip_space(bytes, p, state);
    
    // 2. expect ':'
    if bytes.get(*p).copied() != Some(b':') {
        return Err(ParseErr::expected(b':', *p));
    }
    *p += 1;
    skip_space(bytes, p, state);
    
    // 3. parse value (recursive)
    let value = parse_property_value(bytes, p, state, arena, cursor)?;
    
    // 4. return typed enum directly (no OpenFrame ladder)
    Ok(CssTypedValue::Declaration { name, value: arena.alloc(value) })
}
```

Compare to the pre-W1 emit shape at `audit/RESTART-SKETCH-2026-05-03.md:101-108` (the 86.07% pathology):

```rust
// pre-W1: OpenFrame ladder with Vec<OpenFrame>::clone hot path
attempt_p = *p;
attempt_builder = builder.checkpoint();  // Vec<OpenFrame>::clone — 86.07% inclusive
match parse_declaration_old(input, &mut p, &mut state, &mut builder, &mut cursor) {
    Ok(()) => { /* commit */ }
    Err(_) => { *p = attempt_p; builder.rollback(attempt_builder); }
}
```

The post-W1 emit's checkpoint becomes a single `arena.checkpoint() -> u32` offset; rollback is a `arena.restore(offset)` that resets the bump arena's high-water mark; the `Vec<OpenFrame>::clone` is structurally retired.
