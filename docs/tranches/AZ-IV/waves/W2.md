# AZ-IV.W2 - Optimization Substrate Activation

**Name**: W2 - Optimization Substrate Activation
**Opens after**: W1 - Runtime Surface And Semantic Parity
**Agents**: 5 parallel
**Hard gate**: every existing optimization substrate changes emitted/runtime behavior or is deleted
**Status**: planned

## Scope

1. Wire every non-empty loaded `RuleSet`/ruler output into production egraph saturation and generated-code effects.
2. Make CSP engine/layout/dispatch decisions authoritative at consumers or delete the unused decision surface.
3. Make regex HIR/egraph/CSP decisions select concrete emitted scanner paths.
4. Consume or retire generic shape dictionary and structural scan claims.
5. Reconcile DTA/dfa_codegen with its real role as regex/operator/precedence facts; delete dead helpers.
6. Prove Pratt/view consumers are grammar-general or route hardcoded projections to explicit typed grammar surfaces.
7. Resolve Tailwind timeout-class behavior without per-call map overhead.
8. Preserve BB's Ruler program: CVC enumeration, egraph residue, VM oracle, ranker/tiering, schema/provenance, grammar rewrite dirs, review ledger, and CI status.
9. Produce a full substrate denominator ledger: every mined fact, sidecar, rule, template, shape, scan, Pratt, view, regex, CSP, and egraph decision has generated/runtime evidence or deletion proof.

## Triumvirate Dispatch

Dispatch a triumvirate if any of these occurs:

- a rewrite rule can be admitted only through a test-only path or without VM-residue/ranker evidence;
- CSP authority cannot be made consumer-authoritative without creating a second decision system;
- regex scanner activation needs a parallel hand-written parser;
- shape_dict or structural scan needs a new runtime substrate not already present;
- DTA cleanup reveals a current walker/tape dependency.
- denominator enumeration reveals more active substrates than W2 file bounds can own.

## Agent Units

### AZ-IV.W2.1 Rewrite Ruler Chain

- Mechanism: connect `RuleSet` load, Ruler CVC enumeration, egraph residue split, VM oracle, ranker/tiering, extraction, writeback, and generated Rust.
- Files: `crates/ir/src/rewrites/**`, `crates/egraph/src/ruler/**`, `crates/ir/src/egraph/**`, `crates/core/src/pipeline/compile.rs`, `xtask/src/regen.rs`, `grammar/**/rewrites/**`, `docs/rules/**`.
- Sub-gate: every non-empty loaded ruleset reports search/apply count, residue/oracle count, rank/tier, IR/writeback delta, generated hot-path diff, and parity/bench result. BB floors are preserved: Tranche H rediscovery >=80%, retained-rule hit-rate >=0.1, JSON and Sheets each accept >=5 sound rules, CSS L4 runs wide-alphabet enumeration with target N=50 and accepts >=5 sound rules, BBNF runs wide-alphabet enumeration with target N=40 and accepts >=5 sound rules, rejection rate is <=50% after ranker calibration, >=90% of accepted rules are Class 1/2, generated code shrinks or explains no-shrink with a hot-path throughput gain, and synthetic extensibility proves a new grammar rewrite dir can contribute rules with zero core/emitter edits.

### AZ-IV.W2.2 CSP Regex Authority

- Mechanism: remove sidecar override authority where CSP selected an engine/layout/dispatch and force regex decisions into concrete emitted scanner plans.
- Files: `crates/ir/src/passes/csp_strategy/**`, `crates/core/src/backend/strategy/**`, `crates/core/src/backend/driver/**`, `crates/core/src/generate/regex/**`.
- Sub-gate: tests fail if selected `RegexEngine` is only diagnostic; generated-code evidence exists per selected engine variant; sidecars are payload-only after CSP selection; Tailwind no longer times out.

### AZ-IV.W2.3 Shape SIMD Consumption

- Mechanism: consume generic shape dictionaries and structural scan decisions at runtime or delete unconsumed claims.
- Files: `crates/ir/src/passes/csp_strategy/**`, `crates/core/src/backend/rust/emitter/shapes/**`, `crates/simd-scan/**`.
- Sub-gate: generated parser evidence shows every selected shape/SIMD/structural-scan fact affects runtime behavior, including quote-surface cases, or the fact is suppressed/deleted.

### AZ-IV.W2.4 DTA DFA Cleanup

- Mechanism: delete `emit_dfa_inline_body`, rename/split DTA fact surfaces, and remove walker/tape comments.
- Files: `crates/core/src/backend/rust/emitter/dfa_codegen.rs`, `crates/ir/src/passes/recognizers/dta.rs`, Rust emitter docs/tests.
- Sub-gate: symbol-level search shows no public dead helper and no active source/generated `DTA_TABLE`, walker, tape, or DTA runtime wording outside explicitly archived docs.

### AZ-IV.W2.5 Pratt View Generality

- Mechanism: route Pratt/view projection through grammar facts or explicitly typed grammar surfaces rather than hardcoded operator maps.
- Files: Pratt emitter, view build/format modules, runtime document views.
- Sub-gate: BBNF, Sheets, and CSS projection tests prove Pratt/view behavior from generated operator facts or named typed grammar surfaces; `PatternAnnotations` migration/deletion status is explicit.

## Hard Gate

1. Every non-empty loaded rewrite/ruler ruleset proves the full production chain.
2. Ruler enumeration, egraph residue, VM oracle, ranker/tiering, schema/provenance, grammar rewrite dirs, and review/CI status are production-wired or retired with evidence.
3. BB numeric floors hold or block close: Tranche H rediscovery >=80%, retained-rule hit-rate >=0.1, JSON/Sheets/CSS/BBNF sound-rule quotas above, rejection <=50%, accepted Class 1/2 >=90%, generated shrink or profile-backed throughput gain, and synthetic grammar extensibility with no core/emitter edit.
4. CSP decisions are consumer-authoritative or removed; sidecars do not select strategy after CSP.
5. Regex engine decisions emit the chosen scanner class and resolve Tailwind timeout-class behavior.
6. shape_dict/SIMD/structural-scan decisions have runtime evidence for every active selected fact or are retired.
7. DTA/dfa stale runtime claims are deleted; dead inline code is gone.
8. Pratt/view consumers are proven grammar-general or explicitly typed.
9. `docs/tranches/AZ-IV/audit/W2-substrate-denominator.md` covers every active mined fact/sidecar/rule/template/shape/scan/Pratt/view/regex/CSP/egraph surface.
