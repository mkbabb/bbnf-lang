# B1.W1 — Bench Harness Migration (Bencher → Divan) + iai-callgrind CI

**Opens after**: W0 hard gate green (including ICE-clean + ceiling row)
**Covers**: migration Steps 5-8
**Agents**: 1 (W1.a) + 4 parallel (W1.b) + 1 (W1.c)
**Total budget**: ~1.5 agent-days
**Hard gate**: every bench emits divan JSON; `bencher` removed; iai-callgrind CI workflow drafted; parity within ±5% per group
**Status**: planned

## Scope

1. Port one exemplar bench (`compile_pipeline.rs`) from `bencher` to
   `divan 0.1+` as the reference pattern.
2. Port the remaining 18 bench binaries mechanically against that
   pattern, parallelized across 4 agents grouped by grammar family.
3. Remove the `bencher = "0.1"` dependency from
   `crates/core/Cargo.toml`; there is no dual-harness window.
4. Add a secondary `iai-callgrind` instruction-count surface,
   gated behind the `iai` feature and wired into a new CI workflow
   stub (the workflow itself lands in W2).

## Opening gate (from W0)

W1 does not open until all W0 hard gates are green, **including**:

- `target/rustc-ice-*.txt` count is zero after the final W0
  `iter-check-full` run.
- `iter-check-full-cold-pinned` row present in
  `docs/benchmarks/post-B1-W0-proof.txt`.
- `.cargo/config.toml` `bench-json` alias resolves.

## Phase sub-items

### B1.W1.a — Exemplar bench port + bencher baseline capture (Step 5)

**Opens**: W0 close.
**Agent count**: 1.
**Hard cap**: 90 min.
**Role**: establishes the reference pattern and baseline for parity.

Mechanism:
- **Baseline first**: before any code changes, run
  `cargo bench -p bbnf` under bencher and redirect output to
  `docs/benchmarks/post-B1-W1-baseline.json` (raw bencher stdout
  parsed into JSON rows). This is the pre-migration reference used
  for every parity comparison in W1.b and W1.c.
- Add `divan = "0.1"` to `crates/core/Cargo.toml
  [dev-dependencies]` (the line only, not the bencher removal —
  that is W1.c's responsibility).
- Rewrite `benches/common/timeout.rs` so the harness shim exposes
  divan's sample-setup/body split rather than bencher's single
  `iter` closure. Pattern is in
  `docs/tranches/B1/patches/divan-migration.md §Exemplar`.
- Rewrite `crates/core/benches/compile_pipeline.rs` to call
  `divan::main!()` with `harness = false` preserved in Cargo.toml's
  `[[bench]]` entry.
- Configure divan with `sample_size = 1` and cold-per-parse
  (feedback `no-warm-benches`).
- Run `DIVAN_BENCH_FORMAT=json cargo bench --bench compile_pipeline`;
  redirect output to
  `docs/benchmarks/post-B1-W1-divan-compile.json`.
- Compare divan wall against bencher baseline for each measured
  grammar; verify within ±5%. If the delta exceeds ±5%, diagnose
  the harness shim (the `setup_input` clone is the likeliest
  culprit per `TOOLCHAIN-MIGRATION.md §5.4`) and re-measure before
  releasing W1.b.

Files touched: `crates/core/benches/compile_pipeline.rs`,
`benches/common/timeout.rs`, `crates/core/Cargo.toml` (divan
dev-dep add only), `docs/benchmarks/post-B1-W1-baseline.json`,
`docs/benchmarks/post-B1-W1-divan-compile.json`.

Sub-gate:
- `cargo bench --bench compile_pipeline` produces divan JSON.
- Parity within ±5% of the bencher baseline row for
  `compile_pipeline`.
- `benches/common/timeout.rs` exposes the divan sample-setup/body
  signature; the bencher signature is removed from this shim (but
  not yet from the remaining 18 benches — they still import the
  old shim until W1.b lands).

### B1.W1.b — Port the remaining 18 benches (Step 6)

**Opens**: W1.a sub-gate green.
**Agent count**: 4 parallel, grouped by grammar family.
**Hard cap**: 90 min per agent.

#### W1.b.1 — JSON bench family (5 files)

Files (owner-only): `crates/core/benches/json_*.rs` (5 files named
per `TOOLCHAIN-MIGRATION.md §6 Step 6`).
Output artefact: `docs/benchmarks/post-B1-W1-divan-json.json`.
Mechanism: for each file, apply the exemplar pattern; run
`DIVAN_BENCH_FORMAT=json cargo bench --bench <name>`; append each
bench's rows into `post-B1-W1-divan-json.json` as a merged object.
Parity check against the bencher baseline rows for json-named
grammars.

#### W1.b.2 — CSS bench family (4 files)

Files (owner-only): `crates/core/benches/css_*.rs` (4 files).
Output artefact: `docs/benchmarks/post-B1-W1-divan-css.json`.

#### W1.b.3 — Sheets bench family (2 files)

Files (owner-only): `crates/core/benches/sheets_*.rs` (2 files).
Output artefact: `docs/benchmarks/post-B1-W1-divan-sheets.json`.

#### W1.b.4 — BBNF + misc bench family (7 files)

Files (owner-only): `crates/core/benches/{bbnf_*,misc_*}.rs`
(remaining 7 files enumerated in §Migration order of
`divan-migration.md`).
Output artefact: `docs/benchmarks/post-B1-W1-divan-bbnf.json`.

Sub-gate (applies to all four W1.b agents):
- Every file in the agent's group compiles and runs under divan.
- Divan JSON emitted to the agent's output artefact.
- Per-file parity within ±5% of the bencher baseline.
- Agent's group's `[[bench]]` entries in `crates/core/Cargo.toml`
  remain `harness = false`; the agent does NOT touch the bencher
  dependency declaration (W1.c owns that).

### B1.W1.c — `bencher` removal + iai-callgrind feature (Steps 7-8)

**Opens**: all 4 W1.b sub-agents sub-gate green.
**Agent count**: 1.
**Hard cap**: 60 min.
**Role**: closes the harness migration; ensures no dual-path
survives; drafts the iai-callgrind surface.

Mechanism:
- Remove `bencher = "0.1"` from `crates/core/Cargo.toml
  [dev-dependencies]`.
- Verify `rg -w bencher` returns 0 results across the repo (no
  `use bencher` imports remain, no `#[bench]` attributes targeting
  bencher).
- Run `cargo check -p bbnf --profile ax-iter` — must exit 0 after
  the dep removal.
- Add `iai = ["iai-callgrind"]` feature to
  `crates/core/Cargo.toml [features]`.
- Add `iai-callgrind = { version = "...", optional = true }` to
  `[dev-dependencies]`.
- Create `crates/core/benches/json_callgrind.rs` per the template
  in `docs/tranches/B1/patches/divan-migration.md §iai-callgrind CI`.
- Add `[[bench]] name = "json_callgrind" required-features = ["iai"]
  harness = false` to `crates/core/Cargo.toml`.
- Verify `cargo bench --bench json_callgrind --features iai --no-run`
  compiles. Full execution requires valgrind on Linux CI; local
  dev-host validates compile-only.
- Draft `.github/workflows/bench-iai.yml` under
  `docs/tranches/B1/patches/bench-iai.yml.draft` (the patches
  directory, NOT `.github/workflows/` — W2 is the landing agent
  for CI workflows). The draft names the Linux runner,
  `sudo apt-get install valgrind`, threshold 1%, and the comment
  bot posting format.
- Author `docs/benchmarks/post-B1-W1-parity.txt` — a single table
  cross-referencing every bench name against bencher-baseline vs
  divan-measured wall, delta percentage, and a pass/fail column.
  Every row must be `pass` for W1 to close.

Files touched: `crates/core/Cargo.toml` (bencher removal + iai
feature + json_callgrind `[[bench]]` entry),
`crates/core/benches/json_callgrind.rs`,
`docs/tranches/B1/patches/bench-iai.yml.draft`,
`docs/benchmarks/post-B1-W1-parity.txt`.

Sub-gate:
- `rg -w bencher` returns 0 results.
- `cargo check -p bbnf --profile ax-iter` exits 0.
- `cargo bench --bench json_callgrind --features iai --no-run`
  compiles.
- `docs/tranches/B1/patches/bench-iai.yml.draft` exists.
- `docs/benchmarks/post-B1-W1-parity.txt` records every bench with
  `pass` in the delta column.
