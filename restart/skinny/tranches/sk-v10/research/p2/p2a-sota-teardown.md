# SK-V10 P2-A: SOTA Comparator Teardown

Pass: S-P2 Research. Cycle: V1.
Date: 2026-05-19.
Scope: architecture teardown of asmjson, sonic-rs, simdjson, and yyjson against the SK-V10 S-P1 hot leaves.
Output: this file.
P1 hot-leaf antecedents: `string_tiny_scan`, `string_full_scan`, `string_escape`, `unicode_escape_hex`, `number_digit_scan`, `number_scan`, `whitespace_skip`, `array_walk`, `object_walk`, `direct_struct`, `simd_movemask`, `alloc`.
Lock surface: both Lock 1 and Lock 14.

## §1 — Findings (concrete; file:line on bbnf claims, citation on external claims)

The live SK-V10 frontier is not parse-only. P1-F records 17 parse rows as `S / NO-GO`, 17 direct rows with 3 `A / GO` and 14 `N-direct / NO-GO`, and six typed rows all `A / GO` (`restart/skinny/tranches/sk-v10/research/p1/p1f-results-delta.md:35-40`). P1-F further excludes parse-only from SOTA admission (`restart/skinny/tranches/sk-v10/research/p1/p1f-results-delta.md:74-77`). The comparator plane for P2-A is therefore strict direct digest and strict typed direct, with parse-only used only to explain hot leaves.

The S-P1 product-plane leaves are local and call-site specific. P1-E classifies the direct and typed hot leaves as tiny/full string scan, escape/hex, number scan, whitespace, object/array walk, movemask, direct digest, and one allocation anomaly (`restart/skinny/tranches/sk-v10/research/p1/p1e-hot-leaf-attribution.md:38-48`). Its direct row map ties these classes to `twitter`, `github_events`, `instruments`, `update_center`, numeric rows, unicode rows, `distinct_values`, and `y_string_unicode` (`restart/skinny/tranches/sk-v10/research/p1/p1e-hot-leaf-attribution.md:51-69`). P1-C rejects eager decode as a route because eager decoded-value materialization is slower on every row, up to 5.71x on `unicode_escapes` (`restart/skinny/tranches/sk-v10/research/p1/p1c-samply-mode-3.md:75-87`).

Strictness is load-bearing. `skinny/RESULTS.md` marks native Rust comparators as same-run strict but C++ sidecars as historical or absent and never strict anchors in W0 (`skinny/RESULTS.md:142-145`). P1 hardening accepts S-P1 for S-P2 and carries the direct/typed PMU absence as instrumentation fact only (`restart/skinny/tranches/sk-v10/research/p1/hardening/HARDENING-S-P1-V1-CONSOLIDATED.md:44-48`). Lock 1 forbids parallel substrates and treats a retained structural projection as tape (`restart/locks/LOCKS.md:52-52`). Lock 14 forbids grammar-specific generic code and requires grammar-neutral expression (`restart/locks/LOCKS.md:78-78`). Lock 16 requires scalar parity, corpus parity, and citation for SIMD/ASM primitives (`restart/locks/LOCKS.md:87-112`).

`asmjson` is an architecture source, not a strict anchor by default. It exposes a SAX sink and flat DOM/tape paths: `parse_json_zmm_sax` calls writer methods through a vtable, while `parse_json_zmm_dom` writes `DomEntry` values directly into a preallocated tape (`https://github.com/atomicincrement/asmjson/blob/3d6965d5a013677198366758cb50fb8637d54d58/src/lib.rs#L193-L220`). Its API exposes portable SWAR and AVX-512BW assembly DOM/SAX variants (`https://github.com/atomicincrement/asmjson/blob/3d6965d5a013677198366758cb50fb8637d54d58/README.md#L193-L204`). Its SAX strings and numbers can borrow source slices, while escaped strings remain raw and must be decoded by the consumer (`https://github.com/atomicincrement/asmjson/blob/3d6965d5a013677198366758cb50fb8637d54d58/src/sax.rs#L21-L35`). It also documents that string contents are not scanned for unescaped control characters, so strict JSON comparison requires an added control-byte check (`https://github.com/atomicincrement/asmjson/blob/3d6965d5a013677198366758cb50fb8637d54d58/README.md#L218-L222`). This maps to bbnf's direct output/control path and tiny/string scanner leaves, but only as primitive precedent unless strictness is repaired.

`sonic-rs` is the primary strict Rust typed comparator. Its public docs say deserialization benchmarks enable UTF-8 validation (`https://github.com/cloudwego/sonic-rs/blob/03545a9530346fe279b674dd496e037d94204bc5/README.md#L78-L84`), and the FAQ states UTF-8 validation is enabled by default except unchecked APIs (`https://github.com/cloudwego/sonic-rs/blob/03545a9530346fe279b674dd496e037d94204bc5/README.md#L453-L456`). Source exposes an explicit `utf8_lossy` mode (`https://github.com/cloudwego/sonic-rs/blob/03545a9530346fe279b674dd496e037d94204bc5/src/parser.rs#L253-L255`) and `from_slice_unchecked` requires valid UTF-8 by caller contract (`https://github.com/cloudwego/sonic-rs/blob/03545a9530346fe279b674dd496e037d94204bc5/src/serde/de.rs#L1317-L1334`); both are flaw probes, not strict anchors. The strict path parses numbers into typed numeric visitors and has a raw-number mode (`https://github.com/cloudwego/sonic-rs/blob/03545a9530346fe279b674dd496e037d94204bc5/src/parser.rs#L300-L333`, `https://github.com/cloudwego/sonic-rs/blob/03545a9530346fe279b674dd496e037d94204bc5/src/parser.rs#L398-L425`), and it has a zero-copy string visitor path (`https://github.com/cloudwego/sonic-rs/blob/03545a9530346fe279b674dd496e037d94204bc5/src/parser.rs#L336-L359`). That is the plane bbnf must beat for direct/typed rows in `skinny/RESULTS.md`.

`simdjson` is the structural-index plus tape/On-Demand comparator. Its stage 1 classifies structural characters and ASCII whitespace (`https://github.com/simdjson/simdjson/blob/7732480b25c63e9a12c87dcfd0d68e6c7dd354b9/src/haswell.cpp#L41-L45`), then writes structural indexes using bit scans (`https://github.com/simdjson/simdjson/blob/7732480b25c63e9a12c87dcfd0d68e6c7dd354b9/src/generic/stage1/json_structural_indexer.h#L24-L123`). DOM parsing explicitly runs stage 1 before stage 2 tape building (`https://github.com/simdjson/simdjson/blob/7732480b25c63e9a12c87dcfd0d68e6c7dd354b9/src/haswell.cpp#L132-L163`). Stage 2 has a `tape_builder` with visits for object/array starts, keys, primitives, strings, numbers, and root primitives (`https://github.com/simdjson/simdjson/blob/7732480b25c63e9a12c87dcfd0d68e6c7dd354b9/src/generic/stage2/tape_builder.h#L21-L105`). On-Demand runs stage 1 and starts a document iterator over structural indexes, with a reusable string buffer (`https://github.com/simdjson/simdjson/blob/7732480b25c63e9a12c87dcfd0d68e6c7dd354b9/include/simdjson/generic/ondemand/parser-inl.h#L54-L68`; `https://github.com/simdjson/simdjson/blob/7732480b25c63e9a12c87dcfd0d68e6c7dd354b9/include/simdjson/generic/ondemand/json_iterator-inl.h#L48-L55`). This is exactly the comparator that proves structural indexes can be fast, but P1-C and REDRESS say bbnf may not retain a new sidecar/substrate merely because isolated stage-1-style scanning wins (`restart/skinny/tranches/sk-v10/research/p1/p1c-samply-mode-3.md:111-116`).

`yyjson` is a scalar, inline, DOM-style comparator with explicit strict and permissive flags. `YYJSON_READ_NOFLAG` is RFC 8259 compliant and rejects invalid UTF-8, BOM, trailing commas, comments, and nonstandard numbers (`https://github.com/ibireme/yyjson/blob/95f4c61bc1e24176f2aa4f430902705a995f1c97/src/yyjson.h#L734-L744`). Nonstandard flags separately permit invalid Unicode, JSON5, comments, trailing commas, extended numbers, extended escapes, and extended whitespace (`https://github.com/ibireme/yyjson/blob/95f4c61bc1e24176f2aa4f430902705a995f1c97/src/yyjson.h#L759-L834`). Its default string reader copies non-insitu input to padded storage before parsing (`https://github.com/ibireme/yyjson/blob/95f4c61bc1e24176f2aa4f430902705a995f1c97/src/yyjson.c#L6226-L6265`), chooses minified/pretty/single root readers (`https://github.com/ibireme/yyjson/blob/95f4c61bc1e24176f2aa4f430902705a995f1c97/src/yyjson.c#L6286-L6295`), has a standalone number reader contract (`https://github.com/ibireme/yyjson/blob/95f4c61bc1e24176f2aa4f430902705a995f1c97/src/yyjson.h#L1124-L1149`), and records a memory model of 16 bytes per value with 1.5x growth plus padding (`https://github.com/ibireme/yyjson/blob/95f4c61bc1e24176f2aa4f430902705a995f1c97/src/yyjson.h#L1104-L1122`). Its value to bbnf is the strict scalar hot-leaf/i-cache discipline, not a new retained substrate.

## §3 — Grammar-neutrality (each candidate: JSON-only or CSS/Sheets/BBNF-self generalisable)

`Strict tiny-string terminator` is grammar-neutral as a quoted-token terminator with a grammar-provided escape alphabet and control policy. It generalizes to CSS strings/idents with a different escape table, Sheets quoted strings, and BBNF-self string literals. JSON-only risk: hardcoding `"` and JSON control policy into `bbnf-simd`.

`Strict full-string escape/control scanner` is grammar-neutral as a chunk-spanning quoted-token scanner returning delimiter, escape, control, and validity classes. CSS L4 and BBNF-self need different escape legality; Sheets needs formula-string quote doubling. The primitive must be parameterized by byte-set tables, not named JSON behavior.

`Unicode escape quartet decode/classify` is partially grammar-neutral. The hex-quartet classifier generalizes to CSS escapes and BBNF-self Unicode escapes, but JSON surrogate-pair policy is grammar-specific. The primitive should expose `hex4 -> u16/result`; grammar templates own surrogate or scalar-value policy.

`Digit-run and JSON-number span scanner` is grammar-neutral only if split into a base digit-run / sign / radix / exponent DFA primitive plus a JSON-number policy table. CSS L4 `<number>`, Sheets numerics, and BBNF numeric literals differ enough that a monolithic JSON number parser violates Lock 14.

`Strict whitespace structural classifier as transient primitive` is grammar-neutral as byte-set classification over whitespace, delimiters, open/close, and separator classes. It must not retain a JSON structural-index array. Per-grammar byte sets come from grammar IR.

`Direct SAX-style sink contract` is grammar-neutral as an event-sink/output-plane contract over the existing parser walk: CSS declarations, Sheets formulas, and BBNF-self AST events can all consume grammar-specific generated sink events. It becomes JSON-overfit if the generic crate names JSON event kinds.

## §4 — Risks (REDRESS entries any candidate must NOT re-open)

- Do not reopen W3 union/event substrate. REDRESS and SK-V10 synthesis retired the substrate-ceiling thesis; structural masks may be transient only (`restart/skinny/tranches/sk-v10/SYNTHESIS.md:69-75`, `skinny/REDRESS.md:101-116`, `skinny/REDRESS.md:195-201`).
- Do not treat parse-only rows as SOTA admissions. P1-F excludes them, and `skinny/RESULTS.md` keeps parse-only `S / NO-GO` (`restart/skinny/tranches/sk-v10/research/p1/p1f-results-delta.md:74-88`, `skinny/RESULTS.md:5-41`).
- Do not route string/unicode work through eager decoded materialization or decoded scratch without a new material differential. P1-C measured eager decode slower everywhere (`restart/skinny/tranches/sk-v10/research/p1/p1c-samply-mode-3.md:75-87`).
- Do not use `sonic-rs` `utf8_lossy`, `from_slice_unchecked`, yyjson JSON5/permissive flags, or asmjson's current no-control-scan path as strict anchors. They are flaw probes or primitive precedents only.
- Do not claim direct/typed PMU proof; P1 hardening records direct/typed PMU absence in V1 (`restart/skinny/tranches/sk-v10/research/p1/hardening/HARDENING-S-P1-V1-CONSOLIDATED.md:44-48`).
- Do not create JSON-specific generic crate code. Lock 14 requires grammar source/metadata/templates only for per-grammar behavior (`restart/locks/LOCKS.md:78-78`).
