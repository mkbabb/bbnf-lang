# Tranche B1 — Dev-Loop Truth + Proof-Surface Hardening

B1 is the bounded prelude annex that restores truthful development
infrastructure before AY-II resumes. It owns no runtime architecture.
It closes only when the public command surface, the bench/profile/
bootstrap/regen surfaces, the substrate pin, and their documentation
agree on measured reality. AY-II.W0' stays paused until B1 closes;
AY-II resumes immediately afterward on the refreshed proof surface.

## Architectural thesis

1. **B1 precedes AY-II's next runtime step.** As a prelude annex,
   B1 closes before AY-II.W0' close ceremony and W1 dispatch resume.
   There is no parallel annex execution.
2. **B1 owns infrastructure only.** Substrate pin, alias surface,
   bench harness, test runner, CI workflow, command surface, scripts,
   and documentation are in scope. Parity-critical runtime architecture
   remains in AY-II.
3. **One public workflow surface.** Cargo aliases, Make targets,
   scripts, CI, and docs must describe the same workflow. Stale comments,
   stale docs, and superseded command claims are infrastructure debt and
   must be deleted.
4. **Bench truth is cold-per-parse.** The bench harness migrates from
   `bencher = "0.1"` to `divan 0.1+` in a single pass; `bencher` is
   removed outright. A secondary `iai-callgrind` surface gates CI-side
   instruction-count regressions.
5. **Substrate is pinned.** `rust-toolchain.toml` freezes the nightly
   to eliminate the 93-ICE cluster observed against ambient
   `1.96.0-nightly (9602bda1d 2026-04-05)`. Every sibling repo
   participating in the path-patched crate graph pins the same date.
6. **Delete legacy workflow cruft in the same commit that supersedes it.**
   B1 does not layer new guidance on top of obsolete surfaces. No
   script is deleted until its replacement cargo alias is live and
   proven. No alias is added that does not carry a documented cost.

## Invariants

1. No B1 commit touches parity-critical runtime architecture.
2. B1 blocks AY-II.W0' close ceremony and AY-II.W1 open until B1 closes.
3. Every public routine command remains seconds-scale on the declared
   routine surface or is removed from that surface.
4. Every public proof command (`bootstrap`, `expand`, `samply`,
   `ay-bench-close`, `bench-json`) is runnable and documented on the
   exact command path users and agents will invoke.
5. Every documentation claim about the public command surface is
   re-verified against the live repo state during B1.
6. No stale `#[allow(dead_code)]`, `#[ignore]`, `#[cfg(false)]`, or
   dead workflow prose is introduced to hide incomplete work.
7. Samply closes on symbol-resolved captures, not `nm`-only salvage.
8. B1 closes with a benchmark/timing artefact trail of its own,
   captured under divan and nextest.
9. B1 carries no successor debt tree; anything runtime-facing routes
   back to AY-II immediately.
10. Every `--exclude`d crate on the routine-surface `iter-check` alias
    has a named fast-path cargo alias that validates it under
    `--profile ax-iter`. Concretely: `iter-check-lsp` covers
    `bbnf-analysis` + `bbnf-lsp`; `iter-check-prettify` covers
    `gorgeous`; `iter-check-bootstrap` covers `bbnf-bootstrap`. All
    four aliases are named in `.cargo/config.toml`'s alias comment
    block and their wall-clock outputs land in
    `docs/benchmarks/post-B1-W0-routine.txt`.
11. `cargo iter-check-full` (the workspace close-gate) records a
    measured wall-clock ceiling in `docs/benchmarks/post-B1-W0-proof.txt`;
    the ceiling is an explicit number, not "exit 0".
12. `target/.bbnf-cache/` is neither created nor destroyed as a
    side-effect of any B1 command — scripts that previously relied on
    unconditional `rm -rf target/.bbnf-cache/` are fixed so cycle-2
    bootstrap is measurably cheaper than cycle-1.
13. No script listed in the abrogation catalog is deleted until its
    REPLACE target is live on a cargo alias and validated on current
    repo state. Deletion and replacement land in the same commit.
14. No divan bench port begins until the pinned toolchain has been
    applied, `cargo clean` has cleared the ICE cache, and
    `cargo iter-check-full` exits clean under the pin.
15. `bencher = "0.1"` is removed from `crates/core/Cargo.toml` in the
    same commit that lands the final ported bench; there is no
    dual-harness window.
16. `rust-toolchain.toml` in bbnf-lang, `../parse-that`, and
    `../pprint` all carry the same pinned nightly date. The pin lives
    in one source of truth and is mirrored, not independently chosen.

## Operational posture

1. B1 executes in four waves — W0 (substrate + surface), W1 (bench
   harness migration), W2 (CI + scripts + cross-repo), W3 (docs + close).
2. Each wave's sub-agents own strictly disjoint file bounds, with
   append-only shared artefact files following the SPEC §N-agent
   shared-file disjoint-row convention.
3. Every B1 claim about command behavior cites a measured artefact.
4. Any runtime defect surfaced during B1 is recorded and routed to
   AY-II rather than fixed in-annex.
5. B1 closes before any further AY-II runtime or semantic dispatch.

### Sequencing reconciliation (divan)

Two prior planning artefacts speak to divan's home: the abrogation
catalog recommends holding bench-framework-dependent script abrogations
(bench_regression.sh, cost-grid-sweep.sh, extract_hotspots.py, bootstrap
syn-rewrite, ay-bench-close) until divan is live; the migration draft
places the divan port itself in B1 Steps 5-7. Both are correct; the
reconciliation is:

- **Divan migration lives in B1.W1.** The bench harness is dev-loop
  truth; cold-per-parse is a feedback invariant (`no-warm-benches`);
  deferral would leave every downstream measurement compromised.
- **Bench-framework-dependent script abrogations live in B1.W2.a.**
  They depend on divan JSON being emitted, which W1 guarantees.
  Abrogation catalog's "BB (divan-gated)" phrasing refers to a
  successor tranche only insofar as that tranche was drafted before
  B1 existed. B1 now absorbs those abrogations — no carryover.
- **Deeply structural follow-ons** (derive-cache relocation, watt
  proc-macro precompilation, bench architecture restructure) remain
  BA/BB territory; they are named in `TOOLCHAIN-MIGRATION.md §6
  Deferred` and do not belong in B1.

### Sequencing reconciliation (ICE cluster)

The 93-ICE cluster observed in `meta-audit/04-toolchain-pain.md`
corrupts the on-disk incremental cache under ambient nightly. The
pin alone does not clear the corrupt cache — a `cargo clean` plus
`rm -rf target/ax-iter/incremental` must run before any port begins.
Therefore W1.a (exemplar port) does not open until W0 closes AND
the pinned-toolchain smoke gate (`cargo iter-check-full` exits
clean under the pin) passes. W0.d's hard gate carries this check
explicitly; W1.a opens only on its green.

## Hard gates summary

### W0 — Substrate + alias surface (Steps 1-4)

1. `rust-toolchain.toml` committed; `rustc --version` reports the
   pinned nightly on a fresh shell.
2. `.cargo/config.toml` resolves every declared alias; comment block
   names the full cost model (routine / per-exclude fast-paths /
   close-gate / bench-json).
3. `.config/nextest.toml` carries 4 profiles; `cargo nextest run
   --workspace --profile ax-iter` exits 0 under the new pin.
4. `Makefile` simplified; every target delegates to a cargo alias
   or a single script invocation; no GNU-timeout cascade remains.
5. `cargo iter-check`, `cargo iter-test-leaf`, `cargo iter-check-lsp`,
   `cargo iter-check-prettify`, `cargo iter-check-bootstrap`,
   `scripts/test-tier.sh leaf --profile ax-iter` all exit 0 under
   the pinned nightly.
6. `cargo iter-check-full` exits 0 with a symbol-resolved ICE-clean
   compile under the pin; cold wall-clock recorded as
   `iter-check-full-cold-pinned` in
   `docs/benchmarks/post-B1-W0-proof.txt`. **This is the gate
   W1.a opens on.**
7. Stale command-surface claims removed from `.cargo/config.toml`,
   `Makefile`, and `docs/instructions/PROFILING.md`. No obsolete
   alias survives.

### W1 — Bench harness migration (Steps 5-8)

1. `cargo bench --bench compile_pipeline` produces divan JSON output
   within ±5% of the bencher baseline captured pre-migration.
2. All 19 bench files in `crates/core/benches/` compile under divan;
   each emits structured JSON via `DIVAN_BENCH_FORMAT=json`.
3. `bencher = "0.1"` removed from `crates/core/Cargo.toml`;
   `rg -w bencher` returns 0 results across the repo.
4. `benches/json_callgrind.rs` exists; `iai = ["iai-callgrind"]`

5. Divan JSON captured per-grammar into
   `docs/benchmarks/post-B1-W1-divan-{json,css,bbnf,sheets,compile}.json`.
6. Parity check between divan and bencher walls within ±5% per
   bench group; any breach documented with cause.

### W2 — CI rewire + scripts + cross-repo (Steps 9-11)

## AY-II handoff contract

B1 does not close until all of the following are true:

1. The public command surface and its docs are internally consistent
   under the pinned nightly.
2. The bootstrap, expand, profile-prep, samply, divan, iai-callgrind,
   and nextest-close paths are proven on current repo state.
3. Every abrogation-catalog entry has been executed or explicitly
   deferred with a named successor tranche owner.
4. Sibling-repo pins (parse-that, pprint) match the bbnf-lang pin.
5. AY-II.W0' is explicitly unblocked in AY-II's planning/status docs.
6. No B1 change introduced runtime drift into AY-II.

## Defensible floor

B1's defensible floor is:

1. Truthful routine command docs and comments under a pinned substrate.
2. Measured bootstrap/expand/profile/bench proof surfaces on divan.
3. An abrogation catalog executed or explicitly deferred with owner.
4. A cross-repo pin triad (bbnf-lang / parse-that / pprint) in sync.
5. An AY-II handoff that no longer depends on ambiguous or stale
   infrastructure claims.

Anything less leaves AY-II blocked on infrastructure debt rather than
engineering truth.

## Cross-tranche debt

- Runtime parity, fused-substrate closure, projection/materializer
  totality, and all semantic-wave work remain in AY-II.
- If B1 surfaces runtime regressions while proving bench/bootstrap/
  profile surfaces, those regressions route to AY-II immediately with
  artefact citations.
- B1 inherits the **infra** scope that W0'.d4-d7 landed on
  master pre-B1 (`AY-II/PROGRESS.md:287-310` + `audit/W0p-infra-*`).
  B1.W0 re-audits those landings on current repo state. This is
  not a prelude-annex successor debt tree (SPEC §B0 prelude
  invariant: prelude annexes carry no successor debt tree); it
  is a one-time inheritance of the infra pivot that opened B1.
- The following items are **explicitly deferred** to BA/BB with
  rationale in `TOOLCHAIN-MIGRATION.md §6 Deferred`:
  - Derive cache relocation to `$XDG_CACHE_HOME`.
  - Watt / WASM-precompiled proc-macros.
  - Bench architecture restructure (`crates/bench-*`).
  - Parametric bench collapsing.
  - sccache (conditional on CI cache-hit rate ≥80%).
- Appurtenant assay's wider fleet modernization (gorgeous sibling,
  csp-solver, csc411, crates/ai, etc.) extends beyond B1's three-repo
  cross-repo subset. Those repos are named in W2.c's scope but their
  CI workflows and bench harnesses remain out of B1 — they route to
  a post-B1 appurtenant tranche.

## Escape clause

None. If B1 discovers a broader runtime blocker, it records the
evidence and stops; it does not absorb AY-II work.

## Indefatigability

When B1 closes correctly, the repo has one truthful workflow surface,
one pinned substrate, one bench harness emitting cold-per-parse JSON,
one CI workflow gating both correctness and instruction-count
regressions, zero stale infra prose, and one immediate next step:
AY-II.W0' close, then AY-II W1-W5 on the refreshed surface.
