# Tranche B0 — AY Execution Runway

B0 is a bounded prelude annex for AY. Its job is to remove the
repository's current build, bench, profiling, and command-surface drag
that would otherwise slow `AY.W5-W7` to a crawl. B0 owns no runtime
architecture and no parity-critical parser work. If an item is required
to hit AY's near-parity close gates, it stays in AY.

## Architectural thesis

1. **B0 exists only to unblock AY execution.**
2. **Workflow truth must live in commands, profiles, and scripts, not
   just prose.**
3. **The annex is bounded.** It closes before `AY.W5` and does not
   grow a successor debt tree of its own.
4. **No parity-critical runtime design moves here.**

## Invariants

1. No parser-runtime or semantic-architecture work belongs in B0.
2. B0 may touch only the command/build/bench/profiling runway required
   to execute `AY.W5-W7` rapidly and truthfully.
3. B0 closes before `AY.W5` opens.
4. Any command or script added in B0 must be the actual public path,
   not a side note in docs.
5. Heavy correctness, profiling, and final-proof loops must be
   intentionally separated.

## Operational posture

1. B0 measures routine, profiling-prep, and heavy-proof costs
   separately.
2. Every command-surface change must shorten a named AY loop, not
   improve “developer experience” abstractly.
3. B0 captures the exact `cargo expand`, `cargo asm`, bench, and Samply
   entrypoints required by `AY.W5-W7`.
4. B0 ends as soon as AY has a fast truthful runway; anything broader
   routes to BA first, then later BB/BC as appropriate.

## B0 → AY handoff contract

B0 does not close until all of the following are true:

1. Routine iteration no longer defaults into full-workspace or
   final-proof loops.
2. Exact public commands exist for the AY `W5-W7` expand, asm, bench,
   and Samply gates.
3. Profiling preparation is reusable rather than rebuild-heavy.
4. Routine correctness, profiling-prep, and heavy bench/proof surfaces
   are separated.
5. No parity-critical AY runtime or semantic work has been moved out of
   AY into the annex.

## Defensible floor

B0's defensible floor is:

1. public fast-path commands,
2. prepared-binary profiling for AY proof loops,
3. separated routine and heavy surfaces,
4. measured lower wall-clock cost for the commands AY actually needs.

Anything less means AY is still being forced through a self-inflicted
toolchain bottleneck.

## Post-tranche review candidates

Decision at B0 close, not mid-wave:

- Whether any remaining compile-time or cache-key work is still
  load-bearing for AY or should wait for BA and then later BB.
- Whether the public command surface is minimal enough to avoid
  reintroducing workflow sprawl.

## Indefatigability

When B0 closes correctly, `AY.W5-W7` can run on a fast truthful command
surface without reopening the old failure mode where tooling reform
swallows parity-critical runtime work.
