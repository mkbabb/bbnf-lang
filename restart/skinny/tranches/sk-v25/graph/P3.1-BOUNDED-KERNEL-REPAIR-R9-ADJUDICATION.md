## Rulings

### R1 — full-graph sizing precedes byte-sensitive admission: CORRECT

`validate_projection_from_graph` calls `admit_validation_setup_bytes` before
`admit_canonical_privacy`. The former charges only `graph.truth.len()` at
`evidence/validate.rs:465-469`, then calls `serialized_len_capped(graph, ... )`
at `:491`. Only after that complete serialization attempt does
`admit_canonical_privacy` charge `4 * serialized_bytes + truth_rows` at
`:511-515`; its first phase event is at `:528`.

The 512 KiB one-below test at `tests/architecture/evidence/validate.rs:725-740`
therefore traverses the long graph during sizing and then reports canonical
phase counts `[0, 0, 0]`. The count is true only of late manual markers. It is
not evidence that byte-sensitive traversal did not start.

This is an inner credited path, not routed outer validation. R9's named
canonical/privacy precharge claim is false.

### R2 — nested-percent decoding is quadratic and `4 * n` is false: CORRECT

`schema/identity.rs:339-367` copies the input, then repeatedly scans and
reallocates the entire shrinking string. For

```text
S(k) = "%" + "25" repeated k times
```

one round maps `S(k)` to `S(k-1)`. The scanned lengths are
`2k+1, 2k-1, ..., 1`, totaling exactly `(k+1)^2` byte visits before the other
privacy scans. Input length is only `2k+1`. The one-megabyte portable-string
limit does not make this compatible with the eight-million-unit projection
work limit.

Independently of that counterexample, post-admission `validate_canonical`
serializes for `validate_size`, clones payload strings, serializes the clone in
`canonicalize::validate_size`, serializes edge records for identity checks,
serializes the complete graph for privacy, reparses every string, and decodes
it. Four serialized bytes per input byte is not a derived upper bound. The
quadratic family alone disproves it decisively; no exact alternative constant
was proven by R9.

The current small nested-encoding privacy test proves semantic detection only.
It supplies no asymptotic work oracle.

### R3 — SCC/cycle work is length-blind; the writer cap is not a work cap: CORRECT

SCC admits `5V + 6E` work at `project/scc.rs:358-364`, independent of identity
or edge-record byte length, then serializes those values at `:384-386` and
rehashes complete edge records at `:440`.

Cycle domain admits `V + 3E` at `project/cycle.rs:52-61`, then serializes at
`:73-77` and clones/rehashes every complete edge record at `:85-89`. Cycle
member hashing admits only `members.len()` at `:791-796`, then serializes all
member identities at `:809-813`. Same-cardinality short and one-megabyte
identities therefore receive equal phase work despite unequal traversal,
comparison, clone, and hash work.

Pinned `serde_json 1.0.149` proves why the byte writer ceiling does not repair
this. `ser.rs:2074` writes the opening quote; `:2088-2100` scans bytes until an
escape; only `:2108` or `:2132` sends a string fragment to the writer. With a
ceiling that admits the quote but not the fragment, a long unescaped or
late-escape string is scanned before `CountingWriter` can reject it. The
existing hash cap test uses an element-wise sequence and does not exercise this
string behavior.

### R4 — allocation/visit evidence is late and self-reported: CORRECT

`ValidationOperation` is emitted by production calls to `observe_validation`;
it is not connected to `GlobalAlloc` or Serde. In cycle-domain validation,
`edge.validate_identity()` clones the complete record and allocates canonical
JSON at `project/cycle.rs:85-89`. `PhaseAllocation(CycleDomain)` is emitted only
at `:94-95`, after those allocations.

The phase tests count the same production-emitted markers. The global allocator
test records the first operation's active heap and one whole-validation peak;
it does not record phase-local allocations or prove one-below phases
allocation-free. Passing phase counts therefore cannot cure R1-R3.

### R5 — public `ComponentIdentity::validate_members` bypasses the budget: CORRECT

`project::scc` is public and `ComponentIdentity::validate_members` is public.
The method accepts no `ProjectionBudget` and calls full-buffer
`hash_serialized` at `project/scc.rs:153-165`; that helper calls
`serde_json::to_vec` at `hash.rs:90-95`.

It can be invoked with an arbitrarily large member slice and a mismatching
digest, allocating and hashing the complete serialization before rejection.
Credited inner callers in `evidence/validate.rs`, `project/cycle.rs`, and
`project/cluster.rs` also invoke it without transferring the caller-owned
budget. Earlier aggregate reservations do not charge this method's
content-sensitive work and do not make the public entrypoint bounded.

### R6 — cycle basis/output/adjacency allocation is under-reserved: CORRECT

`admit_basis_search_bytes` reserves logical slots only:

- one `(Identity, Vec<usize>)` per member;
- one `usize` per edge;
- one `CycleWitness` per target rank; and
- one logical GF(2) row per target.

Production builds `outgoing` as `BTreeMap<Identity, Vec<usize>>` and each bucket
with `or_default().push(...)` at `project/cycle.rs:504-509`; it builds output as
`Vec::new()` and pushes witnesses at `:512` and `:650`.

The pinned ARM `RawVec` source defines minimum nonzero capacity four for every
element of size at most 1 KiB (`alloc/raw_vec/mod.rs:153-165`) and applies that
minimum during amortized growth (`:520-524`). Both `usize` and `CycleWitness`
meet that condition. A rank-three output thus allocates four witness slots
while R9 reserves three. Every sparse one-edge outgoing bucket allocates four
`usize` slots while R9 reserves one.

The pinned `BTreeMap` leaf has capacity eleven key/value pairs
(`alloc/collections/btree/node.rs:43-66`), including node header and unused
slots; `size_of::<(Identity, Vec<usize>)>() * logical_members` does not reserve
that representation or cloned string payloads. The linked rank-three fixture
passes because it asserts semantics, not allocator deltas. The R9 phase-prefix
fixture uses rank four, exactly masking first-capacity rounding.
