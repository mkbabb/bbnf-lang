## Findings

### C1 — HIGH — quotient “cycle witnesses” are not replayable graph evidence

`project/quotient.rs:89-101` rewrites each crossing edge's endpoints to virtual
cluster identities while preserving the original edge identity, then runs the
ordinary edge-witness basis builder. The emitted witness therefore names original
graph edges but is head-to-tail only in the rewritten quotient records. Two
successive crossing edges can meet at a virtual cluster while their original
physical endpoints do not meet. No emitted internal connector path reconstructs
that step.

The validator at `evidence/validate.rs:253-299` checks quotient edge grouping and
rehashes the already-emitted bases. It never independently replays a quotient
basis, validates its GF(2) rank, or proves reconstruction through shard-local
paths. `F20` merely checks that `quotient.json` exists. This contradicts the
cycle/clustering law requiring quotient cycle evidence sufficient to reconstruct
cross-shard cycles. Presence and self-consistent hashing do not make the evidence
true.

### C2 — HIGH — F18 does not prove the real stage matrix, and one publication
failure can replace the current target before durability

The implementation contains useful real failpoints, but the executable bank is
far smaller than F18. `tests/architecture/evidence.rs:154-209` covers writer-side
failpoints only; `tests/architecture/frontend.rs:50-87` adds Node spawn and helper
decode. It does not execute manifest read, repository resolution, inventory
walk/read, Git, Cargo spawn/read/decode, Rust, frontend, artifact, projection,
basis, cluster, validation, or final-recensus failures through the complete
pipeline with stage-appropriate artifacts.

Several advertised stages are not operation-local. `architecture/mod.rs:225-244`
injects only a broad projection stage around a function that internally performs
SCC, basis, cluster, and quotient work. There is no typed `Cycle`, `Cluster`,
`Generation`, or `Complete` stage injection in the driver despite those being
accepted by `PipelineStage::parse`. Source-binding capture failures are labeled
`Bootstrap` at `architecture/mod.rs:191-203`, after manifest, inventory, worktree,
and nomination work has already completed, so their failure receipt is not
stage-true.

There is also an untested durability hole. On corrupt same-run replacement,
`evidence/write.rs:359-376` quarantines the old directory and installs staging
before `generations/` fsync. A failure at `generations-directory-fsync` returns
without restoring the quarantined directory. If `CURRENT` already named that run
ID, its unchanged bytes now address the newly installed, not-durably-committed
directory. The test uses a different binding/run ID for this failpoint and checks
only pointer bytes, so it cannot see the target replacement.

### C3 — HIGH — F06 relational validation admits an unowned cross-workspace face,
and the live documentation plane omits its governing P3 authority

The product/face checks are real, but they are not the complete reciprocal schema.
At `manifest.rs:321-345`, a package face is accepted when its repository matches
the workspace repository and its product happens to own both the face and the
workspace. A generated frontend face can therefore be reassigned between
`bbnf-root` and `bbnf-wasm` without changing repository or product; because the
generated faces are absent from every context, no context check catches the
cross-workspace mutation. The F06 test covers a cross-repository product workspace,
one omitted face, one context repository mutation, and one nomination mutation,
not this required cross-workspace inverse.

The checked-in manifest's documentation rows at
`constellation-v3.toml:215-239` stop at P1/P2 authorities. The current P3
adjudication—the document that defines v3.1 and F01-F20—is neither a documentation
node nor a superseding authority. Consequently a successful export would publish
a documentation projection that is relationally tidy but stale about its own
governing verdict. This keeps F06/F07 and documentation closure RED.

### C4 — HIGH — ignored-content safety is a prose string, not an executable
collector-access invariant

`inventory/worktree.rs:131-133` serializes the policy claim
`collector-readable-bytes-source-bound`, while the worktree digest deliberately
uses `--exclude-standard` at `worktree.rs:217-245`. That division is acceptable
only if collector access is mechanically reconciled with the source inventory.
It is not.

The frontend helper independently hardcodes its directory exclusions at
`frontend/program.mjs:41-60`; it does not consume the manifest exclusion grammar
or typed captured physical identities. Conversely, the manifest accepts any
well-formed `<path>/**` exclusion and reconciliation checks tracked paths only.
A well-formed exclusion over an ignored directory that the helper still traverses
can therefore remove its bytes from inventory while leaving them readable by the
collector and absent from the worktree digest. F11 only checks that the policy
string contains `source-bound`; it never executes this three-way invariant.
F08's unsupported-pattern and tracked-file cases do not cover it.

### C5 — HIGH — semantic symlink rejection is frontend-local, not a constellation
law

The inventory records a symlink's link-text hash and attaches every enclosing
semantic face, but `inventory/filesystem.rs:60-131` never resolves or rejects a
semantic symlink target. Only the frontend helper rejects symlinks, at
`frontend/program.mjs:55`. The F12 test invokes that helper directly on a
frontend face.

A symlink under the parse-that Rust face but outside its TypeScript face is
therefore accepted by inventory, receives a semantic-face attachment, and is not
rejected by the Rust boundary collector. Escape and dangling targets do not fail
before semantic collection as F12 requires. Either all semantic symlinks need an
inventory-level rejection or allowed in-repository targets need typed target
identity and bound target bytes.

### C6 — HIGH — the universal privacy law is bounded to two decode rounds

`schema/identity.rs:264-285` percent-decodes exactly twice. A URI/path encoded
three or more times remains encoded when `validate_portable_string` performs its
`file:`, POSIX, drive, and UNC checks at `identity.rs:223-260`. The F17 test covers
plain and one-layer encoded cases only. The contract requires encoded forms
universally, not up to a silent depth of two. This is a direct validator escape
and keeps F17 RED even though the ordinary fixture passes.

### C7 — HIGH — several named F tests are surrogates for materially stronger
contract cases

The largest mismatches are:

- F14 (`tests/architecture/evidence.rs:142-150`) clones a minimal binding, changes
  one field, and calls an equality check. It never mutates a bound repository input
  after capture during collection, never drives `verify_unchanged`, and never
  proves that a mixed-snapshot graph cannot publish.
- F16 (`tests/architecture/project.rs:167-199`) proves hard-signature mutations and
  fan membership movement, but its articulation assertion checks only that the
  post-hoc `Articulation` label exists. The contract explicitly says no
  post-hoc-only label passes; articulation must affect cut membership/eligibility.
- F19 proves compact serialization of 100 synthetic isolated nodes, but measures
  no full-constellation wall time, RSS, generation bytes, or projection bytes and
  has no external gate that converts a wall/RSS miss into
  `RESOURCE_BUDGET_EXCEEDED`.
- F20 publishes one tiny synthetic payload once. It does not exercise fresh and
  repeated full output, byte determinism, full file-set hashing, or the actual
  resource limits. It also inherits C1's unvalidated quotient basis.

The P3.1 stopping rule additionally requires the entire F01-F20 bank born-RED
against P3 and twice green against one immutable P3.1 ledger. No bound born-RED
F01-F20 receipt or double-pass semantic receipt exists in the reviewed subject.
The passing one-shot suite cannot substitute for that history.

### C8 — MEDIUM — the topology misses its explicit KISS target and duplicates
proof helpers

`xtask/src/architecture/mod.rs` is 353 lines against the adjudicated orchestration
target of at most 220. It still mixes stage driving, failure-publication assembly,
semantic-boundary scheduling, injection parsing, workspace discovery, and
diagnostic path rewriting. The 314-line promoted bank also duplicates graph and
projection helpers and several assertions from the source-isomorphic architecture
suite. This is not the primary correctness failure, but it is real KISS debt in a
wave whose contract explicitly makes topology part of acceptance.
