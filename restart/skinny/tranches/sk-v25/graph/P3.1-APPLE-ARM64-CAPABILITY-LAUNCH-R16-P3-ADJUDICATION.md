## Apple primary-source resolution

The direct-listing disputes resolve without executing an Apple tool:

1. Apple's tagged [`otool-classic(1)` manual](https://github.com/apple-oss-distributions/cctools/blob/cctools-1035.1.102/man/otool-classic.1)

   multi-slice file.
2. Tagged [`libstuff/ofile.c`](https://github.com/apple-oss-distributions/cctools/blob/cctools-1035.1.102/libstuff/ofile.c)
   assigns a null printed architecture label when exactly one architecture
   flag is supplied.
3. Tagged [`otool/main.c`](https://github.com/apple-oss-distributions/cctools/blob/cctools-1035.1.102/otool/main.c)
   prints the architecture annotation only for a non-null label. The correct
   one-selection header is therefore plain `<root>:`. Both critics' rejection
   of the preliminary annotated-header objection is correct.
4. Tagged [`otool/ofile_print.c`](https://github.com/apple-oss-distributions/cctools/blob/cctools-1035.1.102/otool/ofile_print.c)
   prints each packed version as unsigned decimal major/minor/patch
   components, with a 16-bit major component and 8-bit minor and patch
   components. `%u` emits canonical decimal spelling. Frozen `valid_version`
   accepts leading zeros, unbounded digit strings, and values outside those
   component ranges. A-3 is correct.
5. Apple's [command-line tools settings documentation](https://developer.apple.com/documentation/xcode/configuring-command-line-tools-settings)
