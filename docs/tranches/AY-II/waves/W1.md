## Phase sub-items

### AY-II.W1.a — close evidence capture

Mechanism:
1. `make ay-prepare-profile-wave WAVE=II` produces prebuilt bench
   binaries under the `profiling-prep` profile.
2. `make ay-bench-close WAVE=close` runs the full fat-LTO bench
   matrix (5 binaries × their respective fixture counts), writing
   per-bench logs under `docs/benchmarks/post-AY-II-close-*.txt`.
   Aggregate these into `docs/benchmarks/post-AY-II.json`.
3. `cargo bench --profile bench -p bbnf --bench json_monolithic_value`
   runs the eager-JSON value-bench matrix (bbnf vs sonic vs any
   lightweight competitor present in the bench sources). Write
   `docs/benchmarks/post-AY-II-eager.json` with the derived
   ratios.
4. `make ay-samply-json-twitter WAVE=II` captures the samply
   profile for the eager JSON twitter path under `.profiles/samply/AY-II/json_twitter_eager/`.
   Summary emission to `docs/benchmarks/post-AY-II-samply-summary.txt`.
5. `cargo asm -p bbnf <unified-compound-close-symbol>` captures
   the asm evidence for the close-time stamping (or lack thereof
   — the unified API may close purely via a span-update, which is
   the AUDIT-C prescribed form).

Sub-gate: every artefact listed in §File bounds exists with
non-empty content; JSON files parse valid.
