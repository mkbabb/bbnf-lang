# P7 — CSS typed values

**Unit:** sk-v27 LW2.CON-1. **Goals:** G-C2 (P7 typed; G-C1b in PLAN's numbering), G-E1 (CSS rows). **Family:** F-CSS-P2 (G-C1b cells) until the U13t vertical opens its own family.

## What an arm does

It parses each declaration whose property is on the **typed-coverage manifest** into a typed value (lengths with units, colours as their sRGB or specified colour space, keywords, functions with typed arguments), and walks a checksum of every typed value. The output-parity class is **TYPED**: per input, the verdict and, after ACCEPT, the digest of the canonical typed projection.

The coverage manifest is Lightning CSS's own property list intersected with BBNF's typed coverage, committed and hashed (competition C2-4). Until it is committed, P7 has no admissible cell, and every P7 row is OWED.

## Policies

Decoding, preprocessing and escapes are P2's.

| Policy | P7 rule |
|---|---|
| **UTF-8 validation** | As P2 (decode with replacement). |
| **Escapes** | As P2; a property name and a keyword are compared after unescaping and ASCII case-folding (CSS Values 4 §2.1: keywords are ASCII case-insensitive). |
| **Number fidelity** | Numbers are binary64 as P2. A computed conversion (for example `in` to `px`, or a colour space conversion) is not part of the projection: values are compared as specified, in their own units and colour spaces, so neither arm is charged with or excused from a conversion. |
| **Duplicate keys** | Every declaration is projected, in order, including repeated properties. |
| **Error offsets** | A declaration whose value is invalid for its property is projected as `invalid` with the byte offset of the declaration's first value token (the position in the decoded, preprocessed input mapped back to a byte offset of the original input). G-E1 compares these offsets. |

## Canonical form

A list of `(property, typed value | invalid@offset)` pairs in source order, serialized with P4's length-prefixed scheme. The schema of each typed value is the manifest's; the projection of each opponent's AST onto it lives with the opponent's adapter and is reviewed by a seat that did not write it (competition C2-4, U5).

## Witness inputs

`bench/planes/witness/css/` (shared with P2), read through each arm's typed projection.

## Equal work

- Both arms parse the same manifest's properties and nothing else is counted; an opponent's work on properties outside the manifest happens outside the timed region or is charged to the opponent, and the row says which.
- Values are not serialized back to text in the timed region by either arm.
