## Repair

### One serialized buffer, no duplicate JSON tree

`validate_serialized_strings` now serializes once to canonical JSON bytes and
scans every JSON string token, including object keys and values. Each token is
decoded by `serde_json` before the existing repeated-decoding privacy law is
applied. The implementation holds one output-sized byte buffer and one decoded
token, never a second typed graph tree.

The nested privacy regression covers keys, values, escaped paths, and safe
controls. It fails on private-path mutations and passes on the unmodified
artifact.

### Borrowed validation

Validation now builds borrowed node and edge indexes, carries selected edge
references, computes each projection SCC set once, derives bases from borrowed
components/edges, records only explicit cluster ownership, synthesizes implicit
owners on demand, and checks exact quotient coverage against one borrowed
index. The independent structural laws remain total.

A new mutation bank proves missing quotient edges, duplicate crossings, and
internal edges represented as quotient crossings all fail. Existing SCC,
basis, cluster, cut-role, and quotient mutations remain GREEN.

### One-member publication and bounded verification

The production sink renders and writes one complete canonical member at a time
inside the existing atomic staging directory. It retains only each member's
name, size, and hash. Transaction verification hashes files through one 64 KiB
buffer. Atomic rename, quarantine, exact directory-set verification, receipt
identity, failpoints, verified reuse, `CURRENT`, rollback, and directory fsync
semantics are unchanged.

The pure in-memory assembler remains as one code path over the same
`assemble_into` core solely for the exact-ordering test gate; production does
not use it.

### Captured-byte release and hash-only recensus

The initial inventory still captures every byte required by frontend helpers.
The source binding still binds their exact path and hash, and the frontend
still consumes and verifies the captured snapshot. Immediately after that last
consumer, captured bytes are released before artifact collection, projection,
validation, recensus, and publication.

The final recensus still rereads and hashes every required source byte, but no
longer retains a second frontend byte corpus. It derives the exact collector
input bindings from freshly hashed inventory records. A regression proves the
hash-only census reconstructs the exact collector set and hashes while
retaining zero input bytes.
