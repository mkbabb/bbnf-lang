# BB.W4 - Grammar-Colocated Rewrite Dirs

**Name**: W4 - Grammar-Colocated Rewrite Dirs
**Opens after**: W3 - Ranker + Tiering
**Agents**: 5 parallel
**Hard gate**: `grammar/<name>/rewrites/*.ron` schema lands; `cargo xtask regen` discovers and compiles per-grammar rule files; base rules land; generated `.rs` shrinks ≥ 10 LOC for one grammar; rule admission chain proves end-to-end
**Status**: planned

## Scope

1. Codify the `grammar/<name>/rewrites/*.ron` schema. Each `.ron` declares one rule per file: `name`, `lhs`, `rhs`, `cost_delta`, `provenance: Inferred(...)`, `tier`. The schema validator (W0) accepts the per-grammar files; malformed RON is rejected with file/line diagnostics.
2. Modify `xtask/src/regen.rs` to scan `grammar/<name>/rewrites/` for every grammar; parse each file against the schema; compile matching rules into that grammar's `cost_config`. Fleet-wide rules are statically linked from `crates/ir/src/rewrites/`.
3. Land per-grammar `rewrites/*.ron` files for the W3-accepted rules. Per-grammar count ≥ 5 (the W3 acceptance count). Each rule's `provenance` cites the W3 enumeration run.
4. Verify rule admission chain: each landed rule shows `search > 0`, `apply/work > 0`, extraction selected the new form, and generated code changed in a parser hot path. Per-rule report at `docs/rules/<rule-id>.md`.
5. Generated `.rs` shrinks ≥ 10 LOC for one grammar. The shrink is verified via `cargo xtask regen` diff vs the W3 baseline. The grammar that shrinks is named in the W4 close commit body.
6. Class 1 auto-accept audit log: every Class-1 rule has a signed entry in `docs/rules/audit-log.ndjson`.
7. Hard cap: 25 accepted rules per grammar. New accepts must displace older accepts on measured cost delta if the cap is hit.

## Triumvirate Dispatch

Dispatch a triumvirate if any of these occurs:

- the regen integration breaks the rule admission chain (a rule passes the schema but does not produce `search > 0` in the e-graph saturation; substrate bug);
- the per-grammar count cap (25) is hit and the displacement logic fails to retire older rules cleanly (the cost-delta comparison is non-monotonic on some pair);
- generated `.rs` does not shrink for any grammar after the W3-accepted rules land (the rules' apply/work happens but the extraction does not select them; cost model misalignment);
- a Class-1 auto-accept regresses a parity test (the audit log is signed but the rule is unsound; soundness violation, immediate revert);
- three diagnostic-loop iterations fail to isolate why a rule does not fire on the production corpus;
- JSONL transcript quiet >15 minutes;
- first-pass return with no commit and no evidence (after one verbatim redispatch).

## Disjointness

W4.1 (xtask integration + per-grammar discovery) writes `xtask/src/regen.rs` + `crates/core/src/rewrites/mod.rs`. W4.2 (per-grammar `rewrites/*.ron`) writes `grammar/<name>/rewrites/*.ron` per grammar. W4.3 (regenerate generated outputs) writes `crates/core/src/grammar/generated/**`. W4.4 (per-rule docs + audit log) writes `docs/rules/`. W4.5 (rule admission chain verification + LOC delta) writes `docs/tranches/BB/audit/W4-*`. The five sub-units have disjoint primary write paths.

### BB.W4.2 Per-Grammar RON

- Files: `docs/rules/<rule-id>.md`, `docs/rules/audit-log.ndjson`.
- Sub-gate: every accepted rule has a doc; every Class-1 acceptance has a signed audit-log entry.
