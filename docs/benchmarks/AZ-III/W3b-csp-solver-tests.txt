Alignment summary
-----------------

The csp-solver crate already exposed `Csp::add_equals(var, value)`
as the canonical pin primitive (`crates/csp-solver/src/lib.rs:184`).
The three new W3b constraint installers (`shape::install`,
`layout::install`, `dispatch::install`) were initially landing
inline `LambdaConstraint::new(vec![var], move |a| ..., format!())`
boilerplate per pin. Per `feedback_isomorphic_api` ("bindings mirror
the parent crate's API exactly; no adaptor layers"), the inline
boilerplate is an orthogonal API.

W3b.4 collapses each installer's `make_*_pin` helper to a single
`csp.add_equals(var, value)` call. The CSP solver and the IR
consumer now share one pin surface.

------------------------

  - `Csp::add_equals` (lib.rs:184)

  - `Csp::add_soft_constraint` (lib.rs:167)

All eight surfaces are covered by the existing csp-solver test
suite (`crates/csp-solver/tests/`). Run:

The strategy-domain consumer (`crates/ir/src/passes/csp_strategy/`)
