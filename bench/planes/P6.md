# P6 — JSON typed (direct to struct)

**Unit:** sk-v27 LW2.CON-1 (spec only). **Goal:** G-J5, stretch (Wave F, U18). **Family:** none in LW2.

## What an arm does

It deserializes the input straight into the Rust structs of a fixed schema and walks a checksum of the structs. The schema is the citm_catalog and twitter serde structs from the simd-json and sonic-rs bench suites, at pinned commits (competition C2-4). The output-parity class is **VAL**, over the P4 canonical form of the struct's serde serialization (fields in declaration order become an object, so the canonical form orders them by key like any object).

## Policies

- **UTF-8 validation:** P1's rule, over the whole input, including members the schema ignores.
- **Escapes:** every string field is unescaped; a field of a borrowed string type is allowed only when both arms borrow, and the row says so.
- **Number fidelity:** each field has the schema's numeric type; a value that does not fit the field's type is a rejection by both arms, and so is a non-finite float.
- **Duplicate keys:** serde's behaviour for the schema's struct (a duplicate field is an error) is the plane's rule; the witness `dup-keys` is therefore a REJECT on P6.
- **Unknown members:** skipped, but still validated (the first bullet).
- **Error offsets:** not compared on P6.

## Witness inputs

`bench/planes/witness/json/` read through a witness schema (one struct per witness shape), and the two corpora's own schemas.

## Equal work

Both arms use the same struct definitions, the same field types and the same allocator, and neither may skip validation of ignored members.

## Comparators

serde_json `from_slice`, sonic-rs `from_slice`, simd-json `serde::from_slice` (programme G-JSON-3 names serde_json and jiter for this plane).
