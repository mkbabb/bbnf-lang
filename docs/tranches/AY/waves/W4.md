# AY.W4 — Regex-Scan Specialisation

**Opens after**: W1 close (independent of W2/W3; can ship in parallel)
**Agents**: 2 parallel (CSS + Sheets)
**Hard gate**: `__regex_scan_CssL4Parser` self-time on tailwind drops from 26% baseline to ≤ 15%; `__regex_scan_GoogleSheetsParser` self-time on parse_stress drops from 12% baseline to ≤ 7%; no regression on grammars where regex_scan is not a hot symbol (JSON, BBNF); all 14 parity harnesses green; bootstrap regen cycle-1 = cycle-2 byte-identical.

## Scope

1. **Byte-class pre-filter** for regex scanners. Per A2 L3 + A4 L-B: CSS L4's regex scanner emits per-regex DFA transition tables as inline `match` ladders (`dfa_codegen.rs`). A cheap first-byte `match` pre-filter dispatches by leading byte class (ascii-alpha / digit / hyphen / quote-variants) before entering the full DFA. Saves most cold branches on property-name / number-literal / identifier scans.
2. **Property-name PHF** for CSS L4 + sheet function names. Per A4 L-D. For grammars with a fixed set of known keywords, emit a `phf::Map<&str, u32>` lookup table + dispatch by longest-match + fallback to generic regex.
3. **Hoist DFA tables to `pub(crate) const`** (A4 L-B). Currently the `dfa_codegen.rs` emits transitions as inline match ladders; hoisting to const arrays reduces code-size + improves BTB behaviour. Complementary to §1.
4. **Optional: Sheet-specific operator dispatch byte-class**. Sheets has `<<`/`>>`/`<=`/`>=`/`<>`/`=`/`<`/`>` operator tokens. Byte-class dispatcher can route on first byte then disambiguate by second byte.

## Phase sub-items

### AY.W4.1 CSS L4 regex specialisation (parallel agent A)

Mechanism:
- Audit `__regex_scan_CssL4Parser` emit path in current generated.rs. Identify per-call hot regexes (property names, identifiers, number literals, color hex).
- Emit a byte-class pre-filter at each `__regex_scan_*` call site: single `match` on first byte → dispatch to specialised sub-scanner.
- For property names: emit a keyword PHF covering the ~400 CSS property names in the grammar. Miss falls through to generic regex.
- Hoist DFA tables to `pub(crate) const`.

Files: `crates/core/src/generate/regex/{emit,dfa_codegen,phf,byte_class}.rs`, `generated.rs`.

**Sub-gate**: fresh samply on CSS L4 tailwind shows `__regex_scan_CssL4Parser` self-time ≤ 15% (from 26% baseline).

### AY.W4.2 Sheets regex specialisation (parallel agent B)

Mechanism:
- Audit `__regex_scan_GoogleSheetsParser` emit path. Identify hot regexes (identifiers, number literals, operator tokens).
- Emit operator byte-class dispatcher for `<`, `>`, `=`, `<<`, `>>`, `<=`, `>=`, `<>`.
- Emit keyword PHF for built-in function names (if enumerable; Sheets has ~400 built-in functions — identical PHF pattern as CSS properties).
- Hoist DFA tables.

Files: same as W4.1, different emit call sites.

**Sub-gate**: fresh samply on Sheets parse_stress shows `__regex_scan_GoogleSheetsParser` self-time ≤ 7% (from 12% baseline).

### AY.W4.3 Verification + bench

## Archaeology

Pre-AX regex engine work (`.cargo/patches/parse_that` regex HIR) landed the bespoke DFA infrastructure. Per A3/A4: `__regex_scan_<Parser>` remains a visible hot symbol on token-heavy grammars. AY.W4 is the first wave to add PER-GRAMMAR specialisation layers on top of the generic DFA emission.
