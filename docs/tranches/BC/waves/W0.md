**Status**: planned

## §1 Deliverable

Hereupon the codegen surface formalises into a backend-agnostic typed IR + per-backend lowerer per Lock 5. The IR contract specifies the input (grammar IR + Layout output from `bbnf-parse`'s lowering, per BA→BC.C1 + BB→BC.C2) and the output (backend-agnostic typed IR consumed by the per-backend lowerer). The contract names every IR node kind, specifies Lifetime / Layout / TypeDesc resolution, specifies what is per-backend (only leaf source emission) and what is shared (decision dispatch, IR walk, strategy selection).

The contract emerges from refactoring the existing `Emitter` trait in `crates/core/src/backend/emitter.rs` (post-BC.W3 split: `bbnf-codegen/src/emitter.rs`); the trait's current shape names what is shared between backends. BC.W0 documents the existing contract through the act of refactoring the consumer to consume it through a typed IR rather than walking the grammar IR directly. The Rust source emitter at `crates/core/src/codegen/rust/emitter.rs` becomes `crates/core/src/codegen/rust/lower.rs` consuming `TypedIRNode`; existing emitter shapes — struct_direct, dispatcher, alt_dispatch — refactor to consume typed IR; the IR contract is the boundary between optimiser-output and per-backend-lowerer-input.

The IR contract spec at `docs/codegen-IR-CONTRACT.md` documents the typed IR node alphabet derived from `audit/RESTART-SKETCH-2026-05-03.md:404-413`:

```
TypedIRNode:
  | TypedRule { rule_id: RuleId, body: TypedIRNodeId, layout: Layout, type_desc: TypeDesc }
  | TypedAlt { branches: Vec<TypedIRNodeId>, dispatch: AltDispatch, layout: Layout }
  | TypedSeq { children: Vec<TypedIRNodeId>, layout: Layout }
  | TypedRepeat { body: TypedIRNodeId, kind: RepeatKind, layout: Layout }
  | TypedCharClass { class: CharClassId, layout: Layout }
  | TypedKeyword { keyword: KeywordId, layout: Layout }
  | TypedRef { rule_id: RuleId, layout: Layout }
  | TypedRegex { regex_id: RegexId, layout: Layout }
  | TypedMap { inner: TypedIRNodeId, fn_id: HostFnRef, layout: Layout }
  | TypedHost { inner: TypedIRNodeId, fn_id: HostFnRef, layout: Layout }
```

The contract specifies that every node carries its resolved `Layout` (per BA→BC.C1) and `TypeDesc` (per the layout-lowering canon at `audit/SOTA-2026-05-03.md:251-273`); per-backend lowerers consume these resolved fields without re-deriving them.

## §4 Invariants

§I1. **Lock 5 (IR + per-backend lower)**: BC.W0 codifies the IR contract; the Rust emitter consumes typed IR exclusively. No backend's lowerer walks grammar IR directly.

§I2. **Lock 2 (Layout lowering canon)**: the IR contract uses canonical `Layout`/`LayoutSink` terms only; old terms (`type_projection`, `TypeMap`, `StructLayout`, `TypeDesc`, `schema_synthesis` as a pass name) survive only in archived docs.

§I3. **Lock 13 (no god directories)**: the new `crates/ir/src/typed_ir/` directory carries 3-5 cohesive children (mod.rs, node.rs, lower.rs, plus tests/); every file < 500 LOC; every sibling exports a uniform sub-API.

§I4. **No metalanguage**: `docs/codegen-IR-CONTRACT.md` does NOT reference commits, conversation history, or the plan's draft history; cites path:line for prior-art references.

§I5. **Same-wave consumer**: the IR contract spec lands in the same wave as the consumer (the Rust emitter refactor); Era V failure mode structurally precluded.

§I6. **Lock 1 (tape and columnar dead) preserved**: the typed IR alphabet does not introduce a tape or columnar substrate; the IR is the typed-AST hash-cons (per `audit/RESTART-SKETCH-2026-05-03.md:404-413`); no `TapeRec` / `TapeCursor` / columnar SoA.

§I7. **Lock 6 (xtask emits committed source)**: the typed IR is consumed at xtask regen time; no proc-macro façade; the regen output is committed.

## §5 Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| The IR contract spec over-specifies what is per-backend, foreclosing future backend-specific optimisations | Medium | The contract emerges from refactoring the existing `Emitter` trait, not from forward design; the trait's current shape names what is shared. Per-backend lowerer optimisations remain free below the leaf-emission boundary. |
| The typed IR alphabet diverges from the grammar IR alphabet, creating two parallel taxonomies | Medium | The lowering at `crates/ir/src/typed_ir/lower.rs` is mechanical (one-to-one mapping for most variants); divergence only at the level of resolved `Layout`/`TypeDesc` annotations; round-trip test asserts no information loss. |
| The Rust emitter refactor breaks regen-equality with BB close artefact | Medium | Regen-equality is the W0-G3 gate; the refactor is a rename + interface narrowing, not a behaviour change; xtask regen `--check` between sub-commits. |

| The new `typed_ir/` module duplicates `crates/ir/src/dag/` (the existing hash-cons substrate) | Low | The typed IR uses the same hash-cons interner; `TypedIRNodeId` is `NodeId` with a layout/type tag; no duplicate storage. |
| The IR contract spec drifts from the BB→BC.C2 carry's "direct-to-struct emit shape is grammar-agnostic" because the Rust lowerer's per-shape consumers re-derive structural decisions | Medium | The typed IR carries pre-resolved `Layout` + `TypeDesc`; the per-shape consumers (BC.W1 §2.1-§2.4) read these fields directly; the round-trip test (W0 §2.8) catches any re-derivation. |
| The IR contract spec is published as a doc but consumers (BD's TS/WASM activation, future backends) have no enforced schema | Medium | The `Emitter` trait is the schema (compile-time); the contract doc is the human-readable reference; the cross-backend test (BC.W2 §2.6) verifies the trait surface is the contract. ## §9 Closing posture

The IR contract is the boundary; the Rust emitter is the first consumer; subsequent waves (W1 closer, W2 scaffold, W4 visitor) consume the same contract. The spec emerges from the refactor, not from forward design; the existing trait surface names what is shared and what is per-backend, and W0 documents the contract by changing the consumer to consume it through a typed IR rather than walking the grammar IR directly. Lock 5 closes here; subsequent BC waves verify the contract supports TS + WASM and that the core crate splits along the contract boundary.

## §10 Wave-author posture

The wave does not invent the IR contract; it documents what the existing `Emitter` trait already names as shared vs per-backend. The author's task is observational: walk the existing emitter, note what is shared vs per-backend, narrow the consumer's interface to consume only the shared (typed IR) surface, document the result. The wave is not creative; it is descriptive. Era V's failure mode (substrate-first/consumer-later) was creative substrate without a consumer; BC.W0's invariant is that the consumer (Rust emitter refactor) lands in the same wave as the spec.
