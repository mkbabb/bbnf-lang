# BB.W3 — Grammar-specific rule discovery + per-grammar authoring

**Opens after**: W2 close
**Agents**: 2 parallel
**Hard gate**: Every shipped production grammar has a populated
`grammar/<name>/rewrites/` directory with at least the rules surfaced
by the enumerator for that grammar's idioms; grammar-specific rule
discovery is exercised on at least three grammars; `cargo xtask regen`
compiles every populated directory into the corresponding cost-config
without manual edits.
**Status**: planned

## Scope

1. Extend the enumerator to operate on per-grammar corpora with
   grammar-local alphabet constraints (shorthand folds, nonterminal
   inlining, grammar-specific literal fusion).
2. Exercise the pipeline on every production grammar — JSON, Sheets,
   CSS L4, BBNF, plus any additional grammar in the workspace — with
   per-grammar budget and ceiling.
3. Author `grammar/<name>/rewrites/*.ron` files for rules that belong
   to a single grammar rather than the fleet; `cargo xtask regen`
   picks them up automatically at IR-pipeline time.
4. Confirm end-to-end extensibility: add one synthetic grammar with
   three handcrafted rewrite rules under `grammar/<synthetic>/
   rewrites/`, confirm they compile and take effect with zero edits to
   `crates/core/` or the regen-emitter.

## File bounds

| File | Access |
|---|---|
| `grammar/<name>/rewrites/*.ron` | create (per production grammar) |
| `grammar/synthetic-extensibility/rewrites/*.ron` | create (smoke) |
| `docs/rules/runs/W3-<grammar>.md` | create (per grammar) |
| `docs/rules/<rule-id>.md` | create (per-accept) |
| `docs/rules/rejected/<rule-id>.md` | create (per-reject) |
| `docs/rules/audit-log.ndjson` | append |

**Do NOT touch**: the enumerator / oracle / ranker / regen rewrite-
discovery modules (frozen at W0); any `crates/core/` file; fleet-wide
rule files from W1 + W2.

## Phase sub-items

### BB.W3.1 — Per-grammar enumeration sweeps

Run the enumerator with grammar-local alphabet constraints on every
production grammar. Emit per-grammar run reports.

Sub-gate: each production grammar has a `docs/rules/runs/W3-<name>.md`
with ranked candidates, tier assignments, and acceptance verdicts.

### BB.W3.2 — Grammar-colocated rule authoring

Rules that score as grammar-specific (low generality score) land
under `grammar/<name>/rewrites/`; fleet-wide winners land under
`crates/ir/src/rewrites/inferred/`. The ranker's generality signal
drives the decision automatically.

Sub-gate: every production grammar with accepts has a populated
`rewrites/` directory; no rule mis-routed across the fleet-wide /
grammar-specific boundary.

### BB.W3.3 — Extensibility smoke

Author `grammar/synthetic-extensibility/` with a trivial grammar and
three handcrafted `rewrites/*.ron` files. Run a clean build. Confirm
the rules compile into cost-config and apply at emission with zero
edits to `crates/core/`, the regen-emitter, or any other crate.

Sub-gate: `cargo check --workspace --profile ax-iter` green after the
synthetic grammar lands and after it is removed; build log confirms
discovery.

### BB.W3.4 — Review ledger

Per-rule docs + rejected rationales.

Sub-gate: every accept / reject has its markdown.

## Hard gate

1. `cargo check --workspace --profile ax-iter` green before + after the
   synthetic extensibility grammar.
2. Every production grammar ships a `grammar/<name>/rewrites/` directory
   populated with the W3 accepts for that grammar.
3. 17-entry AU-baseline matrix at or above AZ close on every entry.
4. Parity harnesses green for all production grammars with accepts.
5. No edit required to `crates/core/` or the regen-emitter for the
   extensibility smoke.
