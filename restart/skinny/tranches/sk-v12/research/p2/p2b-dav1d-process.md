VLC's standalone checkasm project describes checkasm as a correctness-verification and benchmarking tool for assembly code, with reference/optimized calls and platform checks for register, stack, and vector-state mistakes [VLC1]. Its history records a dav1d internal origin, itself derived from FFmpeg/x264-style checkasm variants [VLC2].
12. FFmpeg's checkasm contract is the mechanical model: `check_func` pairs reference and candidate functions, `call_ref` invokes the reference under signal-handler state, `call_new` invokes the optimized function through checked-call/stack-clobber wrappers, and `bench` repeats timed calls with an outlier filter [FF1] [FF2].
13. dav1d's `msac` checkasm shows the stateful scalar-oracle pattern: clone reference/candidate decoder state, call C/reference and ASM/candidate, compare return values plus mutated state/CDF buffers, and only then benchmark [D1].
14. bbnf-simd already has the local checkasm shape: deterministic xorshift inputs, cloned reference/candidate buffers, source mutation detection, alignment sweeps, stack canaries, signal guards, strict mode, corpus parity, and outlier-filtered bench reporting (`skinny/crates/bbnf-simd/CHECKASM-REPORT.md:41-63`; `skinny/crates/bbnf-simd/tests/checkasm_parity.rs:1-20`, `:200-226`, `:233-371`, `:387-410`).
15. The existing scalar oracle surface covers table byte-class, eq-set byte-class, bitmap prefix-XOR, next-set-bit, bulk position emit, and EOB tail clamp (`skinny/crates/bbnf-simd/src/scalar/byte_class_from_table_64.rs:1-10`; `skinny/crates/bbnf-simd/src/scalar/byte_class_from_eq_set_64.rs:1-38`; `skinny/crates/bbnf-simd/src/scalar/bitmap_prefix_xor_64.rs:1-14`; `skinny/crates/bbnf-simd/src/scalar/bitmap_next_set_bit.rs:1-13`; `skinny/crates/bbnf-simd/src/scalar/bulk_emit_positions_64.rs:1-13`; `skinny/crates/bbnf-simd/src/scalar/eob_pad_clamp.rs:1-19`).
16. The local coverage audit names five carried aarch64 orphans: `bitmap_prefix_xor_64`, `bitmap_next_set_bit`, `bulk_emit_positions_64`, `byte_context`, and `cache_hints`; close requires zero orphans by admission, removal, or inventory demotion (`restart/skinny/tranches/sk-v12/research/skv12-aarch64-simd-coverage-audit.md:34-61`; `restart/skinny/tranches/sk-v12/SYNTHESIS.md:57-65`).

Admission process S-P3 gates against:

1. Scalar oracle first: exact scalar reference defines output, invalid inputs, tail behavior, carry state, fallback, and mutation contract.
2. Differential/checkasm second: cloned inputs, alignment/adversarial/corpus cases, strict mode, source immutability, stack canary, signal/crash guard, and bug-injection proof where harness code changes.
3. Lock 16 provenance third: allowlisted instruction family or appended cited primitive, feature-gated dispatch, scalar fallback, no handwritten `asm!` where `core::arch` intrinsic exists.
4. Micro-prove-first fourth: caller-local microproof on the selected baseline slice, with strict output equality and a named threshold before production wiring.
5. Same-wave consumer fifth: no orphan primitive; same wave must consume in generated/runtime/parser/report/oracle code and record consumer class.
6. Strict comparator sixth: consumer proof and any row movement use the same corpus, same output plane, strict equality, and the correct comparator; permissive/lossy rows are flaw probes only.
7. Lock 1/14/16 close seventh: no sidecar substrate, no grammar policy in generic crates, no SIMD before `escape_mask_64` is resolved, and zero production orphan kernels at close.

## §4 — Risks (REDRESS entries any candidate must NOT re-open)

1. `escape_mask_64` blocks SIMD admission until fixed. S-P3 must not schedule any new SIMD row before the strict xorshift/checkasm repro is green and the fix is verified (`skinny/crates/bbnf-simd/CHECKASM-REPORT.md:102-126`; `restart/skinny/tranches/sk-v12/HANDOFF.md:125-138`).
2. USER PIN D3/D4 reopen categories, not old patches. REDRESS 96/97/98 and 88/89/90 remain measured history; new union or ASM-gen attempts must cite them, name a material differential, micro-prove, pass checkasm/parity, and wire a same-wave consumer (`restart/skinny/tranches/sk-v12/USER-PIN-W1-CSS-L4-SOTA.md:39-69`, `:108-121`).
3. PMULL prefix-XOR and CSSC CTZ/body-fill remain rejected as measured implementations. REDRESS 88 rejected PMULL prefix-XOR despite correctness/asm visibility after parse regressions (`skinny/REDRESS.md:2508-2540`). REDRESS 89 rejected the CTZ/bulk consumer despite correctness gates (`skinny/REDRESS.md:2542-2585`). D4 permits new material-differential consumers; it does not admit these bodies by citation alone.
4. Union substrate cannot become a parallel sidecar. REDRESS 96/97/98 show full class-column and streaming-cursor variants were correctness/parity green but measured worse; any D3 attempt must stay inside Lock 1's single substrate and not resurrect a retained side vector or parser-owned structural projection (`skinny/REDRESS.md:2850-2940`; `restart/locks/LOCKS.md:52`).
5. String/Unicode proof-only routes stay constrained. REDRESS 106 rejected the broad string primitive proof at caller level despite scalar/checkasm parity (`skinny/REDRESS.md:3150-3170`). REDRESS 117 blocks escaped-segment production and admits no x4 production consumer (`skinny/REDRESS.md:3434-3460`). P2-B candidates must be narrow and caller-proved.
6. Numeric shortcuts stay constrained. REDRESS 114 rejected numeric direct closure after measurement (`skinny/REDRESS.md:3357-3380`). A digit-span primitive must attach to the selected generated baseline and leave grammar numeric policy outside the SIMD body.
7. Output digest is not parser optimization by default. REDRESS 118 blocks the digest/hash host-sink route without a legal residual row, consumer, and independent oracle (`skinny/REDRESS.md:3462-3493`).
8. JSON direct residuals are a guard ledger, not S-P2's primary target. REDRESS 119/120 close SK-V11 direct residuals as measured fixpoint and route SK-V12 toward generated non-JSON/CSS L4 first (`skinny/REDRESS.md:3495-3553`; `restart/skinny/tranches/sk-v12/HANDOFF.md:50-69`).
9. Orphans fail close. The SK-V12 close requires the carried aarch64 orphan set to be zero by admission, removal, or inventory demotion (`restart/skinny/tranches/sk-v12/SYNTHESIS.md:57-65`; `restart/skinny/tranches/sk-v12/research/skv12-aarch64-simd-coverage-audit.md:34-61`).
10. Strict comparator discipline is mandatory. CSS L4 admission requires generated Track 1 > `lightningcss_mbps + 1` on the same corpus, same output plane, same host, and strict equality; JSON parse-only and permissive/lossy comparator rows remain diagnostics/flaw probes (`restart/skinny/tranches/sk-v12/SYNTHESIS.md:37-60`; `restart/skinny/tranches/sk-v12/HANDOFF.md:54-67`).
