# AZ.W5 — CSS L4 @import Split + DFA Hoist + Shared PHF (Compile-Time A/B/D)

**Opens after**: W3 close (after `<Grammar>Value` emission lands; compile-time work may restructure emit surface + shouldn't precede W3 surface stabilisation)
**Agents**: 3 parallel (@import split + DFA hoist + shared PHF)
**Hard gate**: CSS L4 test-binary cold compile time ≤ 1.3s (from W0 baseline ~1.81s); CSS L4 `.bbnf-cache` byte count reduced ≥ 25%; workspace cold build time reduced ≥ 10%; all 14 parity harnesses green; no parse-time regression ≥ 2%.

## Scope

1. **CSS L4 @import split emission** (A4 L-A): today CSS L4 emits a single ~13 MB token stream (197 kloc) under one `#[derive(Parser)]` invocation. Split per `@import` module → each imported grammar gets its own `mod __part_<N>` with per-module regen + rustc isolation. Reduces macro_expand_crate cost + enables per-CGU parallelism under release cgu=1.
2. **Hoist DFA + keyword + byte-class tables to `pub(crate) const`** (A4 L-B): currently these emit as inline match ladders inside per-rule parse fns. Hoisting relocates 20-30% of cache lines out of fn bodies. Compile-time win + mild runtime win (BTB).
3. **Shared keyword-dispatch PHF across CSS L4 rules** (A4 L-D): color keywords + property-name keywords + at-rule-keyword sets overlap. Dedup into shared `pub(crate) const` PHF tables; per-rule lookup references the shared table. 0.5-1.5 MB cache savings.

## Phase sub-items

### AZ.W5.1 CSS L4 @import-split emission (parallel agent A)

Mechanism:
- Audit current CSS L4 expansion: `grammar/css/l4/stylesheet.bbnf` `@import`s 14 sibling files. Currently all tokens flatten into one stream.
- Modify `crates/derive/src/lib.rs` proc-macro: when grammar has `@import` directives, emit `mod __part_<module_name> { … }` per imported grammar + cross-module `pub(super) use` re-exports.
- Verify split preserves IR equivalence (same rule set + types post-inline).
- Measure cold-compile cost on CSS L4 test binary.

Files: `crates/derive/src/lib.rs`, `generated.rs` regen.

**Sub-gate**: `cargo test --no-run -p bbnf --test css_l4_comment_probe --profile ax-iter` wall ≤ 1.3s (from ~1.81s). Per-module compile successfully on shallow fixtures.

### AZ.W5.2 DFA + byte-class hoist (parallel agent B)

Mechanism:
- `crates/core/src/generate/regex/dfa_codegen.rs` currently emits transition tables as inline match ladders. Refactor to emit each DFA as `pub(crate) const DFA_<rule>_<regex_id>: […; N]` at module top-level + per-rule parse fns reference the const.
- Same for byte-class dispatch tables.
- Verify cache-size reduction via `.bbnf-cache` byte count.

Files: `crates/core/src/generate/regex/dfa_codegen.rs`, `generated.rs`.

**Sub-gate**: `.bbnf-cache` byte count reduced ≥ 15% on CSS L4 (cumulative with W5.1 + W5.3 → ≥ 25% target).

### AZ.W5.3 Shared keyword PHF (parallel agent C)

Mechanism:
- Audit per-rule keyword-dispatch emissions in current CSS L4 generated.rs. Identify overlapping keyword sets (color names × color rules; property names × styleRule + inline-style rules; at-rule keywords × `@media` + `@supports` + `@import`).
- Emit shared `pub(crate) const PHF_COLORS: phf::Map<&str, u32>`, etc. Per-rule parse fns reference the shared consts.
- Dedup via StringId equivalence at codegen time.

Files: `crates/core/src/generate/keyword/phf.rs`, `crates/core/src/backend/rust/emitter/shapes/keyword.rs`, `generated.rs`.

**Sub-gate**: CSS L4 `.bbnf-cache` byte count reduced ≥ 10% attributable to PHF dedup (measured via before/after diff with only W5.3 active on a probe branch).
