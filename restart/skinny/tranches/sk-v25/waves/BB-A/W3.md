# BB-A.W3 — architecture policy clean cut

## Authority

Consumes BB-A.W2 dispositions and the relevant parse-that scanner contract. It may
delete a route only with same-change replacement proof.

## Implementation

1. Remove x86 names and code at their sources: Cargo features/cfgs/dependencies,
   intrinsics, emitters, generated code, CI, benchmarks, reports, comparators,
   documentation, fixtures, and dispatch tables. Do not rename scalar code NEON.
2. Establish scalar Apple/aarch64 references. Retain or add NEON only where actual
   intrinsics win paired corpora and pass exhaustive tail/boundary differentials.
3. Route regex/scanner ownership directly to the sealed parse-that packages.
   Delete root/skinny duplicates in the same cut; no aliases, vendor copies, or
   fallback dispatch.
4. Remove false architecture wrappers and regroup surviving scan code by operation
   invariant. Strip directory/module-name stutter in child files.
5. Make unsupported target attempts typed build failures instead of scalar routes
   hidden behind architecture names.

## Evidence gates

- Repository-wide authored/config/CI/docs/generated scan contains no x86/AVX/SSE
  vocabulary except historical supersession evidence explicitly excluded from
  builds and search gate inputs.
- Scalar/NEON/parse-that differentials cover empty, short, unaligned, boundary,
  tail, invalid Unicode, and guard-page inputs.
- Every retained specialization has raw paired Apple Silicon measurements and a
  real intrinsic implementation.
- Graph extraction finds one scanner/regex production home and no compatibility
  edge.
- Clean builds regenerate x86-free outputs twice identically.

## Completion

Apple/aarch64 policy is structural truth rather than feature rhetoric; duplication
and architecture theater are deleted.
