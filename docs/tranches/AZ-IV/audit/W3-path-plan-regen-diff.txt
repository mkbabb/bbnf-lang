Grammar generality enforcement
------------------------------

`crates/core/src/backend/rust/emitter/path_plan.rs` is grammar-general
by construction:

- The emitter walks `StructRegistry::iter()` (every layout, in `RuleId`
  order) and projects from `LayoutKind` + `StructField::source` —
  both facts the `project_types` CSP solver computes from grammar
  data.
- No literal rule names, parser idents, or grammar-name strings
  appear in the emitter.
- AST scan over the file:

    rg -n '"json"|"css"|"sheets"|"bbnf"|"csv"|"ebnf"|"math"|"bnf"' \
       crates/core/src/backend/rust/emitter/path_plan.rs

  returns zero hits (verified at commit time).
- `match` arms in the emitter key off `LayoutKind` / `FieldSource` /
  `SegmentKindTag` / `Decision` — the projected discriminator
  vocabulary, never a rule-name string.

Adding a new grammar to the workspace manifest produces a
deterministic path plan for that grammar with zero changes to this
module.
