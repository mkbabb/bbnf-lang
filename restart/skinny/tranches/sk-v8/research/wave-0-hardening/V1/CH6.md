# CH6 W0 Hardening Review - SK-V8

## Decision

REJECT

## Acceptance Probability

58%

## Blocking Findings

1. Strict-admission and unsupported-outcome checks are implemented only as isolated unit helpers, not as live `gate-json` admission gates. `SPEC.md:73-79` and `SPEC.md:140-143` require executable gate rejection for strictness mismatch, stale sidecar evidence, unsupported outcomes, and other non-admission telemetry; W0 Section 3 repeats that `gate-json` must reject unsupported outcomes and strict admission failing Section 0.2 (`restart/skinny/tranches/sk-v8/SPEC.md:357-359`). The production gate path only calls `report.validate_schema_v3().and_then(|_| report.validate_sk_v8_w0())` before writing (`skinny/crates/bbnf-bench/src/bin/gate.rs:281-283`). `validate_sk_v8_w0` checks required fields, row ids, parse-only `K|S`, and throughput deltas, but never calls `parse_outcome_id` or `validate_strict_admission` (`skinny/crates/bbnf-bench/src/report.rs:275-367`, `skinny/crates/bbnf-bench/src/report.rs:489-515`). The strict-admission validator itself is present (`skinny/crates/bbnf-bench/src/gate.rs:133-169`), but `rg` found uses only in unit tests (`skinny/crates/bbnf-bench/src/gate.rs:443-478`). This leaves the core W0 negative gate paper-closed.

2. The malformed sidecar manifest requirement is not actually covered by a manifest parser or gate input. W0 requires sidecar freshness validation and malformed-manifest rejection (`restart/skinny/tranches/sk-v8/SPEC.md:357-370`), and P3-D says populated sidecar cells need manifest coverage for corpus identity, binary identity, hardware, build flags, run date/run id, comparator plane, comparator strictness, and freshness (`restart/skinny/tranches/sk-v8/research/p3/p3d-telemetry-schema.md:173`). Current code still populates C++ sidecar Mbps from hard-coded maps (`skinny/crates/bbnf-bench/src/bin/gate.rs:690-702`, `skinny/crates/bbnf-bench/src/bin/gate.rs:721-758`) and stamps them as `historical:sk-v7-sidecar-profile` string evidence (`skinny/crates/bbnf-bench/src/bin/gate.rs:491-512`). The negative test named as malformed sidecar coverage only mutates in-memory comparator evidence to make a value conflict with `absent:*` (`skinny/crates/bbnf-bench/src/report.rs:1230-1252`); it does not parse or reject a malformed sidecar manifest. That does not satisfy the W0 close condition that `gate-json` reject one intentionally malformed sidecar manifest.

3. The committed `RESULTS.md` manifest is not current-tree idempotent because its run id embeds a pre-commit SHA. The gate builds `run_id` from `git rev-parse --short HEAD` (`skinny/crates/bbnf-bench/src/bin/gate.rs:333-341`), current `HEAD` is `6d8cb701`, but the committed manifest rows contain `sk-v8-open:0bd16f6d:/tmp/skv8-w0-target/criterion` (`skinny/RESULTS.md:48`). W0 verification requires refreshed `RESULTS.md` to be generated by the gate path (`restart/skinny/tranches/sk-v8/research/wave-0-plan.md:134`) and the W0 verification research requires a second `gate-json` run to leave `RESULTS.md` unchanged (`restart/skinny/tranches/sk-v8/research/wave-0-verification-plan-research.md:68-80`). With the current run-id construction, a current-tree `gate-json` rerun would rewrite the run id even if measurements are unchanged.

## Nonblocking Findings

- The required W0 plan command is syntactically invalid: `(cd skinny && cargo test -p bbnf-bench report::tests gate::tests lock14_baseline::tests)` (`restart/skinny/tranches/sk-v8/research/wave-0-plan.md:112-119`) fails with Cargo's "unexpected argument 'gate::tests'". This is nonblocking only because `cargo test -p bbnf-bench` itself passes, but the plan should name a runnable command.
- `skinny/RESULTS.md` uses `S` for parse-only non-admissions, while the plan's admit gate says `K` (`restart/skinny/tranches/sk-v8/research/wave-0-plan.md:126-131`). SPEC permits `K` or `S` if W0 amends the schema (`restart/skinny/tranches/sk-v8/SPEC.md:364-367`), so this is a plan wording mismatch, not a blocker.

## Exact Remediation If Rejected

1. Wire strict-admission and unsupported-outcome validation into the production W0 gate path, not just unit tests. `Report::validate_sk_v8_w0()` or an adjacent gate validator must parse every row outcome, reject unknown ids, and call `validate_strict_admission` whenever a row is represented as an admission claim. Add report/gate-path tests proving unsupported non-parse outcomes and deferred/view-boundary strict claims fail the same validator that `gate-json` invokes.
2. Replace hard-coded populated C++ sidecar cells with either a structured manifest parser/validator or explicit `absent:<reason>` cells. If populated sidecars remain, add a malformed manifest fixture that goes through the `gate-json` validation path and fails on missing run id/binary identity/corpus mismatch/unsupported freshness, not merely an in-memory value/freshness contradiction.
3. Make committed `RESULTS.md` idempotent under the current tree. Either remove volatile `HEAD` from `run_id`, derive it from the measured metadata source revision, or regenerate the manifest with a stable run-id scheme; then prove the documented second `gate-json --advisory` leaves `RESULTS.md` unchanged.
4. Fix the W0 plan's focused test command to a runnable form, for example `cargo test -p bbnf-bench` or separate filtered invocations.
