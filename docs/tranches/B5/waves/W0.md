### Cluster A — VariantShape::Cursor panic stub (6 failures)

**Failing tests**:

- `value_api_apples_to_apples json_roundtrip_object`
- `value_api_apples_to_apples json_roundtrip_array_of_strings`
- `value_api_apples_to_apples json_roundtrip_nested_array`
- `value_api_apples_to_apples json_roundtrip_mixed_value_types`
- `ay_w3b_value_api_smoke`
- `parse_count_invariant`

**Symptom**: panic at the `VariantShape::Cursor` arm of `peel_body`
in `crates/core/src/backend/rust/view/value.rs:249-254`. The
function only handles `Map` and `OptionalWhitespace`; JSON's
`array` and `object` body shapes peel to `Skip` / `Next` and fall
through to the panic stub.

**Root cause** (audit β finding): the sibling
`unwrap_structural_wrappers` in
`crates/core/src/backend/rust/view/named_types.rs:170-185`
already handles `Skip` / `Next` correctly. The two functions are
duplication-with-divergence — the same peel logic implemented
twice, one branch correct, the other incomplete. Per
`feedback_no_god_modules` and the user's gestalt directive, the
fix is consolidation: hoist `unwrap_structural_wrappers` into a
shared module, route both callsites through it, delete
`peel_body`.

**Mechanism**:

1. Create `crates/core/src/backend/rust/view/peel.rs`. Move
   `unwrap_structural_wrappers` there. Re-export from
   `view/mod.rs`.
2. In `value.rs`, delete `peel_body`. Replace its single
   callsite with `peel::unwrap_structural_wrappers(...)`.
3. In `named_types.rs`, replace the local
   `unwrap_structural_wrappers` reference with `peel::...`.

LOC: ~5 net. The peel module gathers the function; the two
callsites switch to the shared name.

### Cluster B — `[U32, U32]` synthesis layout mismatch (1 failure)

**Failing test**: `projection_totality projection_totality_runtime_call_count`.

**Symptom**: outer materialiser panic on
`tape.payload_bytes(rec, 8)` returning `None` for a JSON `string`
admission.

**Root cause**: the resolver in
`crates/core/src/backend/rust/view/named_types.rs:154-156`
synthesises a `[U32, U32]` aggregate for any single-leaf regex /
literal kernel admission. JSON's `string -> ... : String`
admits as 2×u32 (`total_bytes=8`). The runtime emits via
`parse_string_escaped` writing a different layout (a borrow-via-
frame). When the materialiser asks for `payload_bytes(rec, 8)`
it gets `None` — the layout the resolver synthesised is not the
layout the runtime wrote.

**Architectural fix** (per `feedback_pluggable_components`):

1. Introduce a `MaterializerKind::SpanFromFrame` arm in
   `crates/core/src/backend/rust/emitter/shapes/value_materialize.rs`
   for borrow-via-frame admissions. The arm reads the span from
   the frame stack instead of from the payload column.
2. Remove `TypeDesc::Span` from `is_scalar_payload()` at
   `crates/ir/src/types/type_desc.rs:89-104`. Span is not a
   scalar payload; it is a frame-borrow. The classification
   was the upstream cause of the wrong synthesis.
3. Stop synthesising `[U32, U32]` for non-`Tuple` kernel
   admissions in `named_types.rs:154-156`. Single-leaf admissions
   that are not `Tuple` projections do not get aggregate
   synthesis; they get the pluggable materialiser arm chosen
   by their actual kernel kind.

LOC: 30-50 net. The fix is pluggable per
`feedback_pluggable_components`: a new `MaterializerKind` arm,
not a special case.

A per-grammar regen sweep follows because the synthesis change
ripples into generated `view` code for the nine grammars.

### Cluster C — `ParserAttributes` lock-step invariant (2 failures)

**Failing tests**:

- `pipeline_compile_request compile_paths_preserves_pretty_directives_json`
- `pipeline_compile_request compile_paths_preserves_pretty_directives_bbnf`

**Symptom**: runtime invariant violation at
`crates/core/src/backend/rust/ir_enums.rs:36`
asserting `paths.len() == grammar_rel_paths.len()`.

**Root cause**: `ParserAttributes::default()` followed by partial
struct update `{ paths, ..Default::default() }` violates the
lock-step `paths` / `grammar_rel_paths` invariant. The runtime
assert at `ir_enums.rs:36` papered over what should have been a
constructor invariant.

**Architectural fix**:

1. Add `ParserAttributes::with_paths(paths: Vec<PathBuf>) -> Self`
   constructor at `crates/core/src/backend/rust/ir_types.rs`. The
   constructor populates both `paths` and `grammar_rel_paths`
   atomically — the lock-step invariant holds at the type
   surface, not at runtime.
2. Delete the runtime assert at
   `crates/core/src/backend/rust/ir_enums.rs:36`. The constructor
   invariant replaces it.
3. Migrate the two test fixtures at
   `crates/core/tests/pipeline_compile_request.rs:175,216` to
   call `ParserAttributes::with_paths(...)`.

LOC: ~15 net.

### Cluster D — Recursive walker stack overflow (1 failure)

**Failing test**: `sheets_parity::child_iter_walks_complex_formula`
SIGABRT.

**Symptom**: stack overflow in the recursive `walk()` helper at
`crates/core/tests/sheets_parity.rs:45-64` when fed a
`=IF(A1>10, SUM(B1:B10), 0)`-class formula.

**Root cause**: pre-existing test-helper bug, unrelated to the
substrate weld. The recursive walker overflows on deep formulas;
the iterative form does not.

**Mechanism**: convert `walk()` to an iterative `Vec<TapeCursor>`
worklist. Push the root, then in a loop: pop, visit, push
children in reverse order. Same traversal order, no stack
exhaustion.

LOC: ~15 net.

### Bonus — `payload_bytes` precondition

**File**: `crates/tape/src/tape.rs:743-753`.

**Symptom**: latent. No test fails today, but the audit flagged
this as silent-misread risk: `payload_bytes` does not check the
`PAYLOAD_IN_ARENA_BIT` precondition before reading from the
arena column. A future caller that violates the bit invariant
gets a silent garbage read instead of a `None` or panic.

**Mechanism**: prepend a `debug_assert!` (or `if !rec.has_bit(...)`
returning `None`) gating the arena read on the bit. The
precondition is documented in the existing function comment but
not enforced; W0 enforces it.

LOC: ~5 net.

## Archaeology

The four-cluster pattern emerged from the β agent of the
pre-tranche four-agent gestalt audit. Each cluster's root cause
was reduced from "this test fails" to "this architectural
duplication / classification / invariant is the actual fault";
the audit's distinguishing rigour was insistence that a six-test
cluster does not justify six band-aids. Cluster A's peel
duplication, Cluster B's classification + synthesis chain,
Cluster C's runtime-vs-constructor invariant placement, and
Cluster D's straightforward recursion-to-iteration are the root
causes. The bonus precondition is independent: a separate audit
finding flagged the silent-misread risk; the wave folds it in
because the surface is open and the cost is five lines.
