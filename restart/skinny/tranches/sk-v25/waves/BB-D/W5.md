# BB-D.W5 — legible capability and novelty product

## Goal

Expose the new compiler/runtime system as understandable user capabilities and add
one end-to-end ability that did not exist at campaign start.

## Implementation

1. Let a user choose authoritative entry rule, edit grammar/input, parse, and inspect
   typed value, qualified spans, diagnostics/recovery, and generated/runtime face.
2. Present sealed stage summaries—dependency/SCC, inferred rule/node types, analysis
   facts, selected LoweringPlan decisions, optimizer reports, and artifact provenance—
   through focused views, not undifferentiated debug dumps.
3. Connect parse-that/value.js dogfood visibly where it aids understanding, without
   leaking provider internals or inventing a second product model.
4. Implement a novel route, such as tracing one value path from grammar constraint
   through inferred type/layout into parsed runtime value and generated artifact.
5. Start the novelty route from empty generated outputs and packed dependencies;
   record its semantic and browser journey as a release gate.

## Gates

- A new user can trace source -> semantic stages -> typed value/artifact without
  hidden state or code knowledge.
- Every displayed fact is keyed to and invalidated with the active revision.
- Novelty is load-bearing end-to-end and fails on stale/disconnected stage mutation.
- UI remains pithy: progressive disclosure, no walls of internal JSON.

## Completion

The demo proves why the architecture exists rather than merely surviving it.
