## §1 — Findings (concrete; file:line on bbnf claims, citation on external claims)

### §1.1 — Lock 14 binding restated for primitive admission

`restart/locks/LOCKS.md:220` (Lock 14 main clause): "The substrate carries ZERO grammar-specific code. … Generic crates … carry ZERO `match grammar { Json => ..., CssL4 => ..., ... }` arms; ZERO grammar-named modules; ZERO grammar-specific types in their public APIs; ZERO per-grammar feature flags." This binds the **upper** end — what generic crates must not contain. The **lower** end — what a single primitive must do to qualify as grammar-neutral — is in the Lock 14 v+1 amendment at `restart/locks/LOCKS.md:255-263`:

> Shared `bbnf-simd`, parse-that, and future regex APIs expose grammar-neutral facts and primitives only. Quote, escape, control, delimiter, number, string, and no-string/no-number policy must come from generated grammar config or caller data, not hardcoded JSON/CSS constants. **A primitive claimed grammar-neutral must exercise at least one non-JSON consumer or record a measured deletion/rejection.**

This is the operative admission gate. P2-F partitions every candidate primitive into one of five verdict buckets keyed off this clause:

| Verdict | Meaning | S-P3 disposition |
|---|---|---|
| **NEUTRAL-WIRED** | grammar-neutral by construction; concrete non-JSON consumer (CSS L4, Sheets, BBNF-self) named in the same wave as JSON admit | shortlist candidate as-is |
| **NEUTRAL-PENDING-CONSUMER** | grammar-neutral by construction; non-JSON consumer named for the SAME wave (cannot defer to later wave); fails closed if consumer doesn't materialise | shortlist with same-wave-consumer gate |
| **NEUTRAL-CONFIG-DRIVEN** | grammar-neutral if and only if quote/escape/control/delimiter/number policy is sourced from generated grammar config or caller data, never hardcoded; non-JSON consumer reuses the same primitive with different config | shortlist with config-source binding |
| **JSON-OVERFIT-REFRAMABLE** | currently JSON-specific in source but the underlying byte-set/classifier/tape operation generalises; S-P3 must re-express as a NEUTRAL-CONFIG-DRIVEN primitive or reject | REVISE — re-express required |
| **JSON-OVERFIT-IRREDUCIBLE** | tied to JSON grammar shape (structural roles, object/array/pair vocabulary, JSON-specific number form); cannot be re-expressed without re-importing JSON policy into a generic crate | REJECT — JSON policy never enters generic crate |

CSS L4 cross-grammar witness sources (spec + grammar-source authority since profile evidence is absent per CH2 F2):
- `grammar/css/l4/tokens.bbnf:7-9`: `ident = /[a-zA-Z_\x80-\xff][\w\x80-\xff-]*/`; `string = /"(?:[^"\\]|\\[\s\S])*"/ | /'(?:[^'\\]|\\[\s\S])*'/` — CSS L4 has identifier and string primitives byte-isomorphic to JSON's identifier-key and quoted-string-value, except CSS allows single-quoted strings and the identifier byte-set is wider (Latin-1 extended `\x80-\xff` allowed; CSS-escape sequences `\\[^\n]` allowed). The byte-set widening is grammar-config-driven, not grammar-structural.
- `grammar/css/l4/value-unit.bbnf:15`: `number = /[-+]?(\d+(\.\d+)?|\.\d+)([eE][-+]?\d+)?/ -> f64` — CSS L4 number grammar admits bare `.5` leading-dot literals that JSON-strict scanner rejects. Per the file's prose comment lines 9-14: "The emitter reads `allow_leading_dot: true` off the regex classifier and routes this rule through `parse_that::scan_number_f64` (`GENERIC_NUMBER_CONFIG`) rather than the JSON-strict scanner." This is the Lock 14 v+1 paradigm working in extant code: one number primitive, two grammar configs (JSON-strict and CSS-permissive), parametrised by `allow_leading_dot`.
- `grammar/css/l4/value-unit.bbnf:20-58`: `absoluteLengthUnit`, `viewportLengthUnit`, `containerLengthUnit`, `fontLengthUnit`, `angleUnit`, `timeUnit`, `frequencyUnit`, `resolutionUnit`, `flexUnit`, `percentageUnit` — CSS L4 ships dozens of keyword-set primitives (3-letter to 5-letter ASCII keyword sets like `"px"`, `"rem"`, `"vmin"`, `"cqmax"`). These are byte-isomorphic to JSON's keyword set `{"true", "false", "null"}` but larger and per-rule scoped. The primitive shape "match-one-of-a-tiny-keyword-set" generalises directly.
- `grammar/google-sheets/google-sheets.bbnf:6`: `number = /(\d+\.?\d*|\.\d+)([eE][+-]?\d+)?/ -> f64` — Sheets shares CSS's "leading-dot allowed" number policy.
- `grammar/google-sheets/google-sheets.bbnf:12`: `string = /"([^"]|"")*"/` — Sheets uses **doubled-quote escape** (`""` decodes to `"`), not backslash-escape. The escape primitive must be config-driven: JSON uses `\\`-escape with the JSON escape alphabet; CSS uses `\\`-escape with the CSS escape alphabet; Sheets uses doubled-quote with no backslash. **One escape-decode primitive, three escape-config tables**.
- `grammar/google-sheets/google-sheets.bbnf:34-42`: `error_literal = "#N/A" -> 0u8 | "#VALUE!" -> 1u8 | …` — Sheets has its own 9-entry tiny-keyword set; same primitive shape as JSON `{"true", "false", "null"}` and CSS `{"px", "em", ...}`.
- `grammar/google-sheets/google-sheets.bbnf:52`: `sheet_prefix = /'(?:[^']|'')*'!|[A-Za-z_]\w*!/` — single-quoted string with doubled-quote escape; reuses the Sheets string primitive's escape config.
- `grammar/google-sheets/google-sheets.bbnf:63`: `cell_ref = /\$?[A-Za-z]{1,3}\$?\d+/` — alphanumeric identifier with `$` sigil; reuses the identifier classifier primitive with an `allow_sigil: '$'` config.
- `grammar/bbnf/bbnf.bbnf:9`: `identifier = /[_a-zA-Z][_a-zA-Z0-9-]*/ -> Span` — BBNF-self identifier byte-set; subset of CSS's selector-ident byte-set, superset of JSON object-key byte-set (which is the quoted-string range, not bare identifier).
- `grammar/bbnf/bbnf.bbnf:11-13`: `literal = ( "\"" , /(\\.|[^"\\])*/ , "\"" | "'" , … | "`" , … ) -> Span` — BBNF-self uses triple-form quoted strings (double, single, backtick) with backslash-escape. The string primitive is identical in shape to JSON's, with a 3-entry quote-set rather than a 1-entry quote-set, and the same backslash-escape config.
- `grammar/bbnf/bbnf.bbnf:15`: `regex = ( "/" , /(\\.|[^\/])+/ , "/" ) -> Span` — BBNF-self regex literal: forward-slash delimiter with backslash-escape. Same string primitive shape with `quote: '/'` config.
- `grammar/bbnf/bbnf.bbnf:17-18`: `big_comment = ( "/*" , /[^\*]*/ , "*/" )`; `comment = ( "//" , /.*/ )` — block comment and line comment primitives. CSS L4 has identical `/* */` block comment surface; JSON has neither but `json-commented` (`grammar/misc/json-commented.bbnf`) does. The comment-skip primitive is grammar-neutral with `block_open / block_close / line_marker` config.

These eight grammar-source observations are the cross-grammar generalisation evidence base for the CH2 verdicts in §3.

### §2.3 — Candidate C3 — escape-canonicalisation (`\uXXXX` hex-unit decode + JSON-escape alphabet)

- **Shape**: byte-stream input → owned-or-borrowed string output. Per-byte cases: literal byte (copy); backslash + simple-escape (replace per escape alphabet); backslash + `u` + 4 hex digits (decode UTF-16 code unit, possibly pair with surrogate pair → emit UTF-8). Escape alphabet is config-driven: JSON alphabet is `{n→\n, t→\t, r→\r, b→\b, f→\f, "→", \\→\\, /→/, u→\uXXXX}`; CSS alphabet is `{any char→that char, hex-digits→\xXX..X, newline-escape→continuation}` (broader, fewer named escapes, hex form `\26 ` not `&`); BBNF-self uses JSON-shaped alphabet; Sheets uses doubled-quote-escape only (no backslash alphabet).
- **Scalar-ref status**: existing (`parse_that_regex::unescape_string` at `parse-that-regex/src/lib.rs:718`); the JSON-specific escape alphabet is currently hard-coded inside this function (CH2 risk — Lock 14 v+1 mandates "Quote, escape, control, delimiter, number, string, and no-string/no-number policy must come from generated grammar config or caller data, not hardcoded JSON/CSS constants"). The candidate primitive is the **generalised** form: `unescape(input, escape_alphabet, hex_form)` with the alphabet + hex form table-driven.
- **Arch**: portable scalar (no SIMD admissible against the per-byte branching shape); the only SIMD opportunity is the inner `\uXXXX` hex decode loop (4-byte hex → u16) which Lock 16 :286 admits as a digit-block decode primitive.
- **P1 antecedent**: P1-E §2.2 — `unescape_string` is the `unicode_escapes` direct-plane rank-1 hot leaf at 46.7% self-time (THE only clean primitive leaf in the entire direct plane per P1-E §2.2 summary); P1-E §2.1 — `read_hex_unit_scalar` at `parse-that-regex/src/lib.rs:945` is the `y_string_unicode` parse-only rank-1 at 100% self-time.

### §2.5 — Candidate C5 — digit-block number decode (Eisel-Lemire + UDOT)

### §3 note 1 — Sheets doubled-quote escape (C2 + C3 config divergence)
