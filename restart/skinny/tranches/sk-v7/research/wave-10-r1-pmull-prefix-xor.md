## Recommended intervention and falsifiability gates

- Intervention: replace only `skinny/crates/bbnf-simd/src/aarch64/bitmap_prefix_xor_64.rs` with an AArch64 PMULL body behind `#[target_feature(enable = "aes")]` or an equivalent safe wrapper gated to the already-AArch64 dispatch surface. Keep the public signature unchanged. Compute `let product = vmull_p64(mask, u64::MAX)`, extract `(product as u128 as u64)` or the equivalent low 64-bit lane, then return `low ^ if carry_in { u64::MAX } else { 0 }`. Do not alter `dispatch.rs`, `lib.rs`, or the runtime scan call shape unless implementation evidence shows Rust requires a feature-gated wrapper.
- Scalar parity cases that must be explicit, in addition to the existing random sweep: `(0, false) -> 0`, `(0, true) -> u64::MAX`, `(u64::MAX, false) -> 0x5555_5555_5555_5555`, `(u64::MAX, true) -> 0xAAAA_AAAA_AAAA_AAAA`, `(1, false) -> u64::MAX`, `(1, true) -> 0`, `(1 << 63, false) -> 1 << 63`, `(1 << 63, true) -> !(1 << 63)`, `0x8000_0000_0000_0001` under both carries, and at least one nontrivial sparse/run mask such as `0b101101`, `0x0000_0000_FFFF_0000`, and `0xFFFF_0000_0000_0000` under both carries.
- Consumer parity gate: keep the current JSON scan surface and compare `scan_structurals` against `scan_structurals_scalar` for blocks with no quotes while `in_string=true`, opening quotes at bit 0, closing quotes at bit 0, quote pairs spanning bit 63 to the next stripe, and escaped quote/backslash carry shapes. These cases pin down the `prefix_xor_64(real_quotes_fast, in_string)` use in the active OffsetTape scan path.
- Checkasm gate: run `cargo test -p bbnf-simd --test checkasm_bitmap_prefix_xor_64` and the primitive/checkasm suite used by this tranche. During this research pass, the current scalar-backed `cargo test -p bbnf-simd --test checkasm_bitmap_prefix_xor_64` passed with 2 tests.
- Codegen/ISA gate: inspect AArch64 optimized assembly for one `pmull` in `bitmap_prefix_xor_64_neon` and no six-stage shift-XOR chain. The Rust intrinsic is `#[target_feature(enable = "neon,aes")]`, so the implementation must not make non-PMULL AArch64 targets execute it without an `aes`/`pmull` feature guarantee.
- Bench/falsifiability gate: rerun the W10 gate after the body lands. Admission fails if checkasm diverges from scalar for any carry, if AArch64 assembly lacks `pmull`, if the same-wave scan consumer is not exercised, or if the refreshed gate shows any row regression against the current `RESULTS.md` baseline.
