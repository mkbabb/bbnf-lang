## Scope

The gestalt move. The post-B4 substrate is two welded halves —
`Tape<R>` and a value-side bookkeeping struct that wears the name
`FusedBuilder`. The naming admits the weld; the user's directive
demands "one substrate, named correctly". W1 promotes the
value-side fields into `Columns`, deletes `FusedBuilder` outright,
collapses rollback triplication to a single `Columns::rollback_to`,
retires the `columns_mut()` escape hatch, removes the
`extern crate self as bbnf;` self-alias, and runs the regen sweep
that updates 1061+ generated callsites.

The five parts compose as a single transposition; landing them
piecewise leaves the substrate in an intermediate state that no
gate can describe. W1 is one wave because the work is one move.

### Part 1 — Promote value-side state into Columns

`FusedBuilder` today carries:

- `value_frames: Vec<ValueFrame>` — value-side frame stack.
- `value_payloads_narrow: Vec<u32>` — narrow payload column.
- `value_payloads_wide: Vec<u64>` — wide payload column.
- `value_open_stack: Vec<ValueCheckpoint>` — open-frame stack
  for rollback semantics.

These are part of the substrate. They must live in `Columns` —
the substrate type — alongside the existing tape columns. After
W1, `Columns` carries them as additional fields:

```rust
pub struct Columns {
    // existing tape-side columns ...
    pub kinds: Vec<TapeKind>,
    pub child_offs: Vec<u32>,
    pub sib_skips: Vec<u32>,
    pub pay_narrow: Vec<u32>,
    pub pay_wide: Vec<u64>,
    pub pay_f64: Vec<f64>,             // merged into pay_wide in W2
    pub frame_depth: Vec<u8>,
    pub current_depth: u8,
    pub open_stack: Vec<Checkpoint>,

    // promoted value-side columns
    pub value_frames: Vec<ValueFrame>,
    pub value_payloads_narrow: Vec<u32>,
    pub value_payloads_wide: Vec<u64>,
    pub value_open_stack: Vec<ValueCheckpoint>,
}
```

The `Tape<R>` API methods that read/write value-side columns
move from `FusedBuilder`'s `impl` to `Tape<R>`'s `impl` (or to
the new `Columns::` surface). Their bodies remain identical;
only the receiver type changes.

### Part 2 — Delete FusedBuilder outright

The three builder files:

- `crates/tape/src/builder/mod.rs` (~1258 LOC) — `FusedBuilder`
  itself.
- `crates/tape/src/builder/output.rs` (~210 LOC) — `FusedOutput<R>`
  wrapper.
- `crates/tape/src/builder/value.rs` — `ValueFramesOutput<R>`
  wrapper.

All three deleted outright. `crates/tape/src/builder/` is empty
and removed; `crates/tape/src/lib.rs` no longer declares the
`builder` module.

The `FusedOutput<R>` aliases are 7 method pairs:

| Prefixed alias | Un-prefixed canonical |
|----------------|------------------------|
| `value_frame_at` | `frame` |
| `value_payload_for` | `payload_for` |
| `value_children` | `children` |
| `value_payload_narrow` | `payload_narrow` |
| `value_payload_wide` | `payload_wide` |
| `value_frame_index_at` | `frame_index_at` |
| `value_open_at` | `open_at` |

Pick the un-prefixed name (the canonical surface in the
substrate); delete each prefixed alias. No "transitional alias"
period — per the directive, no backward-compat shims.

### Part 3 — Restore Parsed to a 3-field record

`crates/core/src/runtime/parsed.rs` today carries:

```rust
pub struct Parsed<'p, R: ?Sized> {
    pub tape: Tape<R>,
    pub input: &'p str,
    pub root_offset: TapeOffset,
    // value-side weld fields (welded by FusedBuilder pattern)
    pub value_frames_output: ValueFramesOutput<R>,
    // ... possibly others
}
```

After W1:

```rust
pub struct Parsed<'p, R: ?Sized> {
    pub tape: Tape<R>,
    pub input: &'p str,
    pub root_offset: TapeOffset,
}
```

A 3-field record. The value-side state lives in `tape.columns`
(per Part 1). Accessor methods that consumers used to call on
`Parsed::value_frames_output` move to `Tape<R>` directly.

The renames consumers face:

- `Parsed::value_frames_output` → `Parsed::frames` (returns
  `&Tape<R>`-borrowed view, or moves to `Tape<R>::frames()`).
- `into_value_frames_output` → `into_frames`.

Generated parser code adopts the new names via the regen sweep
at wave close.

### Part 4 — Remove `extern crate self as bbnf;`

`crates/core/src/lib.rs:6`:

```rust
extern crate self as bbnf;
```

The self-alias exists because the `bbnf-bootstrap` external
consumer references `::bbnf::runtime::*`, and the in-crate
`grammar/generated.rs` module needed the same path to resolve
inside the `bbnf` crate. After W1's transposition removes the
two-substrate mediation, the resolution issue dissolves: the
generated module references the substrate's canonical paths
(`crate::runtime::...` or fully-qualified `::bbnf_tape::...`),
and the self-alias is no longer load-bearing.

The line at `lib.rs:6` deletes outright. If any callsite breaks,
it indicates a remaining trace of the welded substrate; the
agent re-routes the callsite, not re-introduces the alias.

### Part 5 — Collapse rollback triplication; retire `columns_mut()`

Three rollback primitives exist today:

1. `FusedBuilder::rollback_to(open: TapeOffset)` — documented as
   "the canonical full rollback".
2. `Columns::rollback_to(open: u32)` — documented as "the
   canonical position-rollback bypassing the builder for parser-
   emitted retry paths".
3. `Columns::truncate(len: usize)` — documented as "the
   canonical truncate primitive used by the AltLinear walker".

Each documents itself as canonical. The conditions distinguishing
them are carve-outs; the substrate has one rollback semantic, and
the duplication is the welded surface masquerading as design.

After W1:

- `Columns::rollback_to(open: TapeOffset)` is the sole rollback
  primitive. It rolls all columns (including the promoted
  value-side columns) back to the `open` offset. The `AltLinear`
  walker routes through it.
- `Columns::truncate` either disappears (no remaining users) or
  narrows to `pub(crate)` if the substrate's internal arena
  reset paths still need it.
- `FusedBuilder::rollback_to` disappears with `FusedBuilder`.

The `columns_mut()` escape hatch — `FusedBuilder::columns_mut() -> &mut Columns`
— exists today because parser-emitted retry paths call
`.columns_mut().rollback_to(open)` directly, bypassing the
builder's full rollback. This forced the migration of
`frame_depth: Vec<u8>` and `current_depth: u8` into `Columns`
"because the builder's rollback couldn't see them otherwise".
The escape hatch retires; in its place:

```rust
impl<R> Tape<R> {
    /// The current write position. Generated parsers capture
    /// this at branch entry as the `open` offset for rollback.
    pub fn position(&self) -> u32 {
        self.columns.kinds.len() as u32
    }
}
```

`Tape::position()` replaces every `.columns_mut().len()` call
in generated code (1061 callsites in CSS L4 alone). The regen
sweep at wave close updates them all.

`frame_depth_mut()` and `columns_and_frame_depth_mut()` retire
similarly; their callers route through `Tape::position()` and
`Columns::rollback_to(open)`.

## Phase

Five ordered phases. Each compiles before the next; the wave's
internal commits map roughly one-to-one to phases (with the
regen sweep folded into the final commit).

### W1.1 Promote value-side fields into Columns

1. Add the four value-side fields to `Columns`. Initialise in
   `Columns::new` / `Columns::with_capacity` mirroring the
   existing tape-side initialisation.
2. Move the value-side methods from `FusedBuilder`'s `impl` to
   `Columns` (or `Tape<R>`, depending on which receiver the
   method's body uses). Bodies unchanged.
3. The value-side accessors (`frame`, `payload_for`,
   `children`, etc.) live on `Tape<R>` (read paths) and on
   `Columns` (mutation paths). Pick the un-prefixed canonical
   name immediately; do not stage through aliases.

### W1.2 Delete FusedBuilder

1. The substrate now has every method `FusedBuilder` exposed.
   Delete `FusedBuilder` and the wrapper types
   (`FusedOutput<R>`, `ValueFramesOutput<R>`).
2. Delete the three builder files. Remove the `builder` module
   declaration from `crates/tape/src/lib.rs`.
3. Update consumers: every `FusedBuilder::method(...)` callsite
   becomes `tape.method(...)` or `columns.method(...)` depending
   on receiver.

### W1.3 Restore Parsed to 3 fields

1. Edit `crates/core/src/runtime/parsed.rs`: drop the welded
   value-side fields. Keep `tape`, `input`, `root_offset`.
2. Rename `Parsed::value_frames_output` → `Parsed::frames`;
   `into_value_frames_output` → `into_frames`. The body returns
   a borrow / consumes into the substrate-canonical type.
3. Update non-generated callsites of these accessors.

### W1.4 Remove the self-alias

1. Delete `extern crate self as bbnf;` at
   `crates/core/src/lib.rs:6`.
2. If any callsite breaks, route it through the canonical path
   (`crate::...` or the proper external crate name). Do not
   re-introduce the alias.

### W1.5 Collapse rollback + retire columns_mut()

1. Make `Columns::rollback_to(open: TapeOffset)` the sole rollback
   primitive. Audit every callsite:
   - `FusedBuilder::rollback_to` callsites → `tape.columns.rollback_to(...)`
     (or via a `Tape::rollback_to` thin re-exposure).
   - `AltLinear` walker truncate calls → `Columns::rollback_to`.
   - Remaining `Columns::truncate` callers (if any) → either
     `rollback_to` (if they want full state-rollback) or a
     `pub(crate)` `truncate` if they genuinely want bare
     truncation.
2. Add `Tape::position(&self) -> u32` returning `self.columns.kinds.len() as u32`.
3. Retire `columns_mut()`, `frame_depth_mut()`,
   `columns_and_frame_depth_mut()`. Generated parsers call
   `tape.position()` instead of `tape.columns_mut().len()`.
4. `cargo xtask regen` to sweep all 9 grammars. The sweep
   updates the 1061+ callsites in CSS L4 plus the cohort across
   the other grammars.

## Archaeology

`FusedBuilder` was introduced during the B-series
(B2 / B3 / B4) as the seam between tape-write paths and the
value-side bookkeeping the typed-materialisation epilogue
needed. It was always intended as a transitional surface; the
B4 close called the post-B4 substrate "two welded halves" and
the four-agent gestalt audit (δ aesthetic) named it as the
single largest aesthetic debt remaining. The seven method-pair
aliases on `FusedOutput<R>` accumulated over three tranches as
the welded boundary widened to admit each new value-side
column. The `columns_mut()` escape hatch existed because the
welded surface couldn't otherwise admit the parser-emitted
retry paths' need for direct rollback. Each piece was a local
fix; the aggregate is the smell W1 retires. The
`extern crate self as bbnf;` self-alias is a downstream symptom
of the same weld: the welded boundary forced two crate-resolution
contexts to mediate, and the alias papered the gap.

W1's mechanism is the substrate-correct version of what each
local fix was approximating. Promoting the value-side fields
into `Columns` is the unification the welded surface was
deferring; the deletions are the consequence of unification, not
the goal. The bench gate is the contract that semantics survive
the move.
