# LOCK-8 pass-3 — family 8C: THE CORRESPONDENCE PLANE (ISOMORPHIC MIRROR)

The mechanism: a **machine-generated divergence ledger** — one checked-in, CI-diffable
row per combinator / leaf / subsystem across the Rust and TypeScript parse-that surfaces,
each row classified MIRRORED / LAWFUL-NON-MIRROR(reason) / DRIFT — and, riding on it, the
**two-engine regex reconciliation**: a priority-preserving DFA construction (LOCK-5 engine
decision) plus a build-time grammar-surface constraint (classify-gate) that together dissolve
the measured regex divergence classes down to a named, irreducible non-regular residue.

The correspondence plane is a *diff artifact*, not a rewrite: it never edits parse-that (READ-ONLY;
any landing rides letter BBNF-PT-G). It emits a ledger, a paired-triple corpus, and a scratch
priority-DFA prototype, all of which are evidence the isomorphism claim is measured, not asserted.

---

## 1. The two surfaces, censused

Rust `rust/parse_that/src` carries **two combinator engines**; TS `typescript/src/parse` carries **one**.

- **Rust closure-Parser engine** — `combinators/methods/{sequence,alternation,repetition,sep_by,
  minus,map,recover}.rs` + `leaf.rs` + `combinators/macros.rs` (`seq!`/`alt!` box-collapsing).
- **Rust SpanParser engine** — `span_parser/` (10 files: enum-dispatched, vtable-free zero-copy;
  `sp_*` leaves, `*_span` combinators). No V8 analogue exists.
- **TS single engine** — `parser.ts` (`Parser<T>` class, all methods) + `leaf.ts` (leaf constructors).
  The TS `*Span` combinator family was **excised at 1.0.0** (S.H2) and is guarded dead by
  `proof:no-span-surface`.

The census method (P1, below) greps `pub fn <name>` over the Rust modules and class-method /
`export function` names over `parser.ts`+`leaf.ts`, joins on a name-map, and auto-classifies.

## 3. THE REGEX ROW — two engines, the hazard classes, the corpus

`regex()` is the one **DRIFT** that is not a layout difference but a *semantic engine* difference.
TS drives V8's Irregexp (backtracking, Perl/PCRE **leftmost-first**) via a sticky `/y` clone and
`.test()`/`.exec()` at offset (leaf.ts:344). Rust drives **bbnf-regex** `rust/regex/`
(HIR→Thompson-NFA→subset-DFA→Hopcroft-min), matched anchored via `Dfa::find_at`
(`rust/regex/src/automata/dfa.rs:116`) — and its `find` records `last_accept` on **every** accepting
position (dfa.rs:122-138) = **leftmost-longest** (POSIX). The two engines therefore disagree by
construction on the order-sensitive and non-regular fragments.

### 3a. The FULL hazard-class enumeration

| id | class | discriminating triple `(pattern, input) → js / rust` |
|---|---|---|
| H1 | **alternation order** (leftmost-first vs longest) | `(/a\|ab/, "ab")` → `"a"` / `"ab"` |
| H2 | greedy extent under overall-match-first | `(/a*a/, "aaa")` → both `"aaa"` (usually agree; probe interaction w/ H1) |
| H3 | **lazy / non-greedy** `*?`,`+?`,`??` | `(/<.*?>/, "<a><b>")` → `"<a>"` / depends on DFA shortest-mode (dfa.rs:141 exists — **verify parity**) |
| H4 | **backreferences** `\1` | `(/(a+)\1/, "aaaa")` → matches / bbnf-regex HIR **rejects** (non-regular) |
| H5 | **lookahead / lookbehind** `(?=)`,`(?<=)` | `(/\d(?=px)/, "5px")` → `"5"` / HIR support unknown — **verify** (non-regular in general) |
| H6 | **capture-submatch semantics** | parse-that TS `.exec()` yields groups; Rust `find_at` yields span only — divergent *output*, not just match |
| H7 | anchors / boundaries / flags `^ $ \b`, `m`, `s` | `(/^b$/m, "a\nb")` → flag-dependent |
| H8 | **Unicode** `/u`,`/v`, case-fold `i`, `\p{}` | `(/\w/i, "İ")` → V8-ICU code-point / bbnf `utf8.rs`+`unicode.rs` byte-level |
| H9 | empty-match / zero-width advance under `g`/sticky | `(/a*/y, "")` → `""` at offset |
| H10 | **catastrophic backtracking** (perf, ReDoS) | `((a+)+$, "aaaa…!")` → V8 exponential / bbnf linear — *the reason the two engines coexist* |
| H11 | anchoring mode (sticky `/y` at offset vs `find_at`) | both anchored-start — mostly aligned; corpus must test **at-offset**, not free search (R4) |

The **paired-triple corpus** is a fixed file: N rows, one class-tag per row, each with
`{pattern, input, js_result, rust_result, agree?}`, produced by running the current engines
(P2). Its purpose is to establish the **true, measured** divergence set — many classes (H2, H7, H9,
H11) may be *latent-agreeing* on the anchored-scanner usage parse-that actually exercises, which
would shrink the problem dramatically (R3).

### 3b. The priority-preserving DFA (routed to LOCK-5 as a decision)

**Confirmed defect.** The NFA already carries priority — `EpsilonEdge{priority:u8}` (nfa.rs:23,
"Lower priority values are preferred during DFA construction"), assigned index-order for
leftmost-first intent (nfa.rs:313), and greedy/lazy is threaded into the fragment builders
(nfa.rs:326-433). But `epsilon_closure` (dfa.rs:189) computes over a `BTreeSet<StateId>` and
`move_on_byte` (dfa.rs:205) returns a `BTreeSet` — **priority is discarded at determinization**.
The DFA then does leftmost-longest. The NFA's leftmost-first intent never reaches the matcher.

**Route A — priority-preserving subset construction** (the RE2 / regex-automata mechanism).
Replace the set-based ε-closure with a **priority-ordered thread-list closure**: a DFS/stack that
visits ε-successors in `edge.priority` order, dedupes by state-id keeping the *first* (highest-priority)
occurrence, and keys determinization on the **ordered sequence** rather than the set. The DFA state
records its highest-priority accepting NFA member; `find` in leftmost-first mode reports the match of
the highest-priority thread and **prunes threads reachable only after a higher-priority accept**.
This is exactly `MatchKind::LeftmostFirst` in regex-automata and RE2's Perl mode. It **dissolves
H1, H2, H3** (regular, order-sensitive) — engines agree on the full regular fragment.

**Route B — build-time grammar-surface constraint** (the classify-gate). `classify.rs:55`
(`RegexClass`) + `classify_regex` (classify.rs:157) already exist; extend them to **reject** the
irreducibly non-regular constructs — H4 backrefs, H5 lookaround — at grammar-compile time with a
diagnostic naming the grammar span (no-silent-epsilon discipline). Route B cannot fix H1 without
*also* forbidding overlapping alternations (draconian), so B alone is insufficient.

**Synthesis (the recommendation): A + B, complementary.** Priority DFA (A) closes the regular
fragment {H1,H2,H3}; the classify-gate (B) rejects the non-regular residue {H4,H5} that **no DFA can
mirror**. H6 (submatch) is a separate output-contract decision (Laurikari tagged-DFA if capture
parity is required; else document `regex()` as span-yielding). The **discriminating corpus for A-vs-B**
is the §3a triple set partitioned: A-alone leaves H4/H5 red; B-alone leaves H1 red-or-over-rejected;
A+B is all-green-or-explicitly-rejected. **The engine question ships to LOCK-5** (bbnf-regex is its
home, XL-C); 8C supplies the corpus and the scratch prototype (P3) as the decision's evidence.

## 4. Prior art (citations)

- **RE2 / Russ Cox** — "Regular Expression Matching Can Be Simple And Fast" (2007) and "…the Virtual
  Machine Approach" (2009): `MatchKind` LeftmostLongest (POSIX) vs LeftmostFirst (Perl); priority
  thread-lists in the Pike VM; priority-carrying determinization. The canonical answer to §3b.
- **regex-automata** (BurntSushi) — `MatchKind::{LeftmostFirst, All}`; `thompson::NFA` priority
  order; dense/sparse DFA determinization that *preserves* leftmost-first through the subset
  construction. Directly transposable to `rust/regex/src/automata/dfa.rs`.
- **Laurikari** (2000), "NFAs with Tagged Transitions" — TNFA/TDFA submatch extraction in DFAs; the
  reference for H6 if capture-group parity is contracted.
- **V8 Irregexp** (backtracking, the JS `RegExp` reference; the H10 ReDoS surface) and V8's newer
  **experimental linear (Thompson) engine** — the comparison baseline; confirms the two-engine gap is
  a known industry divergence, not a parse-that peculiarity.
- **tree-sitter**, **GHC/alex**, **flex** — leftmost-longest lexer DFAs (POSIX), the contrast case:
  lexers *want* longest; PEG/backtracking parsers *want* first. parse-that is a PEG-style backbone →
  leftmost-**first** is the correct target, which is precisely what the current DFA lacks.
- **Brzozowski / Might-Adams derivatives** — an alternative determinization where priority falls out
  of ordered derivatives; a candidate the P3 prototype may compare against subset-with-priority.
- **Hopcroft minimization** (dfa.rs:294+) — the known hazard: it minimizes by Myhill-Nerode language
  equivalence, which is **not** a leftmost-first-preserving relation. R2 below.

## 5. LOCK-6 coordination (handshakes, homes, fences)

- **Ledger ↔ linter-whitelist handshake.** The divergence ledger (§2) **is** the isomorphism
  linter's whitelist. LOCK-6's mirror-tree linter (6A) verifies module/name correspondence; every
  **LNM row is a whitelisted exception carrying its reason string**; every **DRIFT row is a lint
  failure** (mirror it, or promote to LNM with a reason). Single source of truth: the ledger TSV;
  the linter *reads* it; CI fails on any Rust/TS surface pair with no covering row. This makes "hand-
  written TS minimized" (8C charter) and "drift impossible by construction" (6B) the *same*
  mechanism.
- **Tape-crossing artifact home.** The offset-tape decoder (PROVE-14, §0 #14 — byte-exact node-for-
  node, stop-early get 4.4-4.6×) is **generator-side / TS-backend-seed** (GN-4.W4), *not* a
  parse-that combinator. It is a **generated skeleton** (6B) and is **out of scope for the 8C
  combinator ledger** — the ledger covers `parser.ts`/`leaf.ts`, the tape decoder is the generator's
  emission. Name the boundary explicitly so the two artifacts do not double-home: LOCK-6 owns the
  tape-crossing home; 8C owns the combinator-surface correspondence.
- **Decode-speed fence (SPEC §0, binding).** Any decode number **fences its measured path**: *pure-
  JS-decode* (the offset-tape walk in TS, no wasm — 4.4-4.6× stop-early, ~0.91× full-walk) vs
  *wasm-boundary* (crossing into the Rust core via wasm-bindgen). Distinct paths; the ledger and any
  8C table must never conflate them. Full-walk 2× is honestly unmet (native `JSON.parse` is near-
  optimal for full materialization) — carry that as a fenced fact, not a target.

## 6. Named risks / counterexamples

- **R1 — state-count blowup.** Priority-ordered (sequence-keyed) determinization can be exponentially
  larger than set-keyed; leftmost-first is not a pure language property so states that are language-
  equal but priority-distinct no longer merge. Counterexample: `(a|a)*b`-shaped patterns. The P3
  prototype **must** measure DFA state-count on the real 50-pattern bench corpus (`rust/regex/benches/
  regex_dfa_compile`).
- **R2 — Hopcroft unsoundness under priority.** Minimization (dfa.rs:294+) merges Myhill-Nerode-
  equivalent states, which can re-erase the priority distinction and re-introduce the divergence. The
  prototype must verify: does minimize-after-priority-determinize preserve leftmost-first, or must
  minimization be disabled / replaced (weighted/priority-aware minimization)?
- **R3 — the divergence may be latent-only.** If parse-that's *actual* regex usage (anchored `/y`
  scanners, no overlapping alternations, no backrefs/lookaround) never exercises H1/H4/H5, the cheap
  fix is Route B's classify-gate rejecting non-regular constructs, and priority-DFA is unneeded
  complexity. **Counterexample the other way:** the P4 consumer census may find the whole hazard set is
  theoretical for this corpus — that would *retire* Route A. Measure before building.
- **R4 — anchored-at-offset narrows the surface.** `regex()` is a sticky scanner at a cursor, not a
  free search; H10 is bounded and H11 mostly aligns. The corpus must test **at-offset** semantics
  (leaf.ts:344 sticky; Rust `find_at`), or it over-states the divergence.
- **R5 — ledger staleness.** A hand-authored ledger is a workaround; it drifts from code. The ledger
  **must** be regenerated by the P1 census tool in CI and diffed against the checked-in copy (regen-
  only discipline). The §2 table is a seed, not the shipped artifact.
- **R6 — the SpanParser asymmetry.** The Rust-only `span_parser/` engine is the largest single DRIFT.
  Its disposition (LNM(rust-perf-engine) as a *named* supersession, or a mirror obligation) is a
  ledger decision, not something to leave silently divergent — the constitution forbids silent
  contradiction of the mirror principle.

## 7. What a prototype must test (to move family 8C)

- **P1 — THE LEDGER TOOL.** An AST/grep census over `rust/parse_that/src` (`pub fn`/method names)
  and `typescript/src/parse` (class methods + `export function`), joined on a name-map, emitting the
  §2 TSV with auto-classification (both-sides→MIRRORED-candidate; one-side→DRIFT; whitelisted→LNM).
  Deliverable: the ledger file + the tool, CI-diffable against a checked-in copy. This is the family's
  core artifact.
- **P2 — THE PAIRED-TRIPLE REGEX CORPUS.** N rows tagged H1–H11, each `{pattern, input,
  js_result (node `RegExp` at offset), rust_result (bbnf-regex `find_at`), agree?}`. Run on the
  **current** engines to establish the *measured* divergence set (expose which classes are latent-
  agreeing on anchored usage). Deliverable: the corpus file + runner.
- **P3 — THE PRIORITY-DFA SCRATCH.** A fork of `dfa.rs::subset_construction` swapping the BTreeSet
  ε-closure for a priority-ordered thread-list closure + highest-priority-accept `find`. Measure:
  (a) does it flip H1–H3 to JS-parity on P2's corpus, (b) DFA state-count delta on the 50-pattern
  bench corpus (R1), (c) does Hopcroft still hold (R2). Deliverable: the scratch engine + the
  discriminating corpus that decides A vs A+B — **routed to LOCK-5** as the engine decision.
- **P4 — THE CONSUMER-REGEX CENSUS.** Extract every regex literal from value.js
  (`src/parsing/{math,units,color,timeline}`) and latex-paper (`src/bibtex`, `src/grammar/*`) grammars,
  run through P2's harness, count how many are actually order-sensitive / non-regular. Decides whether
  Route A (engine work) is needed at all, or Route B (classify-gate) alone suffices (R3). Deliverable:
  the census + the A-vs-B recommendation with numbers.

The family converges when the ledger is generated-and-CI-diffed with zero unexplained DRIFT rows, the
regex row is classified by measured evidence (not assumed), and LOCK-5 holds the priority-DFA decision
with P3's corpus as its input.
