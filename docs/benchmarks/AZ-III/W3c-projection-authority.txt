3. Upstream blocker — egraph extractor strips Map wrapper
--------------------------------------------------------------------------------

Per-branch instrumentation (eprintln in `branch_payload_push`) showed that
EVERY namedColor branch arrives at the alt_dispatch emitter with NO `Map`
wrapper at all:

  [W3c.1.dbg] branch_payload_push branch_root=Literal      <-- "violet"
  [W3c.1.dbg]  -> no Map fn
  [W3c.1.dbg] branch_payload_push branch_root=Literal      <-- "khaki"
  [W3c.1.dbg]  -> no Map fn
  [W3c.1.dbg] branch_payload_push branch_root=Seq[len=2]   <-- post-prefix-factor
  [W3c.1.dbg]  -> no Map fn
  [W3c.1.dbg] branch_payload_push branch_root=Seq[len=2]   <-- (148 more)
  [W3c.1.dbg]  -> no Map fn

Investigation traced the loss to the egraph cost-guided extractor:

  crates/ir/src/egraph/cost.rs:130
    GrammarENode::Map { inner, fn_id: _ } => structural + child_cost(*inner),

  Map costs `structural + inner_cost`; the inner alone costs `child_cost`.
  When semantic equivalence rules (e.g. `WrapOfEpsilonScalar` in
  `crates/ir/src/egraph/rules/universal.rs`) union a Map(Literal) class
  with the Literal class, the cost-guided extractor picks the cheaper
  Literal form and the Map (carrying the `fn_id` that points at the
  `MapExpr::IntLit(0xRRGGBBAAu32)` projection) is discarded.

This is a deeper-stack blocker than the W3c.1 carve admits. The Map fn_id
must survive the egraph's cost-guided extraction so the emitter can read
it. The fix sits in:

  - crates/ir/src/egraph/cost.rs (cost model: tag Map with fn_id payload
    weight so it dominates inner cost when fn_id is non-trivial), or
  - crates/ir/src/egraph/rules/* (rewrite rules that fold Map into
    Literal lose the projection — they should not apply to Map(Literal)
    when fn_id has typed payload), or
  - crates/ir/src/egraph/write_back.rs (extractor: when extracting an
    Alt branch, prefer the Map form over the unmapped form whenever
    both exist in the class).

All three sit OUTSIDE W3c.1's file bounds (`crates/ir/src/egraph/**` is
W3a/W3b carve, not W3c). Routing required.
