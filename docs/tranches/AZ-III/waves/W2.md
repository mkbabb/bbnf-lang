# AZ-III.W2 - Semantic Parity and Bootstrap Canonicalization

**Name**: W2 - Semantic Parity and Bootstrap Canonicalization
**Opens after**: W1 O5 reclose.
**Agents**: up to 10 parallel.
**Hard gate**: JSON sonic-rs, CSS lightningcss, Sheets, and BBNF semantic parity are green on the struct-only path, and generated BBNF self-hosting is canonical or blocks close.
**Status**: planned

## Scope

1. Run and repair JSON parity against sonic-rs without tape adapters.
2. Run and repair CSS parity against lightningcss, including color,
   selector, bootstrap, and tailwind admission gaps.
3. Run and repair Sheets semantic parity and serializer/range gaps.
4. Prove BBNF generated self-hosting is the canonical parse path or
   retain `bootstrap_parser.rs` only as a named blocker with W3/W5 owner.
5. Convert ignored semantic tests into passing tests or named blockers.

## Agent Units

### AZ-III.W2.1 JSON Parity

- Mechanism: run sonic-rs and canonical/value parity suites; repair
  materialization defects at root.
- Files: JSON tests and shared materialization only if proven root.
- Sub-gate: focused JSON parity suites pass.

### AZ-III.W2.2 CSS Parity

- Mechanism: run lightningcss parity on normalize, colors, bootstrap,
  and tailwind; repair grammar/type/projection causes.
- Files: CSS tests, grammar, shared projection/type code as needed.
- Sub-gate: lightningcss parity passes or blocks with exact source owner.

### AZ-III.W2.3 Sheets Parity

- Mechanism: run Sheets self/parity suites; repair mapped branch,
  range, and serializer defects at shared lowering/projection points.
- Files: Sheets tests and shared lowering/projection only as needed.
- Sub-gate: Sheets parity suites pass.

### AZ-III.W2.4 BBNF Bootstrap Canonical Path

- Mechanism: replace canonical `bootstrap_parser` routing with generated
  self-host parse if green; otherwise produce blocker proof.
- Files: BBNF grammar/parser/pipeline entry points.
- Sub-gate: generated parser self-host proof or named terminal blocker.

## Hard Gate

1. Focused parity commands pass with archived output.
2. No harness masks external-library failures with early returns.
3. Ignored semantic tests are either unignored and green or routed into
   W3 with exact authority substrate owner.
4. BBNF canonical parser path is documented by source and test evidence.

## Format And Lint Cadence

Run `cargo fmt --check`, focused parity commands, and `git diff --check`
after each accepted integration batch. Run `cargo xtask regen --check`
whenever grammar, emitter, or generated parser files change, and again
before W2 close.
