## Goal criterion

This wave succeeds if every load-bearing runtime claim holds on the PUBLISHED core —
not the prototype clone it was first proven on — and stays held mechanically: the
dual-engine evidence suite becomes a repeatable CI gate at the owning root, so a future
glass-ui change that breaks `compensateScrollTop`, the hydration guard, print
reveal-all, or a11y semantics is caught at the root before any consumer sees it.

WHY: the W1 evidence (`traces/w3/`) proved the SHAPES in `virt-p4` at `761ba9d`/
`4391629`. Cherry-picking is content-preserving but the landed root is a different
integration context (different HEAD, different bundler surface); re-proving on the real
cut is the cheap insurance the whole consumer rollout (W5) stands on. Promotion to CI
converts one-shot evidence into a standing invariant.

## Triumvirate Dispatch

- **File-bound expansion**: any clause failure requiring a glass-ui SOURCE change
  (this wave owns harness/CI files only) is a scope reveal → triumvirate (the fix
  lands via a W2-style root change + re-cut consideration, never a harness fudge).
- **Non-recoverable gate failures**: a red clause that was green in `traces/w3/`
  (regression introduced by landing) — root-cause research mandatory before any edit;
  an engine-version drift changing a floor (VR-22 table) — plan augment.
- **Diagnostic loops**: 3 iterations on any flaky lane without isolating cause → halt;
  flakiness is disqualifying for CI promotion (the job must be deterministic or
  quarantined-by-design with rationale).
