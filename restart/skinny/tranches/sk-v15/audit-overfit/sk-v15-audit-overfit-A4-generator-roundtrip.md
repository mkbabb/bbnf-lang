## Generator Header Audit

Skinny runtime outputs carry the expected generated header: CSS companion files start with `// @generated by skinny bbnf-codegen; do not edit by hand.` in `config.rs`, `generated.rs`, `mod.rs`, `parser.rs`, and `sink.rs` (`skinny/crates/runtime/src/grammars/css_l4_stylesheet_selectors/generated.rs:1`, `skinny/crates/runtime/src/grammars/css_l4_stylesheet_selectors/config.rs:1`, `skinny/crates/runtime/src/grammars/css_l4_stylesheet_selectors/parser.rs:1`).

Root Pattern H runtime outputs do not. The count is 67 runtime files and 0 generated headers. This is not a cosmetic failure: without line-1 provenance, future audits cannot distinguish generated root runtime files from hand edits, and the current root regen commands offer no non-writing `--check` path for those files.

## Round-Trip Feasibility

Skinny CSS companion round-trip is mechanically feasible: `skinny/xtask/src/regen_css.rs:99` writes all seven CSS targets through `regen::write_targets`, each target names the same 15 CSS L4 sources (`skinny/xtask/src/regen_css.rs:5`, `skinny/xtask/src/regen_css.rs:165`), and per-target checks route through `regen::check_target` (`skinny/xtask/src/regen_css.rs:131`, `skinny/xtask/src/regen.rs:34`). The existing test `css_l4_generated_runtimes_reproducible_from_request` checks generated bytes against checked-in runtime dirs (`skinny/crates/codegen/src/lib.rs:547`, `skinny/crates/codegen/src/lib.rs:554`).

That round-trip would still reproduce a relocated fixed Rust string. Therefore A4 cannot accept the CSS companion modules as grammar-derived until `CSS_GENERATED_RS` is replaced by emission whose parser/value/document shape depends on the parsed CSS L4 grammar facts, not only on profile metadata and source hashes.

Root Pattern H round-trip is not acceptably feasible today. `cargo xtask regen-css` writes root CSS runtime files directly (`xtask/src/regen_css.rs:195`), and `cargo xtask regen-{math,csv,bbnf,bnf,ebnf,css-pretty,google-sheets,json}` also write through `regen_simple_runtime::run` (`xtask/src/main.rs:101`, `xtask/src/main.rs:108`, `xtask/src/regen_simple_runtime.rs:87`). There is no root runtime `--check` or delete+regen proof path analogous to skinny `check_dir`.

## CSS_GENERATED_RS Relocation

The SK-V14 finding still holds in substance. The seven CSS companion provider files now have generated headers, but the generated body is centralized in `skinny/crates/codegen/src/runtime_generator.rs` as `CSS_GENERATED_RS` and copied into every CSS L4 profile (`skinny/crates/codegen/src/runtime_generator.rs:97`, `skinny/crates/codegen/src/runtime_generator.rs:713`). The relocation changes ownership appearance, not derivation.

The profile switch also embeds CSS row IDs and output planes directly in generic codegen (`skinny/crates/codegen/src/runtime_generator.rs:114`, `skinny/crates/codegen/src/runtime_generator.rs:126`, `skinny/crates/codegen/src/runtime_generator.rs:146`). This should be routed with PRUNE-WAVE-C, but the parser/fact-stream retirement belongs to PRUNE-WAVE-A because it is the live CSS admission/provider surface.

## A4 Close Verdict

A4 does not pass. The skinny CSS companion modules can likely round-trip byte-for-byte, but the bytes come from a relocated hand-curated Rust string. Root Pattern H generated ownership also fails: 67 files, zero generated headers, and no non-writing runtime round-trip gate. Forward motion should route through PRUNE-WAVE-A, PRUNE-WAVE-C, and PRUNE-WAVE-D before any CSS or Pattern H evidence is used for SK-V15 close.
