## Fold Requirements For S-P3

- Preserve `CSS-ROW-SCOPE-CONDITIONAL` exactly: CSS rows 1-6 are row-production
  scopes only, requiring fresh narrow CSS parser profiling or same-wave strict
  lightningcss/cssparser row movement before admission.
- If any SIMD primitive is embedded in a CSS row, inherit the P2-B gate:
  executable scalar reference, strict checkasm/differential parity,
  same-host microbench, same-wave production consumer, grammar policy, and
  strict row gate.
- Keep C7/B2 `ByteSetRunSkip64` as conditional route-production: prior W4
  microbench evidence is not row movement.
- Do not promote D1 lazy capacity, EOR3/BCAX, cache hints, standalone
  prefix/next/bulk bitmap helpers, standalone byte-context, or LD4/TBX/SMIN/SMAX
  refinements without fresh accepted P2 evidence and same-wave row consumer.
- Carry resolver cost fences forward: code size participates in active cost and
  CSP objectives, CSP timeout is 200 ms with >1 s abrogate risk, stale-cost
  evidence over 30% abrogates W3, e-graph saturation stays budgeted, and CSP
  problem codegen over 1000 LOC abrogates W4.

## Disposition

CH4 accepts V3 for S-P3 consumption. The V3 CSS row-scope fold preserves enough
cost and micro-proof information for planning: CSS work is conditional
row-production, SIMD routes inherit scalar/checkasm/consumer gates, and
generated-size plus resolver-time constraints remain visible through the
decision-engine carry-forward.
