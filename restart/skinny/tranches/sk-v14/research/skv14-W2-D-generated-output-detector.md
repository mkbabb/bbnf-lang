# SK-V14 W2-D: Generated Output Detector

Date: 2026-05-24.
Scope: Trace generated-header conventions and define the W2 bypass-header detector.
Output: this file.

## §1 — Findings (concrete, file:line cited)

- Core generated grammar files use a doc-comment header emitted by `xtask::regen::file_header`: the `Regenerate: cargo xtask regen --grammar <ident>` line is produced at `xtask/src/regen.rs:524-534`, and `crates/core/src/grammar/generated/css_l4.rs:1-2` carries the same header for CSS L4.
- Core root regen writes grammar outputs to `crates/core/src/grammar/generated/<ident>.rs` at `xtask/src/regen.rs:259-268` and sidecar registries at `xtask/src/regen.rs:270-285`. This is a different generated convention from skinny runtime files.
- Skinny runtime files use `// @generated by skinny bbnf-codegen; do not edit by hand.` as the generated header, with the constant at `skinny/crates/codegen/src/lib.rs:96`. Existing CSS and JSON runtime files under `skinny/crates/runtime/src/grammars` carry that header.
- `EmittedSource::check_dir` already rejects missing files, different files, and unexpected `.rs` files that begin with the skinny generated header at `skinny/crates/codegen/src/lib.rs:65-92`. This is per-directory drift checking, not a global generated-header ownership detector.
- The W0 Lock 14 companion lint scans `crates/runtime/src/grammars` and `crates/codegen/src` for `@generated by skinny bbnf-codegen` at `skinny/crates/bbnf-bench/src/lock14_baseline.rs:528-655`, then compares the paths against `GENERATED_HEADER_TOKEN_BASELINE` and `GENERATED_HEADER_RECOGNIZED_EMISSION_ROSTER` at `skinny/crates/bbnf-bench/src/lock14_baseline.rs:674-705`.
- W2's detector scope is broader than the W0 lint: `restart/skinny/tranches/sk-v14/SPEC.md:491-495` requires `git grep -l '@generated by skinny bbnf-codegen' -- skinny/crates/runtime crates/core/src/runtime` to trace every match to registered xtask emission.

## §2 — Recommendations (named falsifiability gates)

- `G-W2-HEADER-REGISTRY`: implement or plan an explicit runtime emission registry containing `regen_command`, `check_command`, `output_root`, `files`, and `header` for every W2-owned generated runtime tree.
- `G-W2-BYPASS-DETECTOR`: run `git grep -l '@generated by skinny bbnf-codegen' -- skinny/crates/runtime crates/core/src/runtime` and require every path to appear in exactly one W2 emission registry entry.
- `G-W2-ROUNDTRIP-OWNER`: for each registry entry, execute its `check-css-l4-*` command after `cargo xtask regen-css`; reject duplicate owners, missing companions, and header-bearing paths outside the roster.
- `G-W2-CORE-CONVENTION-SPLIT`: keep core `AUTO-GENERATED` grammar output checks under root `cargo xtask regen --check`; do not classify `crates/core/src/grammar/generated/css_l4.rs` with the skinny `@generated` detector.

## §3 — Risks (REDRESS entries to pre-block)

- A path-prefix detector can bless fake headers under a broad directory. The W2 detector needs exact roster ownership.
- The existing W0 generated-header lint's baseline is not enough for W2 because it does not scan `crates/core/src/runtime`, and it has a historical baseline list rather than actual `regen-css` command ownership.
- Writing skinny `@generated` headers into `crates/core/src/runtime/css_l4/` without adding registry ownership and check commands would fail the W2 bypass-header gate.
