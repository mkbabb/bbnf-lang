## Phase sub-items

Mechanism:

#### Step 1: CI gate

Edit `.github/workflows/ci.yml` to add a step under the `rust` job:

```yaml
      - name: regen check (xtask)
        run: cargo xtask regen --check
        timeout-minutes: 5
```

This step regenerates the per-grammar tree to a tempdir + diffs
against checked-in. Non-zero exit blocks the PR.

Place this step **before** `iter-check` so CI catches drift early
without paying a full workspace check.

#### Step 2: Pre-commit hook

Create `.git/hooks/pre-commit` (or extend the project's husky/lefthook
config — verify which is active):

```bash
#!/usr/bin/env bash
set -euo pipefail

# Skip on rebase or merge in progress
if [ -f .git/MERGE_HEAD ] || [ -f .git/REBASE_HEAD ] || [ -d .git/rebase-merge ]; then
    exit 0
fi

# Only run when grammar files or xtask source changed in this commit
if git diff --cached --name-only | grep -qE '^(grammar/|xtask/src/|crates/.*/src/grammar)'; then
    cargo xtask regen --check || {
        echo "regen drift detected; run 'cargo xtask regen' and stage the result" >&2
        exit 1
    }
fi
```

Document the hook in PROFILING.md §Dev-host setup.

## Archaeology

W4's CI + pre-commit gate replaces the pre-B2 `BBNF_SCHEMA_VERSION`
discipline (which lived in `crates/derive/src/lib.rs:81`,
content-keying the proc-macro cache). The discipline is structurally
preserved — workspace consumers depend on a checked-in surface that
must match the source-of-truth grammar — but the mechanism shifts
from in-band cache invalidation (relying on every consumer's
build.rs honoring the version constant) to standard "diff after
regen" hygiene (CI runs `cargo xtask regen --check`; pre-commit runs
the same when relevant files change).

The transposition is: schema-version drift detection moves from
*inside the proc-macro cache* (an in-band protocol every consumer
must respect) to *the workspace's git history* (a standard SCM
discipline every consumer already respects). The latter is more
robust + idiomatic.
