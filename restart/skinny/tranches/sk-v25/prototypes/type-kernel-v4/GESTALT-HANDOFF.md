# Type-kernel V4 hostile gestalt handoff

Disposition: **INCOMPLETE_ASSAY**. This is a routing brief for two fresh hostile
gestalt passes, not an author review.

## Friction encountered

1. Keeping draft handles compile-time isolated required a consumed builder and a
   second root capability; a runtime “closed set” on V3 handles would not suffice.
2. Deep safety required flattening not just solver terms but host descriptors,
   solved terms, rows, schemes, printers, canonical encodings, and destruction.
3. Batch schemes needed private source identity for shared free variables while
   excluding that allocation identity from public canonical bytes.
4. Row level lowering had to traverse every field and reachable row before a row
   substitution became visible; tail-only lowering reproduced the V3 defect.
5. Projection required semantic symbol interning separate from normalized spelling
   collision allocation. Rust and TypeScript also required genuinely separate
   printers and precedence policies.
6. A standalone crate cannot simultaneously depend on live production enums. The
   assay therefore uses a local generic snapshot model and must not claim live
   semantic agreement.

## Specification deviations and routed RED work

- `HostTypeNode` is supplied explicitly. It is not yet derived solely from BBNF
  module syntax; exact host/effect/ownership/backend declarations remain RED.
- The local `GrammarNode` assay covers the adjudicated operator shapes but is not a
  live exhaustive match over production `IrNode`/`FnDescriptor`/`TypeDesc`.
- Heterogeneous alternatives are represented as semantic variants, but the exact
  production obligation/lowering-plan differential is not implemented here.
- The row matrix is direct and deterministic, but no claim is made about randomized
  hash seeds or worker scheduling because the carrier uses ordered maps and no
  workers.
- The compiler crater is broad enough to falsify the known V3 symbol/precedence
  defects; it is not credited as the entire target-language/product matrix.
- Apple-arm64 evidence is a narrow explicit carrier model. It is not Rust ABI,
  tape layout, library-container, backend, or product authority.
- JSON is one recursive assay. CSS L4 shapes prove representability only. Full CSS
  semantics, tape execution, value fabric, ten-plus complete/profiled candidates,
  cost, and portfolio selection belong to successor tranches.
- Gates 8–9, production cutover, corpus/runtime consumers, benchmarks, and audits
  remain wholly outside this directory.

## Greater-tranche relationship

The generic constructors can feed a grammar-derived schema without extra markup
once BBNF module syntax itself owns rule signatures, host signatures/effects, and
constructor labels. That later stage can lower one sealed solution into an L4
grammar/value typing API. V4 supplies only an isolated equality/row/scheme assay;
it is not a complete product candidate and must not be counted among the required
ten-plus complete portfolio implementations.
