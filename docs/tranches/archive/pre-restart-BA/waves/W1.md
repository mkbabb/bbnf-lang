# BA.W1 - Inverse-Layout-Audit IR Pass

**Name**: W1 - Inverse-Layout-Audit IR Pass
**Opens after**: W0 - Truth, Regen, Cleanup Absorption
**Agents**: 5 parallel
**Hard gate**: every compound-typed rule has a non-empty `StructLayout`; `cargo build` fails when a `->`-less compound rule's layout is empty; named test fixtures cover Seq, Alt, Repeat, HeterogeneousAltJoin
**Status**: planned

## Scope

This wave lands the **inverse-layout-audit IR pass**: the existing invariant is "every `StructLayout` has a `TypeDesc` reachable through `project_types`"; W1 adds the *inverse* — every compound-typed rule (annotated OR `->`-less) has a `StructLayout` consumable by the emitter. The audit fails-closed if a compound-typed rule has no layout. This is the codegen prerequisite for W2's direct-projection emit.

1. Define the `inverse-layout-audit` IR pass at `crates/ir/src/passes/inverse_layout_audit.rs`. Pass runs **after** `populate_struct_registry` (which consumes `project_types` output). The pass enumerates every rule whose projected `TypeDesc` is a *compound* shape (not `Span`/`F64`/`Bool`/etc.) — `Tuple`, `Vec(inner)`, `Option(inner)` of a struct, `HeterogeneousAltJoin` — and asserts each has a `StructLayout` entry in the registry.
2. The pass produces `Result<(), InverseLayoutAuditError>`; on failure, the error names the rule, its projected `TypeDesc`, and the absent layout's expected shape. Build fails with a `proc_macro2::Span`-anchored diagnostic.
3. The pass also surfaces `->`-less rules whose layout would be deficient (a Seq of three Spans collapses to a single Span; the current registry skips it). The audit confirms either (a) the collapse is intentional (codegen consumes the scalar projection), or (b) the rule needs `@no_collapse` for prettify identity.
4. Add a named test fixture for each compound shape: `->`-less Seq of disagreeing children producing `Tuple`; `->`-less Alt with branches projecting to different Named rules producing `HeterogeneousAltJoin`; `->`-less Repeat producing `Vec(inner)`; `->`-less Option of a struct producing `Option(struct)`.
5. Failing-test fixture: a synthetic grammar with a `->`-less compound rule that the registry skips by today's logic. The fixture compiles cleanly under HEAD; under W1 it fails the build with the audit-error diagnostic.
6. Test redress: any AZ-IV-closing test that depended on `compound_kind_for_layout` runtime resolution (and would surface after W2 lands) gets its expectations updated here. The audit is the gate; the codegen consumption is W2.

## Triumvirate Dispatch

Dispatch a triumvirate if any of these occurs:

- the audit pass needs to fail rules outside the W2 file bounds (e.g., a `->`-less rule that the registry cannot project under any extension because the `TypeDesc` is genuinely opaque — a sign the inference itself has a gap);
- audit-driven layout extension requires changes to `project_types` itself (modifying the inference contract is outside W1 scope; route to a triumvirate that decides between extending W1 or augmenting `project_types` in a separate sub-wave);
- failing-test redress reveals that more than three AZ-IV-closing tests had implicit dependencies on runtime registry resolution (scope reveal beyond W1's named bounds);
- three diagnostic-loop iterations fail to isolate why a compound-typed rule has no layout (the audit error's recovery path requires knowing the inference→layout boundary; the third iteration must halt);
- JSONL transcript quiet >15 minutes;
- first-pass return with no commit and no evidence (after one verbatim redispatch).

Empty/no-evidence returns get one verbatim redispatch with the same worktree pointer. A second empty/no-evidence return triggers mandatory triumvirate.

## Agent Units

### BA.W1.1 Audit Pass Implementation

- Mechanism: implement `inverse_layout_audit` IR pass. Walks every `RuleId` in the post-`project_types` registry; for each rule whose `TypeDesc` is compound, checks `StructRegistry::layout_for(rule_id)` returns `Some(StructLayout)`. On `None`, emits `InverseLayoutAuditError { rule_id, type_desc, expected_layout_shape }`. The pass returns `Result<(), Vec<InverseLayoutAuditError>>` — collected errors so a multi-rule failure surfaces all of them in one build run.
- Files: `crates/ir/src/passes/inverse_layout_audit.rs`, `crates/ir/src/passes/mod.rs`.
- Sub-gate: pass compiles cleanly; running against a synthetic grammar with one un-projected compound rule produces the correct error; running against the 9 production grammars produces zero errors at HEAD (because AZ-IV's discipline keeps them clean) and surfaces any drift introduced by W0's substrate-audit refresh.

### BA.W1.2 Registry Inspection Helpers

- Mechanism: add read-only helpers on `StructRegistry`: `layout_for(rule_id) -> Option<&StructLayout>`, `is_compound_typed(rule_id) -> bool` (returns true if the rule's `TypeDesc` is `Tuple` / `Vec(inner)` / `Option(struct)` / `HeterogeneousAltJoin`), `compound_typed_rules() -> impl Iterator<Item = RuleId>`. The helpers consume only the existing registry surface; no new state.
- Files: `crates/ir/src/registry/struct.rs` (modify-carve), `crates/ir/src/passes/types/mod.rs` (expose post-populate hook if needed).
- Sub-gate: helpers compile; `cargo nextest run --test substrate_audit` GREEN (the new helpers must be consumed by W1.1 in the same wave; substrate-audit invariant per BA invariant 7).

### BA.W1.3 Positive Fixtures

- Mechanism: write `crates/core/tests/inverse_layout_compound_fixtures.rs` covering each compound shape: a `->`-less Seq of disagreeing children (produces `Tuple` and a layout); a `->`-less Alt with heterogeneous branches (produces `HeterogeneousAltJoin` and a layout); a `->`-less Repeat (produces `Vec(inner)` and a layout); a `->`-less Option of a struct (produces `Option(struct)` and a layout). Each fixture grammar compiles and the audit pass returns Ok.
- Files: `crates/core/tests/inverse_layout_compound_fixtures.rs`.
- Sub-gate: all fixtures compile; `cargo nextest run --test inverse_layout_compound_fixtures` GREEN; `docs/tranches/BA/audit/W1-fixture-coverage.txt` records the shape→fixture map.

### BA.W1.4 Negative Fixtures

- Sub-gate: the negative fixture's `cargo build` fails with the named diagnostic; the test asserts the error text matches an expected substring; the test runs at the IR-crate test surface, not workspace.
