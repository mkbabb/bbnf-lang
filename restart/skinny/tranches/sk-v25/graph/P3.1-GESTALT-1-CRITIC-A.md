## Numbered hostile findings

### 1. BLOCKER — the actual full constellation cannot clear F08 inventory truth

The manifest declares `**/node_modules/**` as an ephemeral exclusion, while the
current bbnf repository tracks a `node_modules` symlink at the path named above.
`reconcile_tracked_exclusions` correctly rejects it. This means the P3.1 source
does not produce a full graph on its actual subject. All late-stage and budget
claims are absent, not merely pending formatting.

The correct behavior is to keep this RED until the tracked input receives an
explicit source-policy disposition that satisfies the adjudication. Silently
weakening F08 or treating this as an ignorable final-twin nuisance would be a
contract violation.

### 2. BLOCKER — identical `SourceBinding` hashes can drive different graph facts

`evidence/binding.rs:44-47,133-136,316-334` binds only each tool's name and
version text. It does not bind the resolved executable identity, path, bytes, or
an execution capability receipt. `collect/frontend.rs:48-54` later resolves
`node` from live `PATH` and trusts its stdout.

The compiled/wrapper probe shows the consequence: the real and substitute Node
commands both report `v26.0.0`; `SourceBinding::capture` produces the same exact
binding hash; helper output changes from 12 Unknowns to zero. A final recensus
under the same substitute executable repeats the same version and cannot detect
the difference. This falsifies complete binding, toolchain truth, deterministic
input epochs, and mutation locality.

The helper protocol compounds the issue. `HelperOutput` at
`collect/frontend.rs:16-18` deserializes only `unknowns`; it does not validate
the advertised schema or the `edges` field, and source anchors are not checked
against captured physical identities. A stale or substituted helper response
can therefore erase required frontend failures without a typed schema error.

### 3. HIGH — F14 is an end-of-run equality check, not a source transaction

Collectors do not consume immutable captured bytes. The frontend collector
receives live repository roots, walks them in another process, and reads current
bytes. `SourceBinding::verify_unchanged` at `binding.rs:286-314` performs a new
census only at the end. A bound file can change, be consumed while changed, and
be restored before recensus; the binding compares equal while the graph contains
facts from the transient epoch. This is the ordinary ABA problem.

The test named `f14_final_recensus_detects_any_binding_drift` does not mutate an
input or run a collector. It clones a binding, assigns a different digest, and
checks that unequal structs compare unequal. It cannot reject the mixed-snapshot
execution required by F14. The independently reproduced unbound-Node case is an
even stronger executable instance of output changing while recensus-visible
binding state remains equal.

The duplicated exclusion authority in `frontend/program.mjs` is part of the
same defect. The helper hardcodes directory exclusions instead of consuming the
manifest's typed exclusion set. A newly valid manifest exclusion can stop the
inventory while the helper still descends and consumes bytes below it.

### 4. HIGH — F18 does not cover the normative stages and write failures bypass stage-safe fallback

The stage enum parses `cycle`, `cluster`, `generation`, and `complete`, but the
orchestrator never calls typed `inject` for those stages. Basis/cluster/quotient
have separate real failpoints, not complete stage-injection coverage. Cargo has
only a boundary failpoint; the adjudicated Cargo spawn/read/decode sites do not
exist. Tests exercise Node spawn/helper decode and direct publication primitives,
but not the complete orchestrated stage matrix.

More seriously, `generation-assembly` and `publish` are called after `execute`
returns (`architecture/mod.rs:50-69`). Errors there propagate directly and never
enter `publish_failure`. Resource-budget errors have the same shape. Thus logical
generation/write/budget failures do not exercise the required typed fallback
transaction.

Stage-state reporting is also inaccurate:

- `SourceBinding::capture` errors after inventory and worktree census are labeled
  `Bootstrap` at `mod.rs:191-204`;
- `publish_failure` unconditionally passes `graph_validated=false` and omits
  obligations, even for a typed `Write` injection after validation and recensus;
- the real requested `write` injection is currently preempted by the inventory
  defect and publishes `stage=inventory`.

This is not the mandated proof that each named operation was reached with the
stage-appropriate safe artifact set.

### 5. HIGH — cluster membership still performs a non-graph merge

`cluster.rs:216-225` groups an SCC by hard signature and, when a group is under
the target, emits the entire group without checking connectivity or quotient
adjacency. The compiled probe constructs one SCC `a <-> b <-> c`, gives `b` an
incompatible feature, and leaves `a` and `c` compatible but nonadjacent. P3.1
emits cluster `[a,c]` with zero internal edges.

That violates the normative rule that smaller seeds merge only across a quotient
edge with compatible signature and reviewer route. It is effectively a lexical
or bucket relabeling, not a graph partition. The F16 test does not catch it. Its
articulation arm merely asserts that an `Articulation` label appears after
partition; it does not compare cut membership against a controlled one-field
articulation mutation. Optional node attributes also do not constitute a general
ownership/package-feature signature for future exact planes.

### 6. HIGH — F20 does not hash every expected file

`evidence/write.rs:144-177` builds the artifact size/hash map before
`generation.json` exists. Lines 184-189 then add `generation.json` to
`expected_files`, but no `ArtifactPublication::Published` record is ever added
for it. The probe confirms:

```text

generation_hashed=false
```

The F20 test iterates only the entries already present in `generation.artifacts`,
so it never asserts that every expected file has a size/hash record. The run ID
binds receipt fields semantically, but that is not the adjudicated exact file-set,
size, and SHA-256 receipt for every file.

### 7. HIGH — quotient cycle evidence is generated but not independently validated

Component bases are rank/replay-validated and shard-local bases are recomputed.
`validate_quotient` at `evidence/validate.rs:253-300`, however, reconstructs only
quotient edges and hashes whatever `projection.quotient.bases` already contains.
It never recomputes rank, tests independence, replays witnesses, or reconciles
cross-shard cycles. F15 tests only the component basis. This misses the explicit
law requiring an independent validator for component, shard, and quotient cycle
evidence.

### 8. MEDIUM — the universal privacy predicate still has executable bypasses

`percent_decode` is capped at two passes (`schema/identity.rs:264-288`). A
triple-encoded `file:` URI therefore survives. The POSIX detector also requires a
small preceding-boundary set; an absolute path embedded after `>` survives. Both
were accepted by `CanonicalText::new` in the compiled probe.

F17 says whole or embedded POSIX/Windows/UNC/file forms are rejected independent
of host OS, including encoded forms. The current enumerated test bank is not
universal and does not cover these cases.
