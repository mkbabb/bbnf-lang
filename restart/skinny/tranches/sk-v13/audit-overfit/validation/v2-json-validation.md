## §2 W14 Comparator Integrity: sonic_rs Misname

The codex audit claims comparator misuse: `sonic_rs::from_slice::<Value>()` is eager DOM deserialization, not parse_only.

**Source Evidence**:  
`skinny/crates/bbnf-bench/benches/json_parity.rs:87–102`:
```rust
group.bench_function("sonic_rs_anchor", |b| {
    b.iter(|| {
        let value = sonic_rs::from_slice::<sonic_rs::Value>(black_box(&fixture.bytes)).unwrap();
        black_box(value);
    });
});
```

**Analysis**:
- `sonic_rs::from_slice::<T>()` allocates and populates a DOM `Value` object
- It is **NOT a skip/structural-only parser** (sonic-rs v0.5.8 has no public `Skipper` API)
- The amendment (A3) requires "strict-vs-strict parse_only" — comparing two parsers on the **same work**
- **Status**: Both Track 1 (tape build) and sonic_rs (DOM build) do allocation work, making this **NOT strict-vs-strict on parse_only**, but rather eager-typed vs tape-eager comparison
- W14 measures Mbps only, with **no parse_only equality oracle**

**Verdict**: Comparator-misnamed finding **CONFIRMED**. The bench violates the addendum's strict-vs-strict requirement by mislabeling an eager-typed comparator as parse_only.

## §7 Extension Findings Beyond Codex Audit

### 7.1 SK-V12 Carry-over Consistency Gap

The codex audit identified W14 as gate-relabel only. This validation finds SK-V12's direct and typed admits **DO hold** (generated parsers + consistent comparators). However:

- **Direct admits**: Use `parse_direct()` from same generated.rs as parse_only, but measure a **different workload** (sink dispatch). No per-corpus optimizations found in codegen (Lock 14 forbids corpus-specific branches).
- **Typed admits**: Use generated_real_typed wrappers, which ARE codec-generated, but lack **distinct typed-plane optimizations** in codegen (W8's "per-grammar policy" is scaffold-only per synthesis).

### 7.2 Equality Oracle Consistency

All three planes (parse_only, direct, typed) run equality checks **once at startup**, not per-iteration. This is:
- **Acceptable** for startup verification (catches systematic mismatches early)
- **Insufficient** for per-iteration noise isolation (micro-benchmarks may drift between runs)
- **Not a blocker** if margin > 3× sonic baseline (W14 margins are 1.10–1.41×, where startup checks suffice)

### 7.3 Regenerability Conclusion

The JSON grammar, codegen, and round-trip pipeline are **fully functional**:
- Grammar source: `skinny/grammars/json.bbnf` ✓
- Codegen commands: `regen-json`, `regen-real-typed` ✓
- Output re-checksum: Unknown without running round-trip, but git history shows regeneration consistency

No CSS L4 equivalent anti-pattern found in JSON: there IS a source grammar and an xtask command.
