## 1. Branches, worktrees and seat law

- **Integration branch `sk-v27-lw3` in each repo**, cut in Phase 0 from that repo's `origin/master`. BL also takes an ordinary merge of `origin/sk-v27-lw3-order` (this order).
- **Seat branches** are `lw3/<seat>` off the integration tip at seat start, in each repo the seat works in. Worktrees go in `~/Programming/{bbnf-lang,parse-that,pprint}-wt/lw3-<seat>`. A seat merges into `sk-v27-lw3` with `--no-ff` at seat end. A rejected push is answered by fetch and another ordinary merge.
- **The spine merge branch.** `d/compiler` R4 names `integration/backend`. It is created in BL as a branch off `sk-v27-lw3` for COMP-1b alone and merged back by ordinary merge when COMP-1b is GREEN ×2.
- **Git law.** Commit by pathspec. Never stash, reset, rebase or force. Primary checkouts are never switched. LEDGER.md is append-only and a conflict there is resolved as the union. A `Cargo.lock` conflict takes either side plus `cargo update --workspace`, and the `cargo tree --locked` diff outside the workspace's own packages must be empty. A cross-repo move is one commit in the receiving repo with a `Moved-from: mkbabb/<repo>@<sha> <path>` trailer, plus a deletion commit in the source repo citing it.
- **Push order for git+rev pins:** PP, then PT, then BL. A pin names only a SHA that `git ls-remote` already shows.
- **Target directories.** Each worktree has its own `CARGO_TARGET_DIR` under `~/.dev-logs/bbnf-lockstep/target/lw3-<seat>`. Two worktrees never share one (LED:227, LED:239). A seat removes its target directory when its branch is merged.
- **Unit law.**
  - Every unit reads its falsifier RED ×2 for the stated reason, then GREEN ×2, at SHAs in `heads-LW3.json` or pushed by the seat itself.
  - A gate test must fail on the defect it guards. Each unit therefore records one mutant (the defect re-introduced) read RED ×2 against the GREEN test.
  - One ledger addendum row per unit. Evidence in `SK/evidence/LW3.<LANE>/`, logs in `~/.dev-logs/bbnf-lockstep/lw3/<seat>/`.
  - No lint threshold, allow-list, timeout or assertion is widened to make a row GREEN. No `#[ignore]` is added. A born-RED test loses its `#[ignore]` in the commit that cures it.
- **Machine law.** Every process goes through `~/.claude/guard/guarded`, including one-shot drivers, debuggers and stack measurements; quick commands use `--light`. One heavy run per seat. No command name contains `probe`. Bench seats use `--cpu-cores 0 --exclusive bench`. Fuzzing is local smoke only, in shards of at most 80 min, corpora in `~/.dev-logs/bbnf-lockstep/fuzz/<target>`; long runs are scheduled CI jobs. Nothing durable goes in `/tmp`.
- **Unsafe and SIMD law.** Every `unsafe` or SIMD site has a scalar oracle, a differential fuzz target, ASan, the guard-page test, and Miri where it applies. `core::arch` lives only in PT `rust/simd` (X-3). An x86 tier merges only if CI executes it on hardware with the ISA, or under SDE for AVX-512 (X-4).
- **Model law.** Every seat is spawned with an explicit model, Opus 5.5 (`opus`); the recorded model is checked against the declaration in the seat's receipt.
- **Generality law.** PT carries no BBNF vocabulary. Anything entering PT reads `git grep -niE 'bbnf' -- <paths>` = 0, and `rust/regex` reads 0 with no exclusion.
- **Quarry law (X-1).** The root pipeline (`crates/core/src/{pipeline,backend,generate,runtime}`, `crates/ir`) may only lose code. A seat that needs new behaviour builds it on the spine. Root stays as the second oracle until LW4.COMP-1.
- **Record law (the LW2 gate's lessons).**
  - Pins and records are settled before the final CI read (S19, then S20).
  - A reading's records go in BL only. Nothing is committed to the PT or PP integration branches between the final re-pin and the merge.
  - Versions are ruled by `semver-probe.sh` against the published consumers plus a public-API diff, never by intent. A crates.io version is never reused.
  - Identity is by git tree, never by commit hash.
  - A purely stale pin or stale record found during a reading is cured as its own unit (RED ×2 → GREEN ×2, a ledger row), followed by a fresh CI read and a full re-read. Any other RED stops the reading.
