## §1 Deliverable

Hereupon `crates/path-ts/` (frozen API at BC.W5 per Lock 7) graduates from compileable-Rust-shell-with-binding-stubs to runtime-executing NAPI-RS native binary. The cdylib at `crates/path-ts/Cargo.toml`'s `[lib] crate-type = ["cdylib"]` produces a `.node` file via `napi build`; the runtime smoke test imports the binary, calls `compile()` on a trivial grammar, asserts the output is non-empty syntactically-valid TypeScript.

The wave is the production-receiver for BC.W2's TS scaffold (`docs/tranches/BC/waves/W2.md:36-58`): the scaffold compiled the IR contract against `unimplemented!()` paths; W0 fills the proc-macro entry point with concrete logic. The scaffold's smoke test (`crates/core/tests/ts_scaffold_smoke.rs`) graduates from "non-empty source emit verified by AST validator" to "non-empty source emit verified by `node --check` on the runtime binary's output".

The mechanism: `path-ts`'s NAPI-RS exports a `compile(grammar_source: string) -> { source: string, types: string }` function. The function takes BBNF grammar source bytes; runs it through the BC.W0 typed IR contract; calls the BD.W1 TS emitter (instantiated at W1 close, smoke-tested here). For W0, the emitter runs in a vendored mode — the smoke test passes a hard-coded trivial grammar and asserts the emit shape. Full per-grammar emission is BD.W1.

### §2.2 Compile entry point

Mechanism: implement `compile(grammar_source: String) -> Result<TsCompileOutput>`. The function accepts BBNF grammar source bytes; calls `bbnf_parse::parse_grammar(&grammar_source)` to get the typed IR contract; calls `bbnf_codegen::ts::Emitter::lower(&ir)` to get the emitted TS source. For W0, the emitter is the BC.W2 scaffold — `unimplemented!()` paths are present; the smoke test uses a trivial grammar that hits no `unimplemented!()` paths.

```rust
// crates/path-ts/src/lib.rs
use napi_derive::napi;
use bbnf_parse::parse_grammar;
use bbnf_codegen::ts::TsEmitter;

#[napi(object)]
pub struct TsCompileOutput {
    pub source: String,
    pub types: String,
}

#[napi]
pub fn compile(grammar_source: String) -> napi::Result<TsCompileOutput> {
    let ir = parse_grammar(&grammar_source)
        .map_err(|e| napi::Error::from_reason(e.to_string()))?;
    let emit = TsEmitter::new();
    let (source, types) = emit.lower_to_ts(&ir)
        .map_err(|e| napi::Error::from_reason(e.to_string()))?;
    Ok(TsCompileOutput { source, types })
}
```

Files: `crates/path-ts/src/lib.rs` (modify).

Sub-gate: `cargo check -p path-ts` green; the compile fn signature satisfies the NAPI-RS macro requirements; the emit call returns a non-empty source for the trivial grammar.

### §2.3 Runtime smoke test (Node)

Mechanism: extend BC.W2's `crates/core/tests/ts_scaffold_smoke.rs` to a runtime smoke test that imports the built `.node` binary and calls the exported `compile()` fn. The test runs on M1 Pro Node 20.x; the grammar is the cohort CSV grammar (~330 LOC at BB close per `docs/tranches/BC/BC.md:117`); the assertion is that the returned `source` field passes `node --check`.

```javascript
// crates/path-ts/__tests__/smoke.mjs
import { strict as assert } from 'node:assert';
import { compile } from '../path-ts.darwin-arm64.node';
import { readFileSync } from 'node:fs';

const grammar = readFileSync('grammar/csv/csv.bbnf', 'utf-8');
const out = compile(grammar);

assert.ok(out.source.length > 100, 'TS source non-empty');
assert.ok(out.types.includes('export type CsvValue'), 'TypedValue sum emitted');
assert.ok(!out.source.includes('unimplemented'), 'no unimplemented sites for trivial grammar');
```

Files: `crates/path-ts/__tests__/smoke.mjs` (create), `crates/path-ts/package.json` (modify — add test script).

Sub-gate: `node --test crates/path-ts/__tests__/smoke.mjs` passes on M1 Pro Node 20.x; the assertion catches `unimplemented` substring (the emit must be production for the trivial grammar).

## §5 Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| napi-rs version conflict between path-ts and other workspace consumers | Low | The workspace pins `napi = "2"` at the root `Cargo.toml`; per-crate features are uniform; if conflict appears, the workspace pins to a single feature set per W0-G5 |
| `napi build` requires the @napi-rs/cli npm tool, which is a dev-dependency, not a Rust dependency | Medium | The CI matrix at W0-G3 installs `@napi-rs/cli` as a setup step; the local dev workflow includes `npm install --save-dev @napi-rs/cli` in `crates/path-ts/package.json` |
| The smoke test's `import` statement fails because Node's ESM loader doesn't resolve relative `.node` paths | Medium | The smoke test uses `createRequire(import.meta.url)('./path-ts.darwin-arm64.node')` to bridge ESM ↔ CJS for the `.node` binary; documented in `docs/tranches/BD/audit/W0-ts-procmacro-spec.md` |
| The `compile()` fn's return type `TsCompileOutput` collides with a JS reserved word or a TS interface name | Low | The struct name is bbnf-namespaced; no collision with JS / TS standard names; `napi(object)` derive handles serialisation |
| Host-fn graceful failure misfires because the BC.W2 scaffold's error message format diverges from the W0 production format | Low | The verbatim error message is fixed at BC.W2 §2.5 ("host fn not supported in BC scaffold; activate at BD") and propagates through W0 activation; W0's test asserts the verbatim string |
| The CI runner's macOS version is older than Node 20.x's runtime requirement | Low | The CI matrix at W0-G3 pins macOS-14 (Sonoma) explicitly; macOS 12+ supports Node 20.x; older runners are excluded |
| The build pipeline diverges between path (Rust proc-macro) and path-ts (NAPI-RS) in a way that breaks Lock 7's triplet symmetry | Medium | The W0-G6 spec document records both pipelines; the W3 publication wave verifies both ship from the same git tag; divergence is caught at audit |
