## Verdict

ACCEPT FOR REDRESS from CH5.

Plan V2 keeps the hidden-coupling routes blocked at the plan boundary and
redress can proceed from the CH5 lens. The earlier CH5 risk remains real in
the opening codebase: current skinny codegen emits through the JSON provider,
runtime exports are JSON-only, root-workspace CSS and lightningcss surfaces are
available nearby, and the SK-V12 non-JSON gate still relies too heavily on
self-attested strings. Plan V2 now names these as redress-owned executable
separation requirements rather than leaving them implicit.

This is not a source PASS. The redress patch fails CH5 if it implements a
hand-only CSS parser under a generated path, reuses the JSON provider as the CSS
runtime, lets the oracle call Track 1/root CSS/lightningcss/JSON runtime, or
records equality through digest-only or status-text-only evidence.

## Required Redress Preconditions

1. Generated Track 1 proof must be executable. The CSS provider/profile must
   render `mod.rs`, `config.rs`, `parser.rs`, and `generated.rs` to a temporary
   directory and byte-compare them against
   `skinny/crates/runtime/src/grammars/css_l4_declaration_values/`.

2. Provider dispatch must keep CSS declaration/fact policy in CSS-owned files.
   Generic code may register and select profiles/providers, but a generic CSS
   behavior branch, JSON provider clone, or JSON sink reuse for CSS Track 1 is a
   CH5 reject.

3. The skinny CSS Track 1 runtime must not call, re-export, or alias
   `runtime::generated_json`, `runtime::grammars::json`, `parse_that_regex`,
   `bbnf-simd`, root `CssL4Parser`, root `CssStructBuilder`, or
   `crates/core/src/runtime/css_l4`.

4. The oracle must live in
   `skinny/crates/bbnf-bench/src/nonjson_css_l4.rs`, use `cssparser` as the
   parser of record for Track 2, and avoid generated Track 1, root CSS runtime,
   JSON runtime, `lightningcss`, `parse_that_regex`, and `bbnf-simd`.

5. Track 1 and oracle must emit retained canonical fact-stream bytes before
   timing. The gate/report must record Track 1 fact path, oracle fact path,
   stream hash, first-diff artifact path, fixture checksum/bytes, and strict
   equality status. Digest-only authority is insufficient.

6. `SkV12NonJsonRow` validation must consume the V2 fields:
   `strictness`, `grammar_checksum`, `input_checksum`, `input_bytes`,
   `measured_validation_path`, `profile_artifact`, `generated_loc`,
   `generated_module_bytes`, `grammar_size_guard`, `lock14_status`,
   `lock16_status`, `scalar_reference_status`, and
   `checkasm_or_parity_status`.

7. The W1b-1 row must require
   `output_plane = css_l4_declaration_value_fact_stream`,
   `outcome_id = C`, `verdict = GO`,
   `same_wave_consumer_class = companion_gate_generated_baseline`,
   `lock16_status = not_applicable:scalar_only`,
   `scalar_reference_status = generated_scalar_track1`, and
   `checkasm_or_parity_status = parity_pass`.

8. The gate must perform content/import audits over the W1b-1 oracle, bench,
   CSS runtime, CSS provider, and companion report. It must reject
   `runtime::generated_json`, `runtime::grammars::json`, `json_provider` usage
   outside JSON-only provider tests, `CssL4Parser`, `CssStructBuilder`,
   `crates/core/src/runtime/css_l4`, `lightningcss`, `parse_that_regex`, and
   `bbnf-simd` in W1b-1 Track 1 or Track 2 paths.

9. W1b-1 must not emit `lightningcss_mbps`, `lightningcss_command`, CSS ADMIT
   language, main JSON `RESULTS.md` rows/columns, a new outcome enum, or a
   SOTA claim. W1b-2 owns the comparator and admission threshold.

10. JSON guard reruns are mandatory after redress because V2 changes generic
    codegen selection, runtime exports, report/gate validation, and bench
    dependencies. A stale or self-attested `json_guard_state` is a CH5 reject.

## Blockers

- No CH5 plan-time blocker prevents redress from starting.
- PASS is blocked if CSS Track 1 is hand-authored under a generated path
  without a reproducible CSS provider/profile proof.
- PASS is blocked if Track 1 or Track 2 imports or calls root CSS runtime,
  lightningcss, JSON runtime, `parse_that_regex`, or `bbnf-simd`.
- PASS is blocked if the oracle shares generated Track 1 code, calls Track 1,
  or validates equality through status text rather than retained fact-stream
  bytes.
- PASS is blocked if the non-JSON gate remains at the current
  `direct_sink`/string-attestation level and does not consume the V2 provenance,
  size, Lock, scalar-reference, parity, artifact, and JSON guard fields.
- PASS is blocked if W1b-1 records a lightningcss comparison/admission, mutates
  the main JSON telemetry/outcome surface, or skips the JSON guard rerun.
