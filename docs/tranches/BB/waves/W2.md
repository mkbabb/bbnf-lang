# BB.W2 — Five-Grammar Cohort Template Emission

**Thesis** Hereupon the five-grammar template cohort (BNF, CSV, EBNF, CSS Pretty, Math) compresses from ~2,000 LOC of mechanical instantiation across 35 files to ≤250 LOC across 5 thin per-grammar instantiation files via single-template codegen at xtask regen time. **Closer-gate** BB-G5 met (≥1,500 LOC saved); `crates/core/src/runtime/<simple>/{arena,builder,document,view,kind,value,mod}.rs` are template-emitted; cohort byte-equality regression tests pass before deletion of hand-written files.

## §1 Deliverable

Per `audit/CENSUS-2026-05-03.md:507-528`, the five trivial cohort grammars (BNF, CSV, EBNF, CSS Pretty, Math) each carry seven files (`arena, builder, document, kind, mod, value, view`) totalling 350-450 LOC each — byte-near-identical except for type-name substitutions. The total surface is `7 × 5 = 35` files with `~2,000 LOC of mechanical instantiation`. W2 emits these from a single codegen template at xtask-regen time so each cohort grammar's `runtime/<g>/` shrinks to ≤50 LOC of mechanical instantiation.

The existing scaffolding makes this transposition possible: `crates/core/src/runtime/builder_template.rs` (286 LOC, `audit/MODULES-2026-05-03.md:923`) factors the `StructBuilder` trait shared by these five; `crates/core/src/runtime/arena_template.rs` (134 LOC, `audit/MODULES-2026-05-03.md:921`) factors the arena. The `document.rs` / `view.rs` / `kind.rs` / `value.rs` / `mod.rs` files are NOT yet templated; W2 closes that gap.

The four specialised grammars (BBNF, JSON, Sheets, CSS L4) keep their hand-written modules. Per the BB.W1 deliverable, BBNF's bounds-recording, Sheets's specialised leaf-deposit, JSON's typed enum, and CSS L4's 14-variant typed value are each grammar-specific concerns that the template cannot uniformly capture. W2 thereby honours the cohort distinction: five trivial cohort grammars get template emission; four specialised grammars stay hand-written.

W2 also extends the cursor + byte-skip unification (carry BA→BB.C3 from `docs/tranches/BA/BA.md:61`) to all cohort grammars in the same wave. Each cohort grammar's eager `parse(input)` rewrites as `parse_with(input, &EMPTY_PATH)`; the eager fast path elides cursor consultation per Lock 3. The unification was demonstrated on JSON in BA.W4; W2 generalises across the cohort.

The byte-equality regression strategy is critical: per `audit/HARDENING-SYNTHESIS-2026-05-03.md:165` the W2 verification artefact records pre-W2 LOC + warning-count + post-template-emission byte-diff. Template emission generates byte-identical output to the existing hand-written 5-grammar files at first commit; only after the byte-equality gate passes do the hand-written files delete. This precludes silent behaviour drops per the W2 risk row in `docs/tranches/BB/BB.md`.

Estimated edit surface: net deletion of ~1,500 LOC across 5 × 5 = 25 hand-written files (kind, value, mod, document, view); 5 × 2 = 10 files retain (arena, builder — already template-shimmed); 1 new template file at `crates/core/src/codegen/runtime_template.rs` driving the per-cohort emission. The xtask regen pipeline picks up the template; each cohort grammar's `runtime/<g>/` shrinks from ~350-450 LOC to ≤50 LOC.

The cohort-vs-specialised classification draws from `audit/CENSUS-2026-05-03.md:511-515`: the five trivial cohort grammars (BNF, CSV, EBNF, CSS Pretty, Math) carry near-identical runtime surfaces — each `arena.rs` is 54-55 LOC of trivial template instantiation; each `builder.rs` is 54-55 LOC; each `document.rs` is 171-237 LOC; each `kind.rs` is 46-67 LOC; each `mod.rs` is 18 LOC; each `value.rs` is 23-57 LOC; each `view.rs` is 64-80 LOC. The variation between cohort grammars is in type names, not in mechanism; the template emission factors out the mechanism and substitutes the type names per-grammar at xtask regen time.

The four specialised grammars (BBNF, JSON, Sheets, CSS L4) have grammar-specific behaviours that the template cannot uniformly capture: BBNF's bounds-recording, Sheets's specialised leaf-deposit, JSON's typed enum, CSS L4's 14-variant typed value (now retired post-W1). Each specialised grammar's `runtime/<g>/` keeps hand-written modules; W2 leaves them untouched.

The xtask regen pipeline integration per `audit/MODULES-2026-05-03.md:1255-1265` step [16] reads each grammar's IR + analysis output and dispatches to the appropriate emitter. The cohort template emission piggybacks on the existing `cargo xtask regen` invocation: the pipeline detects cohort grammars by metadata (`[workspace.metadata.bbnf.grammars.bnf.cohort = true]`); the runtime emission template fires for those grammars; the result lands at `crates/core/src/runtime/<cohort>/{document,view,kind,value,mod}.rs`.

The byte-equality discipline per `feedback_clean_regen_discipline` mandates that template emission generates byte-identical output to the existing hand-written files at first commit. This is the precondition for safe deletion: M2 verifies byte-equality; only after passing does M4 delete the hand-written files. If byte-equality fails, the template extends to capture the variation rather than the hand-written files persisting as debt. The discipline is mechanical — diff returns zero before deletion happens.

1. The grammar's typed value sum from layout-lowering (carry BA→BB.C2; `Layout`/`LayoutSink` per the canon at `audit/SOTA-2026-05-03.md:251-272`).

## §10 Implementation reference

The cohort template emission shape follows the existing `arena_template.rs` and `builder_template.rs` patterns at `crates/core/src/runtime/`. The new template at `crates/core/src/codegen/runtime_template.rs` extends this to the five other files (`document, view, kind, value, mod`).

The templated `mod.rs` shape per cohort grammar:

```rust
// crates/core/src/runtime/<cohort>/mod.rs (templated; emitted by xtask regen)
//! <Cohort> grammar runtime module.
//!
//! Templated from `crates/core/src/codegen/runtime_template.rs`.

mod arena;
mod builder;
mod document;
mod kind;
mod value;
mod view;

pub use arena::*;
pub use builder::*;
pub use document::*;
pub use kind::*;
pub use value::*;
pub use view::*;
```

The templated `value.rs` shape per cohort grammar emits the `<G>Value` enum:

```rust
// crates/core/src/runtime/<cohort>/value.rs (templated)
use crate::runtime::builder_template::SimpleValue;

#[derive(Clone, Copy, Debug)]
pub enum <G>Value<'p> {
    Null,
    Bool(bool),
    Number(f64),
    String(&'p str),
    // ... per-grammar variants from layout-lowering
}

impl<'p> SimpleValue for <G>Value<'p> {
    fn deposit_str(s: &'p str) -> Self { Self::String(s) }
    fn deposit_f64(n: f64) -> Self { Self::Number(n) }
    // ... per the SimpleValue trait surface at crates/core/src/runtime/builder_template.rs
}
```

The templated `view.rs` and `document.rs` follow the same pattern: each emits a typed-view + path-query implementation that the cohort's path-query consumer reads. Per `audit/CENSUS-2026-05-03.md:511-528`, the existing hand-written cohort modules already compile to this shape; the template simply factors the per-grammar mechanism.
