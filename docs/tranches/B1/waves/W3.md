## Phase sub-items

### B1.W3.a — PROFILING.md refresh + post-B1.json aggregate + FINAL + handoff

**Opens**: W2 close.
**Agent count**: 1.
**Hard cap**: 60 min.
**Role**: single consolidator; no parallel sub-agents at this
stage. The document surface is a single integrated prose and
cannot be raced.

Mechanism:

**PROFILING.md refresh (Step 12)**:
- Add §ICE recovery: the `make clean-incr` target + the
  `rm -rf target/ax-iter/incremental` sequence under the pin
  (incremental cache only; `target/.bbnf-cache/` stays intact
  per B1.md invariant 12 — it is the bbnf-derive content-keyed
  cache and nuking it poisons cycle-2 measurement); explains the
  content-hash guard in `scripts/bootstrap-bbnf.sh`.
- Add §Dev-host setup: `cargo install cargo-nextest --locked`;
  `rustup component add rustc-codegen-cranelift --toolchain
  nightly-2026-04-11` (bare component name, rustup auto-suffixes
  with the host target; no `-preview` suffix on this pin); `brew
  install lld` on macOS as the opt-in fast-linker (separate
  formula from `brew install llvm`, which ships lldb only; path
  after install is `/opt/homebrew/opt/lld/bin/ld.lld`); valgrind
  note for Linux CI.
- Add §Bench alias surface: name every `cargo bench-*` alias
  once; show the divan JSON redirection pattern; show
  `DIVAN_BENCH_FORMAT=json cargo bench-json >
  docs/benchmarks/post-B1-<scope>.json`; note iai-callgrind runs
  on CI only.
- Refresh §Routine surface against the final W0.b comment block
  in `.cargo/config.toml`; name every alias (`iter-check`,
  `iter-test-leaf`, `iter-check-full`, `iter-check-lsp`,
  `iter-check-prettify`, `iter-check-bootstrap`, `bench-json`,
  expand-*).
- Delete stale prose naming scripts that W2.b removed.
- Verify: `rg -c '<alias>' docs/instructions/PROFILING.md` returns
  exactly 1 for every declared alias.

**post-B1.json aggregate**:
- Construct `docs/benchmarks/post-B1.json` as a single JSON
  document with keys `routine`, `bootstrap`, `profile_prep`,
  `samply`, `divan`, `nextest_close`, `iai_baseline`,
  `cross_repo`. Each key holds the measured rows sourced from
  the W0/W1/W2 artefacts.
- Include a `provenance` block naming every source file and the
  commit SHA that produced each row.

**FINAL.md**:
- Author `docs/tranches/B1/FINAL.md` with sections: Scope recap,
  Invariant table (16 rows from `B1.md §Invariants` with a
  citation column), Hard-gate table (one row per wave's hard
  gate, green/red column), Wave commit ledger (SHA + title per
  wave), Cross-tranche debt summary, AY-II handoff block.
- The handoff block names `docs/tranches/AY-II/PATH-FORWARD.md`
  as the next execution anchor.

**AY-II handoff update**:
- `docs/tranches/AY-II/PATH-FORWARD.md`: add an entry under the
  dated log naming B1 close and pointing to `B1/FINAL.md`;
  explicitly unblock AY-II.W0' close ceremony.
- `docs/tranches/AY-II/PROGRESS.md`: same unblock entry.
- `docs/tranches/AY-II/AY-II.md`: refresh the execution-order
  header — "B1 closed; W0' close ceremony resumes; W1-W5
  sequential."
- AY-II wave specs (W0p, W1, W2, W3, W4, W5): update the status
  line to reflect the refreshed substrate (pinned nightly +
  divan harness) where relevant. Delete references to
  `bencher`-specific assertions.

**PROGRESS.md close entry**:
- Add the final dated log entry to `docs/tranches/B1/PROGRESS.md`
  naming B1 closed, every wave's close SHA, and the AY-II unblock.

Sub-gate:
