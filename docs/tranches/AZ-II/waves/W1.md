## Scope

W1 lands the cutover end-to-end. Stage A and Stage B are folded
into one wave because the intermediate state — Stage A produced
but Stage B not yet verified — leaves the tree with two emission
targets wired side by side and no proof that either is
reproducible. That state cannot survive a wave boundary as a
master-green checkpoint; merging the stages keeps the
unworkability bounded to W1's interior, where the byte-equal
close gate is the sole arbiter.

1. Run `project_types` to fixed point on BBNF's grammar. Resolve
   every named-rule type, every `->` field, every compound closure.
   Hard-fail-and-block on any unclosed edge.
2. Populate `StructRegistry` with BBNF's full layout set: `BbnfAst`,
   `Rule`, `Expr`, `Ident`, `Param`, `TypeExpr`, `Import`,
   `Directive`, `Comment`, `RegexPattern`, `RegexHir`, and per-
   variant sub-shapes.
3. Add a struct-writing emission mode to the rust emitter under
   `crates/core/src/backend/rust/emitter/`, exposed via
   `cargo xtask regen --emit-mode <tape|struct>`. Both modes
   (tape-writing and struct-writing) are present during Stage A.
4. Wire the BBNF runtime loader to read `BbnfAst` via the struct
   path when the flag is enabled.
5. **Stage A.** Pre-AZ-II compiler (tape-based, from AZ-I close)
   builds the AZ-II-candidate compiler with struct-writing mode
   enabled. The resulting xtask regen pipeline emits
   struct-writing parsers. Capture Stage A output: run
   `cargo xtask regen --emit-mode struct` against every `.bbnf`
   fixture (`grammar/*/*.bbnf`, `tests/fixtures/*.bbnf`,
   `grammar/bbnf/bbnf.bbnf` itself) and archive the parsed output
   to `docs/benchmarks/archive/AZ-II/W1/stage-a-output/<fixture>/`.
6. **Stage B.** The Stage A candidate compiler rebuilds itself.
   `cargo clean && cargo build -p bbnf` runs with the candidate
   as the bootstrap toolchain; the resulting xtask regen pipeline
   is itself built from a struct-writing parser and produces
   struct-writing parsers. Tape is unwired in both directions for
   BBNF's bootstrap. Capture Stage B output: the same
   `cargo xtask regen --emit-mode struct` invocations on the same
   fixture corpus, archived to
   `docs/benchmarks/archive/AZ-II/W1/stage-b-output/<fixture>/`.
7. **Byte-equal close gate.** `diff -r
   docs/benchmarks/archive/AZ-II/W1/stage-a-output/
   docs/benchmarks/archive/AZ-II/W1/stage-b-output/` returns zero byte
   differences on every fixture. Any divergence triggers the
   reversal path (see §Reversal criteria); the W1 substrate
   reverts and AZ-II re-plans against the observed drift.
8. Land `tests/bbnf_self_parity.rs`: compares `BbnfAst` parsed via
   struct path against the hand-maintained in-memory IR surface;
   covers every fixture.
9. Land `tests/bbnf_bootstrap_reproducibility.rs` as a permanent
   CI test. Encodes the Stage A / Stage B diff as a repeatable
   gate that runs on every commit post-W1; any break fails the
   build.
10. Re-run the full 17-entry matrix on the Stage B compiler;
    confirm no regression from AZ-I close.

Sub-gate: `cargo xtask regen --emit-mode struct --check` green;

## Reversal criteria

`project_types` fails to close on BBNF → build-stop diagnostic
identifies the unclosed edge; W1 re-plans to resolve (likely via
grammar edit or `project_types` pass fix).

`bbnf_self_parity` fails on any fixture → revert the
struct-emission path for that fixture class; investigate drift
source; re-attempt within the wave or escalate to W0 re-plan.

Byte-equal fails on any fixture → wave reverts and AZ-II re-plans:

1. Revert the struct-emission substrate for the BBNF bootstrap.
2. Capture the specific drift source(s) observed: which fixture,
   which class (AST ordering / trivia / numeric / other),
   minimised reproducer.
3. Author a re-plan brief that folds the observed drift sources
   back into `BOOTSTRAP-CUTOVER.md` with concrete mitigations;
   W1 re-opens against the refined design.
4. Full tape abrogation remains the close gate; no partial-close
   floor is accepted.

A 10%+ regression on BBNF self-parse throughput triggers the same
reversal-and-re-plan sequence; BBNF self-parse perf is internal
build cost, but regression is still a re-plan trigger and does
not permit a partial-closure state.
