# BB.W3 - Ranker + Tiering

**Name**: W3 - Ranker + Tiering
**Opens after**: W2 - VM Oracle On Residue
**Agents**: 5 parallel
**Hard gate**: automatic ranker scores every surviving candidate; Class-1/2/3 classifier with target ≥ 90% Class 1 + 2; ≥ 5 accepted rules per primary grammar (JSON, CSS L4, Sheets, BBNF); corpus hit-rate ≥ 0.1 per parse averaged across primaries
**Status**: planned

## Scope

1. Implement `crates/ir/src/rewrites/rank.rs`: automatic ranker. Signals: match frequency (number of corpus matches for LHS pattern across all grammars), cost delta (`cost(LHS) - cost(RHS)` via existing cost model), generality (number of grammars whose IR contains LHS pattern), similarity-to-known (structural edit distance to Tranche H hand-coded rules), novelty (inverse of similarity), tree size (LHS node count). The weighted score feeds the tier classifier.
2. Implement `crates/ir/src/rewrites/tiering.rs`: Class-1/2/3 classifier. Class 1 (trivial / algebraic / rediscovered): auto-accept with machine-generated justification committed to audit log. Class 2 (structural resemblance): fast-track review. Class 3 (novel): full human review.
3. Run W2's surviving-candidate set through the ranker; tier each candidate; record per-tier counts in `docs/tranches/BB/audit/W3-tier-distribution.txt`.
4. Per-grammar acceptance: ≥ 5 accepted rules each for JSON, CSS L4, Sheets, BBNF. Per-wave declared candidates: W3 = grammar-specific corpora.
5. Corpus hit-rate measurement: every retained rule fires ≥ 0.1 times per parse averaged across the 4 primary grammars. The measurement is artefact-bound — `docs/benchmarks/post-BB-W3-hit-rate.json` plus samply attribution proving firings register on the parse hot path.
6. Class distribution: > 90% of accepted rules across all shipped waves classify as Class 1 + Class 2.

## Triumvirate Dispatch

Dispatch a triumvirate if any of these occurs:

- the ranker miscalibrates: > 30% of candidates land in Class 3 (target is < 10%; the ranker weights need calibration; W4's audit may be early);
- the per-grammar acceptance count is < 5 for any primary (the alphabet did not produce enough discoveries; the alphabet narrows or W1's enumerator extends, both outside W3 file bounds);
- the corpus hit-rate is < 0.1 for any retained rule (the rule's LHS doesn't fire on the production corpus; the rule retires per the e-graph cost model);
- a candidate that the ranker auto-accepts (Class 1) regresses a parity test (the e-graph's saturation under the new rule produces a divergent output);
- three diagnostic-loop iterations fail to isolate a Class-3 false-positive;
- JSONL transcript quiet >15 minutes;
- first-pass return with no commit and no evidence (after one verbatim redispatch).

## Agent Units

### BB.W3.1 Ranker

- Mechanism: implement `RankSignals` with the 6 named signals (match frequency, cost delta, generality, similarity-to-known, novelty, tree size). The weighted score is configurable; default weights live in `crates/ir/src/rewrites/rank.rs`. Per-rule report includes the score breakdown for transparency.
- Files: `crates/ir/src/rewrites/rank.rs`.
- Sub-gate: ranker compiles; named test `crates/ir/tests/rank_smoke.rs` covers a known-Class-1 candidate (`Concat(a, Epsilon) → a`), a known-Class-2 (similar to `factor`), a known-Class-3 (novel pattern); the score breakdowns are deterministic.

### BB.W3.2 Tiering

- Mechanism: implement `Tiering::classify(rank_result) -> Tier`. Class 1 thresholds: similarity-to-known ≥ 0.9 OR cost delta < threshold AND tree size ≤ 3. Class 2: similarity-to-known ≥ 0.5. Class 3: otherwise. Each Class-1 acceptance generates a machine-generated justification line; the classifier emits the line for `docs/rules/audit-log.ndjson`.
- Files: `crates/ir/src/rewrites/tiering.rs`.
- Sub-gate: tiering compiles; named test `crates/ir/tests/tiering_smoke.rs` covers each tier; the audit-log entry shape is verified.

### BB.W3.3 Smoke Tests

- Mechanism: write `crates/ir/tests/rank_smoke.rs` and `crates/ir/tests/tiering_smoke.rs` covering the 6-signal scoring + the 3-tier classifier. Run a fixture set of 20 candidates; verify the tier distribution > 90% Class 1 + 2.
- Files: `crates/ir/tests/{rank_smoke,tiering_smoke}.rs`.
- Sub-gate: tests pass; tier distribution > 90% Class 1 + 2 on the fixture set.

### BB.W3.4 W3 Run + Hit-Rate

- Mechanism: run W2's surviving-candidate set through the ranker + tier classifier. For each primary grammar (JSON, CSS L4, Sheets, BBNF), select the top ≥ 5 accepted rules. Run the corpus hit-rate measurement: each retained rule must fire ≥ 0.1 times per parse averaged across the 4 primary grammars. Save `docs/benchmarks/post-BB-W3-hit-rate.json` with per-rule firings + samply attribution.
- Files: `docs/rules/runs/W3-run.md`, `docs/benchmarks/post-BB-W3-hit-rate.json`.
- Sub-gate: ≥ 5 accepted rules per primary; corpus hit-rate ≥ 0.1 per retained rule; samply attribution produced.

### BB.W3.5 Tier Distribution + Audit

- Mechanism: write `docs/tranches/BB/audit/W3-tier-distribution.txt` (per-tier counts), `docs/tranches/BB/audit/W3-ranker-calibration.md` (signal weight rationale), `docs/tranches/BB/audit/W3-acceptance-per-grammar.txt` (per-primary count).
