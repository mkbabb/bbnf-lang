# BD.W3 — Sister-Crate + Path-Triplet Publication

**Name**: W3 — Sister-Crate + Path-Triplet Publication
**Opens after**: BD.W0 + BD.W1 + BD.W2 close (path-ts cdylib + TS runtime + WASM runtime all ship in dev; per-platform CI artefacts available)
**Hard gate**: sister crates (`egraph-derive`, `egraph`, `csp-solver`, `bbnf-regex`) publish to crates.io with `cargo-semver-checks` clean against BC.W5 freeze baseline; path triplet (`path`, `path-core`, `path-ts`) publishes coordinated; `cargo install <crate>` succeeds end-to-end for each
**Status**: planned

## §1 Deliverable

Hereupon the BC.W5 sister-crate freeze (`docs/tranches/BC/waves/W5.md:55-77`) graduates from `cargo publish --dry-run` clean to `cargo publish` actual: the sister crates publish to crates.io in dependency order via `cargo-release`. The path triplet (Lock 7) publishes coordinated: `path-core` + `path` to crates.io, `path-ts` to npm with per-platform NAPI-RS sub-packages.

The publication order is computed automatically from the path-dep graph per `docs/tranches/BD/audit/research-anchors.md:§3`:

```
egraph-derive  → (none)            depth 0 (publishes first)
egraph         → egraph-derive     depth 1
csp-solver     → (none)            depth 0
bbnf-regex     → (none)            depth 0
path-core      → (none)            depth 0
path           → path-core         depth 1
path-ts        → path-core         depth 1 (npm publish, not crates.io)
```

`cargo-release` walks the workspace and publishes the path-dep DAG in topological order; `cargo-semver-checks` validates each against the BC.W5 freeze baseline (catches removed pub items, signature changes, trait modifications).

The `parse-that` disposition per BC.W5c gap-I (`audit/HARDENING-PLAN-SYNTHESIS-2026-05-03.md:67`): if BC chose option (i) "permanent path-dep", BD does not publish parse-that; if option (ii) "deferred publication with named gate", BD.W3 publishes parse-that as part of the sister-crate set; if option (iii) "stabilised + frozen + published in BC.W5", parse-that is already published before BD opens. **Default per the synthesis surgery 33: option (i) permanent path-dep**, hence BD.W3 does NOT publish parse-that. The W3 audit document records the disposition.

```toml
[package.egraph]
```

### §2.2 cargo-semver-checks validation per crate

Mechanism: per `docs/tranches/BD/audit/research-anchors.md:§3`, cargo-semver-checks validates pub-API stability via rustdoc JSON. The BC.W5 freeze baseline is captured at `docs/tranches/BC/audit/W5-{crate}-freeze.md` (per `docs/tranches/BC/waves/W5.md:59-77`). W3 runs cargo-semver-checks against each crate against the freeze baseline.

```bash
# for each sister crate:
cargo install cargo-semver-checks --locked
cargo semver-checks check-release -p egraph --baseline-rev <BC.W5-tag>
cargo semver-checks check-release -p egraph-derive --baseline-rev <BC.W5-tag>
cargo semver-checks check-release -p csp-solver --baseline-rev <BC.W5-tag>
cargo semver-checks check-release -p bbnf-regex --baseline-rev <BC.W5-tag>
cargo semver-checks check-release -p path-core --baseline-rev <BC.W5-tag>
```

Files: `docs/tranches/BD/audit/W3-semver-checks-report.md` (create — per-crate validation result).

Sub-gate: cargo-semver-checks reports clean for each crate; the report records the BC.W5 baseline rev + the W3 candidate rev + the diff; any reported break is resolved before publication (either fixed or version-bumped major).

### §2.5 path-ts npm publication with per-platform sub-packages

## §5 Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| cargo-semver-checks reports a break for a sister crate that was assumed stable | Medium | The BC.W5 freeze baseline is the binding commitment; if a break is reported, the W3 wave amends the freeze docs (with a major version bump) and re-runs validation; the wave does not close until validation is clean |
| crates.io publication fails because the crate name is squatted | Low | The crate names (`egraph`, `egraph-derive`, `csp-solver`, `bbnf-regex`, `path-core`, `path`) are checked at BC.W5 freeze precondition; if any name is taken, the alternative is to scope the names (`bbnf-egraph`, `bbnf-csp-solver`); the W3 audit document records the actual published name |
| npm publication fails because `@bbnf-lang` org is squatted | Low | The npm scope is registered at BD.W0 §2.7 (parent of the `@bbnf-lang/path-ts` reference); if squatted, the alternative is `@bbnf` or the unscoped names with BBNF prefix; the W3 audit document records the actual published scope |
| The path-dep graph has a cycle that cargo-release can't resolve | Low | `audit/MODULES-2026-05-03.md:1149-1156` already verified zero circular dependencies; if a cycle is introduced post-BC, the W3 wave reverts the introduction and re-validates |
| The post-publication smoke test fails because the published binary differs from the dev-build | Medium | The CI workflow uses the same Cargo.toml + source tree for both; the only difference is the registry (crates.io vs path-dep); if the smoke test fails, the root cause is the registry's caching layer or npm's optionalDependencies resolution; the wave does not close until smoke tests pass |
| cargo-release pushes git tags that conflict with prior tags | Low | The tag-name pattern in release.toml uses the crate name as prefix (`egraph-v0.1.0`); collision with workspace-level tags is structurally impossible; the wave's CI workflow uses `--no-push` and a manual push step |
| The npm sub-packages' versions drift from the main package version | Medium | The @napi-rs/cli `napi prepublish` enforces version sync; the per-platform sub-package versions match the main package version exactly |
| docs.rs build fails for a crate because the all-features build has compile errors | Medium | Each crate's `[package.metadata.docs.rs] all-features = true` is tested at the BC.W5 freeze precondition (`cargo doc -p <crate>` clean); if a feature-gated import is broken at W3, the wave runs `cargo doc -p <crate> --all-features` locally before publication |
