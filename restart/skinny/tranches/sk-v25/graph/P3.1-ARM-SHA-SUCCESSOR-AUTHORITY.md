## S2 subject law

S2 has no ordinary or portable SHA dependency. `sha2` exists only under
`target.aarch64-apple-darwin.dependencies`, with `asm` mandatory. The xtask crate
must reject every other target at compile time. Apple AArch64 resolution must
contain `asm`; the release binary must contain `sha256h`, `sha256h2`,
`sha256su0`, and `sha256su1`; and `hw.optional.arm.FEAT_SHA256` must equal one.
Upstream `sha2` contains a generic AArch64 scalar fallback, but S2's sole common
hash constructor carries no capability assertion: release optimization erased
that in-process check, so it was not an executable gate. External
`hw.optional.arm.FEAT_SHA256=1` capture now rejects a mismatch immediately before
every launch; the final symbol/disassembly census must show one hardware
compression body and no soft alternative. Sampled instruction addresses
complete the active-lane proof. The unreachable third-party source branch is
not an admitted route or product credit.
x86 feature-tree probes are negative evidence only, never x86 acceptance or a
portability claim. Existing repository x86 configuration/CI is routed structural
debt under the no-x86 law, not compatibility preserved by this slice. Cargo.lock
may change once for the target dependency and is frozen before measurement.

The existing hash unit test is the semantic gate. Frozen constants independently
cover empty input, `abc`, the 56-byte NIST message, one million `a` bytes, and
binary `byte[i] = i mod 256` messages of lengths 55, 56, 63, 64, 65, 119, 120,
127, 128, and 129. OpenSSL 3.6.2 and `shasum` 6.04 independently agreed on every
constant. Every vector must pass one-shot and chunked hashing across padding,
block, and multiblock boundaries. A mismatch rejects S2.
