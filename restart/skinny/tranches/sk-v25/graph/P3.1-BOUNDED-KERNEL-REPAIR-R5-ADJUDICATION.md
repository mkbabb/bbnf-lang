## Critic A rulings

Critic A is **NOT CLEAN**. All three findings are correct.

### A1 — cyclic complete basis can claim zero rank

**CORRECT; HIGH.** `project/quotient.rs:160-188` validates only ordering and
exact component-key coverage. It does not validate the contents of each basis.
At `project/quotient.rs:109-120`, `basis.rank` is trusted as total rank; a
cyclic component supplied as `rank = 0, cycles = []` therefore skips
`complement_basis`, the only path that would otherwise validate the basis.
This permits a false quotient proof.

R6 must preserve cheap exact-domain admission, reserve the quotient budget,
and then validate every complete basis against the decomposition's exact
members and internal edges with the same caller-owned budget. Only validated
rank may govern complement construction.

### A2 — ClusterBuild is not sealed to its edge domain

**CORRECT; HIGH.** `ClusterBuild` stores its set, ownership, and component maps
at `project/cluster.rs:87-90`, but no originating typed-edge-domain identity.
`ClusterBuild::validate_domain` at `project/cluster.rs:110-189` compares
projection, nodes, components, explicit and implicit ownership, and ordering;
it never compares the exact edge identities that produced the clusters.
`quotient::build` accepts a separately supplied build and decomposition at
`project/quotient.rs:39-48`.

The existing cross-projection test is useful but insufficient. Two inputs can
share projection, nodes, SCCs, and shard ownership while differing in
resolver-bound typed edge identities. R6 must store one private SHA-256 domain
seal over the projection and ordered typed-edge identities when constructing
`ClusterBuild`, then compare that seal with the supplied decomposition before
quotient charge, allocation, or algebra. Duplicating the complete edge vector
is not permitted.

### A3 — validation allocates owners before byte admission

**CORRECT; HIGH for resource acceptance.** `evidence/validate.rs:233` invokes
`explicit_cluster_owners`; that function allocates a `BTreeMap` at
`evidence/validate.rs:325-336`. Only afterward does `validate_clusters` invoke
`admit_cluster_validation_bytes` at `evidence/validate.rs:350-374`. The SCC
cardinality cap makes the allocation finite but does not bind it to the
declared validation byte owner.

R6 must make `validate_clusters` charge and admit first, build the owner index
internally second, and return that index for quotient validation. No additional
preflight framework is permitted.

## Critic B rulings

Critic B is **NOT CLEAN**. B1 and B2 are correct implementation/topology
findings. B3 correctly identifies an unproved claim.

### B1 — lossy non-UTF-8 filesystem ingress

**CORRECT; HIGH.** Repository path ingress uses `to_string_lossy` at the source
census (`evidence/binding.rs:1731-1736`), build-input census
(`evidence/binding.rs:1890-1897`), local-manifest identity
(`evidence/binding.rs:2021-2027`), and inventory repository-path owner
(`inventory/filesystem.rs:616-629`). `RepoPath::new` is strict for the Unicode
string it receives, but cannot distinguish a genuine U+FFFD from replacement
introduced by lossy conversion. Distinct byte paths can collapse to one
serialized identity.

R6 must add one strict `RepoPath` relative-filesystem constructor that rejects
non-UTF-8 components, joins validated components with `/`, and delegates to
`RepoPath::new`. All repository-path serialization owners must use it. Local
manifest paths must use fallible `to_str`. Rejecting all genuine U+FFFD or
adding percent-encoding is not permitted.

### B2 — capped serializer test is colocated

**CORRECT; MEDIUM.** `architecture/hash.rs:76-135` contains a colocated
`#[cfg(test)]` module, including the new capped-measurement test at
`hash.rs:100-113`. No source-isomorphic `tests/architecture/hash.rs` owner
exists. The mechanism and passing observation survive, but the topology does
not.

R6 must move the complete hash test module, including the SHA vectors, into
`xtask/tests/architecture/hash.rs` and add only its router declaration to
`xtask/tests/architecture.rs`.

### B3 — parallel-edge validation remains unproved

**CORRECT AS AN EVIDENCE FINDING; IMPLEMENTATION TRUTH UNPROVEN; MEDIUM.** The
implementation at `evidence/validate.rs:399-429` visibly makes one edge pass,

edges by typed identity at `evidence/validate.rs:460-472`. Existing validation
tests do not mutate one member of a parallel-edge family while recomputing
