Named hotspots (inspection-named per the W6.1 dispatch's relaxed Hard
Gate 9; samply 7-artefact contract gated to post-AZ-IV measurement
follow-on per audit/W6-profiling-deferred.md):

1. bbnf_get_twitter (4196x): the lazy lane's hot path is
   `<bbnf::grammar::generated::json::JsonParser>::parse` followed by
   `<bbnf::runtime::Document<'_> as bbnf::path::Get>::get` walking the
   materialised value tree. sonic_get does NOT parse; it pointer-walks
   the raw bytes. The W3 lazy-bail-out parse landed (per AZ-IV W3) but
   the value-API entry point uses the eager path. Routing: AZ-V
   lazy-API integration to make Document::get<T>(path) take the lazy
   path internally on lazy-aware grammars.

2. bbnf_value_canada (167x): canada.json is a 100k-element array of
   doubles. Hotspot is per-leaf f64 payload allocation in the
   `__value` Number branch — the W5 value-API substrate writes a
   Box<f64> equivalent per element. sonic_rs uses inline f64 storage
   in its Value enum. Routing: BA + AZ-V — Eisel-Lemire fast-path
   parsing (already in fast_float2 dep) + arena-pool reuse for
   numeric leaves.

3. bbnf_value_citm (8.2x): citm is keyword-heavy; hotspot is the
   StructDirect string-decode path (currently arena-copy on every
   string; sonic_rs uses copy-on-write borrow). Routing: AZ-V — the
   AU-2.4 borrow-safe-string path was tape-only; extend to the
   value-API.

4. bbnf_value_twitter (5.2x): same hotspots as citm but smaller fixture
   masks the overhead. Closest comparator; the routing fix for citm
   should bring this under 5x.

5. bbnf_value_data_s (2.6x): smallest fixture; fixed parse overhead
   dominates. Closest comparator across all fixtures. The 2.6x is
   primarily allocator + bench-fixture overhead, not parser logic.

6. bbnf_value_data_xl (WATCHDOG): same hotspots as canada scaled 9.4x
   in input. 21MB JSON exceeds the JSON_PARSE 1s wall-clock guard at
   ~2.5s/iter under fat-LTO. Same routing as canada.
