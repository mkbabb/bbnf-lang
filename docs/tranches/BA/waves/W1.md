# BA.W1 — Lazy Traversal Engine + `path!` Macro + Per-Grammar Bench

**Opens after**: W0 close (path IR + type checker + parent-pointer
strategy picked).
**Agents**: 3 parallel, disjoint file bounds.
**Hard gate**: Lazy traversal over the struct tree reaches ≥ 20% win
over sonic-rs `pointer!` on 3-field citm extraction, parity or better
on 30-field, zero heap allocation on every fixture in the micro-bench
suite (dhat-verified).
**Status**: planned.

## Scope

1. Land the traversal executor over the struct tree. Descent is
   field projection; ascent uses the strategy picked at W0.
2. Land the Rust `path!` proc-macro. Expansion runs the W0 type
   checker against the derive input's `StructRegistry`; output is
   a typed accessor call site.
3. Ship per-grammar lazy-path micro-benches: citm.json, tailwind
   CSS, sheets fixture, bbnf grammar — each at 3 / 10 / 30 field
   extraction depths, cold only per `feedback_no-warm-benches`.
4. Hold the parity harness against sonic-rs / simdjson /
   cssparser / lightningcss at every bench point.

## Phase sub-items

### BA.W1.1 — Traversal executor

`executor::project<'p, T>(root: &'p Node, path: &TypedPath<G, T>)
 -> NodeView<'p, T>`. The executor walks the struct tree by
field projection for descent. For wildcard segments, it yields an
iterator of `NodeView` without collecting. For ascent, it
dispatches through the `AscentStrategy` chosen at W0.

Sub-gate: citm.json fixture extracts a 3-field path with zero
heap allocation (dhat-verified) and ns/access recorded.

### BA.W1.2 — `path!` proc-macro

`path!("$.users[0].name", Users)` expands at compile time to a
call site consuming a `NodeView<'p, Users>` and returning a typed
accessor. The macro body parses the path string with the bespoke
`bbnf-regex` parser, type-checks against the compile-time
`StructRegistry`, and emits a `TypedPath` literal with the
resolved terminal type.

Sub-gate: `path!` expansion produces a typed accessor for every
Named rule in JSON and CSS L4 grammars.

### BA.W1.3 — Per-grammar micro-bench

`benches/path_extract.rs` exercises the executor across four
grammars × three extraction depths. Bench harness is `vitest` /
`criterion` as appropriate per the existing workspace convention;
warm runs forbidden per `feedback_no-warm-benches`.

Sub-gate: 3-field citm beats sonic-rs `pointer!` by ≥ 20%;
30-field citm reaches parity or better; CSS L4 and sheets show
measured ns/access vs. lightningcss / cssparser baselines.

### BA.W1.4 — Parity harness

`tests/path_parity.rs` asserts that bbnf's path output matches
sonic-rs / simdjson / cssparser / lightningcss output for every
compilable path across the four production grammars.

Sub-gate: parity harness green at the wave close commit.
