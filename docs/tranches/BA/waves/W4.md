Read `docs/tranches/BA/waves/W4a.md`, `W4b.md`, `W4c.md` for the executable specs. The sections below are retained for cross-reference but NOT executable as-is.



**Thesis** (one `parse_with(input, &path)` per grammar; `__EAGER_EMPTY_PATH` LazyLock elides cursor consultation when the path is empty; the eager `JsonParser::parse` becomes `parse_with(input, &EMPTY_PATH)`; cursor's `Skip` decision generates byte-skip code at codegen, not at runtime). **Closer-gate** (BA-G9 met: `JsonDocument::get<T>(twitter.json, &path)` ≤ 5× full parse on M1 Pro; `parse` and `parse_with` share one source; samply trace shows zero cursor calls on the eager path).

## §1 — Deliverable

Hereupon the bifurcation between eager parse and cursor-driven parse — extant since the introduction of `parse_with` per `audit/RESTART-SKETCH-2026-05-03.md:35-41` — collapses into a single source. Today's surface (per `audit/RESTART-SKETCH-2026-05-03.md:28-34`) carries: eager `JsonParser::parse(input)` at `crates/core/src/grammar/generated/json.rs:3434`; lazy `runtime::json::parse_with(input, &TypedPath)` at `crates/core/src/runtime/json/parse_with.rs:77`; document accessor `JsonDocument::get<T>(path)` at `runtime/json/document.rs:156`. Per the restart sketch, "The eager path is the lazy path with `__EAGER_EMPTY_PATH`. That is the substrate `feedback_no_orthogonal_codepaths` invariant — but it is only honoured inside the dispatcher; the value-API hot path (`JsonDocument::get<T>` post-eager-parse) is a *second* operation that walks the materialized AST." W4 collapses the second-operation pathology: `JsonDocument::get<T>` reroutes through `parse_with(input, path)`; the post-parse linear AST walk vanishes.

The unification mechanism is `__EAGER_EMPTY_PATH`. Per `audit/RESTART-SKETCH-2026-05-03.md:51-53`, today's eager path already declares `static __EAGER_EMPTY_PATH: LazyLock<TypedPath<Json,&str>>` and constructs a `PathCursor::new(&EMPTY_PATH, |_,_,_| ParseFully)`; the cursor consultation calls (per RESTART-SKETCH:216, "12 | `generated/json.rs:1855-1942` (cursor consultations on eager path) | `cursor.decide`, `cursor.current_kind`, `cursor.match_field` calls return constant `ParseFully` for the empty-path eager case") return constant `ParseFully` for empty-path. W4 hoists this constant-fold to codegen: when the path is statically empty, the cursor consultation generates as a no-op; when the path is non-empty, the cursor's `Skip` decision generates byte-skip code at codegen time (NOT runtime branch).

The closes-the-4196×-gap mechanism for `JsonDocument::get<T>` rewrites at this wave. Per `audit/RESTART-SKETCH-2026-05-03.md:210` (item 6: "Linear pair scan + recursive walk on every path step, post-parse"), today's `JsonDocument::get<T>(path)` traverses the materialised AST tree; sonic-rs's `get_unchecked` is ~0.1× of full parse (per `audit/SOTA-2026-05-03.md:36-37`). The mitigation at the same row: "`Document::get<T>(path)` reroutes through `parse_with(input, path)` (BA's W4 thesis)". W4 makes this concrete: `JsonDocument::get<T>` becomes a thin wrapper over `parse_with(input, path)`; the post-parse linear walk vanishes; the gap closes from 4196× to ≤ 5× per BA-G9.

The Era V failure mode is mitigated because W4's substrate (the unified `parse_with`) has the same-wave consumer of both eager `parse` and `JsonDocument::get<T>`; there is no substrate-without-consumer. The cursor's `Skip` decision generates byte-skip code at codegen, not runtime — meaning the codegen stage at xtask-regen is the consumer of the unification mechanism; the BA.W5 direct-to-struct codegen consumes the `parse_with`-as-source-of-truth pattern.

The four `runtime/<g>/parse_with.rs` files are deleted at BA.W3.M5; W4 reintroduces a single `parse_with(input, &path)` per grammar at `crates/core/src/grammar/generated/<g>.rs` — the generated parser file owns the unified surface. Per `audit/MODULES-2026-05-03.md:1259`, the post-restart pipeline produces "a `pub fn parse(input: &str) -> Result<<Grammar>Document<'_>, ParseErr>` entry"; W4's emitter rewrites this to `pub fn parse_with(input: &str, path: &TypedPath) -> Result<...>` with `pub fn parse(input: &str) -> Result<...> { parse_with(input, &EMPTY_PATH) }` as a one-line surface.

The cursor's `Skip` decision generates byte-skip code at codegen, not at runtime — this distinction is mechanically important. Today's `crates/core/src/path/cursor.rs:431` (per `audit/MODULES-2026-05-03.md:679`) declares the `PathCursor` state machine + `Decision` + `SegmentKind`. The runtime cursor's `decide` method returns `Decision::Skip { bytes: usize }` on certain segment kinds; today the generated parser reads this and advances `*p` by the byte count. W4 hoists the consultation: the emitter inspects the rule's structural alphabet at codegen time and emits direct `*p += <const-byte-count>` when the skip distance is statically known (e.g., for fixed-width keys or count-prefixed segments). For variable-width skip cases, the cursor consultation remains; for empty-path eager case, the consultation evaporates entirely. Per `audit/RESTART-SKETCH-2026-05-03.md:622` (Q2 row 3, "Cursor-parse with byte-skip optimisation **inside** the cursor"), the hybrid is the chosen architecture: one source of truth, codegen-specialised.

Per `docs/HARDENING-PLAN-PROMPT.md:38` ("One parse implementation. Cursor consultation generates byte-skip when consult returns `Skip`. The empty-path case (`__EAGER_EMPTY_PATH`) elides cursor calls entirely so the eager fast path pays no consultation cost"), Lock 3 is honoured by W4's mechanism. The non-empty path case retains cursor consultation; the empty-path case constant-folds out; the runtime cost on the eager path is zero per the BA-G1 closer-gate.

The `__EAGER_EMPTY_PATH` LazyLock pattern is the canonical mechanism. Per `audit/RESTART-SKETCH-2026-05-03.md:51-52`, today's generated parser at `crates/core/src/grammar/generated/json.rs:3443` declares `static __EAGER_EMPTY_PATH: LazyLock<TypedPath<Json,&str>>` — an extant pattern; W4 does not introduce it; W4 unifies the dispatch around it. The LazyLock initialises once globally; subsequent parse-fn invocations consult it without recomputation. The PathCursor constructed against `&__EAGER_EMPTY_PATH` carries the closure `|_,_,_| ParseFully` per `audit/RESTART-SKETCH-2026-05-03.md:52`. Today's pattern is correct; today's pathology is that the cursor is consulted at runtime even though the closure is statically `ParseFully`. W4's M0 hoists the constant-fold to codegen; the cursor's `decide` arm becomes dead code on the empty-path eager pathway.

The mechanism preserves the lazy `parse_with` surface for non-empty paths. Per `docs/HARDENING-PLAN-PROMPT.md:38` ("One parse implementation. Cursor consultation generates byte-skip when consult returns `Skip`. The empty-path case (`__EAGER_EMPTY_PATH`) elides cursor calls entirely so the eager fast path pays no consultation cost"), the bifurcation is by codegen-time path-shape detection, not by runtime branch. The lazy `JsonDocument::get<T>(input, path)` call constructs a `PathCursor::new(&path, decision_fn)` with the user-supplied path; the cursor consultation flows normally; the byte-skip optimisation applies at the cursor's `Skip` decision points (M4).

## §2 — Milestones

> **M0 — Codegen-time `__EAGER_EMPTY_PATH` constant-fold**
>
> *Surface*: `crates/core/src/backend/rust/emitter/grammar.rs` (per `audit/MODULES-2026-05-03.md:827`, 468 LOC; declares the per-grammar entry function); the existing `static __EAGER_EMPTY_PATH: LazyLock<TypedPath<Json,&str>>` declaration at `crates/core/src/grammar/generated/json.rs:3443`.
> *Action*: Rewrite the emitter at `backend/rust/emitter/grammar.rs` to detect the empty-path case at codegen time. When the path is statically empty (the eager `parse` entry), the emitted body skips cursor consultation entirely — the cursor's `decide` / `current_kind` / `match_field` calls do not appear in the emitted source. The non-empty path case retains cursor consultation; the cursor's `Skip` decision generates byte-skip via `*p += skip_count` rather than calling into the cursor at runtime.
> *Gate*: `samply` profile of `JsonParser::parse(twitter.json)` shows zero `PathCursor::decide` / `current_kind` / `match_field` calls; per RESTART-SKETCH:216 (item 12), the constant-fold removes these calls.
> *Exit-criteria*: Per BA-G2 (per BA.md §Hard gates), zero `Vec<OpenFrame>::clone` sites detectable in samply 5K-sample profile (this gate is BA.W5-owned; W4's contribution is the cursor-consultation elision, verifiable via `samply record cargo bench --bench bench_json -- twitter` and inspection of the `crates/core/src/grammar/generated/json.rs` emitted source for absence of `cursor.decide(` calls in the `parse_value` entry).

## §4 — Invariants

§I1. **Lock 3** (cursor + byte-skip unified, cursor branch elided when path empty). One parse implementation per grammar — `parse_with(input, &path)`. The empty-path case (`__EAGER_EMPTY_PATH`) elides cursor calls entirely so the eager fast path pays no consultation cost. Cursor's `Skip` decision generates byte-skip at codegen time, not runtime branch.

§I2. **No orthogonal codepaths** (per `feedback_no_orthogonal_codepaths`). The eager `parse` and lazy `parse_with` share one source; the codegen distinguishes the empty-path case by constant-folding the cursor away, not by emitting two parsers. Per `audit/RESTART-SKETCH-2026-05-03.md:218` ("`feedback_no_orthogonal_codepaths` is alive: items #3, #5, #7 are discriminator branches that should be specialised at codegen time, not re-discriminated at runtime"), W4 closes items #6 and #12 from the wasted-cycles punch list.

§I3. **One codegen path** (per `feedback_one_codegen_path`). ONE monolithic codegen path; no combinator fallback; ONE regex system (HIR); KISS. The `parse_with` emit is the single path; no fallback `parse`-without-`parse_with` survives.

§I4. **Single plan execution** (per `feedback_single_plan_execution`). The cursor unification + byte-skip codegen + `Document::get<T>` reroute land in one wave; not split into separate plans.

§I5. **Beat sonic-rs target** (per `feedback_beat_lightning` extended to JSON). BA-G9 closes the 4196× → ≤ 5× gap; sonic-rs's `get_unchecked` at 0.1× full parse is the asymptote BB pursues; W4 reaches ≤ 5×.

§I6. **No deferrals** (per `feedback_no_deferrals`). The unified `parse_with` lands in W4; the full direct-to-struct codegen at BA.W5 consumes W4's unification but does not depend on its deferral. The cursor + byte-skip mechanism is in-wave; not deferred to BB.

§I7. **No workarounds** (per `feedback_no_workarounds`). The post-parse linear walk in `Document::get<T>` (today's pathology) deletes; not preserved as a fallback.

§I8. **Lock 9** (slice-borrow primary). The post-W4 `parse_with(input: &'p str, &path) -> Result<<G>Document<'p>>` returns slice-borrowed; per `audit/SOTA-2026-05-03.md:122-123`, the default surface is `&'i str` slice. The `parse_in(input, &bump)` and `parse_owned(input)` escape hatches route to BB.W4.

§I9. **Lock 8** (surpass sonic-rs / simdjson / lightning-css). BA-G9's 4196× → ≤ 5× gap closure is the JSON `get<T>` SOTA-anchored gate; sonic-rs's `get_unchecked` at 0.1× is the asymptote BB.W5 pursues. W4 closes the BA-tier of the gate; BB.W5's `pointer!` macro extends.
