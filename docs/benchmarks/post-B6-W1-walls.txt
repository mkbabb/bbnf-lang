== Plan reconciliation — egraph lazy-pass infeasibility

The W1.a hypothesis cannot reduce the targeted wall:

1. The egraph rule set (`crates/ir/src/egraph/rules/mod.rs::default_rules`)
   constructs 9 boxed `RewriteFn`s — `DeduplicateAltBranches`,
   `SupersetAbsorbAlt`, `UnionMergeAlt`, `FuseAltRegexBranches`,
   `CommonSuffixFactor`, `AltOfSingle`, `RepeatOfSingle`,
   `WrapOfEpsilonScalar`, `ConcatLiterals`. Every rule is consumed
   by `bbnf_ir::egraph::build_and_saturate` at
   `crates/core/src/pipeline/compile.rs:593` — the runtime parse-
   compile path. There is no rule whose `--check` consumer-count
   is zero, because the runtime path consumes them all.

2. `cargo iter-check-full` is a `cargo check` invocation under the
   `ax-iter` profile. `cargo check` performs typechecking only —
   it does NOT execute `build_and_saturate`. The egraph saturation
   is runtime work; the iter-check wall is rustc compile time.
   Lazy-deferring rule firing at runtime cannot reduce a typecheck
   cold wall, because the rules never fire during typecheck.

3. To genuinely shrink iter-check's link surface one would need
   `#[cfg]`-gate rules out of the binary — not "lazy-run" them.
   The plan's lazy-run mechanism leaves every rule's monomorphized
   `Box<dyn RewriteFn>` instantiation in the rmeta and the linker
   sees identical symbol surface either way.

The plan's premise ("the full-workspace ax-iter check links the
four heavy crates plus the egraph and CSP scheduler with every
saturation rule eager") conflates runtime saturation work with
compile-time link cost. The two are independent.

== Plan reconciliation — `iter-check-az` alias

W1.b prescribes adding `iter-check-az = "check --profile ax-iter
--workspace --exclude bbnf-bootstrap --exclude gorgeous --exclude
bbnf-analysis --exclude bbnf-lsp"` to `.cargo/config.toml`. That
exclude set is byte-identical to the existing `iter-check` alias
(line 110 of `.cargo/config.toml`). Adding `iter-check-az` as a
duplicate of `iter-check` violates B6 invariant 6 (no source-code
path duplications) and SPEC §Edicts no-shim rule.

The plan allows for "additional excludes per AY-III's plan
declarations", but no such declarations exist in the AY-III
docs presently. Without those, the alias is a literal duplicate.

The plan's ≤ 30 s gate for `iter-check-az` is already satisfied
by the existing `iter-check` alias: warm 0.13 s; cold (estimated
from the iter-check-full 17.02 s wall minus the four heavy
crates' typecheck contribution) is ≤ 17 s, which is ≤ 30 s.

== Verdict — Phase 0 VACUOUS-CLOSE

Per the dispatch's explicit decision criterion ("If iter-check-
full cold is < 200s OR if iter-check-full warm is already < 5s,
the W1 gate is either vacuous or unreachable in 30%-relative
terms"), both conditions trigger:

  Cold:  17.02 s  <  200 s   (vacuous; gate is 27× below threshold)
  Warm:   0.14 s  <    5 s   (vacuous; gate is 35× below threshold)

Per SPEC §Plan-time miscalibration (lines 224–240): when a numeric
gate's measured baseline is dramatically different from the plan's
asserted baseline, the gate is reclassified as plan-time
miscalibration and the wave closes on rationale-satisfied. The
W1 plan was authored against a stale or different-substrate
baseline; the post-B5/post-W0 cold wall is 17.02 s, not 660 s.

The architectural conclusion compounds the verdict:

  - The lazy-pass mechanism the W1.a plan prescribes cannot reduce
    the wall it targets, regardless of the baseline value.
  - The `iter-check-az` alias the W1.b plan prescribes is a
    duplicate of `iter-check` and violates invariant 6.
  - The gorgeous audit is no-op verified.

Recommended W1 disposition: close on rationale-satisfied per
SPEC §Plan-time miscalibration. The infrastructure is healthy;
the bottleneck is genuinely elsewhere. The 192× speedup W0
landed (the unconditional-write fingerprint cycle) was the real
substrate-wide breakthrough; W1 finds nothing because there is
nothing left for its prescribed levers to find.

The W0 precedent (W0 plan's 5-min asserted baseline measured
1m 28s on the substrate, then collapsed to 0.46 s after the
self-invalidation cycle was broken) suggests B6 was authored
against a substrate snapshot that was already partially obsolete
at plan time. W1 inherits the same staleness.

== Cold-wall reproduction recipe

For any reviewer wishing to reproduce the 17.02 s cold figure:

  cd /Users/mkbabb/Programming/bbnf-wt-b6-w1
