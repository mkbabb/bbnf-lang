## Selected Family

Selected candidate family for this protocol:
`a64_ascii_set_run_skip`, implemented as a generated CSS layout/trivia
run-skip caller backed by transient byte-class masks. The implementation may
use existing `BYTE_CLASS_FROM_EQ_SET_64` or `BYTE_CLASS_FROM_TABLE_64` support
and may add a real aarch64 TBL/TBX table body only if that body is consumed in
the same W4 redress. A raw `a64_tbl_tbx_byte_class_mask64` lift is support
only and cannot admit or close W4 by itself.

Reason: SPEC Section 9 allows one W4 candidate from the S-P2 selectable rows.
The CSS L4 generated runtime now has an exact same-wave consumer:
`runtime::generated_css_l4_declaration_values::generated::skip_ws_and_comments`.
The current hot loop skips CSS whitespace before every declaration-value token,
and W1b-2b already measured the strict CSS row:
Track 1 `429.34420791225705 Mbps`, lightningcss
`168.92962215656692 Mbps`, threshold `169.92962215656692 Mbps`.

If W4 plan selects `a64_udot_digit_run_span`,
`a64_wide_string_special_scan64`, or `a64_hex_quartet_decode_x4` instead, this
A5 artifact is not sufficient; it must be revised with that family's scalar
reference, differential corpus, and caller microbench.

## Exact Scalar Reference

The scalar reference is a new production, non-SIMD run-skip oracle for a
caller-supplied byte set:

```rust
fn byte_set_run_skip_scalar(
    bytes: &[u8],
    mut cursor: usize,
    end: usize,
    set: &[u8],
) -> usize {
    debug_assert!(cursor <= end && end <= bytes.len());
    debug_assert!(set.len() <= 8);
    while cursor < end && set.contains(&bytes[cursor]) {
        cursor += 1;
    }
    cursor
}
```

For the CSS L4 consumer, the grammar-supplied layout set is exactly:

```text
[0x09, 0x0a, 0x0c, 0x0d, 0x20]  # tab, LF, form feed, CR, space
```

Comments are not part of the SIMD primitive. `skip_ws_and_comments` remains
the generated caller policy:

1. skip one or more layout bytes with `byte_set_run_skip_scalar` or the W4
   aarch64 candidate;
2. if the next bytes are `/*`, scan to the matching `*/` by scalar generated
   caller logic;
3. repeat.

Fail closed if the candidate moves CSS comment recognition, nested-comment
policy, `url(...)`, string, or identifier escape semantics into `bbnf-simd`.
The SIMD primitive returns only a cursor or transient mask, not token classes,
facts, retained offsets, or a sidecar bitmap.

The byte-class backing references are already present:

- `bbnf_simd::scalar::byte_class_from_eq_set_64::byte_class_from_eq_set_64_scalar`
  for set length `<= 8`;
- `bbnf_simd::scalar::byte_class_from_table_64::byte_class_from_table_64_scalar`
  for full 256-entry tables.

The W4 scalar run-skip reference may call those scalar mask references
internally, but its externally checked behavior is the first nonmember cursor.

## Checkasm Differential

W4 redress must add a dedicated differential test, named either
`checkasm_ascii_set_run_skip_64.rs` or a clearly scoped equivalent. It must use
`tests/checkasm_common.rs` for deterministic xorshift input and stack canaries.
If a direct aarch64 TBL/TBX table body is added, refresh
`checkasm_byte_class_from_table_64.rs` as well.

Required differential cases:

- cursor/tail sweep: `cursor` at every offset `0..=127`, live lengths
  `0..=128`, and end values that exercise short, exact-64, 65-byte, and
  multi-block spans;
- first-nonmember sweep: first miss at every lane `0..63`, all-member blocks,
  empty runs, and immediate miss at cursor;
- CSS layout set: `\t`, `\n`, `\x0c`, `\r`, and space;
- non-CSS ASCII controls: especially `0x0b`, which must be rejected unless the
  generated CSS oracle explicitly admits it;
- high-bit bytes: `0x80..=0xff` must be nonmembers for the selected CSS layout
  primitive;
- alignment: 128-byte backing buffer with every `0..63` alignment;
- adversarial seeds: at least `0xCAFEF00DBAADF00D`,
  `0x5441424c455f3634`, and `0xDEADBEEF12345678`;
- source immutability: cloned input before/after candidate call;
- feature fallback: on non-aarch64 or missing optional feature, dispatch must
  call the scalar reference and still pass the same test.

The checkasm assertion compares:

```text
reference_cursor == candidate_cursor
reference_touched_no_bytes == candidate_touched_no_bytes
```

If W4 adds a mask-returning helper below the run-skip API, its mask check must
also compare candidate masks against `byte_class_from_eq_set_64_scalar` or
`byte_class_from_table_64_scalar` before converting to a cursor.

Required commands:

```bash

BBNF_SIMD_STRICT=1 RUSTFLAGS="-C target-cpu=native" \

BBNF_SIMD_STRICT=1 RUSTFLAGS="-C target-cpu=native" \
  cargo test -p bbnf-simd --release --test checkasm_byte_class_from_eq_set_64 -- --nocapture

BBNF_SIMD_STRICT=1 RUSTFLAGS="-C target-cpu=native" \
```

## CSS / Corpus Parity

Corpus parity is caller parity, not standalone primitive parity. W4 must prove
that the generated CSS fact stream remains byte-identical across:

- Track 1 generated CSS runtime;
- independent cssparser oracle;
- same-plane lightningcss sidecar projection.

Required CSS windows for the run-skip differential:

- every whitespace run in
  `restart/skinny/tranches/sk-v12/research/w1b/css_l4_declaration_values.css`;
- every comment boundary generated or appended for W4 parity tests:
  `/*x*/`, `/**/`, `/* unterminated` fail case, and comment starts at every
  offset modulo 64;
- declaration-value token boundaries before identifiers, numbers,
  percentages, dimensions, `#` colors, function calls, commas, parens,
  brackets, and `!important`;
- synthetic CRLF, form-feed, and vertical-tab cases. Vertical tab must not
  silently pass as CSS whitespace unless the oracle fact stream agrees.

Required commands:

```bash
cargo test -p runtime css_l4_declaration_values_emit_fact_stream -- --nocapture

cargo test -p bbnf-bench nonjson_css_l4 -- --nocapture

  restart/skinny/tranches/sk-v12/research/w1b/artifacts/track1-facts.txt \

cmp -s \
```

## Same-Host Microbench

Micro-prove-first applies before production routing. The microbench must time
the generated CSS caller shape, not just `bbnf-simd` mask throughput.

Required microbench shape:

- benchmark group:
  `skv12_w4_ascii_set_run_skip/{scalar_reference,a64_candidate}`;
- input slices:
  the frozen CSS L4 fixture plus synthetic layout/comment windows above;
- implementation:
  call the full generated `skip_ws_and_comments` caller twice, once forced to
  scalar reference and once forced to the aarch64 candidate;
- output:
  final cursor plus a rolling checksum of visited token starts so dead-code
  elimination cannot erase the work;
- sample count:
  at least 30, with `RUSTFLAGS="-C target-cpu=native"`;
- threshold:
  candidate caller throughput must be at least
  `ceil(reference_mbps * 1.01)` or, in time form,
  `candidate_mean_ns <= reference_mean_ns / 1.01`.

Required command after the bench is added:

```bash
RUSTFLAGS="-C target-cpu=native" \
  cargo bench -p bbnf-bench --bench nonjson_css_l4 -- \
  --sample-size 30 skv12_w4_ascii_set_run_skip
```

Primitive-only speed is not admissible. If the raw byte-class primitive wins
but the generated caller misses the 1% threshold, W4 records a measured reject
or behavior nonclose and must not wire the candidate into production.

## Fail-Closed Conditions

W4 must stop or record MEASURED-REJECT/BLOCKED when any of these occur:

- W2 prerequisite commands fail, including the
  `0xCAFEF00DBAADF00D` escape-mask checkasm.
- The scalar run-skip reference is absent, test-only, or differs from the
  production API used by the candidate.
- Strict checkasm fails for eq-set, table, or the W4 run-skip differential.
- Candidate mutates input, crashes under signal guard, clobbers stack canary,
  or lacks scalar fallback.
- Microbench proves only a raw primitive and not the generated CSS caller.
- Candidate caller misses the 1% microbench threshold.
- CSS fact stream differs from cssparser or lightningcss.
- CSS Track 1 no longer satisfies `track1_mbps > lightningcss_mbps + 1` for
  an ADMIT claim.
- JSON guard command fails or a JSON guard demotion is not recorded in
  REDRESS.
- Generic crates learn CSS/JSON policy branches, new directives, new BIR
  variants, new `BackendShape` variants, or public substrate APIs.
- Any retained mask/position/class sidecar is introduced.
- Any x86 implementation path is added for SK-V12.
- Any carried aarch64 orphan remains production-live without consumption,
  removal, or explicit inventory demotion evidence.
- Criterion/report artifacts are stale or CSS and JSON Criterion roots are
  mixed.
