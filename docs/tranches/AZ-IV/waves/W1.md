# AZ-IV.W1 - Runtime Surface And Semantic Parity

**Name**: W1 - Runtime Surface And Semantic Parity
**Opens after**: W0 - Truth And Canonical Regen
**Agents**: 5 parallel
**Hard gate**: generated parsers, typed path/query surfaces, and runtime projections match grammar-derived type-inference behavior
**Status**: planned

## Scope

1. Harden BA's typed path/query semantics in the existing runtime surface: `Path`, `PathSegment`, `path!`, and every active `*PathQuery`.
2. Close Sheets parity on the current full suite.
3. Close CSS lightningcss parity, including named-color payload materialization and Tailwind non-timeout behavior.
4. Keep JSON and BBNF parity green against regenerated outputs.
5. Make TS backend executable: syntax/typecheck, Node execution, EOF enforcement, discriminated unions, repeat loops.
6. Prove shape generality beyond JSON with real-grammar or synthetic-IR execution tests.
7. Retire old color compatibility exports or move them behind explicit test-support/compat boundaries.
8. Make semantic parity type-inference driven: generated projection tables, `TypeDesc`, `StructRegistry`, obligations, and grammar facts own payload/field/discriminant decisions.
9. Preserve BA host-binding semantics by landing executable TS status and a Python/host-binding decision ledger with exact signatures/errors or explicit no-surface evidence.

## Triumvirate Dispatch

Dispatch a triumvirate if any of these occurs:

- runtime path hardening requires a second parser, untyped fallback resolver, parent-pointer sidecar, or public parallel API;
- CSS or Sheets parity requires a normalizer escape hatch, rule-name projection table, or synthetic payload default instead of grammar-derived structure;
- TS parity needs a separate parser implementation from the emitted backend;
- shape generality cannot be proven without literal parser-name branches;
- three diagnostic loops fail to isolate a parity class.

## Agent Units

### AZ-IV.W1.1 Runtime Path And Projection Surface

- Mechanism: harden `runtime::path`, `path!`, per-document `*PathQuery`, direct struct projection, and runtime view/color boundaries in place.
- Files: `crates/core/src/runtime/path.rs`, `crates/core/src/runtime/*/document.rs`, `crates/core/src/runtime/view.rs`, `crates/core/src/runtime/css_l4/**`, `crates/core/src/backend/rust/view/**`, `crates/core/benches/json/value.rs`.
- Sub-gate: path traversal is zero-allocation, type-inference checked, and same-harness 3-field JSON access beats sonic-rs `pointer!` by at least 20%; 30-field access is parity-or-better.

### AZ-IV.W1.2 Sheets Parity

- Mechanism: fix grammar/type-inference-derived Sheets structure for strings, arrays, range refs, prefixes, errors, discriminants, lexeme tables, and serialization.
- Files: `grammar/google-sheets/**`, `crates/core/tests/*sheets*.rs`, generated Sheets output.
- Sub-gate: full Sheets parity suite green from regenerated output, with no synthetic tag/payload fallbacks and no hand-coded serializer lexeme maps that duplicate grammar facts.

### AZ-IV.W1.3 CSS Parity

- Mechanism: make lightningcss parity field-level where claimed and eliminate early-return payload gaps, rule-name projection tables, and defensive default payload synthesis.
- Files: `grammar/css/**`, `crates/core/src/runtime/css_l4/**`, CSS parity tests.
- Sub-gate: CSS normalize/bootstrap/named-color payload tests green from generated typed structures; normalizers are bounded diagnostics, not the parity proof; Tailwind parses without timeout-class failure.

### AZ-IV.W1.4 TS Backend

- Mechanism: repair discriminated union, repeat loop, EOF, host function wiring, and executable output gates.
- Files: `crates/core/src/backend/ts/**`, `crates/core/tests/backend_ts.rs`, `crates/core/tests/pipeline_compile_request.rs`.
- Sub-gate: `backend_ts`, `pipeline_compile_request ts_backend`, tempdir TS syntax/typecheck, Node execution, EOF rejection, and host-binding behavior pass; Python/other host path binding status is captured in a signature/error ledger.

### AZ-IV.W1.5 Shape Generality

- Mechanism: prove shape detector/emitter equivalence on non-JSON grammar facts.
- Files: `crates/core/src/backend/rust/emitter/shapes/**`, shape tests, synthetic fixtures.
- Sub-gate: every active `ShapeTag`, including transparent cases, executes on two real grammars or one real grammar plus non-JSON synthetic IR, or is removed from the active denominator.

## Hard Gate

1. Regenerated tempdir outputs are used for parity.
2. `Path`, `PathSegment`, `path!`, and every active `*PathQuery` close BA's Rust path requirements without a new path crate.
3. JSON direct struct projection benchmarks include `bbnf_get_twitter` and `bbnf_value_*` rows against sonic-rs peers.
4. JSON sonic-rs and BBNF self-host suites remain green; BBNF parity covers generated document structure, not only rule/directive fingerprints.
5. Sheets full suite is green and projection/serialization derive from grammar/type facts.
6. CSS field/payload parity is green without early-return escapes, rule-name projection tables, or normalizer-only proof.
7. TS is syntax/type/execution checked, enforces EOF, and proves host function wiring.
8. Shape generality tests execute generated parser behavior, not only `syn::parse2`.
9. Duplicate CSS host shims and old color compatibility are deleted or fenced as test support with no production dependency.
