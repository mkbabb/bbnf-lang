# B2.W1 — Consumer Cutover

**Opens after**: W0 close (xtask substrate proven on BBNF self-host)
**Agents**: 4 parallel (W1.a, W1.b, W1.c, W1.d) + 1 closer (W1.e)
**Hard gate**: every `#[derive(Parser)]` site in the workspace migrates to `include!` + marker struct; `rg -nF '#[derive(Parser' --type rust` returns 0 results; `cargo iter-check-full` cold ≤ 5 min; `cargo iter-check` warm ≤ 0.5 s
**Status**: planned

## Scope

W0 proved the `include!` pattern on `bbnf-bootstrap`. W1 mechanically
extends it to every other `#[derive(Parser)]` consumer in the
workspace.

Inventory pre-dispatch (`rg -nF '#[derive(Parser' --type rust`):

- `crates/gorgeous/src/{bbnf,css,ebnf,bnf,json,jit}.rs` — 5 sites
  (gorgeous's grammar variants).
- `crates/core/tests/*.rs` — ~50 sites (per-grammar test fixtures
  that consume the BBNF + JSON + CSS L4 + Sheets parsers).
- `crates/json-prototype/src/lib.rs` (if present) — 0-1 sites.
- `crates/core/benches/*.rs` — 0 sites (bench files use
  `JsonParser::parse` directly; no derive expansion in bench code).

**Total**: ~55-60 sites.

For each site:

1. Replace `#[derive(Parser)] #[parser(path = "...")]` with
   `pub struct <GrammarIdent>;` (the marker struct).
2. Add `include!(concat!(env!("CARGO_MANIFEST_DIR"),
   "/../core/src/grammar/generated/<ident>.rs"));` at the same module
   scope (or whatever the canonical path translation is for the
   consumer's location).
3. Remove the `bbnf_derive` import if it was the only use.
4. Verify the file compiles: `cargo check --profile ax-iter -p
   <crate>` exits 0.

Each consumer crate also needs the corresponding
`crates/core/src/grammar/generated/<ident>.rs` to exist. W1's xtask
runs cover the per-grammar emission for every grammar enumerated in
W0's manifest; consumers just `include!` the result.

## File bounds (4 parallel agents + 1 closer)

W1.a–W1.d each own a disjoint slice of the consumer set; they edit
their slice's `*.rs` files + corresponding `Cargo.toml` (drop
`bbnf_derive` dep iff present). The closer W1.e regenerates xtask
output for every grammar manifest entry, runs the workspace test
matrix, and lands the substrate-update commit if any per-grammar
generated file needs refreshing.

| Agent | Owns |
|---|---|
| **W1.a — gorgeous** | `crates/gorgeous/src/{bbnf,css,ebnf,bnf,json,jit}.rs` (5 derive sites) + `crates/gorgeous/Cargo.toml` |
| **W1.b — core tests JSON family** | `crates/core/tests/{json_*,sonic_rs_parity,phf_keyword_mining,value_api_apples_to_apples}.rs` (≈ 12 sites) |
| **W1.c — core tests CSS + Sheets families** | `crates/core/tests/{css_l4_*,lightningcss_parity,sheets_*,typed_accessor_surface,shape_dispatch_emission}.rs` (≈ 18 sites) |
| **W1.d — core tests BBNF + cross-grammar** | `crates/core/tests/{bbnf_*,grammar_roundtrip,projection_totality,gate_predicate_wire_contract,named_type_preservation,payload_layouts,wrap_compound_elision}.rs` (≈ 20 sites) |

**Do NOT touch**:
- `crates/derive/` (W2 owns deletion).
- `crates/bootstrap/` (W0 owns; bbnf-bootstrap already migrated).

## Phase sub-items

### B2.W1.a — gorgeous derives

**Hard cap**: 60 min.
**Owner**: gorgeous's 5 grammar-variant files.

Mechanism per file (template):

Before:
```rust
#[derive(Parser)]
#[parser(path = "../../grammar/css/pretty.bbnf")]
pub struct CssPrettify;
```

After:
```rust
pub struct CssPrettify;
include!(concat!(
    env!("CARGO_MANIFEST_DIR"),
    "/../core/src/grammar/generated/css_prettify.rs"
));
```

Note: gorgeous's grammars are PRETTIFY variants (e.g.,
`grammar/css/pretty.bbnf` not `grammar/css/l4/stylesheet.bbnf`).
The W0 grammar manifest must enumerate each gorgeous-side variant
under a distinct ident (e.g., `css_prettify`, `bbnf_prettify`,
`ebnf_prettify`, `json_prettify`, `bnf_prettify`, `jit_prettify`).
W1.e regenerates each.

Sub-gate:
- 5 derive sites in gorgeous retire (`rg -nF '#[derive(Parser'
  crates/gorgeous/src` returns 0).
- `cargo check -p gorgeous --profile ax-iter` exits 0 in ≤ 60 s
  (gorgeous's 5 sites no longer trigger 5-derive serial expansion;
  cold cost drops to a normal lib build).
- `crates/gorgeous/Cargo.toml`: `bbnf_derive` dep removed.

### B2.W1.b — JSON family tests

**Hard cap**: 75 min.
**Owner**: ≈ 12 test files referencing JSON-grammar derive sites.

Mechanism: same template as W1.a, with `include!` paths pointing at
`generated/json.rs` (the canonical JSON parser per W0's manifest).
Some test files use a custom JSON variant (e.g.,
`crates/core/tests/sonic_rs_parity.rs`'s `RefParser`); for those, the
derive may already be a non-`Parser`-trait derive (e.g., a hand-rolled
recursive-descent reference). Audit before mechanical replacement:
only `#[derive(Parser)]` (capital-P, parse-that's trait) migrates;
`#[derive(Debug)]` etc. stay.

Sub-gate:
- 0 `#[derive(Parser)]` matches under `crates/core/tests/json_*` and
  related JSON-family files post-W1.b.
- `cargo nextest run --profile ax-iter -p bbnf --test json_parity`
  (and other JSON-family test names) exit 0.

### B2.W1.c — CSS + Sheets family tests

**Hard cap**: 75 min.
**Owner**: ≈ 18 test files for CSS L4 + Google Sheets grammars.

Mechanism: identical to W1.b. CSS L4 uses
`generated/css_l4.rs`; Sheets uses `generated/google_sheets.rs`.

Sub-gate analogous to W1.b for CSS + Sheets test names.

### B2.W1.d — BBNF + cross-grammar tests

**Hard cap**: 75 min.
**Owner**: ≈ 20 test files for BBNF self-host + cross-grammar
verification.

Mechanism: BBNF tests use `generated/bbnf.rs` (which W0 already
emitted). Cross-grammar tests (e.g., `grammar_roundtrip.rs`,
`projection_totality.rs`) consume multiple grammar marker structs;
each `#[derive(Parser)]` site retires independently.

Sub-gate:
- 0 `#[derive(Parser)]` matches across crates/core/tests/.
- `cargo nextest run -p bbnf --tests --profile ax-iter` exits 0.

### B2.W1.e — closer (xtask regen + test matrix verification)

**Opens**: W1.a–W1.d sub-gates green.
**Hard cap**: 60 min.
**Role**: ensure every grammar consumed by W1.a–W1.d has its
`generated/<ident>.rs` file present + valid; verify the workspace
matrix.

Mechanism:

1. Run `cargo xtask regen` (full sweep) — emits every grammar in the
   manifest. Idempotency check: second `cargo xtask regen` produces
   no diff (`git diff --exit-code crates/core/src/grammar/generated/`).
2. Update `crates/core/src/grammar/generated/mod.rs` to declare every
   per-grammar module: `pub mod bbnf; pub mod json; pub mod css_l4;
   ...`.
3. Run the full workspace test matrix:
   - `cargo nextest run --workspace --profile ax-iter` exits 0.
   - `cargo iter-check-full` cold timing recorded.
   - `cargo iter-check` warm timing recorded (must be ≤ 0.5 s per
     B2.md invariant 12).
4. Append timing rows to `docs/benchmarks/post-B2-W1-walls.txt`.

Sub-gate:
- `rg -nF '#[derive(Parser' --type rust` returns 0 across the
  workspace.
- Workspace test matrix exits 0.
- `cargo iter-check-full` cold ≤ 5 min (target).
- `cargo iter-check` warm ≤ 0.5 s.
- Per-grammar `generated/<ident>.rs` files all present + parseable.
- `crates/core/src/grammar/generated/mod.rs` declares every module.

## Delete-then-swap window

W1's cutover is a **delete-then-swap window** per SPEC §Wave
stipulation. During W1.a–W1.d's parallel cutover, master may
intermittently fail to compile cleanly (one consumer migrates while
its dep graph siblings still reference the old derive). W1.e is the
**named restoration wave**; cherry-picks must compose to a clean
`cargo iter-check-full` exit 0 before W1 closes.

If W1.e cannot restore master-green within its 60-min hard cap, B2
relinquishes per `docs/instructions/README.md` §Diagnostic-loop
relinquish + dispatches a triumvirate to investigate the consumer
that resists the `include!` pattern. The thesis (proc-macro retires)
holds; the question would be only how to migrate the resistant
consumer.

## Archaeology

W1's mechanical scope echoes B1.W1's bencher → divan migration in
shape: identify every consumer of a deprecated pattern, mechanically
swap to the new pattern, restore-then-validate. B1.W1 succeeded under
delete-then-swap with target-lock-aware sequential commits (per
B1.W1.b's experience with parallel target contention). B2.W1
inherits that lesson: 4 parallel agents on disjoint files, each runs
its own `cargo check -p <crate>` validation under the SHARED target
(serial cargo invocations via target-lock). The orchestrator
sequences cargo runs; agents do file edits in parallel.
