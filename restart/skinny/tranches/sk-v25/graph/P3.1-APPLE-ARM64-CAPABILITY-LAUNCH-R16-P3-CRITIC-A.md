### 3. P1 — the direct-listing structure matches Apple primary output, but its numeric grammar is not strict

**Verdict: CORRECT header, order, space, modifier, and slice-selection shape;
INCORRECT canonical version validation.**

Primary-source review disproves an initially plausible header objection:

- `otool-classic(1)` defines `-arch arch_type` as selecting the requested
  architecture of a universal file;
- cctools `ofile_process` passes no printed architecture annotation when
  exactly one architecture flag is requested; and
- the classic processor prints `<file>:` followed by `print_libraries` rows.

The production parser's exact `<root>:` header is therefore coherent with its
single explicit `-arch arm64` request. `print_libraries` emits one tab-prefixed
path followed by compatibility/current versions and, where applicable, one of
the accepted modifiers. The parser uses the final metadata marker, so spaces
inside the path are retained. It preserves row order, rejects blank or extra
rows, requires a final newline, and binds the complete raw command transcript.
Those are real corrections over P2.

Primary sources:

- <https://github.com/apple-oss-distributions/cctools/blob/cctools-1035.1.102/libstuff/ofile.c>
- <https://github.com/apple-oss-distributions/cctools/blob/cctools-1035.1.102/otool/main.c>
- <https://github.com/apple-oss-distributions/cctools/blob/cctools-1035.1.102/otool/ofile_print.c>
- <https://github.com/apple-oss-distributions/cctools/blob/cctools-1035.1.102/man/otool-classic.1>

The remaining parser defect is precise. cctools prints the packed version as
canonical unsigned decimal components: a 16-bit major component and two 8-bit
components. `valid_version` checks only “three nonempty digit strings.” It
therefore accepts output that classic cctools cannot emit, including leading
zero forms and components outside those bounds. That contradicts the stated
strict rejection of extra/unparsed output.

The raw transcript hash still preserves every supplied byte, so this is not a
receipt-byte omission. It is an over-permissive semantic acceptance bug. The
existing rejection test covers empty, truncated, wrong-header, extra-row, and
multi-section forms, but not canonical numeric bounds.
