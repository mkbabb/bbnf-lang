# B2.W2 — Proc-Macro Retirement

**Opens after**: W1 close (every `#[derive(Parser)]` site migrated)
**Agents**: 1 + 1 closer
**Hard gate**: `crates/derive/` deleted; `bbnf_derive` dep purged from every `Cargo.toml`; `BBNF_SCHEMA_VERSION` retired; workspace compiles + tests pass without the proc-macro
**Status**: planned

## Scope

W1 retired every `#[derive(Parser)]` site to the `include!` + marker
pattern. The `bbnf_derive` proc-macro crate is now unreferenced. W2
deletes the crate, purges its dependency entries from every consumer
`Cargo.toml`, retires `BBNF_SCHEMA_VERSION`, and removes `bbnf_derive`
from the workspace `[patch.crates-io]` table.

This is the load-bearing structural commit of B2 — it eliminates the
proc-macro IR-pipeline contract entirely.

## Phase sub-items

### B2.W2.a — proc-macro crate + dep purge

**Hard cap**: 90 min.

Mechanism:

1. **Verify W1 closure**: re-run `rg -nF '#[derive(Parser' --type
   rust` — must return 0 results. If non-zero, halt + relinquish to
   orchestrator (W1 left residual sites; W2 cannot proceed).
2. `git rm -r crates/derive/` — delete the entire crate.
3. Edit each `Cargo.toml` listed in §File bounds:
   - Drop the `bbnf_derive` line from `[dependencies]` and/or
     `[dev-dependencies]`.
4. Edit `.cargo/config.toml`:
   - Drop the `bbnf_derive = { path = "crates/derive" }` line from
     `[patch.crates-io]`.
5. Edit workspace `Cargo.toml`:
   - Remove `"crates/derive"` from `[workspace] members` (if listed
     explicitly).
   - Update `[workspace.metadata.bbnf]` table comments if they
     reference the proc-macro contract (e.g., move the comment to
     reference the xtask).
6. Regenerate `Cargo.lock`: `cargo update -p bbnf_derive --offline
   --remove` would be ideal but cargo doesn't support `--remove`;
   instead, `cargo check --workspace --profile ax-iter --offline`
   triggers cargo to rebuild Cargo.lock without the dep. If offline
   resolution fails (e.g., a transitive shifts), allow online
   resolution: `cargo check --workspace --profile ax-iter`.
7. **Verify**: `rg -nF 'bbnf_derive\|bbnf-derive' --type toml` returns
   0 results post-edits. `rg -nF 'BBNF_SCHEMA_VERSION' --type rust`
   returns 0 results (the constant lived in `crates/derive/src/
   lib.rs:81`; it dies with the crate).
8. `cargo iter-check-full` cold under W2 substrate — should be fast
   (no proc-macro to compile; no IR pipeline to run inside rustc).
   Target: ≤ 3 min cold.
9. `cargo nextest run --workspace --profile ax-iter` exits 0.

Bonus consideration — **bbnf-bootstrap as a crate**: post-B2.W0,
`crates/bootstrap/` is reduced to a marker-struct + `include!`
wrapper. Its purpose was to be the self-host bootstrap for the
proc-macro derive. With the proc-macro retired, `bbnf-bootstrap`
serves only as a re-export of the BBNF parser. Two options:

- **(Option A) Retire bbnf-bootstrap entirely** at W2.a: the BBNF
  parser surface lives at `bbnf::grammar::generated::bbnf::*`;
  consumers reference that path directly. The `crates/bootstrap/`
  directory deletes.
- **(Option B) Keep bbnf-bootstrap as a thin re-export crate**: it
  becomes ~30 lines (just `pub use bbnf::grammar::generated::bbnf::*;`
  + the BbnfBootstrap marker struct). Useful if downstream consumers
  reference `bbnf-bootstrap::*` paths.

Pick A iff `rg -nF 'bbnf_bootstrap\|bbnf-bootstrap' --type rust --type
toml` shows fewer than ~10 consumers post-W1; otherwise B. Land the
choice in this commit; document rationale.

### B2.W2.b — legacy monolith retirement

**Hard cap**: 30 min.
**Role**: clean up `crates/core/src/grammar/generated.rs` (the legacy
33 293-line monolithic emission file).

Mechanism:

W0 introduced per-grammar files at `crates/core/src/grammar/
generated/<ident>.rs`. The legacy `crates/core/src/grammar/
generated.rs` (33 K lines) was the proc-macro's direct emission
target; with the proc-macro retired and consumers migrated to
`include!` of per-grammar files, the legacy monolith is dead code.

Two paths:

- **(Option X) Delete `crates/core/src/grammar/generated.rs`
  entirely**. `crates/core/src/grammar/mod.rs` already declares
  `pub mod generated;` which now points at the directory's `mod.rs`
  (per W0/W1's aggregator). Cleanest.
- **(Option Y) Keep the file as a deprecation re-export**: replace
  contents with `pub use generated_dir::*;` to ease migration of
  any straggler consumer that imports `bbnf::grammar::generated::*`
  paths. ~5 lines.

Pick X unless `rg -nF 'bbnf::grammar::generated::' --type rust` shows
post-W1 consumers depending on the flat namespace. The new namespace
is `bbnf::grammar::generated::{bbnf, json, css_l4, ...}`, so flat-imports
(`use bbnf::grammar::generated::*;`) work either way.

Files touched (W2.b):
- `crates/core/src/grammar/generated.rs` (deleted iff X; ~5-line
  shim iff Y).
- `crates/core/src/grammar/mod.rs` (modify if needed to refer to
  the directory aggregator).
- `docs/benchmarks/post-B2-W2-walls.txt` (create; record post-
  retirement walls).

Sub-gate:
- Workspace compiles + tests pass post-edit.
- `cargo iter-check-full` cold timing recorded (post-deletion).

## Archaeology

The proc-macro's role across the codebase's history:

- **Pre-W (early tranches)**: `bbnf_derive` introduced as the
  generative substrate. `BBNF_SCHEMA_VERSION` added at
  `crates/derive/src/lib.rs:81` to invalidate cache on schema
  shifts.
- **AY-I**: 30 423-line `generated.rs` for the BBNF self-host.
- **AY-II.W0/W0'**: IR pipeline accumulation pushed `generated.rs`
  to 33 293 lines + drove the per-derive cold-expand wall from ~10-15
  min to 80+ min.
- **B1**: triumvirate fixed gorgeous's 6-derive serial expansion,
  flagged the bootstrap-side wall as out-of-scope and routed to
  AZ-I.W0 (derive-cache + Watt — neither would have actually fixed
  the cold-miss expansion).
- **2026-04-25 deep audit**: AUDIT-D recommended T3 (xtask + checked-
  in generation), retiring the proc-macro entirely.
- **B2.W0/W1/W2**: T3 lands.

The deletion at W2.a closes the chapter. Future grammar additions
plug into `[workspace.metadata.bbnf]` and run `cargo xtask regen` —
no proc-macro contract.
