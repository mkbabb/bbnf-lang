## §1 Deliverable

The pattern, per `docs/tranches/BD/audit/research-anchors.md:§4`, uses the path-dep cargo workspace pattern: per-grammar `tests/fixtures/<grammar>/` directories ship canonical inputs alongside grammar source; CI matrix runs `cargo test -p bbnf-parse --test fixtures_<grammar>` against each.

## §2 Milestones

### §2.1 xtask `worktree-init --fleet` flag

Mechanism: extend `xtask/src/worktree_init.rs` (modified at BC.W5 §2.7) to accept a `--fleet` flag. When set, the xtask materialises the per-grammar fixture directories AND symlinks the BC.W5 `data/{json,css,bbnf,sheets}` directories into the corresponding fixture trees.

```rust
// xtask/src/worktree_init.rs (modified)
pub fn worktree_init(args: WorktreeInitArgs) -> Result<()> {
    if args.fleet {
        materialize_per_grammar_fixtures()?;
        symlink_bc_w5_data_dirs()?;
    } else {
        // BC.W5 baseline behavior preserved
        materialize_data_dirs()?;
        materialize_rewrites()?;
    }
    Ok(())
}
```

### §2.6 Per-grammar test scaffolding

Mechanism: each grammar gets a `crates/bbnf-parse/tests/fixtures_<grammar>.rs` integration test file. The test iterates the fixture directory, parses each input via the production parser, asserts no errors. The test file pattern is uniform across grammars per `feedback_isomorphic_api`:

```rust
// crates/bbnf-parse/tests/fixtures_json.rs (template)
use std::fs;
use std::path::PathBuf;

#[test]
fn parse_all_fixtures() {
    let fixture_dir = PathBuf::from("tests/fixtures/json");
    let entries = fs::read_dir(&fixture_dir)
        .expect("fixture dir exists")
        .filter_map(|e| e.ok())
        .filter(|e| e.path().extension().map_or(false, |ext| ext == "json"));

    for entry in entries {
        let path = entry.path();
        let bytes = fs::read(&path).expect("fixture readable");
        let result = bbnf_parse::json::parse(&bytes);
        assert!(result.is_ok(), "parse failed for {:?}: {:?}", path, result.err());
    }
}
```

Files: `crates/bbnf-parse/tests/fixtures_{json,css_l4,bbnf,google_sheets,css_pretty,ebnf,bnf,csv,math}.rs` (create 9 files via xtask).

Sub-gate: `cargo nextest run -p bbnf-parse --tests fixtures_*` runs all 9 integration tests; each passes.

### §2.8 Fixture symlink contract

Mechanism: per BC.W5's contract, the worktree fixtures support parallel-agent dispatch infrastructure. W4 extends: when a worker / sub-agent opens a sibling worktree, the `xtask worktree-init --fleet` materialises ALL fixture directories on the new worktree without copying (uses symlinks where possible to avoid duplicate disk usage).

The symlink targets are platform-specific:
- Unix-like (Linux, macOS): `ln -s` to absolute paths
- Windows: junction points via `mklink /J`

Files: `xtask/src/worktree_init.rs` (extend with platform-specific symlink logic).

Sub-gate: `xtask worktree-init --fleet --target-worktree /path/to/sibling` produces correct symlinks; `find /path/to/sibling/crates/bbnf-parse/tests/fixtures -type l | wc -l` reports the expected count on Unix; junction count on Windows.

## §5 Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| Public benchmark datasets (sonic-rs's twitter.json, etc.) have unclear license terms that prevent redistribution | Low | sonic-rs's benchmark data is git-tracked under MIT/Apache-2.0 (the sonic-rs project license); the fixtures are downloaded at xtask time (not bundled), avoiding redistribution; the manifest records source URL + license |
| The hand-crafted cohort grammar fixtures are too trivial to exercise the parser | Medium | The fixtures cover at-least Alt dispatch (cohort grammars typically have nested expressions); for grammars with thinner coverage, the manifest declares `coverage = "minimal"` and W4 records the limitation |
| Symlink resolution differs between macOS + Linux + Windows in subtle ways that break the parallel-agent dispatch | Medium | The xtask normalises symlinks to absolute paths on Unix; uses junctions on Windows; the W4-G5 gate verifies on each platform; if a regression appears, the fallback is hard-copy with a documented disk-usage note |
| The CI matrix at 27 cells slows the workflow to > 30 minutes | Medium | Per-cell timeout is 5 minutes; the matrix runs in parallel via GitHub Actions matrix strategy; total wall time bounded by the slowest cell (likely WASM × CSS L4); the W4-G4 gate accepts ≤ 20 minute total wall time |
| The per-grammar manifest schema diverges between grammars | Low | The schema is a TOML schema document committed at W4 §2.9; every grammar's manifest validates against it; `cargo run -p xtask -- validate-fixtures` enforces |
| The xtask `--fleet` flag conflicts with BC.W5's existing flags | Low | The flag is additive; BC.W5's behavior is preserved when `--fleet` is absent; the W4-G1 gate verifies both modes work |
| The fixture file size budget exceeds GitHub's 100 MB per-file limit | Low | Twitter.json is 631 KB, canada.json is 2.2 MB, citm-catalog.json is 1.7 MB; CSS L4 fixtures are < 250 KB; cohort fixtures are < 10 KB; total fixture tree ≤ 10 MB; well under GitHub's limits |
| The cross-backend CI matrix flakes because TS / WASM environments have non-deterministic timings | Low | The matrix asserts parse correctness, not timing; timing-sensitive tests are gated separately (BD-G1, BD-G2 in BD.W1, BD.W2) |
