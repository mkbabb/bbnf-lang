## Tranche fit, wave fidelity, KISS, and greater-product effect

### Tranche fit

V4 was a defensible historical kill-carrier after V3 because it made closure,
flatness, rows, schemes, and printer claims executable. It did produce useful
negative evidence. Under the current supersession boundary it is no longer the
right implementation unit. Repairing it would repeat the horizontal sequence
that the portfolio explicitly retired and would still leave the complete product
question unanswered.

The next experiment is not V4 repair or V5. It is the already-bound set of
complete independent VT candidates. Each candidate must implement its own type
and value/tape spine from BBNF module bytes. Sharing this crate, solver, fixtures,
or helper implementation between candidates would collapse orthogonal candidates
into configurations of one authority.

### Wave/specification fidelity

Surviving V3-carrier fidelity:

- new sibling crate; no production edit, alias, flag, or compatibility route;
- exact ten-module/test mirror, external tests, no unsafe/source tests;
- direct draft-to-solve type separation;
- flat successful deep paths and explicit operation context;
- honest author status and explicit routing of gates 8–9.

Failed V3-carrier fidelity:

- exact closure of every endpoint, lexical recursion, owner-qualified handles;
- complete two-kind row laws, deterministic diagnostics, and causal row proofs;
- scope-free schemes and safely reusable rigids;
- fail-before-work total accounting;
- live/BBNF whole-grammar semantics and exact agreement table;
- real semantic-to-layout evidence and complete exact target matrix.

Failed current-wave fidelity is total: V4 is not VT-1…VT-12 and implements no
complete PT/BB/value/tape/JSON/CSS/backend/package/consumer/profile vertical.
Disclosed deviation is honest evidence hygiene, not gate satisfaction.

### KISS and structure

The ten-file Goldilocks split and source-isomorphic tests are worth retaining as
a method. The implementation size is not proportionate to the current product
effect: 5,328 source lines, 1,897 test lines, two public navigation paths, broad
cloneable IDs/proofs/grammar/layout types, and inert wrapper values, with no
consumer. Much of the size implements authorities the portfolio forbids.

The simpler control is to bank the counterexamples, external-test shapes, and
mechanism dispositions while retiring this crate as reusable code. A future VT
candidate should expose only the capabilities its complete vertical consumes;
it should not carry a second grammar schema, caller-asserted measurement table,
or plan wrapper with no decision.

### Greater-product effect

Positive effect: no production/package dependency or legacy route was added, and
several V3 defects gained executable counterexamples.

Negative prospective effect: adopting V4 would create a second semantic/type,
host, target-mapping, layout, and provenance authority beside BBNF, with no value,
tape, parser, package, CSS, or consumer proof. It also cannot be shared among VT
candidates. Its correct product effect is therefore evidence-bank only.
