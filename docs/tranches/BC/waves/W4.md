**Name**: W4 — Visitor Surface Formalisation

**Hard gate**: `Visitor<'i, T>` trait + `VisitTypes` bitflag formalised as the IR contract's traversal API; per-backend lowerer emits `visit_<Name>` methods consuming typed IR; CSS L4 + JSON visitors tested cross-backend (Rust executes; TS emits but does not execute)
**Status**: planned

## §1 Deliverable

Hereupon `Visitor<'i, T>` trait + `VisitTypes` bitflag becomes the IR contract's traversal API per `audit/SOTA-2026-05-03.md:103-118`; per-backend lowerer emits `visit_<Name>` methods consuming typed IR; CSS L4 + JSON visitors tested cross-backend — Rust emits + executes; TS emits but does not execute since BC scaffold defers activation. The wave formalises the visitor pattern that BB.W5 introduced (per carry-tag BB→BC.C3); BC.W4 lifts it into the IR contract so all three backends produce isomorphic visitor surfaces.

The lightning-css visitor pattern at `audit/SOTA-2026-05-03.md:104-118`:

```rust
pub trait Visitor<'i, T: Visit<'i>> {
    type Error;
    fn visit_types(&self) -> VisitTypes;
    fn visit_stylesheet(&mut self, _: &mut StyleSheet<'i, '_, T>) -> Result<(),Self::Error> { ... }
    fn visit_rule(&mut self, _: &mut CssRule<'i, T>) -> Result<(),Self::Error> { ... }
    fn visit_url(&mut self, _: &mut Url<'i>) -> Result<(),Self::Error> { ... }
    fn visit_color(&mut self, _: &mut CssColor) -> Result<(),Self::Error> { ... }
    fn visit_length(&mut self, _: &mut Length) -> Result<(),Self::Error> { ... }
    // ...
}
```

The bitflag `VisitTypes` (RULES = 1<<0 ... TOKENS = 1<<18) lets the framework prune subtree traversal whose `CHILD_TYPES` does not intersect the visitor's interests. BC.W4 derives `VisitTypes` per grammar from the typed IR's record alphabet; CSS L4 exposes `visit_color`, `visit_length`, `visit_url`, `visit_property`; JSON exposes `visit_string`, `visit_number`, `visit_object`, `visit_array`. The visitor surface is grammar-agnostic in shape; per-grammar visitor methods are codegen-emitted from the typed IR's record set.

The cross-backend invariant: the Rust + TS scaffolds emit isomorphic visitor surfaces; the per-backend leaf-emit differs (Rust: `&mut T` on typed enum; TS: `T` on discriminated union; WASM: bytecode walk), but the method-name set per grammar is byte-identical across backends.

## §2 Milestones

### §2.1 `Visitor<'i, T>` trait in `bbnf-runtime`

Mechanism: define the visitor trait in `bbnf-runtime/src/visitor.rs` (new file post-BC.W3 split). The trait carries a `type Error`; one `fn visit_types(&self) -> VisitTypes`; one `fn visit_<Name>` method per typed-record kind. The default impls walk the children; the `VisitTypes` bitflag prunes traversal.

Files: `crates/bbnf-runtime/src/visitor.rs` (create), `crates/bbnf-runtime/src/lib.rs` (export).

Sub-gate: `cargo check -p bbnf-runtime` green; the trait carries the per-backend-agnostic surface; `Visitor<'i, T>` is parameterised over the input lifetime + the record type tree.

### §2.2 `VisitTypes` bitflag

Mechanism: define the bitflag in `bbnf-runtime/src/visitor.rs`; the bitflag is grammar-derived (the record alphabet of each grammar's typed IR determines the bit count). Per grammar, the codegen emits a `pub const CHILD_TYPES: VisitTypes` per record so the visitor framework can prune subtree traversal.

Files: `crates/bbnf-runtime/src/visitor.rs` (modify-carve).

Sub-gate: the `VisitTypes` bitflag definition supports up to 32 record kinds (or u64 if needed); CSS L4's record alphabet (color, length, url, property, etc.) fits within 32 bits; the bitflag is documented.

### §2.3 Per-backend `visit_<Name>` emit

Files: `crates/bbnf-codegen/src/rust/lower.rs` (modify-carve), `crates/bbnf-codegen/src/ts/visitor.rs` (modify-carve), `crates/bbnf-codegen/src/wasm/visitor.rs` (modify-carve).

## §5 Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| The visitor surface drifts between Rust + TS + WASM (different method names) | Medium | The cross-backend test (W4-G5) asserts byte-identical method-name sets modulo idiom; the per-backend lowerer derives the method name from the typed IR's `rule_id`; idiom transformation (snake_case ↔ camelCase) is mechanical. |
| The `VisitTypes` bitflag overflows 32 bits for CSS L4's large record alphabet | Low | CSS L4's record set per `audit/SOTA-2026-05-03.md:104-118` is bounded by ~18 entries (the lightning-css reference); 32 bits is sufficient. If overflow occurs, the bitflag widens to u64 (a one-time amendment). |
| The visitor pattern does not compose with `pointer!` (path-driven) navigation | Medium | The visitor + pointer surfaces are orthogonal; the visitor walks the typed tree; `pointer!` navigates by typed path; both consume the same typed value sum; W4-G6 verifies composition. |
| The per-grammar visitor implementations explode generated/* LOC beyond the BC budget (≤ +2% from BB) | Medium | Per-grammar visitor methods are lightweight (one method per record kind); LOC delta bounded; per-file budget table at the wave commit body verifies. |
| The trait's `type Error` design is too permissive (consumers don't need errors but pay generic param overhead) | Low | The `type Error` design follows `audit/SOTA-2026-05-03.md:106` (lightningcss); a `()` error type is the convention for non-failing visitors; the overhead is compile-time only. |
| TS scaffold visitor emit produces different shape than Rust (interface vs trait) | Low | TS emits a discriminated-union visitor (`visitor: { color?: (n: CssColor) => void; length?: (n: Length) => void; ... }`); the structural set matches the Rust trait method-name set; the cross-backend test (W4-G5) tolerates idiom variation. |
| The `pointer!` macro from BB.W5 has narrow type inference and the `LazyValue::as_<T>()` projection requires turbofish at call sites | Medium | The friction is documented per Lane 7; W4 §2.8 names the user mental model required (turbofish for ambiguous projections); the `pointer!` macro carries grammar registry path validation, which surfaces type errors at compile time, not runtime. |
| The visitor's default impls walk children without the `VisitTypes` bitflag check, regressing the lightning-css pruning behaviour | Medium | The default impls implement the bitflag check at the trait level (`fn visit_<Name> -> if !v.visit_types().intersects(<Name>::CHILD_TYPES) return; walk_children(self, v)`); the per-grammar emit consumes the trait default; the bitflag is the truth surface. |

## §10 SOTA composition

The visitor + pointer surface is the bbnf-lang composition of two SOTA references: lightning-css's `Visitor<'i, T>` per `audit/SOTA-2026-05-03.md:103-118` and sonic-rs's `pointer!["a","b",1]` + `LazyValue<'a>` per `audit/SOTA-2026-05-03.md:33-42`. The composition is novel — neither sonic-rs nor lightning-css carries both surfaces (sonic-rs has pointer + LazyValue but no visitor; lightning-css has visitor but no pointer macro). bbnf-lang carries both because the IR contract supports both: the visitor walks the typed tree post-parse; the pointer navigates by typed path lazy-or-eager. The composition is grammar-derived and uniform across all nine grammars.
