# BB-B.W2 — dependency graph and deterministic bounded worklists

## Goal

Derive recursion and analysis order once from Program and make fixed-point work
explicit, incremental, deterministic, and fail-closed.

## Implementation

1. Derive typed rule/node/reference/producer/consumer edges with source provenance.
   Validate every endpoint and distinguish containment from semantic dependency.
2. Compute SCCs and condensation with stable member-hash identities. Emit cycle
   witnesses and classify legal grammar recursion versus illegal stage cycles.
3. Implement one deterministic worklist kernel parameterized by a finite or proved
   ascending domain, transfer, join, invalidation, budget, and report. Order is
   stable independent of hash seed or worker scheduling.
4. Express nullability/FIRST/FOLLOW/width and later monotone analyses as separate
   products over the shared graph. Do not put dynamic heterogeneous facts in one
   map or allow an analysis to mutate Program.
5. For an edit, compute changed semantic nodes and reverse dependencies; return an
   invalidation explanation. Compare incremental results to clean recomputation.
6. Detect nonmonotone transfer, domain-height/budget exhaustion, missing facts, and
   invalid revisions as typed failures. Never publish a partial solution as facts.

## Gates

- Graph bytes/SCCs/results match across insertion, hash, worker-count, and repeat
  permutations.
- Incremental solutions equal clean recomputation for generated edit sequences.
- Budget and nonmonotonicity mutation probes fail without partial consumers.
- Every analysis result is keyed to the exact Program revision and total over its
  declared node domain.
- Reports expose visits, changes, invalidations, SCC order, and exhaustion.

## Completion

One directed dependency substrate replaces repeated ambient traversals and gives
later solving/analysis a proved schedule.
