# Tranche B2 — Build-Time Codegen Transposition

B2 retires `bbnf_derive`'s proc-macro IR-pipeline contract. The 17-pass IR
pipeline + ~30 K-line `TokenStream` emission move out of rustc's expand
phase into `cargo xtask regen`, a workspace-level build step that emits
per-grammar source files on disk. `#[derive(Parser)]` retires; consumers
`include!` the on-disk product and provide a marker struct. The
`crates/derive/` proc-macro crate deletes outright.

Net delta: ~−1000 LOC; 80-min cold rustc-side IR-pipeline wall on every
`#[derive(Parser)]` consumer drops to zero. Cycle-1 bootstrap regen falls
from > 80 min cold to seconds. AY-II.W0' close ceremony becomes ~15 min
under the new substrate. AZ-I.W0's previously-routed derive-cache + Watt
items retire (no IR pipeline lives inside rustc to cache or wrap).

## Architectural thesis

1. **Code generation is build-time work that produces source on disk.**
   The proc-macro contract is for *small, local* transformations of user
   code, not workspace-wide IR pipeline execution. A 30 K-line
   `TokenStream` emitted at expand-time forces rustc to re-tokenise,
   re-parse, re-borrow-check, and re-metadata-emit the surface for
   every consuming crate; the cost is structural, not optimisable.
2. **One artefact, one path.** The dual surface ("proc-macro emits at
   expand-time" + "`generated.rs` checked in for self-host bootstrap")
   collapses to one: per-grammar `crates/core/src/grammar/generated/
   <ident>.rs` files, generated by `cargo xtask regen`, checked in,
   `include!`'d at the consumer.
3. **The IR pipeline is xtask code.** Move `compile_paths_request` +
   `generate_all` out of `bbnf_derive` and into `xtask::regen`. The
   pipeline runs once per regen invocation (CI, pre-commit, manual),
   not once per consuming-crate compile.
4. **Marker structs replace derive metadata.** `#[derive(Parser)]
   #[parser(path = "...")]` becomes `pub struct JsonParser;` plus
   `include!("grammar/generated/json.rs")`. No proc-macro surface
   touches consumer code at compile time.
5. **CI/pre-commit gate replaces `BBNF_SCHEMA_VERSION`.** `cargo xtask
   regen --check` regenerates to a tempdir + `git diff --exit-code`
   against the checked-in tree. Schema-version drift detection moves
   from in-band cache-key to standard "diff after regen" hygiene.
6. **No legacy code.** `crates/derive/` deletes. `bbnf_derive`
   dependency entries retire from every consumer's `Cargo.toml`.
   `scripts/bootstrap-bbnf.sh` retires (its logic absorbs into the
   xtask). The dual-cache (`target/.bbnf-cache/` + the on-disk
   `generated.rs`) collapses to one artefact: the source tree itself.

## Invariants

1. `crates/derive/` is deleted at B2 close. Evidence: `ls crates/derive
   2>/dev/null` returns no output post-W2.
2. `bbnf_derive` does not appear as a `[dependencies]` or
   `[dev-dependencies]` entry in any `Cargo.toml` post-W2. Evidence:
   `rg -nF 'bbnf_derive\|bbnf-derive' --type toml` returns 0 results.
3. `#[derive(Parser)]` does not appear in any consumer post-W1.
   Evidence: `rg -nF '#[derive(Parser' --type rust` returns 0 results.
4. `cargo xtask regen` is the canonical regen entrypoint. Evidence:
   `xtask/src/regen.rs` exists; `cargo xtask --help` lists `regen` as
   a subcommand; `make ay-prime` and the `bbnf-bootstrap`-related Make
   targets either delegate to `cargo xtask regen` or retire.
5. Per-grammar source emission lives at `crates/core/src/grammar/
   generated/<ident>.rs`. The previous monolithic
   `crates/core/src/grammar/generated.rs` either retires or becomes a
   thin module-aggregator (`pub mod json; pub mod css_l4; ...`)
   matching the per-grammar files.
6. The 17-pass IR pipeline runs **outside** rustc's expand phase.
   Evidence: `cargo expand -p bbnf --lib` post-B2 contains no IR-pass
   invocations (`compile_paths_request`, `generate_all`,
   `bbnf_ir::passes::*`); those calls live only inside
   `xtask/src/regen.rs`.
7. `cargo xtask regen --check` is the CI + pre-commit gate. Evidence:
   `.github/workflows/ci.yml` invokes it; `xtask/src/regen.rs` exits
   non-zero when the regen output diverges from the checked-in tree.
8. `BBNF_SCHEMA_VERSION` retires from `crates/derive/src/lib.rs:81`
   (entire file deletes). Drift detection moves to the regen-and-diff
   gate. Evidence: `rg -nF 'BBNF_SCHEMA_VERSION' --type rust` returns
   0 results post-W2.
9. AY-II's source-level invariants survive unchanged. The B2
   transposition produces byte-identical (modulo whitespace + macro
   hygiene) emission output for the BBNF self-host grammar pre/post
   regen. Evidence: a B2.W0 hard gate compares the post-W0 first regen
   against a pre-B2 reference snapshot of `generated.rs` and rejects
   semantic divergence (formatting differences are acceptable provided
   `cargo iter-check-full` exits 0 and `projection_totality.rs` test
   green).
10. `scripts/bootstrap-bbnf.sh` retires at B2.W3 close. Its logic
    (cargo-expand + post-process via `syn`/`prettyplease`) absorbs into
    `xtask/src/regen.rs` as native Rust functions. Evidence: `ls
    scripts/bootstrap-bbnf.sh 2>/dev/null` returns no output post-W3.
11. `target/.bbnf-cache/` is no longer created or read by any B2 code
    path. The directory's role (proc-macro content-keyed cache) ceases
    to apply when the proc-macro retires. Evidence: `rg -nF '.bbnf-cache'
    --type rust --type toml --type sh` returns 0 results outside
    historical audit docs post-W3.
12. Routine `cargo iter-check` warm restores to the d7 baseline (≤ 0.5 s
    warm; ≤ 12 s cold) under B2's substrate. The pre-B2 rustflags-drop
    fix (commit `81195656`) is the prerequisite; B2 must not regress it.
13. `cargo iter-check-full` cold under B2 falls below the pre-B2
    `bbnf-bootstrap`-bound 80-min ceiling. Target ceiling: ≤ 10 min cold
    under the post-B2 substrate (no IR pipeline inside rustc).
14. `bbnf-bootstrap` crate retires OR is reduced to a marker
    consumer of `crates/core/src/grammar/generated/bbnf.rs`. The
    self-host BBNF parser is now built like every other grammar's
    parser: from a checked-in source file, not from a proc-macro
    expansion.

## Operational posture

1. B2 dispatches **after** the pre-B2 trivial fixes (commit
   `81195656`) land; those restore `iter-check` warm baseline so B2's
   measurements are honest.
2. B2 executes in **five waves**: W0 (xtask substrate + first
   per-grammar emission), W1 (consumer cutover; ~50 sites across
   gorgeous + bbnf-bootstrap + tests), W2 (proc-macro retirement +
   `crates/derive/` deletion), W3 (script simplification + `bootstrap-
   bbnf.sh` retirement), W4 (CI gate + FINAL close + AY-II handoff
   refresh).
3. Master green at every wave boundary except W1.b's named
   delete-then-swap window (consumer cutover); W1.b is the named
   restoration wave for that window.
4. The proc-macro retirement is the load-bearing transposition; W0/W1
   land the substrate; W2 deletes the legacy. W3/W4 are clean-up +
   close ceremony.
5. AY-II.W0' close ceremony resumes immediately after B2 closes, on
   the post-B2 substrate. Its compressed-honest form per
   `audit/2026-04-25-deep-audit/AUDIT-B-AY-II-viability.md` runs in
   ~15 min under B2's substrate (no bootstrap wall).

## Hard gates summary

### W0 — xtask substrate + first per-grammar emission

1. `xtask/` workspace member exists; `cargo xtask --help` lists `regen` subcommand.
2. `Cargo.toml` workspace `[workspace.metadata.bbnf]` table enumerates every grammar (path + ident + features) the workspace consumes.
3. `cargo xtask regen --grammar bbnf` writes
   `crates/core/src/grammar/generated/bbnf.rs` (the BBNF self-host
   grammar) without running rustc proc-macro expansion. Output exists
   and parses as valid Rust (`syn::parse_file` succeeds).
4. **Byte-equivalent gate**: the post-W0 `generated/bbnf.rs` content is
   semantically equivalent to the pre-B2 `generated.rs` for the BBNF
   self-host grammar (same exported surface; `cargo iter-check-full`
   exits 0 with the new file in place; `projection_totality.rs` test
   green).
5. `cargo iter-check-full` cold under W0 substrate is faster than the
   pre-B2 80-min ceiling. Target: ≤ 30 min cold (the bootstrap-bbnf
   crate's own derive expansion is gone; only consumer test crates
   still pay the proc-macro cost until W1).

### W1 — Consumer cutover

1. Every `#[derive(Parser)]` site enumerated in W0's grammar manifest
   migrates to `include!` + marker struct. Evidence:
   `rg -nF '#[derive(Parser' --type rust` returns 0 results.
2. `cargo iter-check` warm under W1 substrate is ≤ 0.5 s (matches d7
   baseline; W1 doesn't regress invariant 12).
3. `cargo iter-check-full` cold under W1 substrate is ≤ 5 min (no
   consumer crate runs the IR pipeline at compile time anymore; the
   xtask owns it).
4. Every consumer test that previously linked through `bbnf_derive`
   compiles via the `include!` pattern. `cargo nextest run --workspace
   --profile ax-iter` exits 0.
5. The W1.b cutover lands as a single delete-then-swap window
   (master not green during W1.b; W1.c is the named restoration wave).

### W2 — Proc-macro retirement

1. `ls crates/derive/ 2>/dev/null` returns no output (entire crate deleted).
2. `rg -nF 'bbnf_derive\|bbnf-derive' --type toml` returns 0 results
   (dep purged from every Cargo.toml).
3. `rg -nF 'BBNF_SCHEMA_VERSION' --type rust` returns 0 results (constant
   retired with the crate it lived in).
4. `[patch.crates-io] bbnf_derive` line removed from workspace
   `.cargo/config.toml`.
5. `cargo iter-check-full` exits 0 with the proc-macro crate gone.

### W3 — Script simplification

1. `ls scripts/bootstrap-bbnf.sh 2>/dev/null` returns no output (script deleted).
2. Makefile's `ay-prime` target either delegates to `cargo xtask regen`
   or retires (no remaining cache-priming role).
3. `rg -nF 'bootstrap-bbnf.sh\|target/.bbnf-cache' --type sh --type makefile
   --type-add 'docs:*.md'` returns 0 results in non-historical files.
4. `cargo xtask regen` (no `--check`) successfully regenerates the full
   per-grammar set; output diff vs checked-in tree is empty (idempotency).

### W4 — CI gate + FINAL

1. `.github/workflows/ci.yml` invokes `cargo xtask regen --check` as a
   gate step.
2. Pre-commit hook (under `.git/hooks/pre-commit` or `.husky/`) invokes
   `cargo xtask regen --check`; CI provides the canonical enforcement.
3. `docs/instructions/PROFILING.md` updated: §Bootstrap regen → "run
   `cargo xtask regen`"; §Dev-host setup adjusts; proc-macro-cache
   prose deletes.
4. `docs/tranches/B2/FINAL.md` exists with invariant + hard-gate +
   commit ledger + AY-II handoff block.
5. AY-II planning docs (`PATH-FORWARD.md`, `AY-II.md`,
   `waves/W0p.md`) reference B2 as predecessor; W0' compressed-honest
   ceremony under B2's substrate is dispatchable.

## Cross-tranche debt

**Inherited from B1 (closed and forwarded to B2)**:
- Bootstrap's > 600 s single-derive proc-macro expansion wall →
  **resolved by B2.W2** (proc-macro retires; the wall ceases to exist).
- Per-bench divan JSON emissions and nextest dry-run wall captures
  (B1 routed to AZ-I.W0) → **re-routed to AY-II.W1+ post-B2**, since
  the wall they were waiting on disappears at B2 close.
- Samply baseline refresh (B1 routed to AY-II.W0' close) →
  **unchanged; lands at AY-II.W0' compressed-honest close** (~15 min
  under B2 substrate).

**Forwarded from B2 to successor tranches**:
- `cargo xtask regen` polish (incremental regen for single-grammar
  edits; faster CI cycles) → post-B2 polish, not load-bearing.
- AZ-I.W0 **rescoped**: derive-cache relocation + Watt items DROP (no
  proc-macro to cache or wrap); classifier unification + IR audit
  retain. AZ-I.W0 plan amendment lands as part of B2.W4 doc-update
  scope.
- Bench architecture restructure (`crates/bench-*`) → AZ-I or later
  (unchanged from B1's forwarding).

## Defensible floor

B2's defensible floor:
1. `xtask/src/regen.rs` exists and produces a valid per-grammar source
   tree under `crates/core/src/grammar/generated/`.
2. The BBNF self-host grammar regenerates byte-identical (modulo
   formatting) to the pre-B2 `generated.rs` for that grammar.
3. AT LEAST the BBNF self-host consumer (`bbnf-bootstrap`) migrates
   to the `include!` pattern at W1; remaining consumer migrations may
   defer with named successor tranche if the cutover scope reveals
   under contact.
4. `crates/derive/` deletion either lands at W2 or formally defers to
   B3 with named rationale (e.g., a consumer migration blocker).
5. `bootstrap-bbnf.sh` retirement lands at W3 unless §4's deferral
   blocks it.

Anything less leaves the proc-macro wall in place and B2's thesis
unrealised.

## Escape clause

**Phase-1 unworkability window**: W1's consumer cutover is a named
delete-then-swap window. During W1.b, master may not compile cleanly
(some consumers cut over while others lag). W1.c is the named
restoration wave; cherry-picks must compose end-to-end before W1
closes. If W1.c cannot restore master-green within its hard cap, B2
relinquishes to the orchestrator + dispatches a triumvirate per
`docs/instructions/README.md` §Orchestration.

**No mid-tranche scope absorption**: B2's thesis is the proc-macro
retirement. If execution surfaces work that contradicts that thesis
(e.g., a consumer site that genuinely cannot migrate to `include!`
without breaking AY-II runtime invariants), B2 closes on what landed +
opens B3 with the residual scope. New letter, not silent deferral.

## Indefatigability

When B2 closes correctly, the workspace has one codegen path
(`cargo xtask regen` → on-disk source files), one consumer pattern
(`include!` + marker struct), zero proc-macros wrapping a 17-pass IR
pipeline, zero `target/.bbnf-cache/` directory, zero `BBNF_SCHEMA_VERSION`
discipline. AY-II.W0' resumes on a substrate where the regen wall is
seconds, not 80 minutes. AZ-I.W0 reduces in scope to its actual
load-bearing items (classifier unification + IR audit pass). Every
downstream tranche (AZ-II, BA, BB) iterates under this transposed
substrate.

The proc-macro contract returns to its idiomatic Rust scope: small,
local transformations of user code. Code generation moves to where
code generation belongs: build time, source on disk.
