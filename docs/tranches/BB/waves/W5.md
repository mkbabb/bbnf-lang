# BB.W5 - Review Ledger + CI

**Name**: W5 - Review Ledger + CI
**Opens after**: W4 - Grammar-Colocated Rewrite Dirs
**Agents**: 5 parallel
**Hard gate**: `docs/rules/audit-log.ndjson` signed for every Class-1; Class-3 reviewer-signed rationale per rule; throughput gain on `post-BA.json` matrix; no regression; CI status integrated; rejected rules have rationale
**Status**: planned

## Scope

1. Land the review ledger CI integration. The rule admission chain is verified at every regen; CI gates new rule acceptance on (a) schema validation, (b) e-graph admission chain green, (c) corpus hit-rate ≥ 0.1, (d) parity tests green, (e) audit log signed for Class 1, rationale present for Class 3.
2. Class-3 review surface: every Class-3 rule has `docs/rules/<rule-id>.md` with reviewer-signed rationale (the reviewer is named; the rationale covers corpus coverage, intentional-divergence probing). The W4-landed Class-3 rules acquire signed rationales here.
3. Rejected rules: any candidate that the ranker tier classifier flagged Class 3 and the reviewer rejected has `docs/rules/rejected/<rule-id>.md` with rationale. The rejected list integrates with the audit log for traceability.
4. Throughput measurement: run the W4-accepted rules through the bench harness; record the throughput delta vs `post-BA.json` close matrix. ≥ 1 grammar shows measurable throughput gain. No grammar regresses.
5. Reversal criteria check: the wave-local 20% rule applies. If the W4-accepted batch fails to produce the declared cost delta by > 20% of target, the wave reverts the batch. Any soundness violation (rediscovered rule failing the corpus) triggers immediate revert.

## Triumvirate Dispatch

Dispatch a triumvirate if any of these occurs:

- a Class-3 rule's reviewer-signed rationale fails the close-honesty checklist (the rationale is templated, vague, or AI-styled per `STYLE.md`);
- a parity test regresses after the W4 acceptance batch lands (soundness violation; immediate revert; root cause must be found before the next wave opens);
- the throughput delta is negative for any grammar (regression on `post-BA.json` matrix; the responsible rule batch reverts);
- the CI integration breaks the existing regen pipeline (the rule admission chain check has a false positive on a known-good rule);
- three diagnostic-loop iterations fail to isolate why a Class-3 rule's rationale cannot pass the close-honesty checklist;
- JSONL transcript quiet >15 minutes;
- first-pass return with no commit and no evidence (after one verbatim redispatch).

## Agent Units

### BB.W5.1 CI Workflow

- Mechanism: create `.github/workflows/rules-ci.yml` (or modify-carve existing CI file) to run the rule admission gate on every PR that touches `grammar/<name>/rewrites/` or `crates/ir/src/rewrites/`. The workflow invokes `cargo xtask rules-ci` (W5.2).
- Files: `.github/workflows/rules-ci.yml`.
- Sub-gate: workflow YAML lints clean; CI run on a draft PR exercises the gate.

### BB.W5.2 CI Gate Logic

- Mechanism: implement `xtask/src/rules_ci.rs` (or extend `xtask/src/regen.rs` with a `rules-ci` subcommand). Validate (a) schema for new RON files; (b) e-graph admission chain green; (c) corpus hit-rate ≥ 0.1; (d) parity tests green; (e) audit log signed for Class 1, rationale present for Class 3.
- Files: `xtask/src/rules_ci.rs`, `xtask/src/main.rs` (modify-carve to register subcommand).
- Sub-gate: `cargo xtask rules-ci` exits 0 on a clean PR; exits non-zero with named diagnostics on a PR with missing rationale, schema error, or admission-chain miss.

### BB.W5.3 Class-3 Rationales

- Mechanism: for each W4-landed Class-3 rule, add reviewer-signed rationale to `docs/rules/<rule-id>.md` covering corpus coverage, intentional-divergence probing, and the reviewer's name. The rationale follows STYLE.md (no AI-styled prose, no templated text).
- Files: `docs/rules/<rule-id>.md` (modify-carve; Class-3 rules only).
- Sub-gate: every Class-3 rule has signed rationale; close-honesty checklist passes.

### BB.W5.4 Rejected List

- Mechanism: for each candidate the ranker classified Class 3 that the reviewer rejected, create `docs/rules/rejected/<rule-id>.md` with rationale.
- Files: `docs/rules/rejected/<rule-id>.md` (per rejected rule).
- Sub-gate: every rejected rule has a doc; the audit log includes the rejection in its trace.

### BB.W5.5 Throughput + Audit

- Mechanism: run the bench harness against the post-W4 generated outputs. Compare against `post-BA.json` close matrix. Save `docs/benchmarks/post-BB-W5-throughput.json`. Verify ≥ 1 grammar with measurable gain; verify zero regressions. Document in `docs/tranches/BB/audit/W5-throughput.md`.
- Files: `docs/benchmarks/post-BB-W5-throughput.json`, `docs/tranches/BB/audit/W5-*`.
- Sub-gate: ≥ 1 grammar with throughput gain; zero regressions on `post-BA.json` matrix.

## Hard Gate

1. CI workflow gates new rule acceptance on the 5 named checks; exit-code-driven.
2. Every Class-3 rule has reviewer-signed rationale at `docs/rules/<rule-id>.md`.
3. Every rejected candidate has rationale at `docs/rules/rejected/<rule-id>.md`.
4. Audit log is signed for every Class-1 acceptance.
5. ≥ 1 grammar shows measurable throughput gain on `post-BA.json` close matrix.
6. Zero regressions on `post-BA.json` close matrix.
7. Wave-local 20% rule: if any rule batch fails the declared cost delta by > 20%, the batch reverts (named test).
8. `cargo xtask regen --check` 9/9 green; `cargo nextest run --workspace --cargo-profile ax-iter` 100% pass.
9. `cargo fmt --all -- --check`, focused `cargo clippy --profile ax-iter`, and `git diff --check` pass.
