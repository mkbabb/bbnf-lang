`skinny/crates/bbnf-bench/Cargo.toml` is a W1b-1 owner path, so adding
`cssparser` to the bench crate is legal in redress. That gives an external,
reviewable declaration/value tokenizer without importing the root

The input corpus should be frozen from existing CSS fixtures. The conservative
choice is `data/css/normalize.css`, because the root test

`restart/skinny/tranches/sk-v12/research/w1b/css_l4_declaration_values.css`
and record both checksums; do not invent a synthetic corpus or use the old W1a
schema-only fixture as parser evidence.

## Fact Schema

The canonical output plane is a UTF-8, LF-terminated byte stream. It is strict
and line-oriented; equality is byte equality after both producers emit this
schema.

```text
css-l4-declaration-value-facts-v1
source	input_sha256=<64-hex>	input_bytes=<u64>
decl	idx=<u32>	property_hex=<hex>	important=<0|1>	value_start=<u32>	value_end=<u32>	tokens=<u32>
tok	decl=<u32>	idx=<u32>	kind=<ident|string|number|percentage|dimension|hash|function|url|delim|comma|paren_open|paren_close|bracket_open|bracket_close>	lexeme_hex=<hex>	flags=<dash-joined-flags-or-none>
end	decls=<u32>	tokens=<u32>	stream_blake3=<64-hex>
```

Canonicalization rules:

- Comments and whitespace are not facts.
- Declaration order is source order; no sorting.
- Non-custom property names are ASCII-lowercased before hex encoding.
  Custom properties beginning `--` preserve source bytes.
- Identifier, function, unit, and hash lexemes are ASCII-lowercased before hex
  encoding. String payload bytes preserve unescaped string value bytes.
- Numeric lexemes preserve the source token spelling for W1b-1. W1b-2 may add a
  lightningcss-compatible numeric normalizer, but W1b-1 must not hide that
  future comparator work.
- `value_start` and `value_end` are byte offsets in the frozen input. They are
  diagnostic and must match between Track 1 and oracle; they are not a sidecar
  substrate.

## Equality Shape

Track 1:

- Generated runtime under
  `skinny/crates/runtime/src/grammars/css_l4_declaration_values/`.
- Exposes one direct function that emits the fact stream for the selected row.
- Must not call root `crates/core` CSS runtime, `runtime::generated_json`,
  `json_provider`, generated JSON helpers, or the oracle module.

Oracle:

- Reviewable module such as
  `skinny/crates/bbnf-bench/src/nonjson_css_l4.rs` or
  `skinny/crates/bbnf-bench/benches/nonjson_oracles/css_l4_decl_value.rs`.
- Uses `cssparser` stylesheet/declaration parsing plus an independently written
  token-to-fact serializer.
- Must not import `runtime`, `codegen`, `parse_that_regex`, `bbnf-simd`, or
  generated Track 1.

Test/bench flow:

1. Load the frozen CSS corpus and compute SHA-256.
2. Emit Track 1 facts and oracle facts into separate buffers.
3. Assert byte equality before any Criterion timing.
4. Write Track 1 facts, oracle facts, and a tiny equality artifact containing
   the stream hash and first-diff preview on failure.
5. Benchmark Track 1 and oracle separately with sample count >= 30.
6. Emit the SK-V12 non-JSON report with `strict_output_equality = "pass"`,
   `track2_independence_status = "independent_verified"`, finite Track 1 and
   oracle Mbps, and `same_wave_consumer_class =
   "companion_gate_generated_baseline"`.

## Independence Argument

The oracle is independent because its parser, token model, and serializer are
not generated by bbnf and do not share Track 1 runtime code. `cssparser` supplies
the token/declaration stream; bbnf-bench supplies only the canonical fact
serializer. That is materially separate from generated Track 1, while still
using the same input, output plane, run id, host, and gate report. It is also
not a lightningcss admission path: W1b-1 proves generated CSS facts are
measurable and independently equal; W1b-2 adds the same-plane lightningcss
facts and the `track1_mbps > lightningcss_mbps + 1` bar.

Reject these couplings in CHALLENGE/redress:

- oracle calls generated Track 1 or generated runtime internals;
- Track 1 or oracle reuses root `crates/core` `CssL4Parser`/`CssStructBuilder`;
- oracle is hidden inside the Criterion closure with no reviewable module;
- equality is digest-only without retaining the canonical fact stream artifact;
- `lightningcss` is used to satisfy W1b-1 oracle independence or admission.
