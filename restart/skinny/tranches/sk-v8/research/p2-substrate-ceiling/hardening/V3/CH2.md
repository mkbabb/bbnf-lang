   ordinals, not generic JSON roles. SC-6 defines it as per-grammar codegen data
   emitted into `runtime/src/grammars/<name>/`, with structural bytes,
   byte-to-ordinal class table, generated quote/escape byte sets, and no
   ordinal-to-role interpretation in generic code
   (`restart/skinny/tranches/sk-v8/research/p2-substrate-ceiling/SC-6-lock1-amendment-generalisation.md:348-374`).
   The generic crates consume only generated byte sets and opaque ordinals and
   never expose a public grammar-selection API or grammar branch
   (`restart/skinny/tranches/sk-v8/research/p2-substrate-ceiling/SC-6-lock1-amendment-generalisation.md:386-395`).
   SC-3 says the same thing at the substrate seam: `StructuralClassTable` is data
   emitted per grammar, and `class`/`fact_id` values are opaque to generic code
   (`restart/skinny/tranches/sk-v8/research/p2-substrate-ceiling/SC-3-union-substrate-design.md:323-352`).

2. The fact lane no longer functions as a generic recovery/layout escape hatch.
   SC-3 narrows `facts` to opaque generated ids, bans generic matching on fact

   excludes density tables, quote caches, skip caches, parser-owned slots, and
