## §1 — Findings (concrete; file:line on bbnf claims, citation on external claims)

S-P1 says P2 must work from parser hot leaves, not benchmark folklore. The normalized ledger binds S-P2 to grammar-neutral scanner, tape/allocation, unicode/string, memory, and direct-parser cursor work; generated wrappers, schema-specific rows, comparator internals, and checksum/harness rows remain blocked unless converted to grammar-neutral parser machinery (`restart/skinny/tranches/sk-v15/research/p1/p1e-hot-leaf-attribution.md:33`, `restart/skinny/tranches/sk-v15/research/p1/p1e-hot-leaf-attribution.md:35`). The PMU ledger makes the empirical floor concrete: parse_only beats the best strict comparator on 17/17 rows, while direct_strict misses `mesh` and `unicode_escapes`, and real_typed misses `unicode_escapes` (`restart/skinny/tranches/sk-v15/research/p1/p1d-pmu-cycles.md:70`). The per-row PMU summary shows `mesh` direct_strict at 1.093x best comparator and `unicode_escapes` direct_strict/real_typed at 1.402x/1.394x (`restart/skinny/tranches/sk-v15/research/p1/evidence/pmu-cpb-summary.tsv:27`, `restart/skinny/tranches/sk-v15/research/p1/evidence/pmu-cpb-summary.tsv:42`, `restart/skinny/tranches/sk-v15/research/p1/evidence/pmu-cpb-summary.tsv:43`).

Lock 1 is binding on the output plane. The only retained substrate is the IS tape; SIMD masks are transient, and retained sidecars, parser-owned cursors, or second tapes require G-Omega abrogation (`restart/locks/LOCKS.md:75`, `restart/locks/LOCKS.md:118`, `restart/locks/LOCKS.md:127`). Lock 1 also rejects retained cross-call classifier carry; carry may exist only inside a single chunk-call, while `retained-across-call-boundary` is a hard reject (`restart/locks/LOCKS.md:137`, `restart/locks/LOCKS.md:150`, `restart/locks/LOCKS.md:155`). Lock 14 keeps the primitive surface grammar-neutral; SK-V15 explicitly demoted CSS rows and retained JSON only as honest admission evidence, with native Apple M5 Max/aarch64 as the admission platform (`restart/skinny/tranches/sk-v15/HANDOFF.md`, `restart/skinny/tranches/sk-v15/SYNTHESIS.md`).

### asmjson

asmjson is a hand-written x86-64 AVX-512BW/SWAR JSON parser. Its README claims AVX-512BW/SWAR classifies 64-byte blocks and skips whitespace/string bodies quickly, and its public API exposes `parse_to_dom_zmm` and `parse_with_zmm` for unsafe AVX-512BW callers (`https://github.com/atomicincrement/asmjson/blob/master/README.md#L7`, `https://github.com/atomicincrement/asmjson/blob/master/README.md#L42`). Its Rust wrapper says the parser is direct-threaded assembly with a stable C vtable, and the vtable separates number, string, escaped string, key, start/end object, and array callbacks (`https://github.com/atomicincrement/asmjson/blob/master/src/lib.rs#L16`, `https://github.com/atomicincrement/asmjson/blob/master/src/lib.rs#L24`). Its SAX assembly classifies whitespace, quotes, backslashes, and delimiters over 64-byte chunks, scans strings to the next quote/backslash, and has a SWAR digit path before falling back to `is_valid_json_number_c` (`https://github.com/atomicincrement/asmjson/blob/master/asm/x86_64/parse_json_zmm_sax.S#L216`, `https://github.com/atomicincrement/asmjson/blob/master/asm/x86_64/parse_json_zmm_sax.S#L388`, `https://github.com/atomicincrement/asmjson/blob/master/asm/x86_64/parse_json_zmm_sax.S#L1165`). Its DOM assembly writes `TapeEntry` records directly into a preallocated array (`https://github.com/atomicincrement/asmjson/blob/master/asm/x86_64/parse_json_zmm_dom.S#L4`, `https://github.com/atomicincrement/asmjson/blob/master/asm/x86_64/parse_json_zmm_dom.S#L31`).

The useful lesson is not "add an x86 parser." For SK-V15, x86/AVX-512 is diagnostic only, not an admission anchor. The useful primitive shapes are 64-byte class masks, local string-event detection, direct tape append, and SWAR number-span classification. asmjson is not a strict comparator anchor because it documents permissive behavior: any byte below `0x20` is accepted as whitespace and string contents are not scanned for unescaped control characters (`https://github.com/atomicincrement/asmjson/blob/master/README.md#L209`, `https://github.com/atomicincrement/asmjson/blob/master/README.md#L218`). Its routes therefore ground flaw probes and primitive shapes, not SOTA strictness claims. P1 ties: structural/movemask rows (`restart/skinny/tranches/sk-v15/research/p1/evidence/p1e-normalized-attribution.tsv:15`), NEON byte scanner rows (`restart/skinny/tranches/sk-v15/research/p1/evidence/p1e-normalized-attribution.tsv:57`), string/unicode rows (`restart/skinny/tranches/sk-v15/research/p1/evidence/p1e-normalized-attribution.tsv:95`), and allocation/tape rows (`restart/skinny/tranches/sk-v15/research/p1/evidence/p1e-normalized-attribution.tsv:93`).

### sonic-rs

sonic-rs is the most relevant comparator for native aarch64 primitive shape. Its performance notes describe On Demand skipping of unnecessary fields, SIMD string bitmaps plus bracket counts for container skipping, SIMD whitespace skipping, and a reused non-space bitmap (`/Users/mkbabb/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/sonic-rs-0.5.8/docs/performance.md:7`, `/Users/mkbabb/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/sonic-rs-0.5.8/docs/performance.md:48`, `/Users/mkbabb/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/sonic-rs-0.5.8/docs/performance.md:62`, `/Users/mkbabb/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/sonic-rs-0.5.8/docs/performance.md:79`). It also documents preallocated arena/vector capacity at `json.len()/2 + 2`, matching a tape-allocation hot leaf (`/Users/mkbabb/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/sonic-rs-0.5.8/docs/performance.md:153`).

The source implements a branchless escaped-mask macro, a 64-byte string-bit scanner with quote/backslash masks and prefix xor, and a container-skip loop that counts braces outside strings (`/Users/mkbabb/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/sonic-rs-0.5.8/src/parser.rs:108`, `/Users/mkbabb/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/sonic-rs-0.5.8/src/parser.rs:153`, `/Users/mkbabb/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/sonic-rs-0.5.8/src/parser.rs:171`). Its parser stores `nospace_bits` and `nospace_start`, which is a retained optimization shape that is not directly portable under Lock 1 unless kept local to a chunk-call or collapsed into the tape/event loop (`/Users/mkbabb/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/sonic-rs-0.5.8/src/parser.rs:209`). The aarch64 backend uses NEON table lookup for non-space bits and explicitly notes that the PMULL prefix-xor route was apparently slow for this code path (`/Users/mkbabb/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/sonic-rs-0.5.8/src/util/arch/aarch64.rs:20`, `/Users/mkbabb/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/sonic-rs-0.5.8/src/util/arch/aarch64.rs:49`). That is directly relevant to Lock 1's PMULL/cache-hint/ASM-gen warnings: any PMULL route needs a material differential and micro-proof, not assumption (`restart/locks/LOCKS.md:547`).

Strictness discipline is mostly separable. sonic-rs has an opt-in `utf8_lossy` mode that replaces invalid UTF-8 with U+FFFD, but the default parser errors on invalid UTF-8 (`/Users/mkbabb/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/sonic-rs-0.5.8/src/parser.rs:251`, `/Users/mkbabb/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/sonic-rs-0.5.8/src/parser.rs:685`). It supports borrowed no-escape strings, copied escaped strings, lazy borrowed values, and raw numbers (`/Users/mkbabb/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/sonic-rs-0.5.8/src/parser.rs:658`, `/Users/mkbabb/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/sonic-rs-0.5.8/src/serde/de.rs:341`, `/Users/mkbabb/.cargo/registry/src/index.crates.io-1949cf8c6b5b557f/sonic-rs-0.5.8/src/serde/rawnumber.rs:10`). P1 ties: whitespace/string scanner (`restart/skinny/tranches/sk-v15/research/p1/evidence/p1e-normalized-attribution.tsv:23`, `restart/skinny/tranches/sk-v15/research/p1/evidence/p1e-normalized-attribution.tsv:94`), direct skip cursor (`restart/skinny/tranches/sk-v15/research/p1/evidence/p1e-normalized-attribution.tsv:31`), unicode/string (`restart/skinny/tranches/sk-v15/research/p1/evidence/p1e-normalized-attribution.tsv:95`), and allocation/tape (`restart/skinny/tranches/sk-v15/research/p1/evidence/p1e-normalized-attribution.tsv:80`).

### simdjson

simdjson's general stage 1 is a structural-indexer pipeline. The generic indexer owns a `json_scanner`, `utf8_checker`, `bit_indexer`, and `prev_structurals`, then processes blocks by scanning strings/scalars/operators, checking UTF-8, and outputting previous-iteration structurals (`https://raw.githubusercontent.com/simdjson/simdjson/master/src/generic/stage1/json_structural_indexer.h:127`, `https://raw.githubusercontent.com/simdjson/simdjson/master/src/generic/stage1/json_structural_indexer.h:176`, `https://raw.githubusercontent.com/simdjson/simdjson/master/src/generic/stage1/json_structural_indexer.h:239`). The string scanner computes escaped and real quote masks using backslash masks and prefix xor, then updates `prev_in_string` and reports unclosed strings on finish (`https://raw.githubusercontent.com/simdjson/simdjson/master/src/generic/stage1/json_string_scanner.h:40`, `https://raw.githubusercontent.com/simdjson/simdjson/master/src/generic/stage1/json_string_scanner.h:62`, `https://raw.githubusercontent.com/simdjson/simdjson/master/src/generic/stage1/json_string_scanner.h:87`).

Its DOM tape builder visits document/array/object/key/primitive events, writes root/container/string/number values to tape, parses strings without replacement, and has a number-as-string route for big integers (`https://raw.githubusercontent.com/simdjson/simdjson/master/src/generic/stage2/tape_builder.h:21`, `https://raw.githubusercontent.com/simdjson/simdjson/master/src/generic/stage2/tape_builder.h:130`, `https://raw.githubusercontent.com/simdjson/simdjson/master/src/generic/stage2/tape_builder.h:166`, `https://raw.githubusercontent.com/simdjson/simdjson/master/src/generic/stage2/tape_builder.h:182`). On Demand still begins by allocating/running stage 1 and returning a document or raw iterator (`https://raw.githubusercontent.com/simdjson/simdjson/master/include/simdjson/generic/ondemand/parser-inl.h:54`, `https://raw.githubusercontent.com/simdjson/simdjson/master/include/simdjson/generic/ondemand/parser-inl.h:126`).

The important negative result is substrate shape. simdjson's retained structural indexes, previous-string state, and stage separation are productive for simdjson, but SK-V15 cannot import them as retained sidecars or parser-owned cursors. REDRESS 51 rejected byte-class whitespace cursor sidecars (`skinny/REDRESS.md:742`), REDRESS 53 rejected a structural-mask parser-local cursor as a second scanner (`skinny/REDRESS.md:784`), REDRESS 97 rejected a streaming structural cursor (`skinny/REDRESS.md:2852`), and REDRESS 98 retired the union-substrate hypothesis (`skinny/REDRESS.md:2910`). The admissible extraction is narrower: local mask constructors and same-call consumption into the existing tape/event loop.

### yyjson

yyjson is a portable ANSI C DOM comparator, not a SIMD comparator. Its README says it is portable, avoids explicit SIMD, validates strict RFC 8259 UTF-8 by default, offers JSON5/custom allocator options, and prioritizes modern CPU ILP/branch prediction/optimizer quality (`https://raw.githubusercontent.com/ibireme/yyjson/master/README.md:10`, `https://raw.githubusercontent.com/ibireme/yyjson/master/README.md:73`). It also documents DOM limitations and scope: arrays/objects are stored as data structures/linked lists, duplicate keys are preserved, immutable parse results are immutable, and benchmark comparisons are DOM-only while simdjson On Demand can be faster when fields are known at compile time (`https://raw.githubusercontent.com/ibireme/yyjson/master/README.md:22`, `https://raw.githubusercontent.com/ibireme/yyjson/master/README.md:27`).

The source path worth copying is scalar shape. `skip_trivia` has standard and extended whitespace/comment paths under flags, number parsing includes raw-number flags plus unrolled digit handling, and string parsing uses an unrolled ASCII fast path before storing no-escape strings (`https://raw.githubusercontent.com/ibireme/yyjson/master/src/yyjson.c:3366`, `https://raw.githubusercontent.com/ibireme/yyjson/master/src/yyjson.c:3889`, `https://raw.githubusercontent.com/ibireme/yyjson/master/src/yyjson.c:3967`, `https://raw.githubusercontent.com/ibireme/yyjson/master/src/yyjson.c:4765`, `https://raw.githubusercontent.com/ibireme/yyjson/master/src/yyjson.c:4817`). The read result stores root, data read, values read, and string pool, while the iterative object/array state machine advances value slots and parent offsets in a single DOM plane (`https://raw.githubusercontent.com/ibireme/yyjson/master/src/yyjson.c:5290`, `https://raw.githubusercontent.com/ibireme/yyjson/master/src/yyjson.c:5488`). The header exposes a max-memory-usage calculation: max value count is `json_size / 2 + 1`, with 16 bytes per value plus growth/padding (`https://raw.githubusercontent.com/ibireme/yyjson/master/src/yyjson.h:1104`). P1 ties: allocation/tape rows (`restart/skinny/tranches/sk-v15/research/p1/evidence/p1e-normalized-attribution.tsv:9`, `restart/skinny/tranches/sk-v15/research/p1/evidence/p1e-normalized-attribution.tsv:44`, `restart/skinny/tranches/sk-v15/research/p1/evidence/p1e-normalized-attribution.tsv:93`), number/mesh rows (`restart/skinny/tranches/sk-v15/research/p1/evidence/p1e-normalized-attribution.tsv:46`), and unicode/string rows (`restart/skinny/tranches/sk-v15/research/p1/evidence/p1e-normalized-attribution.tsv:116`).

## §3 — Grammar-neutrality (each candidate: JSON-only or CSS/Sheets/BBNF-self generalisable)

| Candidate primitive | Grammar-neutrality judgement |
|---|---|
| `byte_class_mask_64<const CLASS>` | Generalisable. JSON structural/whitespace classes are one instantiation; CSS punctuation, Sheets delimiters, and BBNF-self token classes can use the same shape with grammar-owned class tables. |
| `skip_byte_set_run` | Generalisable. The primitive is a byte-class run skipper; JSON whitespace, CSS trivia, Sheets spacing, and BBNF-self trivia differ only in the grammar-provided class and strictness policy. |
| `scan_string_event_64` | Generalisable if the API takes grammar string policy: quote byte(s), escape byte, forbidden controls, and whether multiline/newline forms are legal. JSON-only control-byte rejection must remain policy, not hard-coded primitive behavior. |
| `decode_escape_run` | Generalisable only if escape tables and unicode policy are grammar-owned. JSON `\uXXXX`, CSS escapes, Sheets strings, and BBNF-self strings can share sink mechanics, but the JSON escape table cannot be compiled into the primitive. |
| `raw_number_span_classify` | Generalisable if the numeric DFA is grammar-owned. JSON number strictness, CSS numeric units, Sheets numbers, and BBNF-self numeric forms require separate policies over the same span/classify shell. |
| `container_skip_local_count_64` | Generalisable for balanced-delimiter grammars only. It must accept grammar delimiter sets and string/comment policies; JSON object/array skipping is one instantiation, not the primitive contract. |
| `tape_reserve_upper_bound` | Generalisable if the upper-bound rule is provided by each grammar. JSON's value upper bound does not automatically hold for CSS or Sheets, but the reserve/report mechanism is grammar-neutral. |

## §4 — Risks (REDRESS entries any candidate must NOT re-open)

REDRESS 28 and 33 block replaying the old 16-byte active tiny-string recognizer as if it were new work; the admitted parser remained on the 8-byte scalar tiny recognizer after the SIMD route regressed (`skinny/REDRESS.md:324`, `skinny/REDRESS.md:394`). Any `scan_string_event_64` proposal must be a strict grammar-neutral scanner primitive with scalar proof, not that closed tiny-string route.

REDRESS 50 blocks parse-time auxiliary side tables and keeps the admissible route on typed event consumption over the existing tape, with string/number rescans confined to grammar-neutral primitives (`skinny/REDRESS.md:715`). REDRESS 51 blocks byte-class whitespace cursor sidecars (`skinny/REDRESS.md:742`). REDRESS 53 blocks a parser-local structural-mask cursor because it became a second scanner; only scanner-to-tape/event emission or same-loop live-mask consumption is admissible (`skinny/REDRESS.md:784`). These are the governing risks for `byte_class_mask_64`, `skip_byte_set_run`, and `container_skip_local_count_64`.

REDRESS 54, 55, 66, 67, 68, and 69 block most escaped-string materialization shortcuts under the current direct/product contracts. They respectively rejected exact decoded-string stats, quote-source fused materialization, source-hook field-layout folding, parser-owned decoded scratch, byte-output materialization inside the current `Cow` API, and semantic string fact hashing (`skinny/REDRESS.md:815`, `skinny/REDRESS.md:846`, `skinny/REDRESS.md:1688`, `skinny/REDRESS.md:1736`, `skinny/REDRESS.md:1789`, `skinny/REDRESS.md:1839`). `decode_escape_run` is therefore blocked unless it proves a materially different scalar primitive and same-wave consumer.

REDRESS 96/97/98 and Lock 1 block a retained union-substrate import of simdjson or sonic-rs. Streaming structural cursors, class-lane replays, retained mask streams, parser-owned sidecars, and second tapes are not shortlist-safe without fresh material differential, scalar/checkasm proof, same-wave consumer, gate, rollback, and abrogation (`restart/locks/LOCKS.md:129`, `skinny/REDRESS.md:2852`, `skinny/REDRESS.md:2910`). This blocks a direct simdjson stage1 clone and a retained sonic-rs `nospace_bits` clone.

asmjson carries two additional risks. First, its strictness profile is not JSON-strict because it accepts any byte below `0x20` as whitespace and does not reject unescaped control bytes inside strings (`https://github.com/atomicincrement/asmjson/blob/master/README.md#L209`, `https://github.com/atomicincrement/asmjson/blob/master/README.md#L218`). Second, its AVX-512 implementation is x86-only and therefore diagnostic for SK-V15 admission, where native aarch64 is the anchor. asmjson can seed primitive shapes, not comparator-beating strict claims.

Harness-hash rows are a negative antecedent. P1-E marks checksum/harness rows as blocked unless they map to parser machinery (`restart/skinny/tranches/sk-v15/research/p1/p1e-hot-leaf-attribution.md:33`), and normalized rows such as `tinycanada` harness hash are explicitly `blocked_harness_digest` (`restart/skinny/tranches/sk-v15/research/p1/evidence/p1e-normalized-attribution.tsv:22`). No candidate above uses hash/checksum work as a parser primitive.
