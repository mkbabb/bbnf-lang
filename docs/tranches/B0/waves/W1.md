# B0.W1 — Prepared-Binary Discipline + Exact AY Gate Commands

**Opens after**: W0 close
**Agents**: 3 parallel
**Hard gate**: Profiling preparation is reusable, and the exact public commands for AY.W5-W7 expand/asm/bench/Samply gates exist as first-class entrypoints.
**Status**: planned

## Scope

1. Add prepared-binary discipline for profiling and bench proof loops.
2. Capture the exact command paths AY will use for `cargo expand`,
   `cargo asm`, bench, and Samply proof.
3. Prove lower profiling-prep cost against baseline.

## Phase sub-items

### B0.W1.1 Profile split discipline

Mechanism: define and expose distinct routine, profiling-prep, and
final-proof profiles with explicit tradeoffs.

Files touched: `Cargo.toml`, `.cargo/config.toml`.

Sub-gate: all three paths compile and are selectable.

### B0.W1.2 Prepared-binary workflow

Mechanism: make profiling and heavy bench proof loops reuse prepared
binaries instead of rebuilding unnecessarily.

Files touched: `scripts/prepare-profile-wave.sh`,
`scripts/prebuild-benches.sh`, `docs/instructions/PROFILING.md`.

Sub-gate: profiling-prep can be run once and reused across captures.

### B0.W1.3 Exact AY gate commands

Mechanism: publish the exact command paths for AY `W5-W7` expand, asm,
bench, and Samply gates so those waves do not improvise their proof
surface mid-execution.

Files touched: `Makefile`, `docs/instructions/PROFILING.md`.

Sub-gate: the AY gate commands exist as public documented entrypoints.
