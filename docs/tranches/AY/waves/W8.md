# AY.W8 — Document-Parallel Fork (Amortisation Multiplier)

**Opens after**: W6 close (per A7 proposed chain)
**Agents**: 2 parallel (fork heuristic + consumer bench)
**Hard gate**: `ParseOptions::parallel_threshold` heuristic lands; tailwind CSS parallel fork delivers ≥ 1.5× over single-thread baseline (matching AW-IV.W4.4 historical); JSON data_xl parallel delivers ≥ 1.3× over W1-post baseline; no regression on sub-threshold inputs; all 14 parity + canonical harnesses + new AY harnesses green.

## Scope

Per A7 verdict: AX.W9 "Document-parallel fork (heuristic `fork_cut_byte`)" demoted from its scheduled position + renamed to AY.W8. Still a legitimate amortisation multiplier for ≥ 1 MB inputs; AW-IV.W4.4 historical data showed tailwind +131% (9 → 37 MB/s). Post-W1 tape inline baseline is different; expected delta recalibrated to ≥ 1.5× (conservative vs historical +131% pre-W1 baseline).

1. **`ParseOptions::parallel_threshold`** — user-configurable threshold (default: 1 MB) for activating the parallel fork. Below threshold: single-thread. Above: fork at heuristic byte-offset.
2. **`fork_cut_byte` heuristic** — identify a structurally-safe fork point in the input. For CSS: next `}` at column 0 (rule boundary). For JSON: next top-level `,` or `]`/`}` at depth 1. For Sheets/BBNF: typically no parallel gain (inputs too small); gate off.
3. **Fork machinery**: split input at cut byte, parse both halves on `rayon::join` or `std::thread::scope`, merge resulting Tapes via Column concatenation + offset shift.
4. **Tape merge correctness**: `sib_skip` + `child_off` + `span_hi` back-patches on the boundary record must preserve post-merge invariants. Reuse W1's fused back-patch helpers.
5. **Consumer bench**: tailwind CSS + canada/data_xl JSON entries gain `_parallel` variants in existing bench files.

## Phase sub-items

### AY.W8.1 fork_cut_byte heuristic (parallel agent A)

Mechanism:
- For CSS: SIMD scan for `\n}` sequences; pick closest to `input.len() / 2`. If none found, fall back to single-thread.
- For JSON: depth-1 structural scan; pick closest top-level separator. Relies on W1.3's structural-alphabet pre-pass (cheap first-pass depth computation).
- Return `Option<usize>`; None → single-thread.

Files: `crates/core/src/runtime/parallel.rs` (new).

**Sub-gate**: cut-byte heuristic unit tests: 10 fixtures × cut-byte correctness (split halves are independently parseable).

### AY.W8.2 Fork + merge (parallel agent A, same scope)

Given valid cut byte:
- `rayon::join` to parse halves on independent threads.
- Each half produces a Tape (Columns + finaliser-fused back-patches from W1).
- Merge via `columns.concat_with_shift(other, cut_byte, tape_offset_b)` — concatenate column arrays + shift `span_lo`/`span_hi` in the second half by `cut_byte` + shift `sib_skip`/`child_off` by `tape_offset_b`.
- Verify post-merge tape equivalent to single-thread parse of full input.

**Sub-gate**: `parallel_parity.rs` asserts parallel(input) == single(input) across 10 fixtures (5 CSS + 5 JSON).

### AY.W8.3 Consumer bench entries (parallel agent B)

Add `tailwind_parallel` + `canada_parallel` + `data_xl_parallel` variants to existing bench files. Measure vs single-thread baselines.

**Sub-gate**: `cargo bench -p bbnf --bench css_l4 -- tailwind_parallel` delivers ≥ 1.5× speedup over `tailwind` baseline; JSON canada/data_xl ≥ 1.3×.

### AY.W8.4 Parallel parity test (parallel agent B, same scope)

`crates/core/tests/parallel_parity.rs` asserts for each of 10 fixtures: `parallel_parse(input) == single_parse(input)` at tape-column equality. 10 fixtures include 5 CSS (normalize, bootstrap, tailwind, bootstrap×2-repeated, synthetic-large) + 5 JSON (data, twitter, citm, canada, data_xl).

**Sub-gate**: all 10 assertions green.
