PURPOSE
-------

Per AZ-III invariant 7 ("no silent fallback"), the projection CSP must
not collapse under-determined `IrNode::Ref(rid)` resolutions into
`TypeDesc::BoxedEnum` silently. Two production sites swallowed those
resolutions before the W3a wave:

  1. `crates/ir/src/passes/types/constraint/reference.rs:74` — compound
     Ref collapse (this scope).
  2. `crates/ir/src/passes/types/constraint/revise.rs:123` —
     heterogeneous Alt join (W3a.3 scope; not touched by W3a.2).

W3a.2 replaces the line-74 fallback with a NAMED obligation
(`TypeObligation::UnresolvedCompoundRef`) and extends the cycle-break
pathway in `crates/ir/src/passes/types/mod.rs` so cyclic rule grounds
also surface a NAMED obligation.

W3a.3 will append heterogeneous Alt findings to this file when the
revise-line-123 site is replaced.

================================================================
BEFORE (silent fallback @ reference.rs:74)
================================================================

  // crates/ir/src/passes/types/constraint/reference.rs

  let result = {
      let rule_slot = &vars[self.rule_var as usize].domain.solved;
      match rule_slot {
          // Target rule not solved yet — wait for the next pass.
          None => return Revision::Unchanged,
          Some(ty) if is_scalar_projectable(ty) => ty.clone(),
          Some(_) => TypeDesc::BoxedEnum,        // SILENT FALLBACK
      }
  };

The compound-Ref case discarded the structural type information
entirely. The cycle-break path in `mod.rs` similarly grounded
unsolved rule vars to `BoxedEnum` without recording why or where:

  // crates/ir/src/passes/types/mod.rs (pre-W3a.2)
  for var in unsolved_rule_vars {
      system.csp.variables[var as usize].domain.solved =
          Some(TypeDesc::BoxedEnum);              // SILENT GROUND
  }

Existing failure mode (lattice test `cyclic_ref_defaults_to_boxed_enum`):
both sides of `a = b ; b = a` collapse to `BoxedEnum` with no audit
trail; downstream registry / codegen / debug consumers see an opaque
tagged-union wrapper and cannot distinguish a cyclic compound from a
deliberately compound rule.

================================================================
AFTER (named obligation @ reference.rs:117 + mod.rs cycle-break)
================================================================

  // crates/ir/src/passes/types/constraint/reference.rs

  let (result, obligation) = {
      let rule_slot = &vars[self.rule_var as usize].domain.solved;
      match rule_slot {
          None => return Revision::Unchanged,
          Some(ty) if is_scalar_projectable(ty) => (ty.clone(), None),
          Some(structural) => {
              let obligation = TypeObligation::UnresolvedCompoundRef {
                  ref_node: Some(self.ref_node),
                  target_rule: self.target_rule,
                  structural_type: structural.clone(),
                  cyclic: false,
              };
              (TypeDesc::BoxedEnum, Some(obligation))
          }
      }
  };
  if let Some(o) = obligation {
      self.sink.record(o);
  }

The constraint still ASSIGNS `BoxedEnum` (the grammar-general layout
for tagged-union codegen) but the assignment is paired with a NAMED
obligation that records the underlying structural type. The
obligation lands in `GrammarIR::type_obligations` after solver
propagation converges.

The cycle-break path in `mod.rs` walks every Ref into the cyclic rule
(via the new `refs_per_rule` reverse map) and emits one
`UnresolvedCompoundRef { cyclic: true, .. }` obligation per Ref site;
rules with no incoming Refs still record one obligation against the
ground site so the obligation list remains exhaustive.

NOTE ON COEXISTENCE
-------------------
W3a.2 (above) and W3a.3 (this segment) authored their type-obligation
substrates in independent sibling worktrees per the dispatch
contract. Both extended `GrammarIR::type_obligations` and both
authored `crates/ir/src/passes/types/obligation.rs`. The two
`TypeObligation` shapes are distinct (`UnresolvedCompoundRef` vs
`HeterogeneousAltJoin`) and sit on disjoint constraint sites
(`reference.rs:74` vs `revise.rs:123`). Final integration merges the
two obligation enums into a unified variant family; this segment
documents the W3a.3 lane verbatim.

MECHANISM
---------

Replaced the silent `TypeDesc::BoxedEnum` fallback at
`crates/ir/src/passes/types/constraint/revise.rs:123` with a typed
named-obligation lift:

  TypeDesc::HeterogeneousAltJoin(dedup_branch_types(branch_types))

The lift:
  1. Adds `TypeDesc::HeterogeneousAltJoin(Vec<TypeDesc>)` — a new
     variant carrying the deduplicated set of distinct branch types
     observed at join time, in first-appearance order. This IS the
     named obligation in `ir.types`.
  2. Adds `GrammarIR::type_obligations: Vec<TypeObligation>` — the
     diagnostic stream populated post-CSP by walking every Alt node
     whose projected type is `HeterogeneousAltJoin(_)`.
  3. Adds `crates/ir/src/passes/types/obligation.rs` — a new module
     defining `TypeObligation::HeterogeneousAltJoin { rule, node,
     branches }` and `dedup_branch_types`.

Codegen continuity: `TypeDesc::HeterogeneousAltJoin(_)` lowers
identically to `TypeDesc::BoxedEnum` (same `Box<Enum>` view) at
every backend match site. Only the typed surface changes; the
runtime contract is invariant.
