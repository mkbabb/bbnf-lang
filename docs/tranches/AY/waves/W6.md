# AY.W6 — Consumer Unification + General Direct-to-Struct + Pratt Lowering

**Opens after**: W5 close
**Agents**: 3 parallel
**Hard gate**: `view()`, `to_value()`, and `get()` all read the same substrate; grammar-derived direct-to-struct and Pratt/operator lowering fire on production consumers; hot JSON lookup no longer pays generic child-walk cost.

## Scope

1. Move the first-class runtime consumers onto the canonical packed
   substrate with no intermediate rebuild step.
2. Land grammar-derived direct-to-struct admission and storage as a
   general mechanism driven by type inference and projection facts.
3. Land grammar-derived Pratt/operator lowering and object/key
   navigation improvements on that same substrate, including the real
   lazy lookup lane for `bbnf_get_twitter` rather than a synthetic or
   deferred closeout decision.

## Phase sub-items

### AY.W6.1 Unified runtime consumers

Mechanism: change `view()`, `to_value()`, and path lookup so they read
packed nodes directly. Remove or carve any remaining intermediate
rebuild logic in the production consumer path.

Files touched: `crates/core/src/runtime/parsed.rs`,
`crates/core/src/runtime/path.rs`,
`crates/core/src/backend/rust/view/mod.rs`,
`crates/core/src/backend/rust/view/value.rs`.

Sub-gate: `cargo test -p bbnf --test value_api_apples_to_apples --profile ax-iter`
passes with all three consumer surfaces reading the same substrate.

### AY.W6.2 General direct-to-struct

Mechanism: derive projection admission from grammar/type/projection
facts, emit storage for admitted layouts, and project them directly
from the canonical substrate without manual grammar routing.

Files touched: `crates/core/src/backend/rust/emitter/grammar.rs`,
`crates/core/src/backend/rust/emitter/shapes/value_materialize.rs`,
`crates/core/tests/named_type_preservation.rs`.

Sub-gate: `cargo expand -p bbnf --test named_type_preservation` shows
admitted direct-to-struct surfaces emitted from grammar-derived facts.

### AY.W6.3 Pratt lowering and object navigation

Mechanism: emit general Pratt/operator-shape lowering and explicit
object/key navigation metadata so hot lookups use packed run metadata
instead of generic child iteration. This sub-phase explicitly owns the
real lazy lookup lane: `bbnf_get_twitter` must run through substrate
navigation metadata on the production path, or the lazy lane is removed
as a first-class claim.

Files touched: `crates/core/src/backend/rust/emitter/shapes/pratt.rs`,
`crates/core/src/backend/rust/emitter/shapes/compound.rs`,
`crates/core/src/runtime/path.rs`,
`crates/core/tests/value_api_apples_to_apples.rs`.

Sub-gate: eager JSON path lookup profiles no longer show generic child
iteration as a top hot-path cost.

## Archaeology

- W2 and W3 already proved that named preservation and the value surface
  can be grammar-derived; W6 closes the remaining gap by making those
  surfaces consume the canonical substrate directly instead of
  reconstructing after parse.
- Pratt flattening was repeatedly treated as a localized optimization;
  this wave treats it as a grammar-derived lowering mechanism.
