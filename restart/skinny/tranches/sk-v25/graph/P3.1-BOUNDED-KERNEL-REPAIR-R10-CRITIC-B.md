## Verdict

R10 has useful implementation progress: the budgetless public component-member
entrypoint is gone, the credited component-member callers transfer their
caller-owned budget, SCC and cycle use the streaming JSON primitive, cycle
generation uses packed adjacency and exact-capacity witness/path/frame vectors,
and the frozen Apple ARM gates are green.

Those facts do not meet the binding clean bar. The JSON admission token can be
replayed without another budget charge; the component-member oracle required by
T3 is absent; the late cycle oracle was immediately green and therefore has no
born-RED credit; the rank-three allocator test derives its prefix, reservation,
and expected allocator result from production; and validation/complement cycle
allocations still omit cloned payloads and tree nodes expressly named by T4.

Finding total: **5 HIGH**. Clean decision: **NO / NOT CLEAN**.

## Findings

### B1 — HIGH — `JsonAdmission` is a replayable capacity-minting token

- **Binding contract:** R9 requires that no admission token mint independent
  capacity; a token must borrow proof from the same budget charge and be
  unconstructible outside the admitting function
  (`P3.1-BOUNDED-KERNEL-REPAIR-R9-ADJUDICATION.md:309-311`).
- **Exact source evidence:** `JsonAdmission` stores the value and preflight
  totals but no budget borrow, operation kind, or consumed state
  (`xtask/src/architecture/hash.rs:635-642,694-701`). Both `measure(&self)` and
  `stream_hash(&self, ...)` are repeatable shared-reference methods
  (`hash.rs:747-785`). `admit_json` charges the one-measure constant while
  `admit_json_hash` charges the two-pass hash constant
  (`hash.rs:17-26,649-664`), yet either function returns the same token type.
- **Concrete bypass:** crate code can obtain a token from `admit_json`, call
  `measure` repeatedly, or call `stream_hash` after that lower-cost admission;
  none of those later passes receives the caller budget. Private fields prevent
  external construction, but `pub(crate)` methods make replay available across
  the crate. Current reviewed callsites happen to be disciplined; the API does
  not enforce that discipline.
- **Consequence:** T3's one-budget invariant is not a type or state invariant.
  A new credited callsite can silently perform uncharged scans/hashes, and the
  token itself violates the explicit R9 condition.
- **Disposition:** **REPAIR.** Encapsulate the complete admitted operation or
  make admission kind-specific and single-use while tying execution to the same
  caller-owned budget proof. Repeated measure/hash work must require a fresh
  charge.

### B2 — HIGH — the required component-member short/long and exact-boundary proof is missing

- **Binding contract:** T3 requires short/long same-cardinality and exact
  one-below tests for component-member identity validation, with long work
  strictly exceeding short work and zero phase work at one below
  (`P3.1-BOUNDED-KERNEL-REPAIR-R9-ADJUDICATION.md:296-307`).
- **Exact test evidence:** the SCC test compares short and long only through
  `scc_serialization_work_for_test` (`xtask/tests/architecture/project/scc.rs:221-250`).
  Its component-member section constructs only the long component, asks the
  production helper to execute with `usize::MAX`, takes the returned work as the
  boundary, and checks only `member_work - 1`
  (`xtask/tests/architecture/project/scc.rs:252-275`). There is no short
  component-member run, no `long > short` assertion, no independently stated
  exact value, and no exact-limit success assertion.
- **Same-authority problem:** the helper merely creates a budget, calls the same
  production `validate_members`, and returns `budget.used()`
  (`xtask/src/architecture/project/scc.rs:573-584`). It measures the
  implementation under test instead of supplying the missing test-owned
  boundary.
- **Retained implementation credit:** `validate_members` is now `pub(crate)`,
  requires `&mut ProjectionBudget`, and uses `hash_serialized_budgeted`
  (`xtask/src/architecture/project/scc.rs:163-182`). The cluster and validator
  callsites transfer their existing budget
  (`xtask/src/architecture/project/cluster.rs:643-647`;
  `xtask/src/architecture/evidence/validate.rs:778-784`), as do the cycle
  callsites. This repairs the call graph but does not supply the commanded
  adversarial proof.
- **Disposition:** **REPAIR EVIDENCE.** Add a genuinely test-owned
  same-cardinality short/long component-member oracle, exact-limit success, and
  one-below independent phase observations. Do not derive the expected limit by
  first running the implementation under an unlimited budget.

### B3 — HIGH — the late CycleDomain/CycleMemberHash test cannot receive born-RED repair credit

- **Binding contract:** T3 is explicitly “born RED first” for cycle domain and
  cycle member hash as well as SCC and component member identity
  (`P3.1-BOUNDED-KERNEL-REPAIR-R9-ADJUDICATION.md:296-301`).
- **Receipt evidence:** the author receipt honestly states that
  `cycle_domain_and_member_hash_work_are_content_sensitive_before_source_scans`
  was added after the production repair and passed immediately before any
  further production edit
  (`P3.1-BOUNDED-KERNEL-REPAIR-AUTHOR-R10.md:125-141`).
- **Exact test/source evidence:** that test obtains short/long domain work from
  `cycle_domain_work_for_test` and member prefixes from
  `cycle_validation_work_prefixes_for_test`
  (`xtask/tests/architecture/project/cycle.rs:455-501`). Those helpers reproduce
  production admission and call production `EdgeDomain::checked`,
  `admit_member_hash`, `validate_members`, and `charge_linear_work`
  (`xtask/src/architecture/project/cycle.rs:1021-1079`).
- **Consequence:** the test is useful regression coverage, and its one-below
  observations are green, but it proved no pre-repair defect and cannot satisfy
  the adjudicated born-RED condition. Immediate green is evidence that the test
  observes the already-written implementation; it is not a substitute for the
  required counterexample-first transition. R10 therefore cannot be declared
  clean on the binding record.
- **Disposition:** **NO R10 CLEAN CREDIT.** Preserve the regression test. A
  successor must add an independently derived, genuinely failing T3
  counterexample before any corresponding repair, or an adjudicator must
  explicitly amend the contract; the author receipt cannot retroactively turn
  this green test into RED evidence.

### B4 — HIGH — the claimed independent rank-three allocator oracle is production-derived

- **Binding contract:** T4 requires a one-below byte limit from an
  independently derived reservation, an exact-limit pass with a fresh prefix,
  and independent allocator deltas rather than production markers
  (`P3.1-BOUNDED-KERNEL-REPAIR-R9-ADJUDICATION.md:313-332`).
- **Exact test evidence:** the rank-three sparse fixture obtains its prefix from
  `cycle_basis_prefix_bytes_for_test`, reservation from
  `cycle_basis_storage_bytes_for_test`, and expected retained/peak values from
  `cycle_basis_observed_storage_for_test`
  (`xtask/tests/architecture/project/cycle.rs:644-693`). All three are production
  reexports (`xtask/src/architecture/mod.rs:51-55`).
- **Exact production evidence:** the reservation helper directly returns
  `basis_search_storage_bytes` (`xtask/src/architecture/project/cycle.rs:917-961`).
  The “observed” expected values are another production arithmetic function
  over the same layout types (`cycle.rs:965-1004`). The prefix helper executes
  production domain/rank admission and returns the production budget's reserved
  bytes (`cycle.rs:1008-1016`).
- **Why the real allocator counter is insufficient:** the counter at
  `xtask/tests/architecture/project/cycle.rs:53-73` does observe actual heap
  deltas, which is retained credit. But the values compared with those deltas
  are supplied by the implementation being proved. A common omission or
  mistaken layout assumption in production reservation and production expected
  storage can keep the test green. The assertion that `bytes_reserved()` equals
  `prefix + reservation` only proves self-consistency of those same formulas.
- **Additional masking:** production reserves `target + 1` GF(2) row slots
  (`xtask/src/architecture/project/cycle.rs:925-940`), while the production
  expected-peak helper computes only `max(retained, packed_transient)` and does
  not add a transient candidate row to already retained rows
  (`cycle.rs:974-1003`). The chosen fixture can still pass because witness
  payloads dominate that one-row delta; it is not a general exact-peak oracle.
- **Disposition:** **REPAIR EVIDENCE.** Keep the actual allocator observer and
  fixture, but derive prefix, reservation, retained storage, and peak storage in
  test code from an independent allocation census. Include a shape where a
  rejected/transient GF(2) candidate determines peak so the extra-row term
  cannot be masked.

### B5 — HIGH — cycle validation and complement allocations omit the payloads and tree nodes named by T4

- **Binding contract:** T4 expressly requires accounting for linear-row,
  path/frame, cloned identity payload, and retained tree-node storage
  (`P3.1-BOUNDED-KERNEL-REPAIR-R9-ADJUDICATION.md:321-328`).
- **Exact source evidence:** `validate_basis_domain` performs its named linear
  reservation and then validates every witness
  (`xtask/src/architecture/project/cycle.rs:421-448`). `validate_witness` creates
  a fresh `BTreeSet` and inserts each edge identity, then clones the first source
  and every target `Identity` (`cycle.rs:460-480`). Those operations allocate
  tree nodes and cloned string payloads.
- **Reservation mismatch:** `charge_linear_work` reserves boxed GF(2) row bytes,
  pivot slots, and only `size_of::<EdgeIdentity>()` per witness edge
  (`cycle.rs:788-854`). It reserves neither the `BTreeSet` nodes nor the cloned
  endpoint `Identity` payloads. Its work term counts witness edges, not their
  byte lengths, so repeated long endpoints also receive no replay-sensitive
  clone/comparison work derivation.
- **Complement path:** `complement_basis` allocates an exact-capacity outer
  witness vector and clones accepted `CycleWitness` values
  (`cycle.rs:288-320`). The preceding linear reservation has no
  `Vec<CycleWitness>` output term and no cloned `EdgeIdentity` string-payload
  term. Aggregate domain reservations are not an exact phase-owned derivation
  and cannot be treated as unexplained slack under T4.
- **Scope consequence:** the generation path's packed adjacency, exact witness
  capacity, path/frame/visited vectors, boxed rows, and accepted-only witness-ID
  clones are credible local improvements
  (`cycle.rs:497-560,563-611,678-707,917-950`). They do not close every credited
  SCC/cycle allocation because validation and complement remain uncovered.
- **Disposition:** **REPAIR.** Remove the per-witness tree allocation through an
  indexed/bitset duplicate check or account its real rounded nodes; avoid or
  byte-account endpoint clones; and independently reserve complement outer,
  edge-ID, and payload allocations before any clone. Add allocator-observed
  long-payload and rejected-candidate fixtures.

## Retained credit, routed remainder, and tranche fit

Retained narrow credit:

1. One caller-owned `ProjectionBudget` reaches the reviewed component-member
   generation/validation paths, including cluster; the old public budgetless
   method is removed.
2. SCC/cycle serializer and member-hash phases now charge byte-sensitive JSON
   preflight before their observed source scans, and the reviewed one-below
   tests remain useful regression coverage.
3. Cycle generation uses packed adjacency, checked exact capacities for the
   visible search vectors, boxed GF(2) rows, checked arithmetic, accepted-only
   witness-ID cloning, and retained directed-rank/witness semantics.
4. Scope hashes are exact, the authorized `fact.rs` seam and restored sentinel
   are intact, and R10 makes no global or movement claim.

Routed and uncredited exactly as T5 commands: outer manifest/inventory/binding
and graph-wide resource closure; sibling serializers outside the named phases;
global RSS, exporter, controller, live-root, full-order, and final-recensus
campaigns; parser, parse-that, Value, product/backend/UI, x86, and movement work.

Total tranche/wave/KISS decision: **NOT CLEAN.** The core implementation is
smaller and more explicit than R9, but proof authority is inverted where tests
reexport production sizing/allocator formulas, and the replayable admission
token makes the one-budget rule conventional rather than enforced. The KISS
repair is to encapsulate admitted execution and keep expected boundaries in
independent test code, then close the explicitly omitted validation/complement
allocations. No global green, foundation closure, wave movement, or total
architecture claim follows from R10.
