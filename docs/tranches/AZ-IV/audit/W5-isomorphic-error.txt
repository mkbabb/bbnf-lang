Coverage notes
--------------
1. `unknown_field_at_entry_rule_rust_and_ts_match` — drives both surfaces
   with `$.nope` against a JSON-fixture `Document` rule. Asserts identical
   `(reason, segment_index, segment_str, struct_name, alternatives_set)`
   tuples. Top-level case avoids the deeper `Named(_)` descent asymmetry
   documented inline (see file).

2. `index_into_scalar_rust_and_ts_match` — drives `$.id[0]` against the
   same fixture. `Document.id : F64`; both surfaces classify the second
   step as `FieldOnScalar` (the scalar arm fires before the
   non-list-index fall-through in `step_into_type`).

3. `empty_path_rust_and_ts_match` — drives the empty-path/empty-string
   case. Rust returns `PathErrorReason::EmptyPath` from
   `check_path_against_registry`; the cdylib returns
   `PathErrorReasonPayload::EmptyPath` from `compile_path_native("", ...)`.
   `segment_index` and `struct_name` agree.

4. `unregistered_grammar_marker_surfaces_unregistered_rule` — TS-only path
   (the proc-macro handles unknown markers at parse time; no canonical
   counterpart). Asserts the cdylib returns `UnregisteredRule` with the
   canonical alternatives list `["Bbnf", "CssL4", "Json", "Sheets"]`.

5. `reason_variants_are_isomorphic` — exhaustive 8-pair mapping coverage.
   Adding a new variant on either side without updating the mirror fails
   the test by virtue of the exhaustive match in `rust_reason_to_payload`.

Known asymmetry (documented in test source)
-------------------------------------------
The deeper case `$.statuses[0].nope` exercises a known divergence between:
- Canonical offline checker (`bbnf::path::type_check`) — leaves
  `TypeDesc::Named(_)` intact at the cursor and surfaces
  `UnregisteredRule` when a follow-up segment needs to descend (the
  strings table that maps `StringId -> RuleId` lives on `GrammarIR`, not
  on the offline checker entry).
- cdylib (`crates/bbnf-path-ts/src/compile.rs`) — resolves `Named(_)`
  eagerly through `StructRegistry::layout(rule_id)` since the fixture
  uses the 1:1 `rule_id == StringId` shortcut.

The two surfaces converge at the IR `path_check` pass (W2.2) and the
proc-macro's IR-resolved walker (`bbnf-path::path_macro`); the present
test pins the surface where both surfaces agree. The deeper alignment is
a downstream concern for the IR pass that holds the strings table.

Wire format (serde, post serde-wasm-bindgen):
  { "segment_index": <usize>,
    "segment_str": <string>,
    "struct_name": <string>,
    "alternatives": [<string>, ...],
    "reason": <"UnknownField" | "UnknownVariant" | "IndexIntoNonList"
             | "FieldOnScalar" | "EmptyPath" | "UnregisteredRule"
             | "AmbiguousVariant" | "WildcardOverflow"> }

The TS-side `PathError` class (crates/bbnf-path-ts/ts/path.ts) presents
this shape through its readonly fields, with `format(payload)` rendering
`path[N] \`<segment>\` on \`<struct>\`: <reason>; valid: [<alts>]` to
match `bbnf::path::PathError`'s `Display` impl.
