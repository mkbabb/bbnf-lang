### Part 1 — Cousin-leak guard migration

The cousin-leak guard prevents a child iterator from walking off
the end of its parent's child range and into the next sibling's
descendants (a "cousin"). Today the guard lives in two places:

- `crates/core/src/lower/expression/...` (post-W3 split; W3
  carried over the old `expression.rs:561-574` guard) — the
  lowering-time `body_hi` filter.
- `crates/core/src/lower/value_expr.rs:351-358` — the value-
  expression-lowering twin.

Both compute the same range bound. The duplication exists
because the guard was added incrementally — first to the
expression lowering, then to value expressions when the
value-side projection began consuming the same shape — and was
never consolidated. Per `feedback_pluggable_components` and the
gestalt directive, the guard belongs at the iterator level: in
`crates/tape/src/cursor.rs::ChildIter` (or, equivalently, in
the finaliser's `sib_skip` computation that `ChildIter` walks).

**Mechanism**:

1. Move the guard logic into `ChildIter`. The iterator already
   knows the parent compound's `child_off` and the parent's
   `sib_skip`; it can compute the "do not cross" boundary
   natively without help from the lowering caller.
2. Delete the two duplicated guard sites in
   `crates/core/src/lower/expression/...` and
   `crates/core/src/lower/value_expr.rs:351-358`.
3. Update lowering callsites that previously passed the
   `body_hi` filter explicitly; they no longer need to.

If the guard is more naturally expressed at finaliser-time
(stamping `sib_skip` precisely), the migration target is
`crates/tape/src/finaliser.rs` instead — the agent picks based
on which site honours the bound with fewer lines and no
duplication. Either site eliminates the lowering-side
duplication, which is W4's actual contract.

LOC: ~25 net-negative (delete two guards, add one).

### Part 2 — Pratt outer's `child_off` override

`crates/core/src/backend/rust/emitter/shapes/pratt.rs:548-551`
performs a post-call surgery: after the Pratt outer's
`begin_compound` / `end_compound` pair returns, the emitter
reaches into the substrate via `columns_mut().set_child_off_at(rec, override_value)`
and overwrites the just-emitted `child_off` with the Pratt-
specific override.

This was load-bearing in the welded substrate because the
Pratt outer needed a `child_off` semantically different from
what `begin_compound` would write — Pratt outers admit a
non-trivial "first child" (the operand at the deepest binding-
power level), and the substrate's default first-child stamp
doesn't match.

W1 retired `columns_mut()` outright. The post-call surgery
must move into `begin_compound`'s call surface as a flag.

**Mechanism**:

1. Introduce a `PRATT_CHILD_OFF_OVERRIDE` flag (or, more
   idiomatically, a `Columns::begin_compound_with_first_child(...)`
   variant — pluggable per `feedback_pluggable_components`) that
   tells `begin_compound` to expect a Pratt-specific
   first-child stamp.
2. `end_compound` honours the flag: when closing, it stamps
   `child_off` per the Pratt-specific override the flag
   carries, not per the default first-push observation.
3. Delete the post-call `set_child_off_at` surgery at
   `pratt.rs:548-551`.

The flag may be a boolean or a value-carrying flag (the override
value itself). The agent picks the cleaner type. The contract:
no post-call surgery; the override rides through `begin_compound`
to `end_compound` natively.

LOC: ~25 net.

## Archaeology

The cousin-leak guard appeared first in expression lowering
during the typed-AST projection work; it appeared again in
value-expression lowering when value projection began consuming
the same compound shapes. The duplication was incremental: each
addition was a local fix that did not see the other. The
substrate's `ChildIter` (and the finaliser's `sib_skip`
stamping) is the architecturally-correct site because it owns
the iteration boundary; the lowering-time `body_hi` filter was
a surface-level approximation.

Pratt's post-call surgery existed for a similar reason: the
welded substrate's `begin_compound` couldn't admit Pratt-
specific override semantics, so the emitter wrote the default
and patched after. With the unified `Columns` post-W1, the
flag-through-begin pattern is reachable; W4 reaches it.
