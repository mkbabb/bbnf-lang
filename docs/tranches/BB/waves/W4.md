# BB.W4 — Slice-Borrow Primary + Escape Hatches

**Thesis** Hereupon the slice-borrow `parse(input: &'i str) -> Result<<G>Value<'i>, ParseErr>` becomes the default surface; `parse_in(input, &bump)` lands as the bumpalo opt-in escape; `parse_owned(input)` lands as the no-borrow opt-in escape; the three are surfaces over the same parse implementation, the lifetime parameter discriminating per Lock 9. **Closer-gate** BB-G8 met; `cargo doc` shows the three surfaces with consistent docstring shape; per-wave generated-LOC budget verified.

## §1 Deliverable

W4 codifies Lock 9's lifetime-escape-hatch discipline (`docs/HARDENING-PLAN-PROMPT.md:50`). The default surface is `&'i str` slices + `Cow<'i, str>` for transformations (lightning-css model per `audit/SOTA-2026-05-03.md:122-123`). Bumpalo arena is opt-in via `parse_in(input, &bump)` (sonic-rs model per `audit/SOTA-2026-05-03.md:42`). Owned (no-borrow) is opt-in via `parse_owned(input)` (serde_json escape per `audit/SOTA-2026-05-03.md:148`).

The three surfaces share one parse implementation. The lifetime parameter is the discriminant: the inner parse fn (per-rule, generated by BB.W1's direct-to-struct codegen) is generic over the lifetime; each surface specialises differently. `parse(input)` returns `<G>Value<'i>` borrowing the input slice; `parse_in(input, &bump)` returns `<G>Value<'bump>` allocated in the user-provided bump arena; `parse_owned(input)` returns `<G>OwnedValue` with all slices interned to `String`.

The signature shape per grammar:

```rust
// Default — slice-borrow primary, lifetime tied to input
pub fn parse<'i>(input: &'i str) -> Result<JsonValue<'i>, ParseErr>;

// Bumpalo opt-in — lifetime tied to caller-provided bump arena
pub fn parse_in<'i>(input: &'i str, bump: &'i bumpalo::Bump) -> Result<JsonValue<'i>, ParseErr>;

// Owned opt-in — no borrow; all slices interned
pub fn parse_owned(input: &str) -> Result<JsonOwnedValue, ParseErr>;
```

The same shape applies to BBNF, CSS L4, Sheets, and the five cohort grammars. For cohort grammars, the templated emission from BB.W2 picks up the three signatures uniformly; for specialised grammars, BB.W1's direct-to-struct codegen emits the three.

The `JsonOwnedValue` type for `parse_owned` is a derived owned-equivalent of `JsonValue<'i>`: every `&'i str` becomes `String`; every borrowed slice becomes owned. The codegen emits the owned type alongside the borrowed type per `audit/RESTART-SKETCH-2026-05-03.md:540-595` direct-to-struct shape.

W4 also lands the documentation surface: per Lane 7 friction-forecast (`docs/HARDENING-PLAN-PROMPT.md:125-139`), the cookbook entry at `docs/cookbook/lifetime-surfaces.md` carries a decision flowchart so grammar authors pick the right surface for their use case. Per-grammar docstrings at the parse fn site cite the cookbook by path:line.

The Visitor surface (`Visitor<'i, T>` + `VisitTypes` bitflag) is OUT OF SCOPE for W4; it lands at W5. W4 confines to the three parse surfaces.

Estimated edit surface: ~120 LOC of new public API per grammar (3 surfaces × 9 grammars = 27 fn signatures + 9 owned types) — net ~+1,080 LOC across `crates/core/src/grammar/generated/`; docstring + cookbook ~+250 LOC. Per BB.md generated-LOC budget table, the W4 specialised-grammar delta is +1% per grammar.

The decision flowchart at `docs/cookbook/lifetime-surfaces.md` expresses the user mental model:

```
          ┌─────────────────────────────────────────────┐
          │  Where will the parsed value be used?       │
          └────────────────────┬────────────────────────┘
                               │
       ┌───────────────────────┼───────────────────────┐
       ▼                       ▼                       ▼
  Same scope as input      Caller-controlled       Outside input scope
  (zero copies)            scope (bumpalo arena)   (owned, no borrow)
       │                       │                       │
       ▼                       ▼                       ▼
   parse(input)             parse_in(input,         parse_owned(input)
                            &bump)
       │                       │                       │
       ▼                       ▼                       ▼
  <G>Value<'i>             <G>Value<'bump>         <G>OwnedValue
```

The friction-forecast verbatim error message at the lifetime-mismatch case lands at M8: when a user writes `let v: JsonValue<'static> = parse(input)?;`, the compiler emits `error: lifetime '<i>' does not match '<static>'; consider parse_owned(input) for owned scope, or parse_in(input, &bump) for caller-controlled bumpalo arena lifetime`. The error message is a `trybuild` test fixture committed at `crates/core/tests/error_messages/lifetime_mismatch.stderr`.

## §10 Implementation reference

The three-surface emit pattern shows the lifetime-discriminant mechanism explicitly:

```rust
// crates/core/src/grammar/generated/<g>.rs (templated; emitted by xtask regen)

// Inner parse fn: generic over 'i and 'a (the value lifetime)
pub(crate) fn parse_inner<'i, 'a>(
    input: &'i str,
    arena: &'a CssArena<'a>,
) -> Result<CssTypedValue<'a>, ParseErr>
where 'i: 'a,
{
    let bytes = input.as_bytes();
    let mut p = 0;
    let mut state = ScanState::new();
    let mut cursor = PathCursor::new(&__EAGER_EMPTY_PATH, |_, _, _| ParseFully);
    parse_root(bytes, &mut p, &mut state, arena, &mut cursor)
}

// Surface 1: default — slice-borrow primary, lifetime ties to input
pub fn parse<'i>(input: &'i str) -> Result<CssTypedValue<'i>, ParseErr> {
    static DEFAULT_ARENA: LazyLock<CssArena<'static>> = LazyLock::new(CssArena::new);
    parse_inner(input, &DEFAULT_ARENA)
}

// Surface 2: bumpalo opt-in — lifetime ties to caller-provided bump arena
pub fn parse_in<'i>(input: &'i str, bump: &'i bumpalo::Bump) -> Result<CssTypedValue<'i>, ParseErr> {
    let arena = CssArena::new_in(bump);
    parse_inner(input, &arena)
}

// Surface 3: owned opt-in — no borrow; all slices interned to String
pub fn parse_owned(input: &str) -> Result<CssOwnedValue, ParseErr> {
    let owned_arena = CssArena::new();
    let borrowed_value = parse_inner(input, &owned_arena)?;
    Ok(borrowed_value.to_owned())
}
```

Per `audit/SOTA-2026-05-03.md:42` (sonic-rs bumpalo pattern) and `audit/SOTA-2026-05-03.md:148` (serde_json owned pattern), the three surfaces are isomorphic to the SOTA references; the lifetime parameter is the discriminant.
