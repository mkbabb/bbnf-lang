# BB.W2 - VM Oracle On Residue

**Name**: W2 - VM Oracle On Residue
**Opens after**: W1 - Ruler CVC Enumerator
**Agents**: 5 parallel
**Hard gate**: `crates/egraph/src/ruler/oracle.rs` runs candidate `L, R` over fixture corpus; byte-compare tape output; per-candidate budget; Tranche H rediscovery ≥ 80% green; oracle rejection rate ≤ 50%
**Status**: planned

## Scope

1. Implement `crates/egraph/src/ruler/oracle.rs`: VM-as-oracle wrapper. Input: two `IrNode` candidates `L`, `R` plus the grammar's fixture corpus. Compile each to existing bytecode (`crates/ir/src/vm/bytecode.rs`); execute under per-candidate time + memory budget; byte-compare tape outputs across the full corpus.
2. Equivalent: byte-equal tape output across the full corpus. Diverges: not equivalent. Timeout: inconclusive (queued for wave-close review; never auto-shipped).
3. The oracle is narrow: ~1800 LOC at HEAD; W2 neither grows the VM nor revives the deleted token-dispatch walker. Lowering is a restricted subset — only node kinds the enumerator produces.
4. Close the Tranche H rediscovery: `crates/egraph/tests/tranche_h_rediscovery.rs` ≥ 80% green. Named rule list: `factor`, `merge_regex_alts`, `inline_acyclic` (and any other Tranche H hand-coded rules) rediscovered by W1's enumerator + W2's oracle.
5. Per-candidate budget: 100ms wall + 256MB memory. Violations queue as inconclusive.
6. Oracle rejection rate ≤ 50% per wave. Higher rejection indicates alphabet drift; W3 narrows the alphabet before the next pass.
7. Per-wave declared candidates: W2 = 50 CSS + BBNF.

## Triumvirate Dispatch

Dispatch a triumvirate if any of these occurs:

- Tranche H rediscovery is < 80% at W2 close (a soundness or coverage gap; the enumerator + oracle shape is incomplete; root cause must be found before W3 opens);
- the VM's bytecode lowering surface needs an opcode the W1 enumerator produces but the existing VM does not support (scope reveal beyond W2 file bounds);
- the per-candidate budget triggers > 25% inconclusive (the budget is too tight; raising requires triumvirate review of the cost model);
- oracle rejection rate > 50% (alphabet drift; W3 must narrow before opening; if narrowing requires changing W1's enumerator, route to W1-revisit triumvirate);
- a candidate that the e-graph residue check passed (different classes) is byte-equal under the oracle (the residue check is incomplete; substrate bug);
- three diagnostic-loop iterations fail to isolate why a Tranche H rule is not byte-equal under the oracle;
- JSONL transcript quiet >15 minutes;
- first-pass return with no commit and no evidence (after one verbatim redispatch).

## Agent Units

### BB.W2.1 Oracle

- Mechanism: implement `crates/egraph/src/ruler/oracle.rs`. `pub fn validate(l: &IrNode, r: &IrNode, corpus: &Corpus, budget: Budget) -> OracleResult`. Lower L and R to bytecode (consume `crates/ir/src/vm/bytecode.rs`). Execute both against every fixture in the corpus under the per-candidate budget. Byte-compare tape output. Return `OracleResult::{Equivalent, Diverges(fixture_id), Inconclusive(reason)}`.
- Files: `crates/egraph/src/ruler/oracle.rs`, `crates/egraph/src/ruler/mod.rs` (register).
- Sub-gate: oracle compiles; named smoke test passes a known-equivalent pair (`Concat(a, Epsilon) ≡ a`) and a known-diverging pair (`Concat(a, b) ≢ Concat(b, a)`); the result types match.

### BB.W2.2 VM Lowering Surface

- Mechanism: read-only walk of `crates/ir/src/vm/bytecode.rs` to verify W1's enumerator produces only kinds the existing bytecode supports. If a kind is missing, modify-carve to add the lowering arm; do NOT add new opcodes (per BB invariant 2). If the missing kind requires a new opcode, halt and dispatch a triumvirate.
- Files: `crates/ir/src/vm/bytecode.rs` (modify-carve only if needed).
- Sub-gate: lowering surface covers every kind W1's enumerator produces; no new opcodes added; if a new opcode would be required, the wave halts.

### BB.W2.3 Oracle Smoke

- Mechanism: write `crates/egraph/tests/oracle_smoke.rs` covering equivalent / diverging / inconclusive cases. Equivalent: `Concat(a, Epsilon)` and `a` against a 5-fixture corpus. Diverging: `Concat(a, b)` and `Concat(b, a)`. Inconclusive: a hand-constructed pair where one fixture takes > 100ms.
- Files: `crates/egraph/tests/oracle_smoke.rs`.
- Sub-gate: all three cases pass; the inconclusive case is queued (not auto-shipped); named log entry in `docs/tranches/BB/audit/W2-oracle-smoke.txt`.

### BB.W2.4 Tranche H + Budget

- Mechanism: fill `crates/egraph/tests/tranche_h_rediscovery.rs` with the actual rediscovery count. Run the W1 enumerator's full alphabet pass plus the W2 oracle on every candidate; assert ≥ 80% of Tranche H hand-coded rules are rediscovered. Write `crates/egraph/tests/oracle_budget.rs` covering the per-candidate budget enforcement (100ms wall, 256MB memory).
- Files: `crates/egraph/tests/tranche_h_rediscovery.rs`, `crates/egraph/tests/oracle_budget.rs`.
- Sub-gate: Tranche H rediscovery ≥ 80%; budget enforcement test passes; if rediscovery < 80%, the wave halts and dispatches a triumvirate.

### BB.W2.5 Audit Doc

- Mechanism: document the oracle's behaviour, budget, Tranche H rediscovery percentage, and oracle rejection rate. Write `docs/tranches/BB/audit/W2-oracle.md`, `W2-tranche-h.md`, `W2-rejection-rate.txt`.
- Files: `docs/tranches/BB/audit/W2-*`.
- Sub-gate: docs land; `git diff --check` passes.
