# SK-V11 P2-C: Host-Arch ASM/SIMD Esoterica
Pass: S-P2 Research. Cycle: V2.
Date: 2026-05-19.
Scope: aarch64 Apple Silicon instruction inventory mapped to SK-V11 hot leaves.
Output: this file.
P1 hot-leaf antecedents: bounded_plain_string_scan; string_escape_decode; unicode_escape_hex_decode; number_digit_span; ascii_whitespace_skip; container_dispatch; simd_movemask; output_digest_hash.
Lock surface: Lock 1 + Lock 14.

## §1 — Findings (concrete; file:line on bbnf claims, citation on external claims)

1. SK-V11 implementation scope is aarch64 Apple Silicon only. The handoff binds AArch64-only SIMD/ASM as a tranche axis and requires scalar reference, differential/checkasm, same-host microbench, feature gate, and same-wave consumer for each kernel candidate (`restart/skinny/tranches/sk-v11/HANDOFF.md:67-80`). x86 is comparator context only and explicitly out of SK-V11 implementation scope (`restart/skinny/tranches/sk-v11/HANDOFF.md:105-114`, `restart/skinny/tranches/sk-v11/HANDOFF.md:123-134`). P2-C therefore carries no x86 implementation row, fallback plan, or ISA-admission claim.
2. V1 hardening requires P2-C to distinguish row-moving candidates from support inventory, demote cache hints unless fresh behavior evidence ties them to a row-moving P1 hot leaf, fold the strict x4 checkasm caveat, and add scalar/parity/micro-proof/same-wave-consumer/fallback/reject-boundary fields to retained rows (`restart/skinny/tranches/sk-v11/research/p2/hardening/HARDENING-S-P2-V1-CONSOLIDATED.md:12-17`, `restart/skinny/tranches/sk-v11/research/p2/hardening/HARDENING-S-P2-V1-CONSOLIDATED.md:46-56`, `restart/skinny/tranches/sk-v11/research/p2/hardening/HARDENING-S-P2-V1-CONSOLIDATED.md:62-64`).
3. The admitted S-P1 hot leaves for P2 research are exactly the eight header leaves: bounded plain string scan, string escape decode, Unicode escape hex decode, number digit span, ASCII whitespace skip, container dispatch, SIMD movemask, and output digest/hash (`restart/skinny/tranches/sk-v11/research/p1/hardening/HARDENING-S-P1-CONVERGED.md:41-45`). S-P1 also pre-blocks W3/substrate, sidecar/cursor, PMULL/CTZ default rewires, rejected string/materialization families, generic numeric fallback, and object/value-byte carry routes (`restart/skinny/tranches/sk-v11/research/p1/hardening/HARDENING-S-P1-CONVERGED.md:49-52`).
4. NEON TBL/TBX is the primary byte-class esoterica for SK-V11. In-tree AArch64 code already builds a low-6 64-byte table and classifies 16-byte chunks with `vqtbl4q_u8`, equality recheck, and movemask (`skinny/crates/bbnf-simd/src/aarch64/classify_tbl4.rs:7-43`, `skinny/crates/bbnf-simd/src/aarch64/classify_tbl4.rs:74-85`). `match_tiny_plain_string` carries the same shape with a scalar reference, `vqtbl4q_u8`, and low-6 collision constraints (`skinny/crates/bbnf-simd/src/aarch64/match_tiny_plain_string.rs:32-61`, `skinny/crates/bbnf-simd/src/aarch64/match_tiny_plain_string.rs:63-96`, `skinny/crates/bbnf-simd/src/aarch64/match_tiny_plain_string.rs:123-136`). Arm ACLE maps `vqtbl4q_u8` to A64 `TBL` over four 16-byte registers and `vqtbx4q_u8` to `TBX` over the same table width [ACLE-TBL], [ACLE-TBX]. P1 antecedents: bounded_plain_string_scan, ascii_whitespace_skip, container_dispatch, simd_movemask.
5. TBL also anchors the Unicode escape path, but x4 coverage is smoke-only today. `unescape_uxxxx_scalar` is the single-quartet oracle, `unescape_uxxxx_neon` uses a `vqtbl1q_u8` low-nibble LUT plus ASCII range masks, and `unescape_uxxxx_x4_neon` decodes four packed quartets at once (`skinny/crates/bbnf-simd/src/aarch64/unescape_uxxxx.rs:33-47`, `skinny/crates/bbnf-simd/src/aarch64/unescape_uxxxx.rs:58-121`, `skinny/crates/bbnf-simd/src/aarch64/unescape_uxxxx.rs:123-166`). P2-B records that the current x4 targeted input is only a fixed valid packed example, while x1 has broader valid/invalid/alignment coverage; x4 production admission needs invalid-case, alignment, surrogate-policy, caller differential, and strict-mode coverage (`restart/skinny/tranches/sk-v11/research/p2/p2b-dav1d-process.md:124-143`). P1 antecedents: unicode_escape_hex_decode, string_escape_decode.
6. The current string-special primitive is 16-byte NEON compare fan-out, not TBL: it returns terminator, escape, control, and non-ASCII masks against a scalar reference (`skinny/crates/bbnf-simd/src/aarch64/string_block.rs:5-27`, `skinny/crates/bbnf-simd/src/aarch64/string_block.rs:30-72`). `parse-that-regex` uses it in both raw and trusted UTF-8 plain-string scanning (`skinny/crates/parse-that-regex/src/lib.rs:462-507`, `skinny/crates/parse-that-regex/src/lib.rs:546-563`). The full string caller proof is REDRESS-rejected, so any widened special block must be treated as a new micro-proof, not as automatic production (`skinny/REDRESS.md:3150-3170`). P1 antecedents: bounded_plain_string_scan, string_escape_decode.
7. The AArch64 movemask inventory has two in-tree idioms. The shared `aarch64::movemask` uses `vshrn_n_u16`, `vsri_n_u8`, and `vzip1q_u8` before scalar packing (`skinny/crates/bbnf-simd/src/aarch64/movemask.rs:3-25`); `byte_class_from_eq_set_64` uses a pattern mask plus `vaddv_u8` across low/high halves (`skinny/crates/bbnf-simd/src/aarch64/byte_class_from_eq_set_64.rs:59-87`). Arm ACLE maps `vaddvq_u8` to A64 `ADDV`, and `vcntq_u8` to A64 `CNT` [ACLE-ADDV], [ACLE-CNT]. P1 antecedent: simd_movemask.
8. UDOT/DotProd is present as an AArch64-only digit microkernel. `parse_4_digits` gates on `target_feature = "dotprod"` and otherwise uses scalar multiply/add (`skinny/crates/bbnf-simd/src/aarch64/digit_mac.rs:4-23`); `parse_4_digits_dotprod` emits inline `udot` under `#[target_feature(enable = "dotprod")]` (`skinny/crates/bbnf-simd/src/aarch64/digit_mac.rs:25-49`). `parse-that-regex` currently scans number digits with SWAR 8/4/2-byte blocks and scalar tail accumulation (`skinny/crates/parse-that-regex/src/number/mod.rs:105-162`, `skinny/crates/parse-that-regex/src/number/mod.rs:164-223`). Arm ACLE maps `vdotq_u32` to A64 `UDOT` [ACLE-UDOT]. P1 antecedent: number_digit_span.
9. CSSC `CTZ` and PMULL are support inventory, not default hot bodies. Current AArch64 `bitmap_next_set_bit_neon` delegates to the scalar oracle (`skinny/crates/bbnf-simd/src/aarch64/bitmap_next_set_bit.rs:1-4`), whose behavior is `mask >> cursor` plus `trailing_zeros` (`skinny/crates/bbnf-simd/src/scalar/bitmap_next_set_bit.rs:1-13`), and REDRESS 89 rejects replacing the production next-bit/bulk consumer path despite green correctness and explicit `ctz` asm proof (`skinny/REDRESS.md:2542-2585`). Current AArch64 `bitmap_prefix_xor_64_neon` delegates to the scalar shift/XOR prefix oracle (`skinny/crates/bbnf-simd/src/aarch64/bitmap_prefix_xor_64.rs:1-4`, `skinny/crates/bbnf-simd/src/scalar/bitmap_prefix_xor_64.rs:1-14`), and REDRESS 88 rejects PMULL as the default hot body after parse benchmark regressions (`skinny/REDRESS.md:2508-2540`). Arm ACLE maps `vmull_p64` to A64 `PMULL` [ACLE-PMULL]. Any non-official CTZ reference is inventory-only orientation, not an admission source. P1 antecedents if later proven by a non-reopened route: container_dispatch, simd_movemask.
10. SHA3 ternary bitwise (`EOR3`/`BCAX`) and `vextq_u8` are support inventory. Lock 16 allows AArch64 SHA3 ternary bitwise (`restart/locks/LOCKS.md:94-95`), and Arm ACLE maps `veor3q_u8` to A64 `EOR3`, `vbcaxq_u8` to A64 `BCAX`, and `vextq_u8` to A64 `EXT` [ACLE-EOR3], [ACLE-BCAX], [ACLE-VEXT]. `shift_right_one` and `shift_left_one` already splice adjacent 16-byte chunks (`skinny/crates/bbnf-simd/src/aarch64/byte_context.rs:1-11`). None is a row-moving candidate without a same-wave consumer whose P1 hot leaf genuinely needs that support.
11. PRFM/STNP/cache hints are inventory-only in V2. `cache_hints.rs` emits `prfm pldl2strm`, `prfm pstl1strm`, and `stnp` (`skinny/crates/bbnf-simd/src/aarch64/cache_hints.rs:1-33`), but hardening flagged the V1 trace to `output_digest_hash` as over-broad (`restart/skinny/tranches/sk-v11/research/p2/hardening/HARDENING-S-P2-V1-CONSOLIDATED.md:12`, `restart/skinny/tranches/sk-v11/research/p2/hardening/HARDENING-S-P2-V1-CONSOLIDATED.md:64`). The PRFM/STNP references in §5 are non-official mirrors and are retained only as inventory orientation. No cache-hint row may enter S-P3 unless fresh P1 behavior evidence ties it to a row-moving `output_digest_hash` or output-plane writeback hot leaf with a same-wave consumer and no-regression fallback.

## §2 — Candidate primitives (each: shape + scalar-ref status + arch + P1 antecedent)

1. TBL byte-set/classifier.
   Shape: grammar supplies a byte set or table; kernel scans 16-byte or 64-byte windows with `vqtbl4q_u8` low-6 table lookup, equality recheck, optional `TBX` default-preserve extension, and the existing movemask idiom.
   Scalar-ref status: `byte_class_from_eq_set_64_scalar` and `byte_class_from_table_64_scalar` are executable specs (`skinny/crates/bbnf-simd/src/scalar/byte_class_from_eq_set_64.rs:20-38`, `skinny/crates/bbnf-simd/src/scalar/byte_class_from_table_64.rs:1-10`); existing checkasm covers set/table density, alignment, adversarial, and corpus cases (`skinny/crates/bbnf-simd/tests/checkasm_byte_class_from_eq_set_64.rs:1-17`, `skinny/crates/bbnf-simd/tests/checkasm_byte_class_from_eq_set_64.rs:156-180`, `skinny/crates/bbnf-simd/tests/checkasm_byte_class_from_table_64.rs:13-49`).
   Arch: aarch64 NEON TBL/TBX; x86 out of scope.
   P1 antecedents: bounded_plain_string_scan; ascii_whitespace_skip; container_dispatch; simd_movemask.
   Same-wave consumer: one generated direct/typed or parse-that Layer-1 byte-set consumer, such as whitespace skip or bounded string special scanning, must consume the mask in the same wave and move or protect a named P1 residual row. A standalone classifier lift is proof-only.
   Fallback: scalar byte-set/table classifier; low-6 table users must prove collision-free generation or fall back to scalar/TBX/equality-recheck handling.
   Micro-proof: `BBNF_SIMD_STRICT=1` parity over offsets, alignments, tails, set densities, collision/adversarial cases, JSON and non-JSON byte sets, then a same-host caller microbench.
   Reject boundary: reject if the row becomes FIRST-set/prefix-trie dispatch, structural-position sidecar, class-column substrate, JSON-only policy in `bbnf-simd`, or an x86 implementation task.
2. UDOT digit-span.
   Shape: parse digit runs in 4/8/16-byte chunks by subtracting `b'0'`, validating ASCII digit lanes, then using `UDOT`/DotProd weights for block value or digit-count facts, with scalar tail preserving grammar number policy.
   Scalar-ref status: current `parse_4_digits` has scalar fallback and `parse-that-regex::number::scan_digit_run` is the parser oracle (`skinny/crates/bbnf-simd/src/aarch64/digit_mac.rs:4-23`, `skinny/crates/parse-that-regex/src/number/mod.rs:105-162`).
   Arch: aarch64 `dotprod`, feature-gated; x86 out of scope.
   P1 antecedent: number_digit_span.
   Same-wave consumer: a generated direct/typed number consumer or P2-E `pt_digit_run_span_accumulate`-style Layer-1 consumer must replace a real digit-run hot loop in the same wave; narrow `parse_4_digits` asm visibility is not enough.
   Fallback: scalar multiply/add and existing SWAR/scalar digit scanner when DotProd is absent, when alignment/tail policy falls outside the proven body, or when grammar policy needs full number fallback.
   Micro-proof: strict parity over digit and non-digit boundaries, offsets, alignments, lengths 0 through long runs, overflow/truncation, and representative JSON plus CSS/Sheets/BBNF numeric slices; then a row gate on at most one or two named number-heavy rows.
   Reject boundary: reject if it changes exponent/sign/f64 fallback semantics, tries to revive generic numeric fallback work, lacks DotProd feature gating, or cannot show caller-level movement beyond the 4-digit helper.
3. Widened string-special block.
   Shape: widen the existing 16-byte `StringSpecialBlock` to a 64-byte four-lane result, preserving terminator/escape/control/non-ASCII masks and first-interesting extraction; candidate may use compare fan-out, TBL byte-class, shared movemask, and possibly `vextq_u8` for chunk-edge context.
   Scalar-ref status: `scan_string_special_block_scalar` and `sk_v3_intrinsic_parity_aarch64` already cover the 16-byte primitive (`skinny/crates/bbnf-simd/src/aarch64/string_block.rs:30-54`, `skinny/crates/bbnf-simd/tests/checkasm_parity.rs:617-640`); widened form needs its own scalar oracle because REDRESS 106 rejected caller-level proof.
   Arch: aarch64 NEON; x86 out of scope.
   P1 antecedents: bounded_plain_string_scan; string_escape_decode; simd_movemask.
   Same-wave consumer: one narrow generated direct/typed string or key caller must consume the widened result in the same wave. Reusing the previous broad full-string caller proof, or wiring a primitive with no row gate, is proof-only.
   Fallback: current 16-byte scalar/NEON block or scalar byte loop on short tails, boundary uncertainty, non-UTF-8 mode differences, or feature unavailability.
   Micro-proof: strict parity against a new 64-byte scalar oracle over quote offsets, escapes, control bytes, non-ASCII, mixed boundaries, all alignments, and representative string-heavy JSON/non-JSON slices; then same-host caller microbench with no guard-row regression.
   Reject boundary: reject if it reopens REDRESS 61/62/83/106, adds retained decoded scratch or sidecar state, claims production from primitive parity alone, or broadens into a generic string materialization route.
4. x4 escape hex decode, proof-gated only.
   Shape: decode four consecutive `\uXXXX`-shaped hex quartets into four code units; caller-owned per-grammar policy joins surrogate pairs and emits segments/chars. This is not a fixed JSON production primitive.
   Scalar-ref status: `unescape_uxxxx_scalar`, `decode_unicode_escape`, and `read_hex_unit_scalar` define x1 semantics (`skinny/crates/bbnf-simd/src/aarch64/unescape_uxxxx.rs:33-56`, `skinny/crates/parse-that-regex/src/lib.rs:302-344`, `skinny/crates/parse-that-regex/src/lib.rs:919-965`), but x4 requires a new scalar x4 oracle that calls x1 four times and preserves valid/invalid/mixed-lane semantics.
   Arch: aarch64 NEON TBL; x86 out of scope.
   P1 antecedents: unicode_escape_hex_decode; string_escape_decode.
   Same-wave consumer: production requires a real new generated direct/typed escaped-segment caller or equivalent source delta. The already-consuming `unescape_string` route and cosmetic wrappers are explicitly insufficient.
   Fallback: scalar x4 oracle or x1 scalar decode for any invalid lane, mixed-validity pack, surrogate-policy handoff, boundary split, or feature absence.
   Micro-proof: current x4 coverage is smoke only. Add strict x4 parity under `BBNF_SIMD_STRICT=1` for valid, invalid, mixed-validity, alignment 0..63, surrogate-pair, unpaired-surrogate, and boundary/tail cases before any caller proof.
   Reject boundary: reject if it claims W8 proof-only work as production, reuses the W9 already-wired path, hard-codes JSON policy into `bbnf-simd`, or lacks a row-moving caller in the same wave.
5. Whitespace byte-set skip.
   Shape: grammar-supplied ASCII whitespace set skip using TBL or compare-fan classify over 16/64-byte windows, with first-non-whitespace extraction through movemask; JSON newline handling and CSS comment trivia remain caller/template policy.
   Scalar-ref status: `skip_ascii_whitespace` and `skip_ascii_spaces` are the current parser refs (`skinny/crates/parse-that-regex/src/lib.rs:112-147`); `byte_class_from_table_64_scalar` can serve as the unit oracle for arbitrary byte-set membership (`skinny/crates/bbnf-simd/src/scalar/byte_class_from_table_64.rs:1-10`).
   Arch: aarch64 NEON TBL/compare + movemask; possible `ADDV` all-space test; x86 out of scope.
   P1 antecedent: ascii_whitespace_skip.
   Same-wave consumer: a generated direct whitespace call site or P2-E `pt_byte_set_run_skip`-style Layer-1 primitive must consume the skip in the same wave, with a JSON residual row and a non-JSON layout/trivia proof if the generic path is touched.
   Fallback: scalar byte-set run loop for short spans, tails, non-ASCII, comment-aware CSS trivia, or any grammar whose whitespace policy is broader than byte membership.
   Micro-proof: strict parity over offsets, alignments, tails, empty/short/long spans, all JSON whitespace bytes, CSS/Sheets/BBNF byte sets, and first-non-member extraction; then caller microbench on representative whitespace-heavy rows.
   Reject boundary: reject if it stores whitespace bitmaps/cursors/class lanes, folds comment-aware layout into `bbnf-simd`, or counts byte-set compatibility as Lock 14 proof without a generated non-JSON consumer.

## §3 — Grammar-neutrality (each candidate: JSON-only or CSS/Sheets/BBNF-self generalisable)

1. TBL byte-set/classifier: grammar-neutral when the byte set/table is generated from Grammar IR. JSON structural bytes, CSS delimiter/operator bytes, Sheets formula punctuation, and BBNF-self metasyntax all fit the same byte-set/classifier abstraction. Reject any hardcoded JSON structural role in `bbnf-simd`.
2. UDOT digit-span: grammar-neutral for ASCII decimal digit spans in JSON numbers, CSS numeric tokens, Sheets formula numbers, and BBNF-self numeric/count syntax. It becomes JSON-only if it bakes in JSON exponent/sign policy; those stay in the per-grammar parser.
3. Widened string-special block: generalisable if terminator, escape byte, control limit, and UTF-8 validation mode are parameters. It is JSON-only if fixed to quote/backslash/control<0x20 with JSON flags in the primitive.
4. x4 escape hex decode: fixed `\uXXXX` is not CSS L4 generality. The admissible abstraction is hex-nibble/hex-run decode plus generated per-grammar escape policy. JSON-like and BBNF-self callers may use four fixed quartets; CSS needs a separate variable-width escape template.
5. Whitespace byte-set skip: grammar-neutral for ASCII whitespace sets emitted by each grammar. CSS full whitespace/comment policy, if broader than byte-set skip, must remain a caller/template layer and not enter the generic primitive.
6. Support rows: grammar-neutral only as implementation details under a grammar-neutral candidate. Digest/hash/cache placement is benchmark/output-plane or host-sink behavior, not a generic parser primitive.

## §4 — Risks (REDRESS entries any candidate must NOT re-open)

1. Do not reopen PMULL prefix-XOR or CSSC CTZ as default hot bodies. REDRESS 88 and 89 reject those production-path changes despite correctness/asm proof (`skinny/REDRESS.md:2508-2585`).
2. Do not treat PRFM/STNP/cache hints as candidates without fresh P1 behavior evidence, a same-wave row-moving consumer, identical-output fallback, and no-regression gate. They are inventory-only in V2.
3. Do not route candidates through W3 substrate, class columns, structural vectors, streaming cursors, parser-owned sidecars, or class-lane tape changes. REDRESS 96 and 97 both failed every W3 must-improve row after green correctness checks (`skinny/REDRESS.md:2797-2848`, `skinny/REDRESS.md:2852-2905`), and REDRESS 102 firewall-closed W3 as proof-only with no behavior source or row movement (`skinny/REDRESS.md:3040-3058`).
4. Do not admit parse-only SOTA movement or x86 implementation work. The handoff refuses parse-only SOTA admissions, x86 implementation work, new sidecars, and JSON policy in generic crates (`restart/skinny/tranches/sk-v11/HANDOFF.md:123-142`).
5. Do not repackage the rejected full string primitive proof. REDRESS 106 says the NEON string special block was correct but caller-level aggregate speedup was only `0.774x`, with regressions on `unicode_mixed` and `unicode_basic` (`skinny/REDRESS.md:3152-3170`). A widened block needs new representative micro-proof and a narrower consumer.
6. Do not claim x4 escape production by reusing the W8 proof-only result or adding a cosmetic wrapper. REDRESS 107 admits the x4 escape micro-proof only as proof with no row movement (`skinny/REDRESS.md:3174-3196`); REDRESS 108 rejects the existing production reuse route and says future production reuse needs a new SPEC/CHALLENGE route naming a real source delta (`skinny/REDRESS.md:3200-3222`).
7. Do not convert grammar-neutral byte-set primitives into JSON-only policy. PASS-2 requires grammar-neutral expression for CSS L4, Sheets, or BBNF-self, and candidates that need JSON structural roles must be reframed as grammar-neutral primitives or host functions (`restart/prompts/skinny/PASS-2-RESEARCH.md:102-107`, `restart/prompts/skinny/PASS-2-RESEARCH.md:232-240`).
