## §1 — Deliverable

Hereupon the path-crate triplet consolidates per Lock 7 (per `docs/HARDENING-PLAN-PROMPT.md:46`). The renames are mechanical: `crates/bbnf-path/` → `crates/path/` (proc-macro shell, 918 LOC per `audit/CENSUS-2026-05-03.md:241`); `crates/bbnf-path-ts/` → `crates/path-ts/` (cdylib shell, 1,012 LOC per CENSUS:242). The architectural change is the introduction of `crates/path-core/`: a non-proc-macro shared crate carrying `compile`/`lex`/`lower`/`validate` logic that BOTH `path` (proc-macro) and `path-ts` (cdylib) path-dep on; this eliminates the ~500 LOC mirror between `bbnf-path/src/path_macro.rs` (639 LOC) and `bbnf-path-ts/src/compile.rs` (474 LOC) per `audit/CENSUS-2026-05-03.md:263`. The fourth crate name is forbidden (per Lock 7); only `path` + `path-core` + `path-ts` survive.

The legacy borrowed-alphabet duplication retires. `crates/core/src/runtime/path.rs` (163 LOC, the older `PathSegment<'a> { Field(&'a str), Index(usize) }` per `audit/CENSUS-2026-05-03.md:244`) deletes; consumers consume `crate::path::ir::{Path, PathSegment, IntoPathSegment}` from `crates/core/src/path/` (the typed-path runtime). The four `runtime/{json,bbnf,css_l4,google_sheets}/parse_with.rs` files (~480 LOC across four files per `audit/CENSUS-2026-05-03.md:262`) — each manually lowering the typed alphabet to the legacy alphabet via `let mut legacy: Vec<LegacySegment<'_>> = Vec::with_capacity(path.len()); for owned in path.owned_segments() { legacy.push(lower(&owned.as_borrowed())?); }` — delete; the runtime documents' path-query traits consume the typed alphabet directly. Per `audit/CENSUS-2026-05-03.md:200` the `LegacyPath`/`LegacySegment` types are the duplicate alphabet; merge with typed `path::ir::Path` directly.

The synthetic fixture purge closes the T4 closure. `crates/bbnf-path-ts/src/fixture.rs` (248 LOC synthetic per `audit/CENSUS-2026-05-03.md:148`) and `crates/bbnf-path/src/registry.rs` (201 LOC fixture per CENSUS:147) delete; the workspace already writes `<grammar>.registry.json` sidecar per `audit/MODULES-2026-05-03.md:629`. The renamed `path` and `path-ts` consume the production `pub const REGISTRY: StructRegistry` emitted at xtask-regen time (the workspace already writes the sidecar; W3 connects both frontends to it).

The grammar match arms at `crates/bbnf-path/src/registry.rs:132-135` (per `audit/CENSUS-2026-05-03.md:147`, hardcoded `match grammar { "json" => ..., "css_l4" => ..., "google_sheets" => ..., "bbnf" => ... }`) merge with the workspace metadata table from BA.W1: the macro consumes a `RegistryDescriptor` per grammar, with the registry resolution flowing through the BA.W1 `[workspace.metadata.bbnf-strategy]` schema. Per CENSUS:147 ("the lib.rs doc comment as a W2.5/W4 followup — BA-restart must finish that closure"), W3 closes that long-standing residue.

The Era V failure mode is mitigated because W3's substrate (`path-core`) has the same-wave consumer of both `path` and `path-ts`; the merger of `compile.rs` mirrors lands with both frontends consuming the merged surface. No substrate-without-consumer; the legacy lowering deletions are pure consumer migration to the typed alphabet that already exists.

The 639-LOC `crates/path/src/path_macro.rs` (post-rename from `bbnf-path`) and the 474-LOC `crates/path-ts/src/compile.rs` (post-rename from `bbnf-path-ts`) carry parallel implementations of lex / lower / validate logic per `audit/CENSUS-2026-05-03.md:241-242`. Per `audit/MODULES-2026-05-03.md:241`, "the current file mixes proc-macro IO concerns with grammar registry validation"; the W3 split refactors `path_macro.rs` into `path_macro/{lex,lower,validate,emit}.rs` (per the same module-row split recommendation), with the `lex`, `lower`, `validate` sub-modules then extracted INTO `path-core` as the shared body. Post-W3, `path/src/path_macro.rs` is a thin TokenStream-IO adapter (≤ 200 LOC); `path-ts/src/compile.rs` is a thin JS-binding adapter (≤ 200 LOC); `path-core/src/{lex,lower,validate,compile}.rs` carries the merged 500+ LOC body once.

The path-API surface is preserved across the rename. Per the BA.md §Risks row 3 ("`path-core` is non-breaking (path-dep added); `bbnf-path` and `bbnf-path-ts` continue exporting their public API; the rename on disk is a name change, not an API change"), the proc-macro `pub fn path(input: TokenStream) -> TokenStream` survives unchanged in `crates/path/src/lib.rs`; the cdylib `compile_path` / `execute_path` exports survive unchanged in `crates/path-ts/src/lib.rs`. Downstream callers (e.g., `crates/core/tests/`'s `pointer!["a","b",1]` usage) compile without modification.

The path-API surface has three levels of consumer. Per `audit/MODULES-2026-05-03.md:1057-1059`, the `path/` directory in `crates/core/src/` houses the typed-path executor surface (`PathSegment`, `Path`, `TypedPath<G, T>`, `OwnedPathSegment`, `IntoPathSegment`, `PathError`, `PathSchema`, `PathCursor`, `PathExecutor`, `AscentStrategy`, `select_variant`); the proc-macro at `crates/path/` (post-rename) lifts the path literal at compile time; the cdylib at `crates/path-ts/` (post-rename) executes paths from TS/wasm. All three consume the typed alphabet at `crates/core/src/path/ir.rs` (323 LOC per `audit/MODULES-2026-05-03.md:682`); the legacy borrowed alphabet at `crates/core/src/runtime/path.rs` deletes per W3.M4. After W3, one alphabet — the typed `Path<'a>` from `path/ir.rs` — flows through every consumer.

The W3 splits compose with the BA.W2 layout-lowering rename. Per the BA.md §Carry-tags TO BB row C2 (Layout/LayoutSink canon) and `audit/CENSUS-2026-05-03.md:240-265`, the typed-path schema consumes `bbnf_ir::Layout` (post-rename) for runtime path validation. Pre-W3, the schema check at `crates/core/src/path/type_check.rs:338` (per `audit/MODULES-2026-05-03.md:685`) consumes `bbnf_ir::TypeDesc` and `bbnf_ir::StructLayout`; post-W3, it consumes `bbnf_ir::Layout` (the W2 rename's canonical form).

## §4 — Invariants

§I1. **Lock 7** (`crates/path/` consolidation). Three crate names — `path`, `path-core`, `path-ts` — only. The runtime cursor engine consumes the typed alphabet from `crates/core/src/path/ir.rs`; the legacy borrowed alphabet at `crates/core/src/runtime/path.rs` deletes. §I2. **Lock 13** (no god directories). `crates/path-core/` has 4-6 children (`compile`, `lex`, `lower`, `validate`, `lib.rs`); each carries one cohesive concern; the directory has no >10 children mixing concerns. The 639-LOC `path_macro.rs` (per `audit/MODULES-2026-05-03.md:241`'s split recommendation) splits as part of this consolidation: `path/src/path_macro/{lex,lower,validate,emit}.rs`.

§I3. **No backward compat** (per `feedback_no_backward_compat`). The legacy `LegacyPath`/`LegacySegment` types delete at M4; no transitional alias survives.

§I4. **System cohesion** (per `feedback_system_cohesion`). The new `path-core` crate folds into the existing path-crate triplet topology; no orthogonal subsystem; KISS DRY. The proc-macro and cdylib shells become thin adapters over `path-core`.

§I5. **WASM subcrate pattern** (per `feedback_wasm_subcrate_pattern`). `path-ts` (cdylib for TS/wasm) is the WASM binding, isomorphic to the existing TS-binding pattern; not promoted to the workspace's general path namespace; lives at `crates/path-ts/`.

§I6. **No silent epsilon** (per `feedback_no_silent_epsilon`). The post-W3 path-resolution catch-all panics on unknown grammar ident; the deletion of the hardcoded match arms at `crates/path/src/registry.rs:132-135` does NOT introduce a silent fallback — the metadata-driven lookup explicitly errors on unknown idents.

§I7. **Pluggable components** (per `feedback_pluggable_components`). The `RegistryDescriptor` pattern admits per-grammar registry resolution as a pluggable component; the registry itself is a pluggable surface. Per Lock 7 the proc-macro shell IS the plug-in point, not the `match grammar { ... }` arms.

§I8. **Isomorphic API** (per `feedback_isomorphic_api`). The Rust proc-macro and TS cdylib expose isomorphic public surfaces; per `audit/CENSUS-2026-05-03.md:263`, the existing isomorphism test asserts they stay byte-equivalent. Post-W3, both surfaces consume `path-core` for lex/lower/validate; isomorphism is mechanical (one body, two adapters) rather than verified-by-test.

§I9. **Direct-to-struct approach** (per `feedback_direct_to_struct`). The runtime path types post-W3 consume the typed alphabet directly; per `audit/CENSUS-2026-05-03.md:261`, "the runtime documents' path-query traits should consume the typed alphabet directly". W3 closes that long-standing residue.
