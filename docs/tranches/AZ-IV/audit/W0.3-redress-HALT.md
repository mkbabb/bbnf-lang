## Fourth Surface

**File**: `crates/core/src/lower/expression/mod.rs`
**Function**: `dispatch_expression` (and its predicate gate
`is_single_token_span`) at lines 74–193.

### Mechanism

`dispatch_expression` runs a leaf fast-path before compound
dispatch:

```rust
if is_single_token_span(node) {
    if let Some(leaf) = lower_leaf_by_span_text(node, ctx) {
        return leaf;
    }
}
```

`is_single_token_span` is a span-text predicate: it returns true
when the trimmed span text is a bare identifier, regex literal,
quoted string, or epsilon keyword. It does NOT check whether the
focused compound has structural content the span text fails to
represent.

For the BBNF `grammar = ( grammar_item ?w ) *` rule, every wrapper
compound (Alternation → Concatenation → BinaryFactor → MappedFactor
→ Factor → Term) has the SAME `byte_span()` aggregating only the
`"grammar_item"` Span descendant — because the canonical generated
parser pushes Unit leaves (no source) for the inner `?w` modifier
and the outer `*` modifier and consumes group delimiters without
Span pushes. So `is_single_token_span(Alternation)` returns true
(the trimmed span "grammar_item" matches the bare-identifier
pattern), `lower_leaf_by_span_text` resolves the identifier to
`Ref(grammar_item)`, and the leaf fast-path returns immediately
without invoking `lower_alternation` / `lower_concatenation` /
`lower_binary_factor` / `lower_mapped_factor` / `lower_factor` at
all. Result: the IR for the `grammar` rule is `Ref(#51 grammar_item)`
instead of `Repeat(0, MAX, OptionalWhitespace(Ref(grammar_item)))`,
and the freshly-emitted `BbnfBootstrap::parse` cannot round-trip
its own grammar source past byte 36 (the second comment line — the
single-shot dispatcher consumes one grammar_item then bails).

### Defect class

This is the SAME class of bug as the original triad — predicate-driven
detection (`is_single_token_span` is a span-prefix / span-shape
predicate) silently bypassing structural lowering when the predicate
matches a degenerate source-text shape. Per the dispatch packet:

> Replace each predicate with structural detection (positional /
> compound_kind enumeration; source-gap fallback where unavoidable)
> and PANIC on unmatched annotations rather than skip silently.

The triad files were the listed surface; `expression/mod.rs` is the
adjacent dispatcher whose pre-dispatch predicate filter inherits the
same defect class.

## Triad Work Landed

The redress lane HAS landed structural-detection across all three
in-bounds files. Summary of changes:

### `crates/core/src/lower/expression/wrap.rs::lower_mapped_factor`

Replaced span-prefix detection (`c.span_text().trim().starts_with("->")`)
with structural classification: walk children once, classify each
by structural role (factor → first non-Unit / non-modifier-text
child; type_annotation → `:`-prefixed span; value_expr_head → any
remaining substantive child past the factor). The legacy
`->`-prefixed shape is preserved as a fallthrough for any orphan
path. Added typed-materialization-invariant panic if the source
span contains a `->` arrow but no value_expr head was structurally
located. **Closes R1.**

### `crates/core/src/lower/expression/repeat.rs::lower_factor` + `recover_modifier`

Replaced single-pass close-delim-skipping recovery with a
structural dispatcher keyed on `term.is_compound_kind(Term)` +
`term.branch_tag()` ∈ `{5, 6, 7, 8}`:

- **Non-grouped terms** (identifier / literal / regex / sub-expr):
  the term's `byte_span()` covers the full token; the modifier (if
  any) is the first `?w` / `?` / `*` / `+` past optional
  whitespace.
- **Grouped terms** (`( … )` / `[ … ]` / `{ … }` / `@{ … }`):
  count `n_pending_inner_groups` = number of grouped Term
  descendants whose `byte_span().hi == term_hi` (these are inner
  groups whose close-delim hadn't been reached at the moment our
  rightmost descendant span was pushed). Walk source forward
  consuming whitespace + inner-modifier punctuators + close-delims
  until exactly `(n_pending_inner_groups + 1)` close-delims have
  been consumed (the last one is OUR group's close). Then read OUR
  modifier past optional whitespace.

Added typed-materialization-invariant panic in `lower_factor` if a
`Unit` modifier marker is present but `recover_modifier` returns
None — that signals a structural-detection failure rather than a
graceful drop.

### `crates/core/src/lower/expression/alt.rs::lower_alternation` + `lower_concatenation`

Added typed-materialization-invariant panics: if
`iter_iteration_pairs` yields zero parts but the source span is
non-empty, the predicate-based pair filter dropped every operand —
panic with the offending span text instead of silently returning
`Epsilon`. No changes to the iteration shape detection (current
behaviour is structurally sound; the pair filter only drops
empty-span placeholders and bare separator tokens).
