# P3.1 gestalt-2 critic A — independent repair review

Status: **REJECT FOUNDATION CLOSURE / GLOBAL ARCHITECTURE RED / MOVEMENT DENIED**.

The repair is a useful, tranche-fit improvement over P3, but its author disposition
is not yet licensed. Four required guarantees (F14, F17, F18, and F20) remain
contradicted, the clean gate is knowingly red, and the stored proof does not contain
the required born-RED/pass-twice receipts or rerunnable final full-run evidence.
Nothing in this review authorizes a production or source move.

exporter, helper programs, tests and fixtures, the relevant tranche/constitution

## Numbered findings

1. **HIGH — The closure disposition contradicts the mandatory clean gate.**
   `P3-ADJUDICATION.md:509-520` says P3.1 does not close until the strict xtask
   clippy command exits 0 and explicitly says the existing out-of-scope warning
   still prevents calling the repository gate clean. The receipt nevertheless says
   `FOUNDATION REPAIRED` at `P3.1-REPAIR-AUTHOR.md:3,19`, while admitting the same
   exit 101 at `:112-121`. The exact command above reproduced exit 101. Preserving
   the unrelated file is proper scope discipline, but it is not permission to award
   the contract's closure verdict.

2. **HIGH — F14's production “final recensus” never observes the live source.**
   The production pipeline calls only `binding.verify_captured` at
   `xtask/src/architecture/mod.rs:157-166`. That method compares captured bytes to
   the already captured inventory, in-memory helper bytes, and selected tools at
   `xtask/src/architecture/evidence/binding.rs:406-444`; it does not reread the
   manifest, repository inventory, context files, or worktree state. The one method
   that can compare two bindings, `verify_recensus` at `binding.rs:399-403`, has no
   production caller (`rg -n 'verify_recensus|verify_captured'` found it only in its
   definition and `xtask/tests/architecture/evidence.rs:153`). The purported F14
   test at `evidence.rs:146-154` merely mutates a cloned `SourceBinding`, and the ABA
   test at `frontend.rs:71-103` changes and restores a file, then expects collection
   and `verify_captured` to succeed. A non-captured file, manifest, worktree, or a
   helper changed between the inventory and helper captures can therefore yield a
   mixed snapshot without `SOURCE_SNAPSHOT_DRIFT`, contrary to
   `P3-ADJUDICATION.md:288,349-351`.

3. **HIGH — F18's logical write failpoint cannot exercise the required clean
   fallback transaction.** `publish_complete` catches a complete-generation write
   error and invokes `publish_failure` at
   `xtask/src/architecture/evidence/write.rs:139-164`; `publish_failure` calls the
   same `publish` path at `:188-217`. The environment failpoint remains armed at
   `:395-399`, so `file-create`, `file-write`, or `file-fsync` fires again in the
   fallback at `xtask/src/architecture/evidence/transaction.rs:152-159`. The
   governing contract specifically requires logical write failpoints to exercise a
   clean fallback (`P3-ADJUDICATION.md:434-438`). The test at
   `xtask/tests/architecture/evidence.rs:158-213` calls the public publisher once
   and expects an error/old `CURRENT`; it never drives `publish_complete` and never
   proves a fallback failure generation. Operation-local injection and old-current
   preservation are retained, but the receipt's “stage-safe fallback” claim at
   `P3.1-REPAIR-AUTHOR.md:33-34` is false.

4. **HIGH — F20's generation receipt does not record or hash the exact on-disk
   file set.** `expected_files` and `artifacts` are finalized at
   `xtask/src/architecture/evidence/write.rs:340-385`, then
   `publication.json` is inserted only at `:388-390`. A direct safe `/tmp` probe of
   `publish` printed:

   ```text
   actual=["binding.json", "diagnostics.json", "generation.json", "publication.json"]
   expected_names_publication=false
   artifact_map_publication=false
   ```

   The F20 test lists the file at `xtask/tests/architecture/evidence.rs:296-311`
   but checks hashes only by iterating the incomplete artifact map at `:313-325`.
   Transaction-time verification does compare all in-memory bytes, which repairs
   corrupt reuse, but an offline consumer cannot derive the exact file set and
   digest of every published file from the receipt as required by
   `P3-ADJUDICATION.md:423-432`.

5. **MEDIUM — F17's claimed universal privacy predicate still has both false
   negatives and false positives.** `validate_portable_string` recognizes a POSIX
   absolute path only when `/` has a following non-slash byte and a selected left
   boundary (`xtask/src/architecture/schema/identity.rs:223-264`); it recognizes
   only `~/`, not `~user/`, and rejects every substring `file:` rather than a
   tokenized URI. A direct probe against the reviewed library produced:

   ```text
   "/": ACCEPT
   "prefix/Users/reviewer/secret": ACCEPT
   "~reviewer/secret": ACCEPT
   "profile:dev": REJECT
   ```

   The current test bank at `xtask/tests/architecture/schema.rs:14-39` does not
   include those boundary cases. This does not expose a private literal in the
   author's reported final artifact, but it contradicts the universal whole/embedded
   POSIX and tilde law in `P3-ADJUDICATION.md:441-450` and overstates F17.

6. **HIGH — The “exact F01-F20 history bank” is an index, not the required
   born-RED/pass-twice evidence bank.** The stored history fixture contains an
   authority path/hash and one test-function name per ID
   (`xtask/tests/fixtures/architecture/p31-history.json:1-46`). Its test checks those
   hashes and performs a source substring search for `fn <name>` at
   `xtask/tests/architecture_p3_counterexamples.rs:28-75`; it stores no per-case P3
   failure, P3.1 positive/negative result, mutation inversion, normalized receipt,
   or second identical pass. Likewise the ignored “full captured” ordering test
   reads one already-generated graph and directly sorts/deduplicates its `truth`
   vector (`xtask/tests/architecture/project.rs:180-197`); it does not rerun
   collection, projection, rendering, or compare complete outputs. These artifacts
   do not satisfy the exact proof required at `P3-ADJUDICATION.md:267-304,509-530`,
   despite `P3.1-REPAIR-AUTHOR.md:98-101` calling the bank exact.

7. **MEDIUM — Final determinism, relocation, locale, concurrency, wall, and RSS
   claims are not rerunnable from retained evidence.** The final run ID
   `p31-b0aea8e28c1ccd5002582828b115b66c6f905d10b7fb2ac7c26552a9cbc1c893`
   appears only in `P3.1-REPAIR-AUTHOR.md`; an excluded-ledger repository search
   (`rg -l '<run-id>' . -g '!restart/skinny/tranches/sk-v25/graph/*CRITIC*'
   -g '!restart/skinny/tranches/sk-v25/*LEDGER*' -g '!target/**'`) returned only that
   receipt. No captured generation tree, exact output path, raw timing/RSS log,
   concurrent command transcript, relocation fixture, or locale fixture is stored.
   The only retained full-ordering command at `P3.1-REPAIR-AUTHOR.md:103-110`
   depends on an undefined `$GRAPH`. The reported measurements may be true, and
   they are below the numeric caps, but the executable-proof, relocation, locale,
   concurrency, and resource claims remain **UNPROVEN**, not independently
   reproducible evidence.

8. **MEDIUM — The claimed single immutable source ledger omits a repair input.**
   A complete census of `xtask/architecture`, `xtask/src/architecture`,
   `xtask/tests/architecture`, and `xtask/tests/fixtures/architecture` has 93 files;
   adding `xtask/src/{lib,main}.rs`, both architecture test entrypoints, and
   `xtask/Cargo.toml` yields 98. The receipt's 97-row ledger contains every member
   except `xtask/Cargo.toml`, even though that file carries the newly added `sha2`
   dependency at `xtask/Cargo.toml:58`. Its digest is mentioned separately at
   `P3.1-REPAIR-AUTHOR.md:55-62`, but it does not participate in the ledger-text
   SHA-256 at `:170-175`. Thus the single ledger required by
   `P3-ADJUDICATION.md:509-520` does not by itself bind all repaired source/config
   inputs. The listed 97 hashes and separate Cargo manifest/lock hashes are retained
   as accurate individual facts.

9. **MEDIUM — Structural validation does not independently prove complete SCC and
   typed cut incidence.** `validate_components` checks only components that the
   producer supplied and never recomputes SCC membership or rejects missing/extra
   components/bases (`xtask/src/architecture/evidence/validate.rs:161-195`).
   `validate_clusters` reconstructs only `InternalOwner` edges at `:198-258`; it
   never compares the serialized `OutgoingOwner` and `IncomingReference` records to
   the selected edges. The quotient is independently reconciled later, but that
   cannot prove each cluster's complete typed incidence. The producer at
   `xtask/src/architecture/project/cluster.rs:140-202` currently constructs those
   records deterministically, so current output generation is retained; the
   independent fail-closed validation law at `P3-ADJUDICATION.md:398-401` is not.

10. **MEDIUM — The resource/concurrency description understates actual nested
    parallelism.** The receipt says “up to eight bounded workers” at
    `P3.1-REPAIR-AUTHOR.md:75-79`. In fact worktree collection batches up to 24
    concurrent outer threads (or the environment-selected batch size) at
    `xtask/src/architecture/inventory/worktree.rs:97-119`, and each can create up to
    eight entry-hashing threads at `:291-327`. The current configuration can
    therefore have as many as 192 inner hashing workers plus the outer workers,
    each ordinary-file reader allocating a 512 KiB buffer at `:361-371`. The
    author's measured RSS is below the gate, but the prose/KISS claim of an
    eight-worker bound is false and the code contains no global worker or memory
    budget enforcing the 384 MiB guarantee.

## Reviewed planes and retained truths

- **Tranche fit / greater-product effect:** The implementation remains isolated to
  local xtask architecture tooling, its helpers/tests/fixtures, and minimal Cargo/CLI
  wiring. No production source move or second v3 compatibility path was found. This
  is the right narrow repair tranche under `TRANCHE-PORTFOLIO.md:3-19,47-74`.
- **Claim scope / movement:** Global architecture remains honestly RED with semantic
  Unknowns. Generation, projection, cluster, and quotient movement authorization is
  denied. No Cargo/Rust/frontend/generated/WASM/call promotion is claimed.
- **Manifest / inventory / source identity:** v3.1 is the sole manifest path;
  two-repository identity, six context IDs, reciprocity, physical kinds, exclusions,
  nominations, ordinary content hashes, and captured frontend reads are substantive.
  Findings 2 and 8 limit snapshot and ledger completeness.
- **Ordering / deterministic serialization:** BTree collections, explicit sorts,
  canonical graph truth, typed edge-record hashes, and deterministic compact
  projection output are real. The focused permutation and safe suite passed. Full
  exporter twins and 1,000 complete-output permutations remain receipt-only under
  findings 6-7.
- **Mutation sensitivity / worktrees:** Branch spelling, administrative identity,
  tracked diff, and nonignored untracked byte sensitivity are retained. Live final
  recensus is absent, and ignored content is intentionally outside the worktree
  digest unless separately captured.
- **Projection / SCC / basis / clustering / quotient:** The current producers are
  typed, deterministic, compact, signal-sensitive, and the tested GF(2) bases replay.
  Finding 9 limits independent structural validation; no structure authorizes a move.
- **Publication / corruption / concurrency:** Staged synced files, directory rename,
  exact in-memory reuse verification, quarantine, output-root lock, atomic `CURRENT`,
  and rollback on root-sync failure are real. Findings 3-4 limit fallback and receipt
  completeness; the simultaneous-publisher claim is not retained executable proof.
- **Relocation / locale / privacy:** Repository-relative identities, bound tool/helper
  digests, canonical sorting, and current portable-string checks support relocation
  and locale stability. Findings 5 and 7 prevent universal or full-run credit, and
  the graph correctly retains relocation/locale Unknowns.
- **Resources / structure / KISS:** Output-size gates enforce 48 MiB generation,
  24 MiB projections, 128 KiB early-failure limits, and 32/120 shard maxima. The
  orchestrator is stage-oriented and the writer split is coherent. Wall/RSS proof is
  not retained, nested worktree concurrency is not globally bounded, and strict
  clippy remains red.
- **Executable proof / hostile acceptance:** The safe architecture suite is useful
  and source-isomorphic. It cannot replace the required born-RED receipts, full
  deterministic artifacts, two fresh clean hostile passes, adjudication, or the
  clean repository gate required by `LOCK-CONSTITUTION.md:29-56`.

## Verdict

**P3.1 remains open and RED.** The local repair base is materially better and many
foundation organs should be retained, but “foundation repaired” is rejected as a
closure statement. Correct the F14 live/immutable snapshot proof, one-shot logical
write fallback, universal privacy boundaries, self-recording publication receipt,
independent structural validation, single source ledger, and proof retention; then
rerun every clean gate and the exact born-RED/pass-twice bank before another hostile
pass. Movement remains denied without exception.
