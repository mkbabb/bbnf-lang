### Part 5 — Cross-tranche API-rename sweep

Five tranche docs reference the renamed APIs:

- `docs/tranches/AY-II/AY-II.md` and `waves/W*.md`
- `docs/tranches/AZ-I/AZ-I.md`
- `docs/tranches/AZ-II/AZ-II.md`
- `docs/tranches/BA/BA.md`
- `docs/tranches/BB/BB.md`

The sweep updates references:

| Old | New |
|-----|-----|
| `FusedBuilder` | `Columns` (or `Tape<R>` for read methods) |
| `FusedOutput<R>` | (deleted; consumer reads from `Tape<R>`) |
| `ValueFramesOutput<R>` | (deleted) |
| `Parsed::value_frames_output` | `Parsed::frames` |
| `into_value_frames_output` | `into_frames` |
| `columns_mut()` | `Tape::position()` for offset; `Columns::rollback_to(open)` for rollback |
| `frame_depth_mut()` | (retired; route through `Columns::rollback_to`) |
| `extern crate self as bbnf` | (deleted) |

The sweep is mechanical find/replace per the table; the agent
reads each updated paragraph for coherence (a sentence that
read "the FusedBuilder mediates the ..." now reads "the Columns
substrate ..." — confirm the new sentence makes sense).

Per `feedback_doc_integration_style`, the sweep is deft: each
updated paragraph reads cohesively with its surroundings. Bolted-
on "(formerly known as FusedBuilder)" notes are forbidden — per
`feedback_no_workarounds`, no backward-compat-shim language
either.
