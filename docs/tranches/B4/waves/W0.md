# B4.W0 — Codegen-Emission Correctness (`syn::parse2` Fix)

**Status**: in_progress

W0 closes the bbnf self-host xtask regen path. The
`generate_all`-produced TokenStream for the bbnf grammar fails
`syn::parse2` with "expected loop or block expression". The fix lives
at the offending emitter; W0 reproduces the panic, identifies the
file:line, applies the correction at source, and verifies end-to-end
that `cargo xtask regen --grammar bbnf` writes a populated, valid
`crates/core/src/grammar/generated/bbnf.rs`.

## Scope

- Reproduce the `syn::parse2` panic on a clean worktree against the
  current master HEAD.
- Capture the panic context plus the offending TokenStream excerpt
  (via a `tokens.to_string()` dump-and-panic diagnostic that lives in
  the worktree only and is reverted before the fix commit).
- Read every emitter under
  `crates/core/src/backend/rust/emitter/**`,
  `crates/core/src/backend/rust/view/**`, and
  `crates/core/src/grammar/schema/emit/rust.rs` to identify the
  emitter responsible for the malformed fragment.
- Cross-reference the bbnf grammar's structural features against
  json's: Pratt operator chains, alternation depth, recursion-
  elimination dispatchers, visitor codegen scope. Use the divergence
  to narrow the candidate emitter set.
- Apply the fix at source. KISS DRY single-purpose; no tangent
  refactors.
- Verify: bbnf regen end-to-end, json regen sanity, workspace check,
  tape tests.
- Cherry-pick fix + docs to master.

## Phases

### W0.1 — Reproduce + capture

1. Build xtask release (`cargo build -p xtask --release`).
2. Run `BBNF_REGEN_PHASE_LOG=1 cargo xtask regen --grammar bbnf`;
   capture stdout + stderr.
3. Confirm the panic message matches "expected loop or block
   expression" against `crates/core/src/grammar/generated/bbnf.rs`.
4. Add an env-gated dump-and-panic in `xtask/src/regen.rs` immediately
   before the `syn::parse2` call: when `BBNF_REGEN_DUMP_TOKENS=1` is
   set, write `tokens.to_string()` to
   `/tmp/b4-w0-bbnf-tokens.txt` then proceed. The dump is a worktree-
   only diagnostic; it gets reverted before the fix commit.
5. Re-run with the dump enabled; locate the offending region in
   `/tmp/b4-w0-bbnf-tokens.txt`. Save the relevant excerpt (the
   syntactic context Rust rejects, plus surrounding 5-10 lines on each
   side) to `docs/tranches/B4/audit/W0-bbnf-regen-panic.txt` together
   with the panic stack trace.

### W0.2 — Root-cause analysis

1. From the captured excerpt, identify what Rust syntax slot the
   parser rejects (expression, statement, item, block, loop, match
   arm).
2. Map the offending fragment to the emitter that produced it. The
   bbnf grammar exercises shapes the json grammar does not (Pratt
   operator chains via `crates/core/src/backend/rust/emitter/shapes/pratt.rs`,
   recursion-elimination dispatchers via
   `shapes/dispatcher.rs`, visitor codegen via `emitter/visitor.rs`,
   precedence tables via `emitter/precedence.rs`). Narrow to a single
   emitter using the excerpt's structural cues.
3. Read the suspect emitter end-to-end. Identify the position-context
   defect: an item-shaped fragment in expression context, an unbraced
   control-flow form where a block expression is required, a match
   arm missing its `=>` block-wrap, or an off-by-one
   variable-vs-statement emission.
4. Author `docs/tranches/B4/audit/W0-rootcause.md` §Panic location +
   §Root cause.

### W0.3 — Fix at source

1. Apply the correction at the offending emitter. The fix is a
   targeted change at the precise quote!/block construction; the
   surrounding emitter scaffolding stays untouched.
2. Strip the dump-and-panic diagnostic in `xtask/src/regen.rs`.
3. Strip any other diagnostic eprintlns added during root-cause work.

### W0.4 — Verify

1. `cargo build -p xtask --release` exits 0.
2. `cargo xtask regen --grammar json` exits 0; output line count
   matches the pre-existing json grammar emission (regression sanity).
3. `cargo xtask regen --grammar bbnf` exits 0;
   `crates/core/src/grammar/generated/bbnf.rs` lands populated;
   line count is in the same order of magnitude as
   `crates/core/src/grammar/generated.rs` (~30K lines).
4. `cargo check -p bbnf -p xtask -p bbnf_derive --profile ax-iter`
   exits 0.
5. `cargo nextest run -p tape --profile ax-iter` exits 0.
6. Save each command's output to the corresponding audit file.

### W0.5 — Cherry-pick + close

1. Strip diagnostics; commit fix in worktree with message citing
   `B4.W0`.
2. Cherry-pick fix to master.
3. Author `docs/tranches/B4/audit/W0-rootcause.md` final form.
4. Update `docs/tranches/B4/PROGRESS.md` (W0 close entry) and
   `docs/tranches/B4/B4.md` (wave summary table → `complete`); update
   this file's `**Status**` line to `complete`.
5. Cherry-pick docs commit to master.

## File bounds

Allow-list:
- `crates/core/src/backend/rust/emitter/**` — fix at the responsible
  shape emitter.
- `crates/core/src/backend/rust/view/**` — fix at the responsible view
  emitter (if the defect is in a view accessor emission).
- `crates/core/src/grammar/schema/emit/rust.rs` — fix at the schema
  emitter (if the defect is in CST helper / visitor codegen).
- `xtask/src/regen.rs` — worktree-only dump-and-panic diagnostic;
  reverted before fix commit.
- `docs/tranches/B4/**` — plan + waves + audit + PROGRESS.

Forbidden:
- A `try-or-fallback` path at the `syn::parse2` callsite that masks
  the codegen defect.
- Reverting any γ-η commits from the predecessor tranche's W0 chain.
- `crates/core/src/grammar/generated.rs` modifications outside what
  xtask regen produces.
- `git reset --hard`.
