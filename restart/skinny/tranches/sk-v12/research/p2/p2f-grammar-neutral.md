## §1 — Findings (concrete; file:line on bbnf claims, citation on external claims)

1. Accepted SK-V12 P1 authority is narrow but usable: the converged S-P1 file marks all P1 V4/V5 challenges ACCEPT with zero open REVISE, records the current `parse_only`, direct, and typed-result surface, and names the accepted hot families used in this file (`restart/skinny/tranches/sk-v12/research/p1/hardening/HARDENING-S-P1-CONVERGED.md:20`, `:41`, `:47`). The same file states that JSON-only telemetry may nominate families but does not prove CSS L4, Sheets, or BBNF-self behavior (`restart/skinny/tranches/sk-v12/research/p1/hardening/HARDENING-S-P1-CONVERGED.md:60`).
2. The live product surface still makes generated non-JSON baseline work the first material axis: `skinny/RESULTS.md` keeps direct rows as N-direct/NoGo and describes Track1/Track2 as JSON runtime paths (`skinny/RESULTS.md:143`, `:144`), while SK-V12 handoff says S-P2 must map candidates to hot leaves and keep parse-only/JSON residuals diagnostic or preblocked (`restart/skinny/tranches/sk-v12/HANDOFF.md:67`). REDRESS 120 closes SK-V11 with no behavior/source/generated-runtime/bench/gate/RESULTS movement and routes SK-V12 to generated non-JSON baseline first (`skinny/REDRESS.md:3529`, `:3549`).
3. The current generator is not grammar-neutral at the runtime emission boundary. `emit_with_layout` and typed emission both call `json_provider::ensure_runtime_profile` (`skinny/crates/codegen/src/lib.rs:102`, `:108`, `:139`, `:146`), and that provider accepts only `backend.grammar_name == "json"` before inserting JSON templates and module names (`skinny/crates/codegen/src/json_provider.rs:4`, `:15`, `:48`). Runtime exports only generated JSON as `grammars::json`; the Sheets file is witness/test-gated, not a generated runtime grammar (`skinny/crates/runtime/src/lib.rs:3`, `:10`, `:14`).
4. Local code already contains several neutral-looking kernels, but most are currently wrapped in JSON policy. JSON generated code hardcodes the structural alphabet and value dispatch (`skinny/crates/runtime/src/grammars/json/generated.rs:10`, `:47`), bounded-string fast paths hardcode JSON quote/backslash/control handling (`skinny/crates/runtime/src/grammars/json/generated.rs:161`, `:178`), and number matching delegates to a JSON-shaped span matcher (`skinny/crates/runtime/src/grammars/json/generated.rs:205`, `:215`). The reusable tape builder is grammar-agnostic offset/flag accounting (`skinny/crates/runtime/src/tape/assembler.rs:42`, `:61`, `:93`, `:115`), but Lock 1 forbids turning any alternate structural offset table, sidecar, or retained SIMD mask into a second substrate (`restart/locks/LOCKS.md:52`).
5. Lock 14 is the central verdict rule for this artifact: substrate/generic crates may not contain grammar-specific code; runtime modules must be generated from one grammar-agnostic template, and grammar differences must live in grammar source, metadata, or optional per-grammar declaration crates (`restart/locks/LOCKS.md:78`). Lock 16 permits SIMD lifts only as abstract byte-class/movemask/cross-lane/set-membership primitives with scalar parity and corpus parity (`restart/locks/LOCKS.md:87`, `:110`, `:112`).
6. CSS L4, Sheets, and BBNF-self all have concrete non-JSON byte/string/number/dispatch surfaces. CSS has identifiers with escapes and dual quoted strings (`grammar/css/l4/tokens.bbnf:7`, `:8`, `:9`); Sheets has leading-dot/exponent numbers, doubled-quote strings, error literals, cell/range spans, and primary/function dispatch (`grammar/google-sheets/google-sheets.bbnf:6`, `:12`, `:34`, `:63`, `:125`, `:141`); BBNF-self has identifiers, three literal quote forms, regex spans, comments, directive/rule dispatch, and value-expression numbers (`grammar/bbnf/bbnf.bbnf:9`, `:11`, `:15`, `:17`, `:56`, `:75`; `grammar/bbnf/expressions.bbnf:6`, `:7`, `:16`).

No new external comparator or ISA claims are introduced here; ISA/process claims are inherited only through local Lock 16 text.
