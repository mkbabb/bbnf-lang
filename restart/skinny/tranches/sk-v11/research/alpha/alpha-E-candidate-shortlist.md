## Global Eligibility Rules

1. `parse_only` is not a target. It may provide diagnostics only.
2. Every candidate must run after a fresh SK-V11-open S-P1 profile over all
   17 JSON corpora, xctrace CPU Counters + Time Profiler PMU, and samply.
3. Every SIMD/ASM candidate must micro-prove on this aarch64 host before S-P3
   wave scoping. The proof needs a scalar oracle, strict parity/checkasm,
   representative JSON and non-JSON slices, host flags, feature gates, and a
   caller-level speed threshold.
4. Every source-producing candidate must land a same-wave consumer. No orphan
   kernel, renamed scanner, or proof-only production claim is admissible.
5. Every generic crate, codegen, or runtime-outside-JSON edit must carry one
   named non-JSON benchmark, preferably CSS L4 declaration values or Sheets
   formulas. JSON-only success is insufficient.
6. Every row movement must be consumed by `gate-json` in the same wave. No new
   field is emitted unless a same-wave gate consumes it.
7. x86, AVX2, AVX-512, asmjson AVX-512, and future Intel work are out of scope
   for SK-V11 behavior waves.

## Alpha-E Recommendation

S-P1 should profile direct residual rows and one CSS L4 or Sheets workload
first, then S-P2 should micro-prove C2-C5 before S-P3 wave scoping. The likely
SK-V11 path is:

1. C1 as W0 telemetry/micro-proof infrastructure.
2. One of C2, C3, C4, or C5 selected by fresh hot-leaf evidence.
3. Repeat only if the first row-moving candidate admits a direct row or
   produces a measured per-row uncloseable proof.

The target close posture is direct `GO` if the 11 residual floors clear, or a
fixpoint if each miss is recorded with a same-run per-row proof; in both cases
at least one non-JSON grammar must carry an admitted benchmarked SK-V11
intervention.
