# T-P2 V4 CH4 Cost / Executability

Pass: T-P2 Research.
Cycle: V4.
Lens: CH4 COST.
Date: 2026-05-21.

## Verdict

ACCEPT.

V4 resolves the V3 CH4 revise set. The V4 fold addendum keeps the V3 shared
ledger authoritative, then patches the exact rows CH4 named: deferred command
or consumer cells now either carry strict commands / first-consumer paths or are
explicitly non-shortlist until the missing executable cell exists. The REDRESS
bridge is now slice-local enough for S-P3 planning, and the LOC, rollback, and
abrogate fields are concrete rather than aspirational.

## Evidence

1. Deferred executable ledger cells are no longer ambiguous.

   V3 CH4 required executable values or explicit non-shortlist blockers for
   `tbl_tbx_escape_decode_batch`, `escape_mask_64`,
   `digit_run_accumulate_udot`, `pmull_cssc_structural_union_emit64`,
   `string_context_64`, and `cache_hint_prefetch_store`
   (`restart/audit/totality/p2/hardening/V3/CH4.md:95-102`).

   V4 supplies the exact strict command for `escape_mask_64` and a generated
   JSON/CSS first-consumer path, while preserving its prerequisite-only blocker
   (`restart/audit/totality/p2/T-P2-V4-FOLD-ADDENDUM.md:47-50`). Rows that
   still lack a real strict test or first consumer are not paper-admitted:
   `tbl_tbx_escape_decode_batch`, `digit_run_accumulate_udot`, and
   `string_context_64` name the required future command shape and stay
   non-shortlist; `pmull_cssc_structural_union_emit64` names the existing
   prefix/next-bit checkasm commands but blocks admission on a combined matrix
   and exact consumer; `cache_hint_prefetch_store` is blocked until an exact
   caller/equality/perf harness exists
   (`restart/audit/totality/p2/T-P2-V4-FOLD-ADDENDUM.md:50-54`).

2. The REDRESS-slice ownership table covers the CH4 reopen families.

   V3 CH4 required reopened REDRESS-119 direct rows, PMULL/CSSC/union,
   source-present primitives, string/digit routes, and parse-that import routes
   to map to candidate, owner, first consumer or blocker, expected gate, LOC
   budget, rollback, and abrogate threshold
   (`restart/audit/totality/p2/hardening/V3/CH4.md:104-110`).

   V4 now covers REDRESS-119 direct rows for `twitter`, `canada`,
   `github_events`, `update_center`, string/unicode, and numbers
   (`restart/audit/totality/p2/T-P2-V4-FOLD-ADDENDUM.md:66-73`). It also covers
   PMULL/CSSC/union and source-present prefix/next/bulk rows, byte-context,
   cache hints, the CSS ASCII run-skip route, and the parse-that HIR/import
   route (`restart/audit/totality/p2/T-P2-V4-FOLD-ADDENDUM.md:74-79`).

3. LOC, rollback, and abrogate fields are concrete.

   The V4 REDRESS table gives numeric LOC ranges, named rollback actions, and
   concrete abrogate triggers for each slice: for example direct digest rows use
   80-180 LOC with scalar-mix rollback and digest/admitted-row aborts; number
   routes use 120-240 LOC with DOTPROD disable rollback and parity/overflow/row
   aborts; PMULL/CSSC/union uses 280-520 LOC with PMULL/CSSC removal or scalar
   scan rollback and prior-regression/no-consumer/parity/guard aborts
   (`restart/audit/totality/p2/T-P2-V4-FOLD-ADDENDUM.md:68-75`).
   Source-present byte-context, cache hints, CSS run-skip, and parse-that import
   rows likewise carry numeric LOC budgets, rollback paths, and fail-closed
   abrogate conditions (`restart/audit/totality/p2/T-P2-V4-FOLD-ADDENDUM.md:76-79`).

4. The authoritative-state wording is safe for downstream consumers.

   V4 keeps `admissibility_state` reserved for the normalized enum and states
   that local 2B/2E/2F prose tables are owner summaries only, to be read as
   `summary_status`, `disposition`, or `blocker` rather than gate-consumed
   admission state (`restart/audit/totality/p2/T-P2-V4-FOLD-ADDENDUM.md:81-86`).
   The dossiers also point their local summaries back to the V3/V4 addenda as
   the authoritative ledger (`restart/audit/totality/p2/2B-primitive-vocabulary.md:141-149`,
   `restart/audit/totality/p2/2E-host-arch-esoterica.md:140-147`,
   `restart/audit/totality/p2/2F-parse-that-gaps.md:188-196`).
