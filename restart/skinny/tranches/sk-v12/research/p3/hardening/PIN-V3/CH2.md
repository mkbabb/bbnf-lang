   seven value/API leaks to be resolved before CSS L4 emission is legal

   `GrammarConfig + Lock 14 Legality Gate`, requires the plan to name the seven
   leaks, and exits only when generic-crate scan and JSON guard/parity evidence
   pass with no CSS row claimed (`SPEC.md:314-347`). W1b-1 then requires W1a

   preserve the same dependency (`p3b-wave-sequencing.md:135-143`,
   `p3c-falsifiability-gates.md:163-190`).

2. Generic-crate policy leakage is fail-closed. SPEC Section 2.1 forbids
   `JsonParser`, `CssL4Parser`, `GoogleSheetsParser`, `BbnfBootstrap`, grammar
   name branches, JSON structural alphabet, JSON escape/number/key policy, JSON
   `OffsetFlags` meaning, and `JsonSink` shape in generic code
   (`SPEC.md:259-275`). P3-C requires a negative scan for grammar-name behavior
   branches, generic grammar public APIs, handwritten non-generated CSS/Sheets/
   BBNF runtime modules, and generic JSON structural alphabets
   (`p3c-falsifiability-gates.md:173-188`). That matches the value/API audit's
   seven leak inventory: structural alphabet, value dispatch, string escape/
   quote policy, number policy, quoted-key/object-pair policy, `OffsetFlags`
   meaning, and `JsonSink` methods (`skv12-value-api-audit.md:63-108`).

3. Grammar-specific policy stays generated, not generic. P2-F defines the legal
   neutral boundary as generated byte sets, escape and number policy,
   FIRST/follow dispatch tables, sink/view/kind modules, and output planes; it
   rejects generic JSON structural bytes, JSON whitespace, JSON `\u`, JSON number
   grammar, JSON object/array roles, sidecars, and digest-only proof
   (`p2f-grammar-neutral.md:89-99`). The packet carries that into W1a by making
   `GrammarConfig` or equivalent generated metadata the policy surface
   (`SPEC.md:334-339`, `p3d-telemetry-schema.md:143-162`). The allowed surface is
   generated metadata/config, not a directive, BIR, `BackendShape`, or public
   substrate expansion (`SPEC.md:220-224`, `SPEC.md:341-347`,
   `p3e-preblocked-ledger.md:60-62`).

4. The PIN-V2 fallback ambiguity is folded for CH2. W1b-1 now states that a
   scaffold failure records REDRESS but does not satisfy the post-CSS-redress
   fallback condition, and Sheets/BBNF fallback remains blocked until W1b-2
   records measured CSS lightningcss comparator/admission redress unless the user
   re-pins or S-P3 revises topology (`SPEC.md:433-442`). W1b-2 is the first wave
