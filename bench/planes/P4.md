# P4 — JSON DOM (owned value tree)

**Unit:** sk-v27 LW2.CON-1. **Goals:** G-J3 (P4 DOM), G-G1 (generator contest, JSON at P4). **Family:** F-JSON-P4.

## What an arm does

It builds the input's value as an owned tree that outlives the input buffer, and walks a checksum of that tree inside the timed region (PREREG §1). Its output-parity class is **VAL**: per input, the verdict and, after ACCEPT, the digest of the value's canonical form. Error offsets are not compared on P4 (they are P1's and G-E1's).

A lossless concrete syntax tree (spans that re-cover every input byte) is the class **CST**, also on this plane. A CST arm is compared only with CST arms (`tree-sitter-json`; batch mode, its incremental advantage is not measured).

## Policies

Validation is P1's, rule for rule (UTF-8, escapes, number grammar and range, whitespace, BOM). P4 adds what the value holds:

| Policy | P4 rule |
|---|---|
| **UTF-8 validation** | As P1. Every string and key in the tree is valid Unicode. |
| **Escapes** | Strings and keys hold their unescaped scalar values. A surrogate pair is one scalar. An arm that keeps raw lexemes (escapes undecoded) is not a P4 arm; it is refused by admission on the `esc-*` witnesses. |
| **Number fidelity** | An integer lexeme (no fraction, no exponent) whose value lies in [−2⁶³, 2⁶⁴ − 1] is held exactly; `-0` is the integer 0. Any other number is held as its correctly rounded binary64, keeping the sign of zero (`-0.0`). A number that rounds to infinity is rejected (P1). An arm whose number type cannot hold the integer range lists the missing work (for example a source-text recovery) or fails the `num-*` witnesses. |
| **Duplicate keys** | The parser keeps every member. In the canonical form the last value of a repeated key wins. |
| **Member order** | Not part of the value: the canonical form orders members by the UTF-8 bytes of their keys. |
| **Error offsets** | Not compared on P4. |

## Canonical form

The digest is the SHA-256 of these bytes:

- `n`, `t`, `f` for null, true, false;
- `i` + the decimal integer + `;` for an exact integer;
- `d` + the 16 lowercase hex digits of the binary64's big-endian bits + `;` for a float;
- `s` + the UTF-8 byte length in decimal + `:` + the UTF-8 bytes, for a string;
- `[` + each element + `]` for an array;
- `{` + for each distinct key in UTF-8 byte order, the key as a string followed by its last value + `}` for an object.

`bench/contest/oracle_json.py` is the reference implementation and `bench/contest/arms/node_json_parse.mjs` an independent one; they agree on every witness.

## Witness inputs

`bench/planes/witness/json/`, as P1. Every class field is compared: verdict on all of them, digest on the accepted ones.

## Equal work

- The tree owns its strings. A tree that borrows them from the input is P4 only when its row declares the borrow in its checklist, and a borrowed arm is never paired with an owned arm in a certification cell.
- Every string and key is unescaped, every number converted, every member stored. A lazy arm that defers any of it is P5 (get), not P4.
- The checksum walk visits every node.
