## Findings

- W9's spec target is a CostFacts substrate, not a parser rewrite. The required owner path explicitly includes extending `passes/src/lib.rs` with `cost_facts: HashMap<RuleId, CostFacts>` and the tasks require `CostFacts`, `ShapeRationale`, `RejectedAlternative`, `Measurement`, `PriorityStep`, a refactor of `derive_backend_shape_with_diagnostics`, and `LayoutFacts.cost_facts` (`restart/skinny/tranches/sk-v7/SPEC.md:343`, `restart/skinny/tranches/sk-v7/SPEC.md:345`, `restart/skinny/tranches/sk-v7/SPEC.md:351`). The exit gate is also diagnostic/export focused: seven JSON rules with populated CostFacts, `gate-json --with-cost-facts`, and two diagnostics (`restart/skinny/tranches/sk-v7/SPEC.md:358`).

- The current `compile()` path already has a clean producer insertion point. It builds `layout_facts`, derives materialization/shape/recognizer facts, lowers `backend_ir`, then calls `recognizers::derive_backend_shape_with_diagnostics(...)` and assigns `layout_facts.backend_shape = shape_plan.backend_shape` (`skinny/crates/passes/src/lib.rs:26`, `skinny/crates/passes/src/lib.rs:31`, `skinny/crates/passes/src/lib.rs:34`, `skinny/crates/passes/src/lib.rs:42`, `skinny/crates/passes/src/lib.rs:48`). `PipelineOutput` carries diagnostics separately from grammar/layout/BIR (`skinny/crates/passes/src/lib.rs:49`, `skinny/crates/passes/src/lib.rs:52`), so new warnings can remain side-channel data if shape choices and BIR stay unchanged.

- `LayoutFacts` is currently a layout side table with no CostFacts carrier. It contains rule types, node types, layout policies, hot-call facts, and `backend_shape` (`skinny/crates/passes/src/lib.rs:77`). `layout::run()` initializes `backend_shape` as an empty map before backend lowering (`skinny/crates/passes/src/lib.rs:89`, `skinny/crates/passes/src/lib.rs:94`, `skinny/crates/passes/src/lib.rs:99`). This matches B2's recommendation to add `cost_facts` adjacent to `backend_shape` and keep `backend_shape` as a projection of `cost_facts[rule_id].chosen` (`restart/skinny/tranches/sk-v7/research/skv7-B2-costfacts.md:138`, `restart/skinny/tranches/sk-v7/research/skv7-B2-costfacts.md:149`, `restart/skinny/tranches/sk-v7/research/skv7-B2-costfacts.md:159`).

- `derive_backend_shape_with_diagnostics` is presently a short-circuiting shape map builder, not an evidence producer. `BackendShapePlan` has only `backend_shape` and `diagnostics` (`skinny/crates/passes/src/lib.rs:365`). The decision tree tests eager-tape requirements, sink-only admissibility, collapsed-stage admissibility, event-tape preference, an offset-tape default, and missing backend rule fallback (`skinny/crates/passes/src/lib.rs:380`, `skinny/crates/passes/src/lib.rs:389`, `skinny/crates/passes/src/lib.rs:391`, `skinny/crates/passes/src/lib.rs:407`, `skinny/crates/passes/src/lib.rs:409`). It records no rejected alternatives, no priority identity, and no measurement/evidence payload before inserting the chosen shape (`skinny/crates/passes/src/lib.rs:417`).

- The current predicates are usable as CostFacts gates but are not yet auditable. `requires_eager_tape` folds recovery annotations, parse-time host decode, layout policy, and dispatch overlap (`skinny/crates/passes/src/lib.rs:426`). SinkOnly is gated by `direct_only_output`, no retained API consumer, and a `DirectBuild` in the BIR (`skinny/crates/passes/src/lib.rs:599`). CollapsedStage is only AVX512BW plus entry-shaped BIR, with missing author declaration becoming a diagnostic and fallback to OffsetTape (`skinny/crates/passes/src/lib.rs:605`, `skinny/crates/passes/src/lib.rs:396`, `skinny/crates/passes/src/lib.rs:400`). EventTape is a hard threshold on `alt_branch_count >= 8` (`skinny/crates/passes/src/lib.rs:609`). The final `Some(_) => BackendShape::OffsetTape` arm is a silent default (`skinny/crates/passes/src/lib.rs:408`).

- Backend shape derivation currently does not distinguish DirectBuild rules. The JSON compile test asserts all 15 JSON backend shapes are `OffsetTape` (`skinny/crates/passes/src/lib.rs:1273`, `skinny/crates/passes/src/lib.rs:1278`). W9's "seven JSON rules" gate should therefore be tied to materialized DirectBuild rules, not to every backend rule, unless the implementation deliberately broadens CostFacts to all rules as B2's prototype fold does (`restart/skinny/tranches/sk-v7/research/skv7-B2-costfacts.md:182`, `restart/skinny/tranches/sk-v7/research/skv7-B2-costfacts.md:193`).

- The seven JSON DirectBuild roles are structure-derived today: container/object, sequence/array, pair, string, number, bool, and null. `derive_materialization_plan()` inserts descriptors for those roles with `TapeKind` plus field rosters (`skinny/crates/passes/src/lib.rs:757`, `skinny/crates/passes/src/lib.rs:762`, `skinny/crates/passes/src/lib.rs:782`, `skinny/crates/passes/src/lib.rs:802`, `skinny/crates/passes/src/lib.rs:834`, `skinny/crates/passes/src/lib.rs:852`, `skinny/crates/passes/src/lib.rs:870`, `skinny/crates/passes/src/lib.rs:886`). `materialize_rule()` appends `SpanMark`, `TapeEmit`, `DirectBuild`, and `Return` around only those descriptor-backed rules (`skinny/crates/passes/src/lib.rs:970`, `skinny/crates/passes/src/lib.rs:978`, `skinny/crates/passes/src/lib.rs:988`, `skinny/crates/passes/src/lib.rs:991`, `skinny/crates/passes/src/lib.rs:995`).

- The role recognizer is grammar-structure based, not JSON-name based. It selects string/number via regex span kind, bool/null via literal sets, container/sequence via direct brace/bracket literals, value via references to at least four scalar/container targets, and pair via string/value refs plus `:` (`skinny/crates/passes/src/lib.rs:1011`, `skinny/crates/passes/src/lib.rs:1022`, `skinny/crates/passes/src/lib.rs:1041`, `skinny/crates/passes/src/lib.rs:1058`, `skinny/crates/passes/src/lib.rs:1075`). The regression test renames all JSON rules and still expects the same seven materializations (`skinny/crates/passes/src/lib.rs:1349`, `skinny/crates/passes/src/lib.rs:1370`, `skinny/crates/passes/src/lib.rs:1391`). CostFacts selectors should reuse this structural basis.

- The diagnostics surface is small. Current source has constructors for `collapsed_stage_not_viable` and `backend_shape_inconsistent`, and the code enum maps only `BBNF-COLLAPSEDSTAGE-NOT-VIABLE` and `BBNF-BACKEND-SHAPE-INCONSISTENT` (`skinny/crates/passes/src/diagnostics.rs:10`, `skinny/crates/passes/src/diagnostics.rs:19`, `skinny/crates/passes/src/diagnostics.rs:32`, `skinny/crates/passes/src/diagnostics.rs:38`). The lib test asserts diagnostics by string code (`skinny/crates/passes/src/lib.rs:1395`, `skinny/crates/passes/src/lib.rs:1415`), so adding new enum variants plus constructors is enough for `BBNF-DOMINATED-ALTERNATIVE` and `BBNF-COSTFACTS-MISSING-EVIDENCE` to fit the existing reporting model.

- B2 already defines the intended diagnostic semantics. `BBNF-DOMINATED-ALTERNATIVE` fires when a previously regressed rejected alternative would pass under the current target (`restart/skinny/tranches/sk-v7/research/skv7-B2-costfacts.md:370`). `BBNF-COSTFACTS-MISSING-EVIDENCE` fires when a rule's CostFacts has fewer than the audit minimum of rejected alternatives (`restart/skinny/tranches/sk-v7/research/skv7-B2-costfacts.md:375`). Neither condition requires changing BIR lowering or the selected parser shape; both can be emitted after shape selection as CostFacts validation.

## Recommendations with falsifiability gates

- Refactor the producer so `derive_backend_shape_with_diagnostics` either returns a new `CostFactsPlan` or delegates to `derive_cost_facts_with_diagnostics`, then derives `backend_shape` from `facts[rule_id].chosen`. Preserve the public `derive_backend_shape(...) -> HashMap<RuleId, BackendShape>` wrapper as a compatibility projection (`skinny/crates/passes/src/lib.rs:371`). Falsifiability gate: for every populated CostFacts entry, assert `layout_facts.backend_shape[rule_id] == cost_facts[rule_id].chosen`; `cargo test -p passes` must keep the existing JSON assertion that all 15 backend shapes remain `OffsetTape` until a later behavior-changing wave intentionally changes that (`skinny/crates/passes/src/lib.rs:1273`).

- Encode the shape priority order as a data table with gate functions, not as a freehand `match`. Each priority should return both "gate held" and "rejection to append when gate failed"; this implements B2's drift mitigation (`restart/skinny/tranches/sk-v7/research/skv7-B2-costfacts.md:506`, `restart/skinny/tranches/sk-v7/research/skv7-B2-costfacts.md:516`). Falsifiability gate: a unit test should count one rejected non-chosen `BackendShape` for each audited alternative on every DirectBuild CostFacts entry; adding a new `BackendShape` or priority must fail until the static priority table and rejection emission are both updated.

- Populate CostFacts for the seven DirectBuild materializations first, even if the internal producer can compute facts for all 15 rules. Discover them by walking `backend_ir.rules` for `BackendExpr::DirectBuild` and checking the corresponding `TapeEmit`/field roster, not by rule names. Falsifiability gate: compiling the JSON grammar must produce exactly seven DirectBuild-backed CostFacts entries for `Container`, `Sequence`, `KeyValuePair`, `StringValue`, `NumberValue`, `BoolValue`, and `NullValue`, and the renamed-rule test must continue to derive the same seven roles (`skinny/crates/passes/src/lib.rs:1313`, `skinny/crates/passes/src/lib.rs:1349`).

- Keep `LayoutFacts.backend_shape` as the behavior carrier while introducing `LayoutFacts.cost_facts` as evidence. The pass can fill `cost_facts` after `backend_ir` exists and then fold `backend_shape` from it at the same assignment point currently used by `compile()` (`skinny/crates/passes/src/lib.rs:42`, `skinny/crates/passes/src/lib.rs:48`). Falsifiability gate: `cargo run -p xtask --release -- check-json` plus a no-diff check for generated JSON output must remain clean, matching W8's byte-identical output discipline (`skinny/REDRESS.md:2452`, `skinny/REDRESS.md:2455`).

- Emit `BBNF-DOMINATED-ALTERNATIVE` only from CostFacts validation, not from parser selection. A rejected alternative should carry `PreviouslyRegressed` evidence; if the current target and BIR make that alternative's gate pass, push the diagnostic but leave `chosen` unchanged unless a later wave explicitly reopens the route with measurements. Falsifiability gate: an injected test fixture with a `PreviouslyRegressed` SinkOnly or cap-16 alternative whose predicate now passes must produce `BBNF-DOMINATED-ALTERNATIVE`, preserve the same `backend_shape`, and preserve the same generated parser bytes.

- Emit `BBNF-COSTFACTS-MISSING-EVIDENCE` after each CostFacts entry is built. The most direct gate is "DirectBuild rule has fewer than four rejected alternatives" or "DefaultOffsetTape rationale has no diagnostic"; B2 names both as guards against silent defaults (`restart/skinny/tranches/sk-v7/research/skv7-B2-costfacts.md:477`, `restart/skinny/tranches/sk-v7/research/skv7-B2-costfacts.md:483`). Falsifiability gate: force a test-only DirectBuild CostFacts record with an empty `rejected` list and assert the diagnostic code appears while `compile()` still returns `Ok(PipelineOutput)`.

- Backfill REDRESS 72 as evidence, not as a new global policy. The admitted finding is specific: generated retained OffsetTape uses cap 16, while generated direct SinkOnly and hand Track 2 stay cap 8 (`skinny/REDRESS.md:2045`, `skinny/REDRESS.md:2052`). Falsifiability gate: the serialized `gate-json --with-cost-facts` report must contain at least one `EvidenceSource::RedressBackfill` item for REDRESS 72 and must not change cap selection in generated direct SinkOnly output.

## Risks/pre-blocked routes

- Do not reopen REDRESS 60-72 direct-materialization routes. Handoff explicitly pre-blocks those routes, including global tiny-string cap, direct source-hook field-layout materializer, parser-owned decoded scratch, byte-output unescape, and DirectBuild semantic string facts (`restart/skinny/tranches/sk-v7/HANDOFF.md:66`, `restart/skinny/tranches/sk-v7/HANDOFF.md:75`). W8 repeats that W9 proceeds to CostFacts before further route-fact decisions (`skinny/REDRESS.md:2460`, `skinny/REDRESS.md:2464`).

- Do not revive DirectBuild semantic string fact hashing as part of CostFacts. REDRESS 69 rejected that exact route after a roughly 15% `unicode_escapes` regression and says not to reopen it without a different consumer representation (`skinny/REDRESS.md:1839`, `skinny/REDRESS.md:1863`, `skinny/REDRESS.md:1877`). CostFacts may record this rejection; it should not reintroduce semantic string materialization.

- Do not turn REDRESS 72 into a global cap-16 parser change. The evidence admits cap 16 for generated retained OffsetTape only and explicitly rejects the global policy after Track 2 and generated direct SinkOnly regressions (`skinny/REDRESS.md:1996`, `skinny/REDRESS.md:2045`, `skinny/REDRESS.md:2051`). CostFacts should encode the split as accepted/rejected alternatives.

- Do not reintroduce JSON-name allowlists. W8 removed JSON shell coupling, including schema-direct `Json*` allowlists, sink-direct required rule/shape constants, and JSON renderer diagnostics (`skinny/REDRESS.md:2436`, `skinny/REDRESS.md:2455`). The current passes tests prove materialization derives from structure under renamed rules (`skinny/crates/passes/src/lib.rs:1349`).

- Treat diagnostics as non-behavioral unless an xtask gate consumes them. The current pass already returns diagnostics alongside output (`skinny/crates/passes/src/lib.rs:49`, `skinny/crates/passes/src/lib.rs:53`); W9 should keep parser selection stable and let `gate-json --with-cost-facts` decide whether missing evidence is a CI failure.
