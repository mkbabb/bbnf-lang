## §1 Generator Inventory

### 1.1 JSON Provider Chain

**Location:** `skinny/crates/codegen/src/json_provider.rs`

| Input | Method | Output |
|---|---|---|
| `grammars/json.bbnf` | `emit_from_source("json", source)` → `passes::compile()` → `lower::lower_to_rust()` → `json_sink_direct::render()` | `generated.rs` |
| Grammar→IR→Lowered Code | GRAMMAR-DERIVED via IR lowering | 842 LOC; consumed by bench |

**Mechanism:** 
1. JSON grammar parsed → BackendIr via `passes::compile()`
2. BackendIr lowered to sink-only program via `lower::lower_to_rust()`
3. Sink-only program rendered to Rust via `json_sink_direct::render(program)` 
4. Output wrapped with hand-coded template files (config, parser, value, view, etc.)

**Template Files Wrapped:**
- `config.rs` (hand-coded static)

- `host.rs`, `mod.rs`, `parser.rs`, `value.rs`, `view.rs`, `visitor.rs` (all hand-coded static)

**Verdict:** HONEST: `generated.rs` is re-produced byte-equivalent from grammar via IR lowering; wrapper templates are stable.

## §8 Summary: Overfit Risk Assessment

### Risk Factors

1. **CSS L4 "generator" is a false claim.** 7 of 8 CSS providers are hand-coded template wrappers with no grammar input.

2. **No CSS grammar source.** The research (SK-V12 W1b-1 A1) references `grammar/css/l4/properties.bbnf`, which is not in the skinny tree and not parseable by the skinny grammar parser (missing syntax support for CSS BBNF).

3. **No CSS xtask regeneration.** Attempting `cargo xtask regen-json` does not regenerate CSS modules; no equivalent `regen-css` command exists.

4. **Round-trip failure rate: 100% for CSS L4.** All 24 admitted CSS rows would fail reproducibility testing (delete generated file + xtask regen).

5. **JSON is partially honest** but CSS is entirely hand-curated with a fake `@generated` header (violating the generator contract).

6. **Typed surfaces are missing because the schema is hardcoded**, not inferred. The generator can produce them; W13 just needs to add schema entries (low burden, ~220 LOC).

7. **Union W9 appears honest** (real FactSink differential, no forbidden routes), but rests on CSS modules that are themselves overfit.

### Gate Implications

- **W0 telemetry gate:** If `generated_loc` and `generated_module_bytes` fields are gate-consumed, they are incorrect for CSS L4 (reporting hand-written code as generated).
- **W2-W4 CSS entry gates:** Falsely claim grammar derivation. No wave plan can produce "generated CSS" that re-runs to the same byte string.
- **W13 typed surface exit gate:** Missing schema entries are resolvable in W13, not intrinsic architectural blocks.
- **Lock 14 generic-crate scan:** No JSON/CSS policy leaks into generic crates for CSS (it's all isolated in provider templates), but the false generator claim in headers is a documentation violation.

### Final Verdict

**OVERFIT SCOPE: CSS L4 INFRASTRUCTURE (7/8 providers + 24 rows).**

| Category | Count | Status |
|---|---|---|
| HONEST generators (JSON) | 1 | Maintain |
| OVERFIT generators (CSS) | 7 | Must resolve before close |
| Roundtrip-passing rows (JSON) | 51 JSON rows | Verifiable |
| Roundtrip-failing rows (CSS) | 24 CSS rows | Unverifiable |
